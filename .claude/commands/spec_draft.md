暫定仕様書を `instructions/history/NN_<topic>.md` へ起票してください。
暫定仕様書は **暫定仕様先行モード**（`.claude/rules/spec_change_workflow.md`）の主入力であり、
そのフェーズの**確定設計**として実装が従う文書。フェーズ末に正本
`instructions/common/spec_detail/` へ昇格・本書は凍結する。

## 前提確認（起票前）

1. **モード選択の確認**: `.claude/rules/spec_change_workflow.md`「モードの選択」に照らし、
   直接改訂モードで足りる案件（単一ファイル・少数条項・文言確定済・タスク 1〜2）なら
   暫定仕様書は起票しない（正本を直接改訂するフローへ）。迷ったら暫定仕様先行に倒す。
2. **採番**: `instructions/history/` 内の最大番号 + 1（phase 番号・decisions 番号とは独立採番）。
3. **起票元の確認**: idea からの昇格ならその idea を読む。ユーザー要望なら確定済み事項と
   未確定事項を切り分けておく。

## ファイル書式（`instructions/history/NN_<topic>.md`）

```markdown
# 暫定仕様 NN: <題名>（<topic>）

> 状態: **未凍結・vX.Y・主入力**。本書がこのフェーズの確定設計（フェーズ中は正本を直接改訂しない）。
> フェーズ末タスクで正本 `instructions/common/spec_detail/` へ昇格し本書を凍結する。
> 起票元: <ユーザー要望（YYYY-MM-DD・経緯）/ idea_NN / phase NN からの分離 等>。

---

## §1 目的 / 背景

（何を実現するか + ### 現状監査（YYYY-MM-DD）: 現実装・現仕様の裏取り。関連ファイル /
正本の該当節を挙げる）

## §2 確定事項（ユーザー YYYY-MM-DD）

（ユーザーと合意済みの決定。箇条書き・**太字**で要点）

## §3〜 設計本文

（データモデル / 操作フロー / UI / エラー処理等を節分けして規定。案が割れる箇所は
案 A/B を併記し推奨を明示）

## §N 確認事項（ユーザー判断・未確定がある場合のみ）

（未確定でユーザーの判断が要る点。各項に提案と理由を付ける。確定したら §2 へ移す）

## §N+1 受け入れ条件（ドラフト）

（フェーズ完了を判定できる具体条件。各条件に対応 § を付記）

## §N+2 スコープ外（本フェーズでやらない）

（後送り事項。関連 idea があればリンク）

## §N+3 正本反映（フェーズ末昇格・予定）

（正本 spec_detail の改訂対象ファイル・節 / 実装ファイル / テスト・fixture / 別実装同期
= 影響範囲。昇格タスクの入力になる）

## 関連

（関連 idea / 過去フェーズ / 正本の該当節へのリンク）
```

※ §構成は例示。案件に応じて増減してよいが、
「確定事項」「受け入れ条件」「スコープ外」「正本反映（予定）」は必ず置く。

## バージョン運用

- 起票 = **v0.1**。起票時に **`deep-reviewer` エージェントで別視点レビューを 1 回実施**し、
  指摘を反映して版を上げる（例: v0.1「修正して採用」→ v0.2「採用」）。
- ユーザー確定・設計議論の反映ごとに vX.Y を上げ、ヘッダの状態行を更新する
  （「ユーザー確定済・実装着手可」等）。
- フェーズ中の設計微修正は本書を改訂する（正本は触らない）。
- フェーズ末（正本反映タスク）: 正本へ昇格 → ヘッダを
  「**凍結（YYYY-MM-DD・正本反映済）**。正本が最新。本書は経緯記録として凍結」へ書き換える。
  凍結後の編集は禁止。

## 付随更新

- idea からの昇格時: `instructions/backlog/INDEX.md` の該当行の状態を
  「**着手**（→ 暫定仕様 [NN]）」へ更新する（**暫定仕様リンクのみ**。この時点で phase
  フォルダは未存在のため、phase リンクは `/phase_start` の前提 4 で補完する）。
- フェーズと同時起票の場合はフェーズ側（/phase_start）から本書をリンクし、
  「番号対応: phase NN / 暫定 NN / decisions NN」を両方に明記する。

## 禁止事項

- 暫定仕様の確定前に実装へ着手すること（設計先行の不変原則）
- フェーズ中に正本 `spec_detail/` を直接改訂すること（昇格はフェーズ末に一度・原子的に）
- 凍結済み暫定仕様書（本フォルダの過去文書）を編集すること
- 起票時 `deep-reviewer` レビューの省略
- ユーザー未確定の事項を「確定事項」に書くこと（確認事項 § へ分離する）
