ユーザーがこれから不在になる（寝る・出かける）。以下の運用に切り替えてください。

引数: 戻る予定時刻（任意。例 `08:00` / `7:30` / `2h`）。$ARGUMENTS

## 切り替え時（すぐ行う）

1. 戻る予定時刻を絶対時刻にする（今の時刻は `date` で実測。`2h` のような相対指定は今の時刻に足す）。指定が無ければ「未定」
2. `.claude_data/state/session.md` の `## current` に 1 行書く（会話が要約されても忘れないため）:
   `presence: away（戻る予定 YYYY-MM-DDTHH:MM / 未定）`
3. 「不在モードにした・戻る予定・今やっている作業をどこまで進めるか」を 1〜2 行で返し、作業を続ける

## 不在の間の進め方

- タスクは通常どおり進める（フェーズ内のタスクの連続実行の許可・自動コミットの運用はそのまま）
- **ユーザーの判断が要る所**（仕様の確定・Codex レビュー指摘の採否・実機目視・フォールバックの許可・スペックフラグ 等）に当たったら、それより先へ進まず次で振り分ける:
  1. `date` で今の時刻を実測する
  2. **戻る予定まで 1 時間以内** → その場で質問を出して待つ（続けて再開すれば会話の読み直しが安く済む範囲）
  3. **1 時間より先 / 戻る予定が未定** → 終了処理（下記）をして止まる
- 判断待ちとは関係なく、長い待ち（数時間かかる処理の完了待ち等）に入る場合も同じ振り分けをする

## 終了処理

1. 確認したいことを、ユーザーが起きてすぐ答えられる形（選択肢と推奨・根拠の `ファイル:行`）にまとめる
2. `/save_state` を行い、`next_action` の先頭にその確認事項（またはその置き場所）を書く。`presence` 行はそのまま残す
3. `/save_handoff` を行う（確認事項が handoff.md の「次アクション」に載ること）
4. state ファイルの更新をコミットする（push はしない）
5. 最後の応答は短く: 「どこまで進んだか / 何の判断待ちか / 新しいセッションで再開すれば handoff から続く」

## 注意

- 不在を理由に、判断の要る事項を推測で進めない（判断を先取りしない・仕様を緩めない）
- 実行中の委任（サブエージェント）がある場合は、結果を受け取ってから終了処理をする（途中で放置しない）
- 新しいセッションで再開したら、`presence: away` の行は消してよい（再開 = 戻った合図）
