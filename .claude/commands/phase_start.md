新フェーズを起票してください。フォルダ作成 + `phase.md` 起票 + ルーティング / 状態ファイルの
更新までを 1 セットで行う（実装タスクへの着手は含まない）。

## 前提確認（起票前）

1. **ユーザー方針の確認**: 次フェーズが未確定なら、何をやるフェーズかをユーザーに確認してから
   起票する（`instructions/phase/current.md`「作業開始時の指示」）。
2. **採番**: `current.md` 末尾「新フェーズ作成時の更新ルール」の次採番に従う
   （フォルダ実体とも突き合わせる。欠番は current.md の記載が正・再利用しない）。
   フォルダ名は `NN_<topic_snake_case>`。
3. **モード選択**: `.claude/rules/spec_change_workflow.md`「モードの選択」で
   直接改訂 / 暫定仕様先行を判定する。
   - **暫定仕様先行モード**: 先に `/spec_draft` で暫定仕様書を起票し、ユーザー確定
     （実装着手可）まで進めてから本手順に入る（暫定仕様が主入力になる）。
   - **直接改訂モード**: 暫定仕様なし。正本改訂はフェーズ内タスクで行う。
4. **起票元の追従**: idea 由来なら `instructions/backlog/INDEX.md` の該当行を
   「**着手**（→ phase / 暫定仕様リンク）」へ更新する。

## phase.md 書式（`instructions/phase/NN_<topic>/phase.md`）

```markdown
# phase.md

## フェーズ名

<表示名>（<topic>）

## フェーズの目的

（何を実現するか + アーキテクチャ上の方針〔対象レイヤ・スキーマ変更の有無〕を**太字**で）

- 起票元: <ユーザー要望（YYYY-MM-DD）/ idea_NN>。
- 主入力（暫定仕様）: [NN_<topic>.md](../../history/NN_<topic>.md)（vX.Y・ユーザー確定済）
  ※直接改訂モードなら「なし（直接改訂モード）」。
- モード: **暫定仕様先行モード / 直接改訂モード**。番号対応: phase NN / 暫定 NN / decisions NN。

## 確定（ユーザー YYYY-MM-DD）

（ユーザー合意済みの決定事項）

## スコープ

### 含む
### 含まない（後送り）

## このフェーズで読むファイル

（実装時に読む最小限のファイルを番号付きで列挙。広く読まないための絞り込み）

## タスク

（task_01〜 の一覧。1 行ずつ・依存順。最終タスク = 正本反映
〔暫定仕様の昇格・凍結 + decisions_archive + current.md〕を忘れない
※直接改訂モードでも正本反映 / 記録タスクは置く）

## レビュー方針

（このフェーズ固有のレビュー観点。共通観点は `.claude/rules/review.md`）
```

- タスク定義ファイルは `tasks/task_NN_<topic>.md` に置く（起票時に全部作らず、
  着手するタスクから順に起票してよい）。書式は `/task_new`（`.claude/commands/task_new.md`）。

## 付随更新（起票と同時・必須）

1. **`instructions/phase/current.md`**: 「## 現在の参照先」の**先頭**に新フェーズの項を追加
   （直前完了フェーズの項は残してよい。完了フェーズの整理は current.md「フェーズ完了時の指示」に従う）。書くのは概要・確定事項・リンク（phase.md / 暫定仕様 /
   判断アーカイブ / 起票元）・番号対応まで。**実装順序・タスク詳細・チェック内容は書かない**
   （current.md 末尾「注意」）。末尾の次採番の記述も更新する。
2. **起票内容のレビュー**: phase.md（+ 暫定仕様が新規ならそちらも /spec_draft 側で実施済み）に
   ついて reviewer エージェントで別視点レビューを 1 回実施し、指摘を反映する。

※ 進捗記録は current.md へ一本化する。

## フェーズ完了時（参考・本コマンドの範囲外）

- 正本反映タスク完了後に `/refactor_check` を実行してから完了扱いにする（CLAUDE.md）。
- `decisions_archive/<NN_topic>.md` の作成・current.md の完了記載・暫定仕様の凍結は
  最終タスク（正本反映）に含める。

## 禁止事項

- 次フェーズ未確定のままユーザー確認なしに起票すること
- 暫定仕様先行モードで暫定仕様の確定前にタスクへ着手すること
- current.md へタスク詳細・チェック内容を書くこと
- 採番の重複 / 欠番の再利用
- 起票と同時に実装を始めること（タスク実行は `.claude/rules/task_execution.md` の手順で別途）
