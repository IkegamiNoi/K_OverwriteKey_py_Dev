---

`instructions/common/spec_detail/` の正本仕様書の肥大化を判定し、必要なら
「肥大部分を INDEX に置き換え、同名フォルダ配下へ節単位で外出しする」分割を行ってください。
**分割計画の提示 → ユーザー承認 → 実施** の順を守り、承認前に正本を変更しないこと。

規模の大きい一括分割は先に計画書（`instructions/modified_proposal/NN_spec_split_plan.md`）を
起票して承認を得る。本コマンドは通常の**運用**（新たに肥大したファイル/節の分割）を担う。

## 不変条件（すべての分割で厳守）

1. **「ファイル名 + 節番号」の対応を維持する**。凍結文書
   （`decisions_archive/` / `instructions/history/` / phase 文書）は正本を
   「`<ファイル名> §N.M`」形式で参照しており、凍結文書は編集できない。
   節番号・見出しテキストは変更禁止。既存参照の書き換えは行わない（INDEX 経由で解決する）。
2. **本文は verbatim 外出し**。子ファイルの内容は元ファイルの該当行範囲とバイト一致させる
   （見出しレベルも変えない。前書き・frontmatter を足さない）。
3. **仕様内容を変えない**。分割はファイル構造の変更であって仕様変更ではない。
   stale な記述を見つけても直さず、報告のみ（修正は `spec_change_workflow.md` のフローで
   ユーザーが判断する）。
4. **凍結文書（`instructions/history/` の暫定仕様を含む）は分割対象外**。
5. 親（INDEX）ファイルは `spec_detail/` 直下に残す（`file_organization_rules.md` 末尾
   「本リポジトリへの適用注記」の正本ドキュメント例外 = 参照パス安定を優先）。

## 判定（いつ分割するか）

対象ファイルが以下のいずれかに該当したら分割を提案する:

- ファイルが **300 行超**
- 単一の節が **100 行超**でフェーズごとに成長している
- 追記型の節（同期メモ・履歴的な注記）が正本本文の中で増え続けている

該当しても、直近フェーズで触っていない安定したファイルは急がなくてよい
（正本反映で開くタイミングに合わせるとレビューしやすい）。

## 肥大の 3 分類と分割方式

| 分類 | 状態 | 方式 |
|---|---|---|
| 特定節に集中 | 1 つの節だけが数百行に成長 | 当該節のみ INDEX 置換 + 小節を外出し。他の節は親に残す |
| 全体に分散 | 多数の節が均等に大きい | 全節を外出しし親を完全 INDEX 化 |
| 追記型ログ | 同期メモ・履歴的注記が本文中で成長し続ける | ログ全体を 1 ファイルへ分離し、以後の追記先をそちらに固定 |

## 命名・INDEX 規則

- フォルダ = 親ファイル名（拡張子なし）: `spec_detail/<parent>/`
- 子ファイル = **ゼロ埋め節番号 + 内容 slug**: `5_01_<topic>.md` / `4_10_<topic>.md`
  （`5.1_xxx.md` 形式は文字列ソートで 5.1, 5.10, ..., 5.2 と並ぶため禁止）。
  節番号を持たない節は内容 slug のみ（例: `sync_notes.md`）とする
- INDEX 行の形式（親ファイルの元の節位置に置く）:

  ```markdown
  - [5.13 <節タイトル>](<parent>/5_13_<topic>.md) — <節の内容の 1 行要約>
  ```

  1 行要約は節冒頭の「目的」「定義」から機械的に要約する。**新しい仕様判断を含めない**
  （迷ったら節タイトルの言い換えでよい）。要約は「AI がどの子ファイルを開くべきか」を
  判断する材料であり、INDEX 化の価値の半分を担う。

## 手順

1. **実測**: `wc -l` と `grep -n "^## \|^### "` で対象ファイルの節構造・行範囲を確定する
2. **計画提示**: 分割対象の節 / 行範囲 / 子ファイル名の対応表と、親に残すものを提示して
   ユーザー承認を得る（規模が大きい場合は `instructions/modified_proposal/NN_*.md` に起票）
3. **実施**: verbatim 外出し → 親へ INDEX 行を配置。1 ファイル（親 1 つ分）= 1 コミット
4. **検証**（必須）:
   - 子ファイルごとに分割前コミットの該当行範囲と diff → バイト一致
     （`git show <分割前コミット>:<親パス> | sed -n '<a>,<b>p' | diff - <子パス>`）
   - INDEX 内の全リンク先ファイルが存在する
   - 節見出しの集合が分割前後で不変（`grep -h "^## \|^### "` を親+子で結合して比較。
     ユーザー承認済みの見出し補完〔欠落親見出しの追加等〕がある場合はその分のみ差を許容）
   - ⚠ 改行コード: リポジトリの改行設定（`core.autocrlf` 等）によっては working tree が CRLF・
     `git show` 出力が LF となり偽陽性差分が出る。**子ファイルは
     `git show <分割前>:<親> | sed -n 'a,bp' > <子>` で生成**し、必要に応じて diff に
     `--strip-trailing-cr` を付ける（working tree からのコピペ生成は禁止）
5. **記録**: `.claude_data/state/decisions.md` に分割実施を 1 行記録する
   （構造変更であり仕様変更ではない旨を添える）

## 分割後の運用（正本反映タスクへの影響）

- 仕様更新は**子ファイルを編集**する。節の趣旨が変わったら親 INDEX の 1 行要約も追従させる
- 新しい節の追加 = 子ファイルの新規作成 + 親 INDEX へ 1 行追加（採番は既存の連番に続ける）
- 別実装との同期メモは正本本文に書かず、専用のノートファイルへ分離する
- 子ファイルがさらに 300 行超に育ったら本コマンドで再分割を検討する

## 禁止事項

- ユーザー承認なしに正本の構造を変えること
- 仕様内容・節番号・見出しテキストの変更（分割に伴う機械的な移動を除く）
- 凍結文書（decisions_archive / history / phase 文書）の編集
- 均等分割（節の途中で切る・複数節を意味と無関係に束ねる）
- INDEX の 1 行要約に仕様判断・新解釈を書き込むこと
