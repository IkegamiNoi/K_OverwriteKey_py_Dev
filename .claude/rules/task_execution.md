# タスク進行ルール（要点版）

想定外の先行実装への対応手順・判定基準の詳細は
`instructions/common/rules_detail/task_execution.md`（必要時のみ読む）。

## ■ 基本方針

- タスクは番号順（または定められた順序）に進め、未完了タスクを飛ばさない
- 1タスクずつ区切って完結させる
- 後続タスクの先取り・タスクに明記されていない拡張をしない

## ■ タスク開始時

1. 対象のタスク定義ファイルを読む
2. 関連する共通ルール・チェック観点を読む
3. 必要な既存コードのみ読む（広い調査は `Explore` エージェントへ委任 — `agent_selection.md`）
4. 実装対象と非対象を整理する

禁止: 関連が薄いファイルの広読み / 後続タスクの詳細読み / 実装前の広範囲リファクタ

## ■ 各タスクの進め方（この順で）

1. 実装対象の整理 → 2. 最小差分で実装 → 3. 動作確認または静的確認 → 4. チェック実施 →
5. 必要修正 → 6. 完了判定

実装時: 変更は必要最小限 / 既存構造を壊さない / 無関係な整形変更を含めない /
新規ファイルは最小限 / 仮実装を残したまま完了扱いにしない

## ■ 完了判定

以下を**すべて**満たした場合のみ完了とする:
タスク記載内容を満たす / 明確な破綻がない / 指定チェックを実施した / 必要な修正を反映した /
次タスクへ進める状態である

## ■ タスク完了時の報告

対応タスク / 実施内容 / 変更ファイル / 確認内容 / チェック結果 / 残課題 を簡潔に出力する。
想定外の先行実装があった場合は、その有無・確認範囲・判定結果・完了根拠も含める。

## ■ フェーズ完了時（最終タスク = 正本反映タスクの完了条件）

フェーズの最終タスクには以下を含め、実施するまでフェーズを完了扱いにしない。

- 暫定仕様先行モードの場合: 正本 `instructions/common/spec_detail/` への昇格 + 暫定仕様書の凍結
- `.claude_data/state/decisions_archive/<NN_topic>.md` の作成（判断履歴の集約）
- `instructions/phase/current.md` の完了記載更新（次採番の明記）
- 起票元 idea がある場合: `instructions/backlog/INDEX.md` の該当行を完了 / クローズ状態に
  更新して `instructions/backlog/INDEX_done.md` へ移動する
- `/refactor_check` の実行と、判定結果の完了報告への記載（CLAUDE.md）

---

## ■ 禁止事項

- タスク未完了のまま次へ進む / 実装より先に大規模整理を始める
- 仕様不明部分を勝手な判断で拡張する / 「あとで直す」前提で完了扱いにする

## ■ 想定外の先行実装を発見した場合（要点）

1. **新規実装をいったん止める**。現在タスクに関係する範囲だけを確認する
2. 発見した差分をタスク単位で整理し、**採用 / 修正して採用 / 保留 / 除外** で判定する
3. 必要な最小修正のみ行い、チェックとレビューを通したものだけ完了扱いにする
4. 後続タスク相当の実装が既にあっても自動で完了扱いにしない。勝手に広く巻き戻さない・即削除しない
5. 迷ったら広げず、現在タスクを成立させる最小対応を優先する

対応手順・4区分の判定基準の詳細は rules_detail を参照。
