# アンチパターン集

## ■ よくあるミス

1. **後続タスクの先取り実装** — 未要求の機能を親切で追加する / 将来必要そうという理由で広く実装する
2. **無関係なリファクタ** — タスクと無関係な命名変更 / 分割・統合の同時着手 / 全体整理を優先して本題が遅れる
3. **過剰な共通化** — 1箇所でしか使わないものの共通化 / 将来想定しすぎの抽象化増殖
4. **責務の混在** — UI層に業務ロジック / 状態管理・イベント処理に描画都合の処理 / ドメイン層にUIライブラリ依存
5. **必要以上のファイル読込** — 対象外ディレクトリ・関係の薄い task・生成物やキャッシュまで読む
6. **チェック省略** — 未確認で次へ進む / 無レビューで完了扱い / 確認結果を出さない
7. **大きすぎる差分** — 小修正なのに複数レイヤー同時変更 / 原因箇所が狭いのに広く触る
8. **仮置きの放置** — TODO・一時コード・デバッグ出力・暫定分岐を残したまま完了扱いにする
9. **想定外の先行実装をそのまま採用** — 影響範囲を確認せず取り込む / 出所不明の差分を即削除・即採用する /
   task 単位の確認・レビューを省略する
   → 回避: 新規実装をいったん止め、現在 task に関係する範囲だけ確認し、差分を
   「採用 / 修正して採用 / 保留 / 除外」で整理する（手順詳細は `.claude/rules/task_execution.md`）
10. **言語特有の雑な実装** — 1ファイルにUI・状態・描画・保存を詰め込む / グローバル変数で状態持ち回り /
    型注釈なしの複雑データ構造 / 例外の握りつぶし / 安易な外部ライブラリ追加

---

## ■ 判断に迷った時

以下を優先すること。

1. 今のタスクに必要か
2. 最小差分で済むか
3. 既存構造を壊さないか
4. チェックで説明できるか

上記で迷う場合は、広げず小さく実装すること。
