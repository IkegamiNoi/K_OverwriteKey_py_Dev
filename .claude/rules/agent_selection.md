# エージェント選択ルール（Codex 併用モード）

作業種別ごとの「メインセッションで行うか / どのサブエージェントへ委任するか」の基準。
実装は Codex を既定とし、Claude 系エージェントはフォールバックとする。
（非 Codex 環境向け構成への切り替えは `instructions/agent_mode/switch_agent_mode.py`）

> **Codex CLI ランタイム（companion）の操作**（ジョブが詰まった / cancel が効かない /
> ハングを検知したい / state を手修復したい）は `instructions/common/rules_detail/codex_operations.md`
> を参照する（必要時のみ）。要点: ①Codex の自己申告を信じず必ず verifier で `.venv` 再実行
> ②ハング検知はログ停滞で見る（`wait` キーワードでは判定不可）③Bash から cancel するときは
> `MSYS_NO_PATHCONV=1` をその一発だけ前置き ④PID 消滅ジョブは state 手修復。

---

## ■ 実装（コードを書く作業）

### 既定: `codex-implementer`

- タスク定義に基づく実装は、原則 `codex-implementer` エージェントへ委任する
- 呼び出し時は以下をプロンプトに含める
  - 対象タスク定義ファイルのパス
  - 実装対象範囲と対象外の明記
  - **タスクに対応する単体テストの実行まで**を実装範囲に含めること

### フォールバック: `implementer`（Claude）

`codex-implementer` が使用できない場合（Codex CLI 未導入・認証エラー・実行失敗・
プラグイン無効等）は、**無断で切り替えず、必ずユーザーに確認して許可を得てから**
`implementer` エージェントを使用する。

- 確認時は「Codex が使えない理由」と「Claude エージェントで代替してよいか」を提示する
- 許可なくメインセッション自身が代わりに実装するのも不可（フォールバック確認の回避になる）

### メインセッションが直接行ってよい作業

- 数行程度の軽微な修正（typo・定数値・ドキュメント修正等）
- state ファイル（`.claude_data/state/` 配下）やタスク文書の更新
- フェーズ末の正本反映タスク（ユーザー承認済み内容の `spec_detail/` への転記。文書作業のため）

## ■ 起票・調査

- 暫定仕様書・phase.md・タスク分割の起票は**メインセッション**が行う
  （ユーザーとの反復確定が必要なため）
- 起票前の既存コード調査・影響範囲調査・「このフェーズで読むファイル」選定は、
  読み取り専用の **`Explore` エージェント**へ委任し、結論（ファイルパス + 要点）のみ受け取る。
  メインセッションがソースを広く直読みしてコンテキストを肥大させない。
  ただし**対象が数ファイルに特定済みなら委任せずメインで直読みする**（委任量の抑制は
  `.claude/rules/output_style.md`）

---

## ■ 動作確認・テスト実行

- タスク単位の単体テスト実行は実装委任に含める（上記 codex-implementer への指示事項）
- 統合確認（テストスイート全体・smoke 等）は **`verifier` エージェント**へ
  委任し、メインセッションは pass/fail + 失敗詳細の要約のみ受け取る
  （テストの生ログをメイン文脈へ載せない）。判定・完了宣言はメインセッションが行う
- `/refactor_check` のメトリクス収集（手順 1〜2・M1〜M6）も `verifier` へ委任する
  （判定〔手順 3 以降〕と提案書起票はメイン）
- 実機目視はユーザーが行い、結果をメインセッションへ報告する

## ■ レビュー

| タイミング | 使用エージェント |
|---|---|
| 各タスクの必須レビュー（CLAUDE.md「レビュー（必須）」） | `reviewer`（Claude・`.claude/rules/review.md` の5観点） |
| 暫定仕様書のユーザー確定前 | `codex-adversarial-reviewer`（focus text で仕様レビュー観点を指定） |
| 統合テスト・複数タスクを跨ぐ動作確認時 | `codex-reviewer`（標準レビュー） |
| フェーズ完了判定前・設計判断に不安がある時 | `codex-adversarial-reviewer`（敵対的レビュー） |

- **レビュー・検証エージェントの起動はメインセッションの責務**。サブエージェントはサブエージェントを
  起動できないため、implementer 等へ「reviewer に依頼せよ」と指示しない（実行不能・自己申告の温床）
- タスク単位は実装者（Codex）とレビュアー（Claude）が別モデルになるため、別視点レビューとして成立する
- **暫定仕様レビュー**の focus text 例: 「`instructions/history/NN_<topic>.md` の仕様内容を対象に、
  前提の誤り・未定義挙動・条項間の矛盾・実装可能性・正本 spec_detail との整合を疑う」。
  対象ファイルが未コミットなら working-tree のまま、コミット済みなら `--base` を指定する
- Codex レビューの指摘は提示のみで、修正・採否はユーザー確認を経て決める
  （各エージェント定義の「提示後は必ず停止」に従う）
- `reviewer` と Codex レビューは補完関係。どちらか一方だけで完了判定を確定させない
- Codex レビューが使用できない場合は、その旨を報告した上で `reviewer` のみへ縮退してよい
  （レビューはユーザー許可なしで縮退可）。暫定仕様レビューを縮退する場合は、
  仕様レビュー観点（前提・未定義挙動・矛盾・実装可能性・正本整合）を明示して `reviewer` へ渡す

---

## ■ 禁止事項

- Codex が使えないことを理由に、ユーザー確認なしで Claude 系エージェント
  またはメインセッション自身による実装へ切り替えること
- `codex-implementer` の結果を無レビューで完了扱いにすること
- 統合テスト・フェーズ完了時・暫定仕様確定前の Codex レビューを、報告なしに省略すること
