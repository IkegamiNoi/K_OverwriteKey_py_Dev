# 仕様変更ワークフロー（要点版）

`instructions/common/`（特に `spec_detail/`）の仕様書と実装の乖離、または新しい仕様判断が
必要になった場合のルール。仕様変更は **ユーザー主導**。Claude は検出と報告に徹し、
勝手に仕様書を書き換えない。
報告テンプレート・手順詳細は `instructions/common/rules_detail/spec_change_workflow.md`（必要時のみ読む）。

---

## ■ 基本原則

### 順序の厳守（不変原則）

**設計を先に確定してから実装する。実装してから仕様を後追いで緩めない**（禁止。別実装との互換が崩れる）。

確定先（authority）は次の 2 モードのいずれか。どちらでも不変原則は同じ
（暫定仕様もそのフェーズの確定設計であり、実装はそれに従う）:

- **直接改訂モード**: 正本 `instructions/common/spec_detail/*.md` を先に確定 → タスク定義 → 検証 →
  実装 → 完了レビュー
- **暫定仕様先行モード**: 暫定仕様書 `instructions/history/NN_<topic>.md` を起票 →
  **敵対的レビュー**（担当エージェントは `.claude/rules/agent_selection.md` の暫定仕様レビュー欄。
  仕様レビュー観点を指定・指摘の採否はユーザー）→
  **ユーザー確定** → タスク定義 → 検証 → 実装 → 完了レビュー →
  **フェーズ末タスクで正本へ反映（昇格）＋暫定仕様を凍結**。
  フェーズ中は正本を直接改訂しない（暫定仕様がそのフェーズの正）

### モードの選択

- **直接改訂**: 局所的（単一ファイル・少数条項）+ 文言確定済み + タスク1〜2 を**すべて**満たすとき
- **暫定仕様先行**: 複数ファイルに跨る / **探索的（ユーザーと反復して詰める。強いトリガ）** /
  タスク3以上 / 別実装同期で正本を原子的に変えたい、の**いずれか**に該当するとき
- **迷ったら暫定仕様先行に倒す**。規模判断に迷う場合はユーザーへ確認する

### 仕様書は「正本」

正本と実装が食い違ったら: **仕様書が正、実装を直す（既定）**。
「仕様書が古い」と判断して仕様書側を更新するのは**ユーザー承認が必須**。
独断で「実装に合わせて仕様書を緩める」ことは禁止。

## ■ 検出基準（フラグを立てるべき状態）

以下を発見したら**作業を止めてユーザーに報告**する（詳細例は rules_detail 参照）。

- **A. 仕様書 vs 実装の乖離** — 挙動不一致・サンプル不一致・制約未達
- **B. 仕様書の不備** — 未定義挙動・矛盾・実装不可能な要件
- **C. 設計判断の波及** — レビューの「仕様書側で再検討推奨」・スコープ変更・別実装との整合選択
- **D. 危険な誘惑** — 「実装が楽になるから仕様書を緩めたい」「無視しても大丈夫だろう」
  → **D が出た時点で必ず止める。最も事故を起こす経路**

報告は rules_detail の「仕様変更フラグ」フォーマット（検出状態 / 該当箇所 / ズレ内容 /
選択肢 A・B・C / 推奨 / 影響範囲）に従い、報告後は**ユーザーの判断を待つ**。

---

## ■ ユーザー判断後

- **(A) 仕様書更新** → `/spec_update`（`.claude/commands/spec_update.md`）で影響範囲提示 →
  正本更新 → decisions.md 記録 → タスク更新 →（必要なら）再検証タスク起票。手順詳細は rules_detail
- **(B) 実装修正** → 仕様書は無修正。`task_execution.md` に従い実装エージェントへ修正依頼
  （既定エージェントは `.claude/rules/agent_selection.md`）。decisions.md 記録は重要判断のみ任意

---

## ■ 禁止事項

- 独断で `spec_detail/*.md` やサンプル（`samples/`）を修正すること
- 「実装に合わせて仕様書を緩める」を提案・実行すること（ユーザー明示指示時のみ可）
- decisions.md への記録なしに仕様判断を行うこと
- 設計（正本または暫定仕様書）を確定せずに実装を先行させる／確定済み設計を実装都合で後から緩めること
  （暫定仕様先行の「フェーズ末昇格」は設計を先に確定済みなのでこれに当たらない）

---

## ■ 分割後の正本構造（INDEX 化）

正本が肥大化した場合は INDEX 化して分割できる。分割後は実体が同名フォルダ配下の子ファイル
（本文がリンク + 1 行要約なら INDEX）。仕様更新は**子ファイルを編集**し、趣旨が変われば
親 INDEX の 1 行要約も追従。新節は子を新規作成し親へ 1 行追加（命名は `/spec_split`）。
別実装との同期メモは正本本文に追記せず、専用のノートファイルへ分離する。
節番号・見出しは変更しない。運用詳細は rules_detail を参照。
