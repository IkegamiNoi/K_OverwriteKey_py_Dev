# Python 限定ルール

## ■ 読込範囲

- プロジェクト全体を広く読まず、必要な範囲のみ読む（原則アプリ本体のソース配下）
- **原則読まないもの**: `__pycache__/`・`.pytest_cache/`・`.mypy_cache/`・`.ruff_cache/`・
  `.venv/`・`venv/`・`build/`・`dist/`・自動生成ファイル・キャッシュ・実行ログ・バイナリ成果物
- 依存定義（`requirements.txt` / `pyproject.toml` / `setup.cfg` / `setup.py`）と
  実行環境・ビルド関連ファイルは必要時のみ参照する

## ■ 依存追加

- 必要性がある場合のみ。標準ライブラリ・既存依存で実現できるなら追加しない
- 小さな修正のために新規ライブラリを導入しない

## ■ 実装・アーキテクチャ

- UI処理と業務ロジックを混在させない（画面側・イベント層にコアロジックを直接書かない）
- core / domain 相当層にUIライブラリ依存を持ち込まない
- UI層から永続化層・外部I/Oの具象実装を無秩序に直接参照しない
- 入力処理・状態管理・描画・保存処理の責務を混在させない。状態変更の入口を散らさない
- 座標変換・入力解釈のような中核ロジックは再利用可能な形で管理する
- データ構造は明示し、必要に応じて型注釈を付ける
- 例外は握りつぶさず、失敗理由が追える形にする
- 共通化が必要なものだけを共通化する。小さな修正のために大規模構造変更をしない

## ■ python 実行コマンド（EDIT REQUIRED）

> プロジェクト初期化時に、この環境で使う python 実行コマンド（例: `py.exe` の絶対パス、
> `.venv` の python 等）をここに記載する。

## ■ テスト・確認

- 変更箇所に応じて最小限の確認を行う。静的確認・簡易実行確認を省略しない
- 失敗している既存テストは、今回変更との関係を切り分けて報告する
- 新規テストは必要なものだけ追加する

## ■ 禁止事項

- キャッシュ・生成物の手編集 / 仮想環境配下の不要な横断
- UI都合だけで依存方向を壊すこと / 単純な修正への外部ライブラリ追加
- 1ファイルへの責務の過剰集中
