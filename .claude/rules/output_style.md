# 応答・成果物の作法（要点版）

対象は**出力の量と形**（会話応答 / 進捗報告 / 文書成果物 / 委任量）。
実装内容の是非は `implementation.md` / `anti_patterns.md` が正。
Opus 系は放置すると「応答が長い・実況が多い・文書が膨らむ・委任しすぎる」方向へ寄るため、
ここで明示的に抑える。

## ■ 会話応答

- 焦点を絞り簡潔に。前置き・注意書き・免責は短くし、文量は主要な回答に割く
- 説明を求められたら高レベルの要約で答える。詳細な解説は明示的に要求された時のみ
- 選択肢の網羅列挙より、推奨案を1つ示す（採否はユーザー）

## ■ 作業中の進捗報告

- 最初のツール呼び出し前に、これからやることを1文で述べる
- 作業中は**重要な発見・方針転換があった時だけ**短く報告する（各手順の逐次実況はしない）
- 完了時は結論から書く。1文目で「何をしたか / 何が分かったか」、根拠と詳細はその後

## ■ 文書成果物の分量（`.claude_data/state/` ・ `instructions/` 配下の .md）

- 必要な内容は落とさず、埋め草の節・重複した要約・定型文で嵩増ししない
- 各コマンド/テンプレの分量指定（`/save_state` の3行要約・`/idea` の2〜4行 等）が優先
- `.claude/rules/` ・ handoff.md ・ session.md は要点版として維持し、詳細は
  `instructions/common/rules_detail/` や履歴側へ外出しする

## ■ 自己訂正の言及

- 直前の自分の発言を訂正するのは、ユーザーの判断・コード・結論が変わる場合のみ
- 訂正は事実を短く述べて作業を続ける。影響のない言い直しは黙って直して進む
- 経緯の詳説・反省・過去ミスの棚卸しはしない

## ■ 委任量の抑制

`.claude/rules/agent_selection.md` が「どれを誰へ」の正。ここでは**量**を抑える。

- 自分で数回のツール呼び出しで終わる作業は委任しない（少数ファイルの確認・軽微な文書更新）
- **自分の作業を再確認する目的でサブエージェントを起動しない**
- 1つで足りるなら1つ。同種エージェントを並列多重起動しない
- 例外（自己確認ではなく別モデル/別視点の検証であり、既定どおり維持する）:
  Codex 実装物の検証 = `verifier` / 別視点レビュー = `reviewer` ・ `deep-reviewer` ・ Codex レビュー系 /
  広範囲の探索調査 = `Explore` / タスク実装 = `codex-implementer`

## ■ 検証の重ね過ぎ

- 検証は `agent_selection.md` に定義された工程（単体=実装委任内 / 統合=verifier）だけ行う
- 定義外の「念のためもう1周」を自主的に追加しない。追加が要ると判断したらユーザーへ提案する
