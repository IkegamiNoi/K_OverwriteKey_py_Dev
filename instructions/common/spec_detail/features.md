## 4. 機能要件

### 4.1 トリガー

* 複数トリガーを登録できる
* トリガーは単キーのみ（停止トリガーも単キー）
* **追加・キー変更でのトリガーの重複は禁止**（重複・優先順位・グレー表示の規則は `key_input.md` §7.3）。キーを変えない編集（ラベル・suppress・シーケンス等）では重複検査をしない
* **同じキーの行**（複製・貼り付け・読込で生じる。phase 43）: 同じトリガー一覧に同じキーの行が複数あれば**一覧で一番上の行が有効な行**、
  下の行は**グレー表示＋理由「上のトリガーと重複」**（`key_input.md` §7.3）。入力判定・呼び出しの解決・キーボード表示・重なりの判定は有効な行で引く。
  並べ替えで有効な行も入れ替わる。一番上の行のアクションが空なら、そのキーはトリガーとして無いものとして扱い下の行も実行しない（置換が動く）
  * **実行中の状態**（4.2.3 の実行位置・周回・保留・戻す履歴・直前のトリガー・保留中のステップ・連続実行中のトリガー・再入防止）は**キー単位**のまま持ち、有効な行のものとして扱う。グレーの行は状態を持たない
  * **有効な行の交代**: トリガーの削除（範囲を含む）・並べ替え・貼り付け・キー変更の前後で「キー → 有効な行の実体」を比べ、別の既存の行に入れ替わったキーは、
    その状態を**トリガーの削除と同じ処理で消す**（次に有効になった行は状態なしから始まる）。**保存・読込は交代の契機にしない**。
    キーが一覧から無くなる場合は交代ではなく、現行の削除・キー変更の扱い（有効な行のキーを変えたら旧キーの状態を新キーへ移す。旧キーに下の行が残れば旧キーは交代）
  * **交代するキーに進行中の実行があるときは、その操作をしない**（理由を一時メッセージに出す）。進行中 = 連続実行の実行中・一時停止中 /
    単発の呼び出しの文脈（実行中・一時停止中）/ 保留中のステップ・待ち・file_line の読込で、そのキーが実行元・呼び出し元・呼び出し先のいずれかであるもの。
    呼び出し先は**現在入っているフレーム**の呼び出し先（まだ入っていない呼び出し先は開始時のコピーで動くため対象にしない・4.2.9）
  * グレーの行を選んだとき: シーケンス欄はその行のシーケンスを表示し次に実行の `▶` を出さない / シーケンス欄のクリックで次に実行を変えない / ステータスの次に実行の要約は出さない
  * 重複キーを押したときの案内（`key_input.md` §7.3）は出さない（有効な行が動くため）
* トリガーごとに suppress を制御できる
* **トリガー一覧（と従属する出力シーケンス）はキーマップに従属する**（phase 34・`data_schema.md` §5.13）。
  トリガー一覧・シーケンス欄には**アクティブなキーマップ**のものを表示し、キーマップを切り替えると入れ替わる
  （トリガー一覧を持たないキーマップでは空になり置換だけが効く）。アクティブ以外のキーマップの未保存の編集は切替で失われない。
  シーケンスの実行位置・選択行はトリガー一覧ごとに保持し、保存の前後で保たれる
* 読込等でトリガーが停止 / トグル / 直接切替キーと重なった行は**グレー表示＋理由**（`key_input.md` §7.3）。置換元キーとの重なりではグレーにしない
* **トリガーのキーを変えたら**（変えた行が**変更前のキーで有効な行だった場合だけ**・phase 43）、同じトリガー一覧の全シーケンスの呼び出し（4.2.9）の `target` を新しいキーへ書き換え、書き換えたシーケンスを未保存扱いにする（phase 40）。
  書き換えたトリガーの位置・周回・履歴は消さない（シーケンスの編集の契機に当てない）。既に「参照先なし」だった行が新しいキーと一致した場合もそのまま繋がる（受容）
* 「間隔(ms)」の欄は**連続実行 OFF でも編集できる**（呼び出されたときの間隔にも使う・4.2.9。phase 40）

### 4.2 シーケンス実行

* トリガーに対応する出力シーケンス（アクション列）を実行する
* 連続実行（run_to_end）に対応する
* 連続実行の間隔は `run_to_end_delay_ms`（UI 上は「間隔(ms)」）で指定する
* アクションの種別と JSON は `data_schema.md` §5.11。**通常アクション** = hotkey / text / mouse_click / file_line（入力を送る）/
  **system アクション** = ループ / カウンター / 待機 / 戻す / 先頭へ / 停止 / 呼び出し（§5.11.6）。呼び出しを除く system は入力を送らない
  （呼び出しは他のトリガーの出力シーケンスを実行し、実行の上では通常アクションと同じく押下を消費する・4.2.9）。
  以下は phase 37 で定めた実行の規定（停止は phase 39・4.2.8 / 呼び出しと入力の受け付けは phase 40・4.2.9・4.2.10）

#### 4.2.1 ステップ

* **1 ステップ** = 今の位置から system を順に処理し、最初の通常アクションを 1 つ実行し、続けて**先行処理**（4.2.2）をするまで。
  単発実行 = 1 押下 1 ステップ（**呼び出しを除く system は押下を消費しない**）/ 連続実行 = ステップごとに間隔を置く（system の処理には置かない）
* **呼び出しの行**（phase 40・4.2.9）は通常アクションと同じく、そこで止まって実行し 1 ステップを消費する（ループ・カウンターのように通過しない。10,000 の上限には数えない）
* **ステップの中で送る前に達した待機は、待たずに読み飛ばす**（phase 40。直前に送った行が無いため。一覧で位置を変えた・シーケンスの先頭・連続実行の開始 / 再開の位置が待機、
  カウンター・ループの行の後・続く待機・末尾から先頭への回り込みの後を含む）。読み飛ばしは他の system の行と同じ扱い（10,000 に数える・`ms` が不正ならその場でエラー・開始位置で終える規則もそのまま）
* **末尾に達したら**位置を 0 にし周回を空にする（位置 len は持ち越さない）。単発実行で通常アクションをまだ実行していなければ、同じ押下の中で
  先頭から続ける（1 押下で先頭へ回るのは 1 度だけ。回った後に**この押下の開始位置へ達したら、その行は処理せずに終える**）。連続実行は停止する
* **停止の行**（phase 39・4.2.8）: 連続実行はそこで終える（位置は停止の次・最後の行なら位置 0・周回を空・間隔を置かない）。単発実行は押下を消費せずに読み飛ばす（10,000 の上限には数える）
* **1 ステップで処理する system が 10,000 個を超えたら実行時エラー**（待機をまたいで通算）

#### 4.2.2 先行処理とカウンターの保留

* 通常アクションを実行した直後に、続くループの始まり / 終わりをその場で処理し、カウンターの行（+1 / 0 に）は**値を変えずに位置だけ進めて操作を「保留」に控える**。
  これで一覧の「次に実行」が、次に実際に実行される行を指す
* 戻す / 先頭へ / 呼び出し / エラーになる行に達したら、処理せずその行で止まる（エラーは次の押下で通知）。10,000 に達したら黙って止まる。
  **待機の行**に達したら、送った後の通常の先行処理では**同じステップの中で待つ**（4.2.5・phase 40）。止めた後・停止の行の後の先行処理では待機を読み飛ばす（4.2.5）。
  **停止の行**は、連続実行ならその場で連続実行を終え（4.2.8）、単発実行なら通過する。10,000 に達して止まった直後の停止の行は、次のステップの開始時に処理する（連続実行は間隔を 1 回置いてから終える・受容）。
  末尾では位置 0。単発実行はその押下でまだ先頭へ回っていなければ先頭から続け、連続実行は停止する
* 先行処理は「開始位置で終える」規則の対象外（次のステップの準備）
* **保留はそのトリガーの次のステップの開始時**（周回の整合検査の後・system の処理の前）に順に反映する（待機の続きでは再反映しない）。
  **連続実行が末尾に達して停止するとき・停止の行で終えるとき（4.2.8）は、その場で反映する**（通り過ぎたため）。一覧の `(=値)` と file_line の参照値は、直前に実行した通常アクションの時点の値（現在値）になる（file_line は読込開始時点の値・4.2.7）
  * 例: `[カウンター+1, A]` を単発で押すと、1 回目 = n=1 で A（表示 n=1）/ 2 回目 = 開始時に反映して n=2 で A（表示 n=2）
* ループの周回表示は先行処理の結果（次に実行する周回）を示す

#### 4.2.3 runtime 状態（保存しない）

* トリガーごと（トリガー一覧の実体 + トリガーキー。実行位置と同じ単位・`data_schema.md` §5.13.1。同じキーの行が複数あれば有効な行のもの・4.1）: **ループの周回スタック** / **戻す履歴**（上限 100 段）/ **保留中のカウンター操作**
* アプリ全体: **カウンター**（名前 → 整数・未使用は 0・**起動中だけ保持**。構成セットの読込やキーマップの切替では消さない）/
  **直前のトリガー**（最後に戻す履歴へ 1 段積んだトリガー。状態を変えなかったステップでは更新しない）
* 周回・履歴・保留は実行位置と同じ契機（構成セットの読込等・トリガー一覧の破棄 / 代表の変更・トリガーの削除 / キーの変更・有効な行の交代〔4.1〕）で消す・付け替える。直前のトリガーも同様
* **呼び出し文脈**（呼び出しの開始時点のコピー・呼び出しスタック・4.2.9）と一時停止の状態（4.2.10）も保存しない（phase 40）
* file_line の読込キャッシュ（`data_schema.md` §5.11.7）はアプリ全体で持ち、**構成セットの読込等**で全部捨てる（phase 38）
* **構成セットの読込等では連続実行を停止する**（待機中・file_line の読込中を含む。位置・履歴は既に消えているため、止めるときに位置を戻さず履歴も積まない。phase 38）
* **一覧で位置を変えたとき・シーケンスを編集したとき**（位置や内容が実際に変わったときだけ。フォーカスの同期で同じ行が選び直されただけなら何もしない）は、
  周回を今の位置を囲むループの 1 周目として張り直し、履歴と保留を消す（直前のトリガーだったなら直前も消す）
* ステップの開始時に周回スタックを検証し、今の位置を囲むループの列と合わなければ 1 周目として張り直す（ループの終わりの行は内側・始まりの行は外側。対応が崩れていれば張り直さない）

#### 4.2.4 ループ

* 始まりと終わりの対応は括弧の対応。深さの上限 9。始まりで 1 周目を積み、終わりで周回 < 回数（または無限）なら始まりの次へ戻り、そうでなければ終わりの次へ
* 周回は連続実行の停止・停止の行で終えたとき・一時停止・キーマップの切替・エラーでも保持する（手で位置を変えたときは 4.2.3）
* 実行時エラー（`data_schema.md` §5.11.8）: 対応の無い始まり / 終わり・深さ 9 超・回数不正

#### 4.2.5 待機

* 待機は「直前に送った行と次に送る行の間を空ける」ためのもの（行ごとの個別の間隔）。**直前に送った行の後の待ち**として扱う（phase 40）。
  呼び出しの文脈の中の待機は 4.2.9 の規定による（文脈のステップとして待つ・止めたら打ち切りで呼び出しの行）
* **送った後の先行処理（4.2.2）で待機の行に達したら、同じステップの中で待つ**。通常アクション（file_line・成功した呼び出しを含む）の後が対象。
  待機中の位置（「次に実行」）は**待機の行**。明けたら待機の次から先行処理を続け（続く待機も同じく待つ）、4.2.2 の規則どおり送る行・戻す / 先頭へ・呼び出し・エラーになる行等で止まる
  （連続実行の停止の行は 4.2.8 のまま）
  * 単発実行: UI スレッドを塞がずに待ち、押下はその待機が明けるまで続く。**明けても何も送らない**（次の押下で次の送る行から）。
    待機中は止まっている間（4.2.10: 同じトリガーの押下は無視・他のトリガーは動く・戻す / 先頭への対象なら「待機中」で拒否）。続きは世代番号で守る（取り消し後に呼ばれても何もしない）
  * 連続実行: **待機の前に間隔を置かない**（待機が間隔の代わり）。待ち終えて先行処理を終えたら間隔を足さずに次のステップ。待機に達しなかったステップの後は通常の間隔
  * 末尾での先頭への回り込みは 4.2.2 の規則どおり（単発はその押下でまだ回っていなければ先頭から続け、そこで達した待機も待つ / 連続実行は停止）
  * `ms` が不正な待機に達したら先行処理はその行で止まり、次のステップの開始時にエラー。10,000 の上限（待機をまたいで通算）・カウンター操作の保留（待機をまたいで控え、
    次のステップの開始時に反映）・戻す履歴（ステップ全体で 1 段）は通常どおり
* ステップの中で**送る前に達した待機は読み飛ばす**（4.2.1）
* **待機中に止めたとき**（連続実行の一時停止・停止操作〔フック停止・キーマップ一時停止・UI 編集の一時停止〕・単発の待機の取り消し）:
  待機を**終えた扱い**にし、待機の次から先行処理をして、**続く待機も読み飛ばして**次の送る行で止める（例 `[A, 待機1, 待機2, B]` で待機1の最中に止めたら位置は B）。
  単発・連続実行とも。戻す履歴は状態が変わっていれば 1 段（位置変更・編集で履歴を消す規則が優先）。先行処理で控えたカウンター操作は次のステップの開始時に反映する。
  連続実行の一時停止からの再開は、この位置から通常の間隔の後に続ける。
  この先行処理で停止の行・末尾に達したら、一時停止でも連続実行を終える（4.2.8・例 `[A, 待機, 停止, B]` の待機中に一時停止 → 終えて「次に実行」は B）
  * 単発の待機を**取り消す**契機: フック停止（UI 編集中の一時停止を含む）/ キーマップ一時停止 / キーマップの切替 / 他のトリガーの連続実行の開始 /
    一覧で位置を変えた / シーケンスの編集・トリガーの削除・キーの変更 / 構成セットの読込等。
    このうち位置変更・編集・削除（新しい位置が優先・履歴を消す）と構成セットの読込等（位置と履歴を消す）は「終えた扱い」の対象外で従来どおり
* 連続実行のタイマーも世代番号で守る（停止後に残った予約は新しい連続実行を進めない）

#### 4.2.6 戻す・先頭へ

* 対象 = **直前のトリガー**。**戻す** = 履歴を 1 段降ろし、位置・周回・保留をステップ開始時の状態へ戻し、そのステップのカウンター操作を**差分で打ち消す**
  （+1 → −1 / 0 にした → 0 にする前の値を足す。別のトリガーによる変更は残る。負になってもそのまま）。**先頭へ** = 位置 0・周回・保留・履歴を消す（カウンターは変えない）
* 戻した / 先頭へ移した対象は、押したトリガーの選択の後に一覧で選択する
* 対象が無いとき（未設定 / 自分自身 / アクティブなトリガー一覧に無い）は「戻す対象のトリガーがありません」、対象が単発の待機中なら
  「対象のトリガーが待機中のため操作できません」を一時メッセージで出して何もしない。
  処理中（単発の file_line の読込中・単発の呼び出しの実行中・連続実行の実行中）は、戻す / 先頭へのトリガーの押下自体を無視する（4.2.10。メッセージは出ない）
* 対象が**一時停止中**の連続実行・単発の呼び出しなら **2 回押し**で捨ててから実行する（phase 40・4.2.10）
* **戻す・先頭へは、出力シーケンスにそれ 1 つだけで登録する**（編集で制限・4.6「出力シーケンスの編集」）。手編集で他の行と混ざっていれば、その行で実行時エラー
* 戻す・先頭へによる変更は、それを実行したトリガーの履歴・直前のトリガーに数えない

#### 4.2.7 file_line の読込（phase 38）

* **準備**（オプションの正規化・カウンター名とコールバックの確認・encoding / out_of_range / 行番号の型の検証・カウンター値の取得・パス解決）は UI スレッドで行い、
  準備のエラーはその場で実行時エラー。**読込**（更新の確認・サイズ確認・読込・復号・行への分割）は**ワーカー（デーモンスレッド）**で行い、
  **行の選択と送信**は UI スレッドで行う。ワーカーは Tk を呼ばず、UI スレッドが **50 ms ごと**の確認タイマーで結果を受け取る
* 読込中、そのステップは**保留中**（同じトリガーの押下は無視・位置は file_line の行）。
  単発の読込中は**処理中**として他のトリガーも受け付けない（phase 40・4.2.10）。
  確認は読込ごとの世代（読込トークン）で守り、取り消し・一時停止の後に届いた結果は使わない
* 完了したら同じステップの続き: 成功 = 行を送り、通常アクションの後と同じく先行処理（4.2.2）/ エラー = 実行時エラー（`data_schema.md` §5.11.8・位置は file_line の行）。
  単発で、確認時にそのトリガーが無い / アクティブなトリガー一覧が違うなら、保留を外して何もしない（送らない・履歴を積まない）。
  **戻す履歴はどの経路でも 1 ステップ 1 段**。直前のトリガーは完了した順に更新される（受容）
* 確認のたびに、**届いた結果を上限より優先**する。届いていなければ読込開始（単調時計）から 5 秒以上で上限超過（判定は最大 50 ms 程度遅れ得る）
* 単発の取り消し契機は単発の待機（4.2.5）と同じ（処理中のため他のトリガーの連続実行の開始は起きない）。取り消したら結果を捨て、位置は file_line の行・戻す履歴に 1 段（位置変更・編集で履歴を消す規則が優先）。
  ワーカーは止められないため、取り消しは「結果を使わない」の意味
* 連続実行: 読込中は次のステップを予約しない。完了後は通常アクションの後と同じく間隔を置いて次へ / エラーは停止。
  **一時停止**では結果を捨て、再開は通常の間隔の後に file_line の行から読み直す（ステップの snapshot と途中までのカウンター操作を持ち越し、読み直しを含めて 1 ステップ・1 段）。
  **停止操作**では結果を捨て、1 段積み、位置は file_line の行。完了（成功）は停止の行の読み飛ばしの判定で「通常アクションを送った」に数える（4.2.8）。**読込中に一覧で位置を変えた / シーケンスを編集した**ときは結果を捨て、通常の間隔の後に新しい位置から続ける
  （待機中に位置を変えた場合は、残った待機の予約の後に新しい位置から続く。どちらも止まらずに続行する）。
  完了時にそのトリガーが無い / アクティブなトリガー一覧が読込開始時と違うなら、送らずに停止する（一覧が変わっているため履歴は積まない）。
  エラーの通知は閉じるまで待つため、その間に停止操作・別の連続実行の開始が起き得る。結果を受け取った後に連続実行の世代・キー・読込トークンを照合し直し、変わっていれば状態を変えない
* **同じ読込キー（`data_schema.md` §5.11.7）のワーカーは同時に 1 本**。走っていれば新しい要求は**待ち合わせ**、前の読込が終わってから自分の更新確認を始める
  （前の読込の結果は使わない。複数が待っていれば先に確認タイマーが来た要求から起動）。待ち合わせを含めて要求の開始から 5 秒で上限超過（待ち合わせ中は起動前に判定・印は付けない。
  連続実行の一時停止の後の読み直しは、読み直しの開始から 5 秒）。
  上限超過で残ったワーカーには印を付け、それが終わるまで同じ読込キーの要求は即エラー「前回のファイル読込が終わっていません」。別の読込キーは影響しない

#### 4.2.8 停止（phase 39）

* system の操作 `stop`（`data_schema.md` §5.11.6）。連続実行を区切る。他の行と混ぜてよい（戻す・先頭への単独登録の制限に含めない）
* **連続実行**: 停止の行に達したら連続実行を終える。間隔を置かない。ステップの途中・先行処理（4.2.2）・待機の続きのどこで達しても同じ。
  次の押下で続きをまた連続実行する。停止の手前の保留中のカウンター操作はその場で反映し、そのステップの戻す履歴の差分に含める（戻す履歴は通常どおり 1 ステップ 1 段）
  * 終える前に**停止の次から先行処理（4.2.2）をする**（続くループの行を処理し、カウンターの行を保留に控える・その先行処理で出会った停止の行は通過する・
    **待機の行は待たずに読み飛ばす**〔phase 40・4.2.5。例 `[A, 停止, 待機, B]` → A の後に待たずに終えて「次に実行」は B〕）。
    これで「次に実行」が次に実際に実行される行を指す。先行処理で末尾に達したら位置 0・周回を空にし、保留をその場で反映する。停止の行が最後の行なら位置 0・周回を空
  * 例: `[A, カウンター+1, 停止, B]` → A を送り、+1 を反映して終える（「次に実行」は B）/ `[A, 停止, カウンター+1, B]` → A の後に終え、+1 を保留に控える（「次に実行」は B）/
    3 周ループ `[ループ, A, 停止, ループ終わり]` の 3 周目 → ループを抜けて末尾で位置 0（次の押下は先頭から）
  * 先行処理の上限 10,000 に達して止まった直後の停止の行は、次のステップの開始時に処理する（間隔を 1 回置いてから終える・そのステップの戻す履歴は通常どおり・受容）
* **読み飛ばし**: その連続実行で**まだ通常アクションを送っていない**間に達した停止の行は読み飛ばす（停止の直後から押し直したとき・停止の行を選んで開始したときに何も起きない状態を避ける）
  * 「その連続実行」= 開始から終了（末尾・停止の行・エラー・停止操作・構成セットの読込等）まで。一時停止 → 再開、連続実行中の位置の変更・編集では数え直さない
    （既に何か送った後に停止の行へ位置を移すとそこで終える）
  * 「送った」= hotkey / text / mouse_click の行を実行した（hotkey の検証エラー・座標不正など、**シーケンスが止まらない送信エラーで実際には送らなかった場合も含む**）、
    または file_line の完了（成功。空の行・`empty` で何も送らなかった場合も含む）、または呼び出しの成功（呼び出し先が空でも・phase 40）。
    シーケンスが止まるエラーで終わったもの・打ち切られた呼び出しは数えない
  * 例: `[A, 停止, 停止]` を停止の後から押すと、どちらの停止も読み飛ばして末尾に達し、何も送らずに終わる（位置 0・受容）
* **単発実行**: 読み飛ばす（押下を消費しない・ステップの途中でも先行処理でも通過する）
* 呼び出し先の中の停止は読み飛ばす（4.2.9）

#### 4.2.9 呼び出し（phase 40）

* system の操作 `call`（`data_schema.md` §5.11.6）。**同じトリガー一覧の別トリガー**（`target` = トリガーキー）の出力シーケンスを、**先頭から末尾まで一括で実行**して戻る。
  単発実行でも 1 押下で丸ごと実行する。**呼び出し先トリガー自身の実行位置・周回・保留・戻す履歴は変えない**（カウンターは共有なので呼び出し先のカウンター操作はそのまま効く）。
  停止 / トグル / 直接切替キーと重なってグレー表示のトリガー（4.1）も呼べる（キー入力を経ないため）。**呼び出し先のキーの行が複数あれば有効な行（一番上）を呼ぶ**（重複でグレーの行は呼ばない・phase 43）
* **ステップの消費**（4.2.1）: 呼び出しの行で止まって実行し、1 押下（連続実行の 1 ステップ）を消費する。先行処理も呼び出しの行で止まる。単発の先頭への回り込み・開始位置で終える規則は通常アクションと同じ。
  **成功**したら通常アクションの後と同じく位置を進めて先行処理をする。打ち切り・エラーで終わったら位置は呼び出しの行
* **呼び出し文脈**（runtime・保存しない）: 呼び出し元のトリガー一覧 ID / **開始時点のコピー**（呼び出し先から呼び出しの辺を辿れるトリガーを深さ 9 まで集めた
  キー → 〔シーケンスのコピー・間隔(ms)〕の表。見つからないキーは「参照先なし」）/ **呼び出しスタック**（段ごとに キー・位置・周回・文脈の中の保留）
  * **開始時点のコピーだけで最後まで実行する**（実行中に呼び出し先・入れ子の呼び出し先を編集・削除・改名しても影響しない。入れ子もコピーの表から引く）
  * **入れ子**は深さ 9 まで（深さ = スタックの段数・呼び出し元 → 呼び出し先で 1）。超えたら実行時エラー。
    **循環**（スタックにあるキー〔呼び出し元を含む〕を再び呼ぶ）も実行時エラー。キーは開始時点の名前で比べる
  * 文脈の各ステップの前に、文脈のトリガー一覧が今のアクティブなトリガー一覧と同じで、呼び出し元のトリガーがあることを照合する。
    違えば呼び出しを**履歴を積まずに**やめる（単発 = 保留を外す / 連続実行 = 停止する。4.2.7 の完了時の照合と同じ）
* **文脈の 1 ステップ**（単発・連続実行で共通）: 最上段の位置から進め（先頭へ回らない）、通常アクション / file_line / 入れ子の呼び出しを実行して先行処理をする。
  最上段が末尾に達したら、その段の保留を反映して段を降ろし、下の段（または呼び出し元）の続きへ戻る。呼び出し先が空なら何もせず成功。
  system の上限 10,000 は**呼び出しの 1 ステップ全体で入れ子をまたいで通して**数える
* 呼び出し先の中の各行:

| 行 | 扱い |
|---|---|
| 通常アクション（hotkey / text / mouse_click / file_line） | 送る（file_line は読込中の保留を経る） |
| ループ / カウンター | 通常どおり（周回・保留は文脈の中だけ）。**無限ループの始まりに達したら実行時エラー**「呼び出し先に無限ループがあります」（「無限ループ + 停止」の形も呼べない・受容） |
| 待機 | 文脈のステップとして待つ（4.2.5 の「送った後の待ち」の規定の対象外） |
| 停止 | 読み飛ばす |
| 戻す / 先頭へ | 実行時エラー「戻す・先頭へのトリガーは呼び出せません」 |
| 呼び出し（入れ子） | 上の深さ・循環の規則で実行 |

* **間隔**: 文脈の中のステップの間隔 = その段の呼び出し先トリガーの「間隔(ms)」（連続実行 OFF でも欄の値・開始時点のコピーの値）。
  呼び出しの開始直後の最初のステップは間隔を置かない。文脈の中の待機は、前に呼び出し先の間隔を置き、後には間隔を足さない（4.2.5 の「待機の前に間隔を置かない」の対象外）。
  呼び出し元へ戻ったら、単発はそのまま呼び出し元の先行処理で押下を終える / 連続実行は呼び出し元の間隔を置いて次のステップ。
  一時停止からの再開は最上段の呼び出し先の間隔の後に文脈の続きから
* **保留**: 単発は呼び出し中、呼び出し元のステップが保留中（世代で守る・位置は呼び出しの行・**処理中**として他のトリガーを受け付けない〔4.2.10〕）。
  連続実行は呼び出しが 1 ステップ（位置は呼び出しの行・ステップの snapshot と途中の差分を持ち越す）
* **戻す履歴**: 呼び出し元の 1 ステップとして、状態（位置・周回・保留・カウンターの差分）が変わったときだけ 1 段（変わらなければ積まず、直前のトリガーも更新しない）。
  文脈の各ステップのカウンター操作の差分を呼び出し元の保留の差分へ積み増す（打ち切り・エラーでも呼び出し先の操作が含まれ、戻すで打ち消せる）。
  文脈の中の保留（先行処理で控えた操作）は打ち切り・エラーでは反映しない。送った入力は戻らない。直前のトリガーは呼び出し元（完了した順に更新・受容）
* **打ち切り**（取り消し・停止操作・捨てる〔4.2.10〕）: 位置は呼び出しの行。戻す履歴は上の規則。次の押下で呼び出しを最初からやり直す（送った入力をもう一度送る・受容）
* **エラー**（参照先なし・`target` が空・循環・深さ超過・無限ループ・戻す / 先頭へ・文脈の中の system / file_line のエラー・送信が止まるエラー）:
  通知し、呼び出し元はそこで止まる（位置は呼び出しの行・連続実行は停止・戻す履歴は上の規則。参照先なしですぐ止まり何も変わらなければ積まない）。
  runner が検出するエラー（system のエラー・参照 / 循環 / 深さ / 無限ループ・戻す / 先頭へ）の通知には「呼び出し: f5 > f6」を付ける（最初の呼び出し先から最上段まで・呼び出し元は含めない）。
  ActionExecutor が通知する通常アクション・file_line のエラーには付けない（受容）。二重表示の抑止で入れ子の通知が表示されないことがある（受容）
* **通知の後の再照合**: エラー通知・送信・file_line の完了の後に保留の同一性（単発 = 世代 / 連続実行 = 世代・キー・読込トークン）を照合し直し、変わっていれば状態を変えない。
  連続実行のエラー・送信失敗・file_line の失敗の後の照合には一時停止を含めない（通知の表示中に一時停止されても停止する）
* **事象ごとの扱い**（4.2.10 の入力の受け付けと合わせて読む）:

| 事象 | 単発の呼び出し中 | 連続実行の呼び出し中 |
|---|---|---|
| 一時停止 → 再開 | 文脈を保持し、最上段の呼び出し先の間隔の後に続きから（文脈の中の待機は残りを捨てて待機の次から・file_line は読み直す）。終われば呼び出し元の先行処理で押下を終える | 同左 |
| 停止操作（フック停止・キーマップ一時停止・UI 編集の一時停止） | 打ち切り（一時停止中も） | 打ち切って停止 |
| キーマップの切替 | 実行中は打ち切り。加えて各ステップで一覧 ID を照合 / 一時停止中は捨てて切替・通知（4.2.10） | 実行中は切り替えられない（4.3）/ 一時停止中は捨てて切替・通知 |
| 呼び出し元の位置変更・シーケンスの編集 | 打ち切り（位置変更 / 編集で履歴を消す規則が優先） | 文脈を捨て、通常の間隔の後に新しい位置から続行（待機・file_line と同じ） |
| 呼び出し先・入れ子の呼び出し先の編集・削除・キー変更 | 影響しない（開始時点のコピー） | 同左 |
| 呼び出し元の削除・キー変更 | 打ち切り / 各ステップの照合 | 各ステップの照合で履歴を積まずに停止 |
| 構成セットの読込等 | 打ち切り（保留は全消去・履歴なし） | 連続実行を停止（履歴なし） |

* **キー変更時の参照の書き換え**（4.1）・**削除**（参照は残り一覧で「参照先なし」・実行時エラー）・**編集時の検査**（4.6「出力シーケンスの編集」）

#### 4.2.10 入力の受け付けと一時停止（phase 40）

* **処理中** = 連続実行の実行中（一時停止していない）/ 単発の file_line の読込中 / 単発の呼び出し中（一時停止していない）。
  **止まっている間** = 単発の待機 / 連続実行の一時停止中 / 単発の呼び出しの一時停止中
* **トリガーの押下の扱い**（上から順に判定）:
  1. 処理中のものがある → そのトリガーのキーは、連続実行・単発の呼び出しなら一時停止、単発の file_line なら無視。**他のキーはすべて無視**（単発・連続実行の開始・一時停止中のものの再開を含む）
  2. 処理中のものが無い →
     * 一時停止中のもの（連続実行・単発の呼び出し）のキー → 再開
     * 単発のトリガー → 動く（そのトリガーが待機中なら無視）
     * 連続実行のトリガー → 一時停止中のものがあれば**全部捨てて開始し通知**する。単発の待機の保留は取り消す（待機を終えた扱い・4.2.5）
* **同時に持てる数**: 連続実行（実行中または一時停止中）は 1 つ。単発の呼び出しの一時停止はトリガーごとに持てる（複数可）。連続実行の一時停止中に単発の呼び出しを一時停止することもある
* **単発の呼び出しの一時停止**: 次のステップの予約を取り消し、文脈を保持する（文脈の中の待機は残りを捨てる・file_line の読込中は結果を捨てて再開時に読み直す）。
  保留は残る。戻す履歴は一時停止では積まない（呼び出しが終わるか、打ち切り・捨てるときに 4.2.9 の規則で 1 段）。単発の file_line・待機には一時停止を設けない
* **捨てる** = 停止操作による打ち切りと同じ（単発の呼び出しは位置が呼び出しの行 / 連続実行は停止。戻す履歴は状態が変わっていれば 1 段）
* **捨てる操作と知らせ方**（**ダイアログは使わない**。操作中のアプリからフォーカスを奪うため。知らせるのはステータスバーの通知だけ）:
  * 他のトリガーの連続実行の開始 → 一時停止中のもの**すべて**を捨てて開始し、「一時停止中の実行を破棄しました（<キーの一覧>）」と通知する
  * キーマップの切替（切替キー・一覧での切替・アクティブのキーマップの削除）→ 一時停止中のもの**すべて**を捨てて切り替え、同じく通知する。
    同じキーマップへの切替（変化なし）は捨てない。アクティブの削除は既存の削除の確認だけ（「はい」で捨てて削除）。連続実行が実行中なら切り替えられない（4.3）
  * 戻す / 先頭へで、対象が一時停止中の連続実行・単発の呼び出し → **2 回押し**:
    1 回目は何も変えず「一時停止中の <キー> を破棄します。もう一度押すと実行します」と通知し、その状態（戻す / 先頭へのトリガーのキー・対象のキー・一時停止中のものの集合〔キーと世代〕・
    処理中の有無・単発の保留の集合）を控える。**続けて**同じトリガーを押し、控えた状態と今の状態が同じなら**対象だけ**を捨ててから実行する。
    間に他のトリガーの押下があった・状態が変わったら控えを捨て、次の押下を 1 回目として扱う（時間の制限は設けない）。処理中は戻す / 先頭へのトリガーの押下自体を無視する（上の 1）。
    戻す / 先頭へだけのトリガーは、連続実行 ON でも先に一時停止中のものを捨てず、この 2 回押しに従う
* 一時停止の専用の表示は増やさない（連続実行の一時停止と同じ）

### 4.3 keymap

* キー割り当て（keymap）を UI から編集できる
* keymap 個別の 保存 / 別名で保存 / 読込 を持つ
* **キーマップ管理（phase 34）**:
  * 構成セットには**常にキーマップが 1 つ以上**ある（新規作成時は 1 つ自動作成・切替キー不要）
  * **一覧で行を選択（クリック・矢印キー）するとそのキーマップがアクティブになる**。「選択」ボタンは無い。ダブルクリックで編集。
    アクティブの変更（一覧・直接切替キー）では構成セットを未保存にしない。編集・削除・個別の保存 / 読込の対象は常にアクティブなキーマップ
  * **追加（2 つ目以降）は切替キー必須**。キーマップを増やす 3 つの流れ（**追加・個別読込・貼り付け**）は、切替キーが要るキーマップを
    **切替キーのまとめて設定のダイアログ 1 つ**で設定する（phase 43）
    * 開く条件: 既存のキーマップが 1 つ以上あるとき（0 → 1 個の追加・読込はダイアログなし・切替キー不要）
    * 行（上から）: ①切替キーの無い既存キーマップ（一覧順）②増やすキーマップ（追加 = 新規 1 行 / 個別読込 = 読み込んだ 1 行 / 貼り付け = 貼る順に全部）。
      行ごとに 区別（既存 / 新規 / 読込 / 貼り付け）・名前・ラベル・切替キー（キー入力で取得・クリア）。多いときは縦にスクロール。
      **行が 1 つでも同じダイアログ**を使い、高さは行数に合わせる（1 行のときは区別の表示と見出しを省き、通常の編集ダイアログに近い見た目）
    * ラベルの初期値: 既存 = 現在のラベル / 追加 = 空 / 個別読込 = 読み込んだラベル / 貼り付け = 連番（4.6「一覧の操作」）。既存の行のラベルも変更できる
    * **入力の検査は OK のとき**、全行の切替キーについて 空・不正・停止 / トグルとの重なり・全キーマップのトリガーキー・置換元キー・ダイアログ外のキーマップの切替キー・
      ダイアログ内の行どうしの重複（`key_input.md` §7.3 の表）。**検査は反映後の完成予定の状態に対して行う**（増やすキーマップ自身と他の増やす行のトリガー・置換元キーを含む）。
      エラーは理由と行を示してその行の切替キーへフォーカスし、**ダイアログを閉じない**
    * **OK で全行を一度に確定**（既存の切替キー・ラベルの設定とキーマップの追加）。確定は検査・採番・写しの作成をすべて済ませた後に、アクティブ化・確認ダイアログ・
      イベントループを挟まずに行う。**キャンセル（Escape・閉じるを含む）では設定データを何も変えない**（途中まで反映した状態を作らない）。
      確定の前に失敗したら、既存のキーマップ・切替キーの表・未保存の印・トリガー一覧の実体を変えない。
      確定の後に重なりの表の作り直し・一覧とキーボード表示の再描画を行い、フックの再開で追加した切替キーを含めて登録し直す
    * **アクティブなキーマップは変えない**。ダイアログを開いたときのフック停止（実行状態の扱い）は全ダイアログ共通（`key_input.md` §7.2）
    * ダブルクリックでの通常の編集（1 キーマップの編集ダイアログ）はこの流れを使わず、入力エラーでも「閉じない」扱いにしない
  * キーマップの個別読込も追加として扱う（上記の流れ・キャンセルで runtime 不変）。**同じキーマップファイルの二重読込は拒否**する
  * **編集**: キーマップが 2 つ以上のときは切替キーを空にできない
  * **削除**: キーマップが 1 つだけのときは削除できない（ボタン無効）。未保存のトリガー一覧・シーケンスを持つキーマップの削除確認では、
    それらが破棄されることを明示する（共有中で他のキーマップが持ち続ける一覧は警告しない）。旧形式からの移行先キーマップを削除すると、
    構成セットと旧トリガー一覧の関係を解除したものとして扱う（`data_schema.md` §5.13.4）
  * 直接切替キーが停止 / トグルと重なるキーマップは一覧で**グレー表示＋理由**（選択・編集はできる。`key_input.md` §7.3）
  * **連続実行の実行中はキーマップを切り替えられない**（一覧の選択は元の行へ戻す / 直接切替キー / アクティブの削除）。
    試みたら**ステータスバー中央の一時メッセージ領域**に「連続実行中のためキーマップを切り替えられません」を出す。
    **一時停止中**の連続実行・単発の呼び出しは、切り替えると捨てて通知する（phase 40・§4.2.10）
  * アクティブが変わったら（一覧の選択・直接切替キー・削除・読込）トリガー一覧・シーケンス欄・キーボードウィンドウ・省略表示を再描画する
  * 旧形式の構成セットを開いたときの移行と通知は `data_schema.md` §5.13.3
  * **一覧の操作**（phase 43。共通の操作は 4.6「一覧の操作」）:
    * **フォーカス（下線）= アクティブ**。範囲選択の操作でも、離したとき・キーを離したときに下線の行をアクティブにする。
      切替を拒否したら（連続実行中など）選択範囲も下線も元のアクティブの行だけに戻す（通常の拒否と同じ通知）
    * **ドラッグでの並べ替えではアクティブを変えない**（動かさずに離したときはクリックとして扱う）。並べ替えは構成セットを未保存にする（並び順は保存されるため）
    * 次のいずれかがある間は並べ替えをしない（理由を一時メッセージに出す）: 連続実行（実行中・一時停止中）/ 単発の呼び出しの文脈（実行中・一時停止中・
      アクションの間隔待ちを含む）/ 保留中のステップ / 待ち・file_line の読込。**ドラッグの開始時と確定の直前の両方で検査**し、確定時に該当すれば元に戻す
    * 並べ替えで共有中のトリガー一覧の代表が変わったら、実行中の状態を新しい代表 id へ付け替える。個別保存のダイアログの行名（代表のラベル）は並べ替えで変わりうる（受容）
    * 範囲の削除: 全部消すと 0 個になるなら削除しない。範囲にアクティブを含み、削除の規則で拒否される場合（連続実行中など）は範囲全体を削除しない
    * **複製・貼り付け**: キーマップの写しは置換の割り当て・ラベル（連番）・トリガー一覧を含む。**トリガー一覧は共有せず丸ごと写す**（新しい一覧）。
      id は通常の採番。内部の値（キーマップ・トリガー一覧・シーケンスの読込元のパス・参照元・未保存 / 取り込みの印・旧トリガー一覧の移行記録との関係）は写さず、
      写しは未保存の新規扱い。切替キーは上記のまとめて設定で入力し、キャンセルなら何も貼らない。キーマップの切替キーの重複は持たない

#### フル表示の幅配分

フル表示のメイン領域は **キーマップ管理 | トリガー一覧 | 出力シーケンス** の 3 枠と、その間の境界線 2 本で構成する
（phase 18。ヘッダの幅の扱いは phase 19）。保存キーの形式・検証は `data_schema.md` §5.4。

**用語**: 本節の「**ヘッダの要求幅**」は、ヘッダ領域（フック | 表示 | ファイル）の要求幅に**ウィンドウ端までの余白を足したウィンドウ幅換算の値**を指す
（ウィンドウをこの幅にするとヘッダがちょうど切れない）。同様に「両端の表示幅 + トリガー一覧の最小幅」も境界線 2 本とメイン領域の外側の余白を含むウィンドウ幅換算で比べる。

* **ウィンドウ幅の増減はトリガー一覧だけが受ける**（キーマップ管理・出力シーケンスの幅は変わらない）。3 枠とも一覧は枠に合わせて横に広がる
* **境界線のドラッグ**（左ボタンのみ。**中ボタンでは動かない**）でキーマップ管理 / 出力シーケンスの幅を変える。
  **差分はトリガー一覧が吸収し、ウィンドウ幅は変わらない**。**反対側の枠を押し縮めない**（トリガー一覧が最小幅に達したら止まる）。
  ドラッグ中は幅がマウスに追従するが、幅の適用は間引く（出力シーケンスのボタン列等を移動ごとに再配置へ巻き込まない）
* **最小幅**: 各枠 = 中身（ボタン・チェックボックス・見出し・間隔入力）が切れない幅（一覧は 10 文字相当）。フォント設定ごとに再計算する。
  フル表示中のウィンドウ最小幅 = **max(両端の表示幅 + トリガー一覧の最小幅, ヘッダ〔フック / 表示 / ファイル〕の要求幅)**
  （**両端の枠はウィンドウ縮小で縮まない**・**最小幅まで縮めてもヘッダは切れない**）。ヘッダの要求幅もフォント設定ごとに測り直す。
  境界線のドラッグを離した後の最小幅は、**実際の両端の表示幅**から求める（下記「収まらない場合」の縮小規則は通さない）
* **最小の高さ**（phase 20）: フル表示中はウィンドウに最小の高さを設け、**最小の高さまで縮めても何も切れない**
  （ヘッダ・3 枠の中身〔ボタン列・チェックボックス・間隔入力・見出し〕・ステータス欄・ステータスバー）。
  * **基準 = 一覧を既定の行数の半分にしたときの高さ**。キーマップ管理・トリガー一覧 = **6 行** / 出力シーケンス = **9 行**（一覧の行数指定そのものをこの値にしてある。
    表示される行数はウィンドウの高さに応じて伸びた分で決まる）。最小の高さは 3 枠のうち最も高い枠で決まる（実測では全フォントで出力シーケンスのボタン列）
  * **最小の高さ = フル表示中のウィンドウの要求高さ**（追加の余白は足さない）。**ステータスバーの一時メッセージは表示の有無・行数によらず 1 行分として測る**
    （最小付近まで縮めているときに複数行の一時メッセージが出ると、消えるまで下側が切れる = 受容。一時メッセージの表示・消去では測り直さない）
  * 測る契機 = 起動時 / フォント変更（省略表示中の変更はフル表示へ戻ったときに反映）/ **フル表示へ戻るたび**。
    **両端の幅を適用した後に測る**。**フル表示へ戻るときは、ステータス欄等の表示内容をフル表示の状態へ更新し終えてから測る**（省略表示の 2 行のステータスで測らない）
  * 境界線のドラッグの後も最小の高さを保つ
  * 現在の高さが最小未満なら最小まで広げる。**一度広げた高さは、後でフォントを戻す等で最小が下がっても縮めない**（最大化を解除したときに最小まで広がった高さ・ユーザーが広げた高さも縮めない）。
    最大化中・最小化中は高さを変えない
  * 最小の高さが画面の高さを超える場合は、ウィンドウが画面からはみ出す（保証の範囲外）
  * 高さは保存しない（下記「ウィンドウ幅の保存と復元」）。大きいフォントでは起動時の 820 より高く開く
* **希望幅と表示幅**: 両端の枠はユーザーの意図（希望幅）と実際の幅（表示幅 = 希望幅を最小幅以上へ引き上げ、下記「収まらない場合」の規則で縮めた値）を分けて持つ。
  * ドラッグを離したとき、**動かした境界線に接する側の希望幅だけ**を表示幅で更新する。**表示幅が変わらなかったドラッグでは更新しない**
    （最小幅へ自動で広がった幅を保存しない）。希望幅の組が変わったときだけ保存する。保存に失敗しても希望幅（メモリ上）は更新したまま
  * **初めてのドラッグでは、動かしていない側の既定幅も希望幅として保存される**（両端を 1 組で保存するため）
  * フォントを戻す等で最小幅が下がれば、表示幅は希望幅へ戻る
* **既定幅**（保存値が無いとき）= phase 18 以前の固定レイアウトと同じ見た目になる幅で、**既定ウィンドウ幅 780 のときの配置を基準に算出**する:
  * キーマップ管理 = 一覧を 26 文字とした枠全体の要求幅
  * 出力シーケンス = 780 のときのメイン領域の幅 − キーマップ管理の要求幅 − トリガー一覧（一覧 26 文字）の枠全体の要求幅 − 境界線 2 本分（1 本 12px）
  * ウィンドウ幅だけが保存されている場合も、780 から広げた（狭めた）分はトリガー一覧が受ける。既定幅（両端の枠の幅）は保存しない（最小幅を下回る場合は最小幅）
  * ヘッダの要求幅（上記の用語。余白込み）が 780 より広い環境（標準フォントでも該当する）では、起動時にヘッダに合わせてウィンドウが広がって開く。広がった分はトリガー一覧が受ける
* **収まらない場合**（起動時・フォント変更後・フル表示へ戻ったとき）: ウィンドウを必要幅まで広げる。必要幅が画面幅を超えるなら、
  **出力シーケンス → キーマップ管理の順に表示幅だけ最小幅まで縮める**（希望幅・保存値は変えない）。縮める目標は **max(画面幅, ヘッダの要求幅)**
  （ヘッダは縮められないので、それより狭くはしない）。最終値を先に計算して 1 回で適用する（途中の値でウィンドウ幅を変えない）。
  ヘッダの要求幅や両端の最小幅の合計が画面幅を超える場合は、ウィンドウが画面からはみ出す（保証の範囲外）。ユーザーが広げた幅を画面幅へ縮めはしない
* **省略表示との関係**: 省略表示へ入るときはウィンドウの最小サイズ（幅・高さとも）を解除してから幅 270 にする。
  省略表示中のフォント変更では幅・高さを再計算せず、フル表示へ戻ったときに再計算する
* **ウィンドウ幅の保存と復元**: フル表示時のウィンドウ幅を保存し、次回起動時にその幅で開く（高さ・位置・最大化状態は保存しない）。
  * **ウィンドウ幅が変わってから 500ms 変化がなければ保存する**（連続したリサイズの途中では書かない）。
    **最大化中・最小化中・省略表示中 / アプリが自動で決めた幅**（起動時の画面幅への切り詰め・フォント変更やヘッダによる拡幅等）**/ 保存済みと同じ幅は保存しない**
  * **例外 = 起動時の保存値の更新**: 有効な保存値があり、**画面幅へ切り詰める前の保存値が起動時の初回適用後のウィンドウ幅より狭い**（= 最小幅に届かず広げた）ときは、
    広げた幅を 1 回保存する（原因がヘッダかメイン領域かは問わない。**保存値が画面幅より広くても、最小幅より狭ければ書く**）。
    保存値が無い / 不正 / 画面幅へ切り詰めただけ / 起動時以外に広がった場合は書かない。
    → 大きいフォントで起動したときに広がった幅は保存値に残り、標準フォントへ戻しても次回はその幅で開く（縁で縮めれば保存し直される）
    起動時の更新の書き込みに失敗した場合は再試行しない（その起動中は自動決定幅として扱う）。次回起動時に同じ条件で改めて書く
  * ユーザーが幅を変えた後は、アプリが自動で決めた幅と同じ幅へ戻した場合も保存する
  * **終了時には保存しない**。最後の変更から 500ms 以内に閉じる・最大化する・省略表示へ切り替えた変更は保存されない（受容）
  * 保存値が画面幅より広ければ画面幅で開く（ウィンドウ最小幅がそれより広ければ最小幅で開き、上記の起動時の更新条件に当たれば保存値を書き換える）。
    **画面幅は主モニタの幅**（主モニタより広いサブモニタで保存した幅も、次回起動時は主モニタの幅へ切り詰める）
  * **受容する制約**: 自動で決まった幅から別の幅へ変えて 500ms 以内に同じ幅へ戻すと、手で変えた扱いにならず保存されない /
    最大化中にフォントを大きくしてから最大化を解除すると、ウィンドウ最小幅によって広がった幅が保存されうる
* 保存に失敗したときのエラー表示中は、他のダイアログと同様にフックを停止する（`key_input.md` §7.2）
* **ヘッダの配置は変えない**（折り返し等はしない）。ヘッダの要求幅が状態で変わらないよう、フル表示のヘッダで**文言が切り替わるボタン**
  （停止キー / トグルキーの「キー入力で取得」⇔「取得中…（Escで停止）」・「開始（フックON）」⇔「停止（フックOFF）」・「キーマップ一時停止」⇔「キーマップ再開」）は
  **取りうる文言の最大幅で幅を固定**し、フォント変更ごとに当て直す。**省略表示の同じボタンは固定しない**（幅 270 で常に切れるため）
* キーボード選択のドロップダウンは、フル表示・省略表示とも幅 12 文字（表示名が長い外部レイアウトは欄内で切れる = 受容）

#### 一覧の表示形式

```
トリガー一覧        01. key: label
出力シーケンス      01. [type] value: label
プリセット一覧      01. value: label
```

* 出力シーケンスの system / file_line の行（phase 37）:

| 行 | 表示例 |
|---|---|
| ループの始まり | 実行中でない `[loop] ×3` / `[loop] ×∞`、実行中 `[loop] 2/3` / `[loop] 2/∞`（周回 / 回数） |
| ループの終わり | `[loop_end]` |
| カウンター +1 / 0 に | `[count+1] n (=5)` / `[count=0] n (=5)`（括弧内は現在値・§4.2.2） |
| 待機 / 戻す / 先頭へ / 停止 | `[wait] 500ms` / `[back]` / `[rewind]` / `[stop]`（phase 39） |
| file_line | `[file_line] list.txt #n (=5)`（ファイル名 + カウンター名 + 現在値） |
| 呼び出し | `[call] f5（呼び出し先ラベル）`（ラベルが空なら `[call] f5`・キーは正規化後の小文字）/ 参照先なし `[call] f5（参照先なし）`・`target` が空 `[call] （参照先なし）`（phase 40） |

* **出力シーケンスの次に実行は行頭の `▶`** で示す（他の行は同じ幅の空白・選択とは独立。phase 43）。グレー表示のトリガー（4.1）のシーケンスには `▶` を出さない
* 連続実行を停止の行で終えた直後の「次に実行」は、停止の後の先行処理の結果の行（4.2.8）。停止の行を指すのは、一覧で停止の行を選んだときなど
* 省略表示の「次に実行」の要約も同じ表示名を使う（既存種別の要約の文字列は変えない）
* **ネストの色分け**: ループの始まりから終わりまでの行（始まり・終わりを含む）の背景を、その行を囲む最も内側のループの深さの色にする。
  深さ 1〜9 = 青・緑・橙 × 薄・中・濃（3 色相を一巡したら 1 段濃く）。ループの外と対応が崩れた行は色なし。選択行はリストボックスの選択色が優先。色値は `codebase_map.md`

#### 出力シーケンスの編集（phase 37）

* 編集ダイアログの種類に system（ループ / カウンター +1 / カウンターを 0 に / 待機 / 停止 / 戻す / 先頭へ / 呼び出し。停止は phase 39・入力欄なし / 呼び出しは phase 40）と file_line を加える
  * ループ: 回数（既定 1・1 以上の整数のみ）と「無限」のチェック / カウンター系・file_line: カウンター名（既知の名前を候補に出す編集可能なドロップダウン）/
    待機: ミリ秒（1 以上の整数のみ）/ file_line: ファイル（参照ボタン・保存は `data_schema.md` §5.7 の表記）・文字コード（UTF-8 / Shift_JIS）・範囲外（エラーで停止 / 空を送る / 折り返し）
  * 入力エラーはダイアログを閉じない
* **追加ダイアログの「末尾に追加」**（既定 ON・開くたび ON・全種別）: OFF なら一覧の選択行の直後へ挿入（範囲選択中は下線の行の直後・選択が無ければ末尾）。挿入しても「次に実行」は元のアクションを指したまま・追加した行は選択しない
* **ループ**: 始まりと終わりを対で追加（間は空）・対で削除（中の行は残す・確認文で示す）。追加後の深さが 9 を超えるなら追加しない。
  ループの行の編集は、始まり・終わりどちらを開いても対の始まりの設定（回数・無限・ラベル）を編集し、種別・操作は変えられない。他の行をループへ変える選択肢は出さない
* **移動**（上へ / 下へ・ドラッグ。phase 43）: 移動の前後でループの解析を取り、**対（始まりと終わりの組）が行の実体で同じ**・**対応が崩れた行の実体の集合が同じ**・
  **深さ超過の行の実体の集合が増えない**の 3 つをすべて満たせば許す。それ以外は動かさず理由を示す（ループを丸ごと別のループの中へ・通常の行をループの内外へは許し、
  ループの行が他のループの行を越えて組が変わる移動は拒否）
* **対応が崩れたループの行**（手編集）: 削除はその行だけ・編集は開かず案内する
* **戻す・先頭へは単独登録**: 空でないシーケンスへは追加しない / 戻す・先頭へのあるシーケンスに他の行を追加しない / 既存の行を戻す・先頭へに変える編集はその 1 行だけのときに限る
  （いずれも OK 後に理由を示して反映しない）。呼び出しはこの制限に含めない（他の行と混ぜてよい）
* **呼び出し**（phase 40・4.2.9）: system の操作に「呼び出し」。呼び出し先は**同じトリガー一覧から選ぶドロップダウン**（読み取り専用・自分自身は出さない・
  表示は `キー: ラベル`・グレー表示のトリガーも出す。**ただし同じキーの行の重複でグレーになった行は出さない**〔キーで区別できないため・phase 43〕）。既存の行が参照先なしなら、先頭に `f5（参照先なし）` を出して選ばれた状態で開く（そのまま OK すると拒否）。
  「呼び出し」を選んだときは、呼び出し先の「間隔(ms)」が呼び出し時の間隔にも使われる旨の注記を出す
  * OK 時に拒否する（理由を示して閉じない）: 未選択・参照先なし / 自分自身 / **循環**（呼び出しの辺をたどって自分へ戻る）/
    **このトリガーから下流の連鎖の深さが 9 を超える**（上流は数えない）/ **直接の呼び出し先**が戻す・先頭へだけのトリガー
  * 検査は**呼び出しの行を保存するときだけ**。他の操作（改名・追加・構成セットの読込・中間のトリガーの編集）で生じた循環・深さ超過・戻す / 先頭へは実行時の検出に任せる

#### 一覧の操作（phase 43）

対象 = フル表示のキーマップ一覧・トリガー一覧・出力シーケンスと、プリセット編集ダイアログのプリセット一覧。**省略表示のトリガー一覧は対象外**（単一選択のまま）。
キーマップ一覧の固有の規則は 4.3、トリガーの同じキーの行は 4.1。

* **選択**（範囲は連続範囲のみ。Ctrl+クリックの飛び飛び選択はしない）:

| 操作 | 結果 |
|---|---|
| クリック / ↑↓ | 単一選択。アンカー = その行 |
| Shift+クリック / Shift+↑↓ | アンカーから下線の行までを選択。下線は操作した行 |
| Shift+ドラッグ | 押した時点のアンカーからポインタの行までを選択（押下中は帯だけ・離したとき反映） |
| ドラッグ（Shift なし） | 移動（下記） |
| 範囲の中の行を押して動かさずに離す | その行の単一選択（押した時点では範囲を潰さない） |

  * Tk の既定の範囲選択の動作は使わず置き換える（対象の Listbox だけ）: Ctrl+クリックは通常のクリック / Shift なしのドラッグで範囲を伸ばさない /
    一覧の外へ出たときの選択の延長はしない（自動スクロールに置き換え）/ Escape はドラッグの取り消し / 全選択・全解除・Shift+Ctrl+Home/End・Shift+Home/End は何もしない
  * 選択範囲は編集の再描画で保たれる。移動・複製・貼り付けの後は動かした行 / 貼った行が選択範囲。**トリガーの実行による再描画では範囲を保たず**単一選択に戻す
  * トリガー一覧で範囲選択中、シーケンス欄は**下線の行**のシーケンスを表示する。「編集」は下線の 1 行、「削除」は範囲全体
* **ドラッグ移動**: 押した行が選択範囲の中なら範囲全体、外ならその 1 行（単一選択に切り替える）を動かす。ポインタが別の行に入るたびに塊をその位置へ移した表示にし（挿入線は描かない）、
  一覧の上端 / 下端の外では自動でスクロールする。**離したとき確定**（未保存化）・**Escape で取り消し**（その後のボタンの解放では確定しない）。並びが変わらなければ何もしない。
  規則に反する場合（出力シーケンスの移動・4.3 の並べ替えの禁止条件）は元に戻して理由をステータスバーの一時メッセージに出す
* **上へ / 下へ**（出力シーケンス・プリセット一覧）: 選択範囲を塊として 1 行動かす（塊の外側の 1 行と入れ替える）。端では何もしない
* **範囲の削除**: 範囲全体を対象に件数を示して 1 回確認する。出力シーケンスのループの対削除は範囲に含まれる各ループに適用する
* **複製・コピー / 貼り付け**（プリセット一覧を除く 3 つ）:
  * **Ctrl+C**: 一覧にフォーカスがあるとき、選択範囲（無ければ下線の行）をアプリ内の保管庫に**写し**で保持する（一覧の種類つき・OS のクリップボードは使わない）
  * **Ctrl+V**: 同じ種類の一覧にフォーカスがあるとき、保管庫の写しを**末尾**へ追加し、貼った行を選択範囲にして見える位置へスクロールする。繰り返し貼れる。
    種類が違う・保管庫が空なら何もしない。**別の一覧（同じ種類）へも貼れる**（トリガー X のシーケンス → Y、キーマップ A のトリガー → B）
  * **複製ボタン**（出力シーケンスのみ）: 選択範囲の写しを同じ一覧の末尾へ追加する（保管庫は変えない）
  * 保管庫は**構成セットの読込・新規作成で空にする**（構成セットをまたいで貼らない）。保存はしない
  * キーは Caps Lock に依らず効くよう大文字・小文字の両方をバインドし、対象の Listbox だけに付ける（`bind_all` を使わない）。テキスト入力欄の Ctrl+C / V は通常動作
* **出力シーケンスの次に実行**: 変えるのは **Shift なしのクリックとキー移動（↑↓・Home/End・PageUp/PageDown）** だけ（実行位置へ反映し周回を作り直す）。範囲選択・ドラッグ・貼り付け・複製・上へ / 下へでは変えない。
  移動・複製・貼り付け・範囲削除の後も**同じアクション（行の実体）**を指す（指していた行が削除されたら通常の削除と同じ扱い）。移動は編集として扱い、周回の作り直し・戻す用の履歴の扱いは上へ / 下へと同じ
* **出力シーケンスの複製・貼り付けのループ**: 範囲（複製ボタン・Ctrl+C で取る行）に元の一覧で対になっているループの片側だけがあれば、**範囲を取った時点で反対側を補って閉じる**
  （終わりだけ → 対の始まりを範囲の先頭の前 / 始まりだけ → 対の終わりを末尾の後。補う行は元の対の行の写しで、対との間の行は含めない。複数なら元の一覧の並び順）。
  保管庫には閉じた範囲が入り、Ctrl+V は元の一覧を見ない。貼った行の選択範囲には補った行も含む。次の場合は追加せず理由を示す:
  対応が崩れたループの行（相手のいない始まり / 終わり）を含む / 貼った後に深さ 9 を超える行が生じる / 戻す・先頭への単独登録の規則に反する。
  呼び出しの行はそのまま写す（呼び出し先は貼り先の一覧で解決し、循環・深さは実行時に検出）
* **トリガーの写し**はキー・ラベル・suppress・連続実行・間隔・シーケンスを含む。内部の値（読込元のパス・参照元・未保存 / 取り込みの印）は写さない（保存時に新しいファイル）。
  貼ったキーが停止 / トグル / 切替キー・置換元キー・同じ一覧の既存のキーと重なっても受け入れ、読込と同じ扱い（グレー表示・置換にはトリガーが勝つ）にする。
  並べ替え・貼り付け・範囲削除の後は、追加・削除と同じく重なりの表の作り直し・フックの再登録・キーボード表示の再描画を行う。交代の規則（4.1）を適用する
* **ラベルの連番**（トリガー・キーマップ）: 貼るラベルが貼り先の一覧（先に貼った行を含む）の既存のラベルと重ならなければそのまま。重なれば末尾の ` (n)`（n ≥ 2）を除いたものを基にし、
  `基 (n)` で空いている最小の n（2 から）にする（除いた結果が空なら除かない）。空のラベルは空のまま。出力シーケンスの行は連番を付けない
* **プリセット一覧**: 範囲選択・ドラッグ移動・上へ / 下へのまとめて移動・範囲削除のみ（複製・Ctrl+C / V は付けない。移動の規則はなし）。
  ダイアログ内の作業用の一覧に反映し、OK で確定・キャンセルで破棄する。**ドラッグ中の Escape はドラッグの取り消しだけ**でダイアログを閉じない（ドラッグ中でなければ閉じる）

#### メニュー・個別保存

* ファイルメニューの通常読込は「読込（構成セット）…」
* その直後に「履歴から読み込む…」を置く（直近 20 件 + ユーザーが作る分類から構成セットを開き直す。
  データと永続化の規定は `data_schema.md` §5.12）
  * 一覧は **2 列（名前 / パス）の `ttk.Treeview`**。ルート直下に固定ノード「直近」と各分類のノードを並べ、
    子が履歴のエントリ。名前列は拡張子なしのファイル名、パス列は保存表記。
    **分類は名前の昇順**（比較は `casefold`・同値なら保存順）。既定で「直近」は展開・分類は折り畳み。
    **`ui_font_delta_pt` に追従させる**（Treeview は他ウィジェットのフォント指定が効かないため個別に指定する）
  * **不在のファイルは名前列に「（見つかりません）」を付す**。存在確認は再描画のたびに行い、**自動削除しない**
  * 操作 = 読み込む / 履歴から削除（確認あり）/ 直近のエントリを分類へコピー / 分類の追加・名前変更・
    削除（配下ごと・確認あり）/ 閉じる。**選択の種類（エントリ / 分類 / 未選択）で可否を切り替える**
  * **読込は未保存確認（通常の読込と同じ経路）を経て行い、成功したときだけダイアログを閉じる**。
    失敗・キャンセルでは**開いたまま**にし、そのエントリを履歴から自動削除しない
  * **編集は操作ごとに永続化し、成功したときだけ一覧へ反映する**。
    ダイアログは自分の表示内容を正とせず、**読込・編集のたびに永続化済みの履歴を読み直して再描画する**
    （未保存確認の中で保存が走り履歴が変わり得るため）。選択と展開状態は可能な範囲で復元する
  * 履歴ファイルが読めず読み取り専用になっているセッションでは、**編集操作を無効にする**（読込と閉じるは可）
* 起動時設定は「起動時に読む構成セットを指定…」
* キーマップ管理には keymap 個別の 保存 / 別名で保存 / 読込 を置く
* トリガー一覧には trigger_set 個別の 保存 / 別名で保存 / 読込 を置く
* 出力シーケンスには選択中トリガーの sequence 個別の 保存 / 別名で保存 / 読込 を置く
* 個別保存のダイアログで同じキーの行が複数あるときは、行の表示に行番号を併記する（例 `f5（2 行目）`。1 つだけなら併記しない・phase 43）
* 設定メニューに「参照元を掃除…」を置く（子JSON の陳腐化した参照元 `_parent_refs` の除去。
  検査 → 確認 1 枚 → 実行。仕様は `data_schema.md` §5.8.1）
* 設定メニューに「**孤児ファイルの棚卸し…**」と「**隔離の管理…**」を置く
  （仕様は `data_schema.md` §5.8.9）
  * **孤児ファイルの棚卸し…**: ①未保存なら**保存確認**（「保存する / 中止する」の 2 択・
    保存に失敗したら中止）→ ②**走査ディレクトリの一覧ダイアログ**（追加 / 削除。
    ボタンは「**棚卸しを実行**」/「**閉じる**」。**閉じると走査せずに終わるが、一覧の編集は保存される**）
    → ③走査 → ④**候補 0 件ならダイアログを出さず通知のみ** / 1 件以上なら確認 1 枚
    （実行ボタンは「**隔離する**」・右は「キャンセル」）→ 隔離。
    **警告は一覧の先頭**に出し、警告があっても実行できる（**行ごとの選択 UI は設けない**）
  * **隔離の管理…**: 隔離の**実行単位のリスト選択** → 「**復元する…**」/「**削除する…**」/「**閉じる**」。
    どちらも**確認 1 枚を挟む**（確認側の実行ボタンは「**復元する**」/「**削除する**」）。
    削除は**不可逆**のため確認画面の**先頭に取り消せない旨**を書き、**削除されるパスを全件提示**する。
    マニフェスト不正の単位は**復元できず**、削除の確認に**追加の 2 行**が出る
  * 確認・結果表示は `ReferenceCleanupDialog` を**ヘッダ文言と実行ボタンラベルの引数化**で再利用する

#### 子ファイル保存ダイアログ

構成セットの保存で出す子ファイル一覧ダイアログの表示要件
（提示条件・既定選択・保存の意味論は `data_schema.md` §5.8）。

* 列は **種別 / 対象名 / 保存先パス / 共有状況 / 操作（保存・別名保存・保存しないのラジオ）**
* **固定の初期サイズを持ち、リサイズできる**。行数が多いときは**縦スクロール**する
* **対象名・保存先パスは幅に追随する可変列**とし、収まらない場合は省略表示して
  **ツールチップで全文**を出す。**初期表示の時点で省略が効いている**こと
  （リサイズするまで全省略「…」のままにならない）
* **ラジオ列を切らさない**ことを優先し、**縮小しても OK・キャンセルは常に見える**
  （ボタンはスクロール領域の外に置く）
* **スクロール領域内の子ウィジェット（ラベル / ラジオ）上でもマウスホイールが効く**。
  ダイアログを閉じたらホイールのバインドを残さない
* 共有状況の文言は**既存ファイルを上書きするかどうかが読み取れる**こと（`data_schema.md` §5.8.4 の表）

#### モーダルダイアログの作法

* **モーダルダイアログは、表示されている間は閉じるまでモーダルであり続ける**
  （開いている間、他のウィンドウは操作できない。最小化で隠れている間の扱いは下の「最小化」の条項）
* **モーダルダイアログは、開いた時点でキーボードフォーカスをダイアログ内へ要求する**
  （Escape などのキーが親ウィンドウへ抜けない）。**アプリが入力フォーカスを持ち、ダイアログが表示された
  時点で、フォーカスはダイアログ内にある**（開いた時点でアプリが非アクティブ・未表示なら、最初にその条件が
  整った時点で入る）。**ダイアログごとに定めた入力先があればそこへ、無ければダイアログ自身へ入れる**。
  **開いた時点では、窓の前面化・フォーカス強制は行わない**（最小化から復元したときの例外は下の「最小化」の条項）
* **モーダルダイアログは Escape でも閉じられる**。**Escape は閉じるボタン（×）と同じ結果で閉じる**
  （OK・実行などの確定操作は行わない。× で閉じても保存される編集〔本節の「孤児ファイルの棚卸し…」の
  一覧編集など〕は Escape でも保存される）。新しい閉じ方を増やさない
  （フック停止の解除は `key_input.md` §7.2 のとおり閉じ方によらずちょうど 1 回）
* **ただし Esc に別用途を割り当てている状態（キーの記録中・取得中など）では、その用途を優先し、
  ダイアログを閉じない**。**別用途に使った Esc を押しっぱなしにしても閉じない**（離してから押し直した
  Escape で閉じる）。**Escape のハンドラはダイアログにつき 1 つにまとめ、状態で分岐する**
  （別用途を別ハンドラとして重ねない）
* **閉じた後のキーボードフォーカスの戻り先は規定しない**
  （最小化から復元した後のフォーカスは下の「最小化」の条項で規定する）
* **ネストして開いた子を閉じたときは、開いた順で 1 つ外側のモーダルへ戻る**
  （プリセットマネージャ → プリセットの追加・編集 / アクション編集 → プリセットマネージャ /
  プリセットマネージャ → 上書き確認〔`data_schema.md` §5.10.3〕）
* **戻らないのは次の場合**。①戻る先が既に閉じている ②戻る先が表示されていない
  ③**開いた順と違う順で閉じた**（内側がまだ開いている。**内側のモーダル性を優先する**）
  ④親ごと閉じる連鎖破棄。**いずれの場合も例外を出さず、アプリの終了を妨げない**
* **ネストして開いた子は、呼び出し元より前面に留まる**（呼び出し元を掴んで動かしても
  前後が入れ替わらない）。前面維持の相手は**呼び出し元のダイアログ**であり、
  **親ウィンドウ（所有関係）は変えない**（変えると破棄が連鎖し上の③と衝突する。
  実装の窓口は `codebase_map.md` の `presentation/modal.py` 節）
* **呼び出し元を先に閉じた場合、残る子の前面維持の指定は戻らない**
  （「App より前」という指定も失う）。ただし**生存とモーダル性（grab）は変わらない**＝
  上の③「内側のモーダル性を優先する」は保たれる
* **ダイアログを開いたままアプリを最小化しても、復元でき、復元後もモーダル性とキーボードフォーカスは戻る**
  * 最小化で**隠れたモーダルからは、最小化の間だけモーダル性を外す**（外さないと復元の操作が
    隠れた窓へ向かい、アプリを復元できない）。外している間も、**最小化で隠れた窓は操作できない**
    （隠れない窓の例外は下の「残存リスク」）。
    **最小化で隠れずに表示されたままのモーダルからは外さない**
  * 復元の際、アプリは**窓を表示し直したり前面へ持ち上げたりしない**（表示状態は OS が戻したまま。
    下のフォーカスの復帰・強制アクティブ化に伴うアクティブな窓・重なり順の変化は除く）
  * **戻す先**は、外したモーダルが表示されていればそのモーダル。**閉じている・表示されていない場合は
    表示中の最も内側のモーダル**。**別の窓が既にモーダルなら奪わない**
  * **最小化の間にネストの内側を閉じたり新しいモーダルを開いたりしても、復元後に表示中のモーダルの
    モーダル性は失われない**（最小化中は上の①②に当たっても戻す先を捨てず、復元時に戻す）
  * **復元後、キーボードフォーカスは復元後にモーダル性を持っている窓**（上の「戻す先」、または既にモーダルだった
    別の窓）**へ戻す**。戻す先はその窓の中で
    **最後にフォーカスがあった入力先**（開いたときの入力先とは別の欄にいた場合もその欄）。
    それに伴うアクティブな窓・重なり順の変化は許容する。
    モーダル性を持つ窓がアプリ側のモーダルでない（OS 標準のダイアログ等）・表示されていない場合は触らない
  * **上の条項でフォーカスを戻したあとも、アプリ内のどこにもキーボードフォーカスが無く、かつ前面の窓が
    アプリのメインウィンドウである場合に限り、戻し先のダイアログを強制的にアクティブにする**
    （この状態は、例えばタスクバーからの復元で起きる）。**他のアプリ・アプリの他の窓が前面のときや、
    前面の窓を判定できないときは強制しない**（他のアプリの入力を奪わない）。正確な判定は `codebase_map.md` の
    `presentation/modal.py` 節
  * **最小化の間に開いたモーダルには、その回の復元ではフォーカスを戻さない**
    （開いたときの入力先の指定を優先する。次回以降の復元では通常どおり戻す）
  * **残存リスク**: 最小化で隠れない独立ウィンドウ（例: キーボード表示ウィンドウ）は、
    **最小化の間は操作できる**（復元するとモーダル性は戻る）
* 保証の範囲外: **OS 標準のダイアログ**（ファイル選択・メッセージボックス）。
  これが開いている間の最小化も含む（**復元できない症状が残る** / 最小化中にこれが開くと
  **復元後にモーダル性が戻らない**ことがある）。
  また、**最小化中にアプリ側が新しいモーダルを開いた場合に復元できるか**も保証しない
  （その窓が最初から隠れていると預かりが働かない可能性がある。未検証・現状そのように開く経路はない）。
  復元時のフォーカスについても次は保証しない: ①他のアプリが前面かどうかは**判定した時点**のもので、
  その直後に前面が変わった場合はダイアログをアクティブにしうる ②最小化の間に開いたモーダルは、
  1 回目の復元でアプリがフォーカスを持てなかった場合（タスクバーからの復元を含む）、その回はキーが届かないことがあり、
  2 回目の復元で入力先がダイアログ自身になりうる
* **後始末は 2 種類に分け、置き場所を変える**
  * **状態の後始末**（アプリ側の状態を戻す。ウィジェットに触らない）は
    **アプリが動作している間、閉じ方によらず走る**
    （`key_input.md` §7.2 のフック停止解除がこれに当たる。
    **アプリの終了が確定した後は走らせない**＝終了処理と競合させない）
  * **ウィジェットに触る後始末**（値の収集・再設定）は**閉じる操作の側で行う**。
    破棄の時点では**子ウィジェットが既に無い**ため、破棄に載せてはならない
  * **閉じるボタンでも走らせる必要がある後者は、閉じるボタンも閉じる操作として扱う**
    （本節の「孤児ファイルの棚卸し…」の一覧編集の保存がこれに当たる）

#### UI と同期する実行系設定

* run_to_end / delay_ms / suppress は UI と状態を同期する
