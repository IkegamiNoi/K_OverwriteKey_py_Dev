## UI 用語と表記（phase 68）

画面に出る文言の用語と表記の正本。新しい文言を書くとき・ヘルプを書くとき・訳語を決めるときはここに従う。
経緯は `instructions/history/51_ui_terminology.md`（凍結）と `.claude_data/state/decisions_archive/68_ui_terminology.md`。
多言語対応・英語の用語と表記（phase 72）の経緯は `instructions/history/55_multilingual_ui.md`（凍結）と `decisions_archive/72_multilingual_ui.md`。

### 1. 対象

- **対象**: 利用者の目に触れる文字列 = 画面のラベル・ボタン・メニュー・ダイアログの題と本文・ステータスバー / フラッシュ通知・messagebox・入力検査のエラー文・一覧の表示文字列。
  application / domain 層で作られて画面に出る文言（例外文が「〜保存失敗: {e}」の形で出るもの等）も含む。
- **対象外**: JSON キー・コード識別子・ログ専用の文言（`logging` へ出すだけのもの）・テスト名・docstring・コメント・JSON に保存されるデータ値。
- **ファイル・フォルダ名**: 特定のファイル / フォルダそのものを指す表記（パス表示・`startup.json`・`config.json`・`global/`・`keymaps / trigger_sets / sequences`）はそのまま書く。
  種類を指す `keymap_set.json` / `keymap_set` は「構成セット」と書く。
- **内部名**: 文中で語として使う内部名（sequence・trigger_set 等）は用語表の語で書く。アクションの種類の値（`hotkey` / `mouse_click` 等）は画面では表示名（§2「アクションの種類の表示名」）で出す。
  「hotkeyとして反映されます」の hotkey は内部名のまま。

#### 多言語の扱い（phase 72）

- 画面の文言は**言語ごとの文言ファイル**（`keyseq/shared/i18n/locales/<code>.json`）に文言キーで置き、コードは文言キーを `tr` で引いて出す（仕組みは `codebase_map.md`「画面の文言の多言語対応」・`features.md` §4.6「言語」）。対応言語は日本語・英語。
- **ソースに画面に出る日本語の文字列を書かない**（静的テストで検査する。ログ専用・キー名等の例外は許可リストに内容・場所・理由の組で書く）。
- **表示文字列を内部値に使わない**: コンボボックスの値・分岐の比較には内部コードを使い、表示は内部コードから文言を引く（どの言語でも同じに動くため）。
- **訳した文言をモジュール定数に入れない**（定数は文言キーを持ち、表示する時点で引く。import 時に引くと言語を決める前の日本語で固まる）。
- **アプリが作って保存する既定の文言**（旧形式移行のキーマップのラベル等）は作った時点の言語で作る。保存後はデータ値として訳さない。
- 対象外（§1 の対象外に加えて）: キーの名前（`Enter`・`変換` 等）・tkinter / OS 標準のダイアログの部品・同梱のサンプル設定の中身・ライセンス本文。
- 英語の文言は §2 の英語の列と §3「英語の表記の規則」に従う。

#### アクションの種類の表示名（phase 72）

保存する値は内部名のまま（`data_schema.md` §5.11）。表示名はアクションの編集の「種類」のコンボボックスに出す。マウスのボタン（`left` / `right` / `middle`）も、編集のコンボボックスと出力シーケンスの一覧で表示名（左 / 右 / 中・Left / Right / Middle）を出す。
**出力シーケンスの一覧の行頭の印は表示名にせず、全言語共通の英語の短い名前**（`[hotkey]`・`[click]`・`[scroll]`・`[press]` / `[release]` 等・`features.md` §4.6「一覧の表示形式」）。

| 内部名 | 日本語 | 英語 |
|---|---|---|
| `hotkey` | ホットキー | Hotkey |
| `text` | 文字入力 | Type text |
| `mouse_click` | マウスのクリック | Mouse click |
| `mouse_scroll` | マウスのスクロール | Mouse scroll |
| `key_hold` | 押下・解放 | Press / Release |
| `system` | 制御 | Control |
| `file_line` | ファイルの行 | File line |

#### 用語の細則

- **画面上のトリガーのリスト**の見出しは「トリガー一覧」（A8 のトリガーセットとは別。`features.md` §4.6）。
- **A3・A4**: キー置換の通知は「キー置換を更新しました: a -> b (id)」「キー置換をクリアしました: a (id)」の形。
- **A6**: 切替の方式は 1 つだけなので「直接」は付けない。
- **A14**: 「簡易表示」は CompactView の呼び名だけ。長い文字列を「…」で切り詰めることは「省略」と書く（例: 「「…」で省略してツールチップで全文を出す」）。
- **A9**: 「読む」はメニュー「起動時に読む構成セットを指定…」の語としてそのまま使う（A9 の対象外）。
- **A15**: 共有状況の判定名は「別の親ファイル」とする。画面の文言は「別の{親の種類名}に属します」。
- **A11 で「変更」のまま残すもの**: 名前の変更（「名前変更」「分類名を変更」）・指示文（「〜を変更してください」）・名詞（「未保存の変更」）・値の差し替え（「呼び出し先を変更できません」）・結果の通知（「〜を変更しました」「〜に変更はありません」）。
- **「キーマップ一時停止」「キーマップ再開」**はキー置換とトリガーの両方を止めるので、キーマップ（A2）のまま。
- **未保存確認の操作名**（「{操作名}の前に保存しますか？」へ差し込む）は体言で書く（例: サンプル設定の復元・トリガーセット読込・起動時に読む構成セットの変更）。
- **専門語**「キーボードUI」「フック」「参照元の掃除」はこの語のまま使い、ヘルプで説明する。
- **旧形式移行で作るキーマップのラベル**は「旧トリガーセット（{stem}）」（phase 68 以降に作るもの。保存済みのラベルは書き換えない・`data_schema.md` §5.13.3）。

### 3. 表記の規則

個別に確定した文の詳細は `instructions/history/51_ui_terminology.md` §2.2・§3.2〜§3.5 を参照。個別の確定文はここに載せない（実装の文字列が正・ユーザー確定 2026-10-24）。

| # | 規則 | 例 |
|---|---|---|
| D1 | 括弧は中身で使い分ける: 和文を含むなら全角（）、英数字・記号だけなら半角 ()。**全角括弧の前に空白を入れない** | `（なし）`・`（リピート）` / `間隔(ms)`・`({keymap_id})` |
| D2 | 例示は「例: 」 | `例: トリガー: f1` |
| D3 | 省略記号は「…」1 文字。**開いた先で入力・選択をしてから実行するメニュー項目・ボタンだけに付ける**（すぐ実行するもの・確認だけを出すもの・ウィンドウを開くだけのものには付けない）。進行中の表示（「記録中…」）は対象外（phase 68 で確定した「…」の一覧: `instructions/phase/68_ui_terminology/tools/d3_ellipsis_list.md`） | `別名保存…`・`読込…`・`追加…` / `参照元を掃除`・`サンプル設定に戻す` |
| D4 | 区切りのコロンは半角「: 」。**直後が改行のときは空白を入れない**（`:\n`・decisions 2026-10-23）。識別子の組（`kind:key`）は対象外 | `記録中: 切替キーにしたいキーを…` |
| D5 | 半角英数字と和文の間に空白を入れない（英単語どうし・記号〔` -> `・` / `・`: ` の後〕の前後の空白は残す） | `Escで停止`・`1以上の整数`・`[scroll] 下3` |
| D6 | 「すでに」（仮名書き） | `すでに存在します` |
| D7 | 「選択してください」 | `呼び出し先を選択してください` |
| D8 | 画面に出る「不正です」は「正しくありません」（開発者寄りの検査文も含む） | `操作が正しくありません。` |
| D9 | 入力ダイアログの未入力の検査は「〜を入力してください。」（ファイルの中身・内部の検査の「〜が空です」はそのまま）。「hotkey が空です」は据え置く | `値を入力してください。` |
| D10 | Import / Export は英字のまま（メニュー「Import...」「Export...」・通知。D3・D5 も当てない） | — |
| D11 | 「Keyboard UI」は「キーボードUI」、「デフォルト」は「既定」 | `キーボードUI — 編集中: …` |

#### 差し込み（`{...}`）の前後

中身の想定で判定する。数値・ID・キー名は半角英数字として扱い、和文との間の空白を除く（`{n}件`・`{key}は`）。ラベル・名前・パスなど中身が決まらないものは前後の空白を残す（`キーマップ {name} へ`）。列をそろえるための空白は D5 の対象外。

D3 を適用するときは文頭の「…」を外す。D2 の「例: 」に含まれる空白は D5 の対象外。使わない語として据え置いた語・ファイル名の前後にも D1〜D6 を適用する。

#### 英語の表記の規則（phase 72）

Mac でも同じ文言を使う（OS ごとに文言を分けない）。

| # | 規則 | 例 |
|---|---|---|
| E1 | 大文字は**文頭と機能名だけ**（メニュー・ボタン・窓のタイトルも sentence case）。**機能名（E7）は文中・メッセージ・ヘルプでも常に各語の先頭を大文字**。固有名・略語は元の形。`/` で並べた語はそれぞれ先頭を大文字 | `Save as…`・`Edit Presets…`・`Delete the selected Action?`・`OK`・`Press / Release` |
| E2 | 省略記号は D3 と同じ規則で「…」1 文字（Import... / Export... は今の形のまま・D10） | `Load…` |
| E3 | コロン・括弧は D1・D4 と同じ（半角・コロンの後に空白） | `Key: f1`・`Interval (ms)` |
| E4 | ラベル・ボタン・見出しは句点を付けない。文のメッセージは「.」で終える | `Stop Key` / `The file was not found.` |

| E7 | **機能名の一覧**（E1 で大文字にする語）: Profile / Keymap / Key Remap / Source Key / Target Key / Stop Key / Switch Key / Output Sequence（Sequence）/ Trigger Set / Preset・Shared Preset・Profile Preset・Built-in Preset / Sample Settings / Compact View / Full View / Always on Top / Trigger Key / Active Keymap / Cursor Grid / Cell / Trigger / Action / Hook / Keyboard UI。複数形も同じ（`Presets`）。**対象外** = 操作の語（Load・Record・Pick・Edit・Save as・Run・Archive・Clean up…）・Folder・記録や候補の語（Save location record 等）・アクションの種類の表示名。語が機能を指さない一般の用法（動詞の trigger 等）・差し込み名・ファイル名・JSON のキー・内部名は変えない | `Hook: ON`・`Add Trigger…`・`Compact View / Full View`・`Use as a Profile Preset` |

### 4. 確認ダイアログのボタン

はい / いいえ に本文で意味を割り当てない。操作名をボタンに書く（`config_io/choice_dialog.py`。ダイアログの作法は `features.md` §4.6「モーダルダイアログの作法」）。
