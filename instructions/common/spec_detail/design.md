## 2. 設計思想

### 2.1 入力置換の安全性を最優先する

* フック暴走を起こさないことを最優先とする
* suppress の副作用を常に考慮する
* keyboard の例外は必ず吸収し、失敗理由が追える形にする

### 2.2 UI とフックの分離

* フック処理（keyboard）は UI と分離する
* UI 更新は必ず UI スレッドで行う（`after()` を使用）
* UI スレッドをブロックしない

### 2.3 データと UI の分離

* 保存データ（JSON）の形式は `data_schema.md` が正
* JSON の後方互換を必ず維持する（既存キーの削除・意味変更の禁止）
* UI 都合でデータ形式を変えない

### 2.4 既存設計の尊重

* タスク指示なしの独断再設計を行わない
* 既存の設計・命名を尊重する
* 目的達成に必要な範囲で変更し、不要な変更は行わない
