#### 5.8.6 依存関係と保存先の記録の更新

* **子の保存先パスが変わるとき、その子の保存先を記録する親ファイルの保存は必須**とする
  （キーマップ → 構成セット、**トリガーセット → キーマップ**〔共有一覧は全メンバー〕、出力シーケンス → トリガーセットの 3 段。phase 34）。
  キーマップを別名保存に選び直したら、ファイル未作成の トリガーセットの既定名を新しい保存先の stem で再計算する。
  「パスが変わる」には**別名保存だけでなく、source_path を持たない子が新たに実体化する場合**も含む
  （旧形式のインライン 出力シーケンス・「サンプル設定に戻す」直後の子など）
* **例外（deferred index）**: 依存確認の 4 択で「保存しない」を**明示選択**したときのみ、親ファイルの保存を見送る。
  このとき親ファイルの保存先の記録は**旧パスを維持**し、親ファイルは**保存前の dirty 状態にかかわらず未保存にする**
  （次回保存で追随する）。構成セット本体と起動設定は従来どおり保存する。
  `_parent_refs` を更新するのは実際に書いた子のみ
* **書き込み失敗時の保証は best-effort**（完全なトランザクションは行わない）。
  **親ファイルの保存先の記録を新しいパスへ進める前に、子の書き込み成功を確認する**書き込み順序とし
  （子 → 親ファイル → 構成セット→ 起動設定）、子が書けなかった場合は**親ファイルの保存先の記録と起動設定を
  旧内容のまま維持する**（部分的に壊れた保存先の記録を残さない）
* **「保存しない」を選んだ子は、保存後も未保存マークが残る**
* **「保存しない」を選んだ子の保存先の記録**は、**旧 source_path が実在すればそのパスを指し、
  無ければ空にする**。キーマップの保存先の記録が空になった場合、そのキーマップは構成セットの
  `keymaps[]` から落ちる（実体を指せないエントリを書かない）
* 構成セットの「保存」自体は明示操作のため、子の別名保存で保存先のパスが変わっても 構成セットの
  保存に追加の確認は求めない
* **変更が無い状態で保存した場合も**、構成セット・起動設定・未実体化の子は書かれ、保存完了メッセージも出る
