#### 5.8.4 共有状況と既定選択規則

保存先ファイルの `_parent_refs` と現在の親ファイルを比較し、共有状況を判定する。**判定名と画面表示の文言は別物**
であり、分岐は必ず判定名で行う。

| 判定 | 条件 | 既定のアクション | 画面表示 |
| --- | --- | --- | --- |
| 新規作成 | 保存先にファイルが無い | 保存 | 「新規作成」 |
| 単独所有 | 参照元が現在の親ファイルのみ | 保存（上書き） | 「この{親の種類名}のみが所有・既存を上書き」 |
| 共有中 | 参照元に現在の親ファイルを含み、かつ複数 | 保存（上書き） | 「{n}個の{親の種類名}で共有中・全てに影響します」 |
| 別の親ファイル | 参照元に現在の親ファイルが無い | **別名保存** | 「別の{親の種類名}に属します」 |
| 所有元不明 | `_parent_refs` が無い / 空、**または現在の親ファイルが未確定（空）** | **別名保存** | 「所有元不明・安全のため別名」 |

表の「判定」は分岐に使う分類名で、「画面表示」の親の種類名は子の種類ごとに変わる（キーマップの親は構成セット、トリガーセットの親はキーマップ、出力シーケンスの親はトリガーセット）。

* **上表より優先する規則**: **source_path を持たない子（新規）**の保存先に**既存ファイルがある**とき、
  元の判定が「単独所有」「共有中」なら**既定を別名保存**へ倒す（表示「同名の既存ファイルあり・安全のため別名」）。
  * **対象はキーマップ / トリガーセット / 出力シーケンスのすべて**（phase 34 でトリガーセットの除外を撤廃。既定名が親キーマップのラベル由来となり
    他の構成セットのファイルと衝突し得るため。除外の理由だった「単独所有なら確認を出さない」がトリガーセットで空振りし得ることは受け入れる）
  * 「別の親ファイル」「所有元不明」には適用しない（既定は元から別名保存であり、具体的な警告文が失われるだけ）
* 比較する「現在の親ファイル」は直接の親（キーマップ→構成セット、トリガーセット→キーマップ、出力シーケンス→トリガーセット）。
  移行したトリガーセットの特例は §5.8.1
* いずれも**既定**であり、ユーザーは行ごとに選び直せる。共有情報は保存ダイアログ内でのみ表示する
* **帰結**: 既存と同名の構成セットを保存先に指定しても、同名の既存トリガーセットは**黙って上書きされない**
  （既定は別名保存。旧来の「stem 由来のトリガーセットは上書きされる」は phase 34 で廃止）
