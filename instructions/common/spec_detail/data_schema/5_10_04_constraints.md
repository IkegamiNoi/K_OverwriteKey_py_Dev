#### 5.10.4 契約上の制約（既知・実装は変更しない）

* **破損・不存在（＝「読めない」）のときも、プリセットマネージャの保存はファイルを上書きする**。
  破損内容を退避・警告する仕組みは持たない。**保存前に利用者が退避すること**。
  ただし**個別ファイルへの書き込みでは §5.10.3 の上書き確認が挟まる**
  （保存先が読めない場合も「異なる」として確認する。グローバルへの書き込みは対象外）
* **「読めない」ときの上書き内容は入口経路によって異なる**。置き換えを行わないため runtime は
  **起動時の空データフォールバック（E4）＝空 / Import（E5）＝取り込んだ単一JSON のインライン値 /
  それ以外（E1・E2・E3・L1〜L3）＝組込の既定プリセット**となる。
  その状態でプリセットマネージャを確定すると**その内容でライブラリが確定する**
  （例: 空データ起動のセッションでは**空でライブラリが確定し得る**）。
  * **ただし OFF でマネージャを開いた場合には当てはまらない**。§5.10.3 の UI 契約により
    **開いた時点で表示元（グローバル / 読めなければ組込既定）へ一覧を確定させる**ため、
    runtime が個別由来の一覧を持ったまま OFF になっていても、
    **書かれるのは表示元の内容**になる（ラベルと実体が乖離しない）。
    **この確定は runtime への注入ではなくダイアログ内の表示用再読込**である（§5.8.8 の P1）
* **同一 stem の複数 keymap_set が同じ個別ファイルを共有し得る**（無警告）。
  §5.8 の `_parent_refs`・共有状況判定・誤爆保護は**個別プリセットには効かない**。
  §5.10.3 の上書き確認が止めるのは「**共有が始まる瞬間のデータ損失**」であり、共有そのものは許容する
* **`hotkey_presets_individual` キーを持つ keymap_set で `hotkey_presets_path` を手編集した場合**は、
  **記録済みパスがそのまま個別ファイルの保存先になる**（アプリが書いた値かを値から判別できないため。
  config 外なら §5.10.3 の 1. で既定パスへ寄る）
* **個別指定を OFF へ戻すときにグローバルが読めない場合**は、一覧が**組込既定へ差し替わり**、
  OK で**グローバルが組込既定として作成 / 修復される**。
  このとき**壊れた既存のグローバルファイルは退避されずに上書きされる**（1 点目の既定規則どおり）
* **上書き確認と書き込みの間の競合（別プロセスによる作成・置換）は対象外**とする
  （§5.8.3 の「保存先に実体があれば保存しない」等と同水準の既知の性質）
* **別名保存での複製は keymap_set の保存より前に実行され、保証は best-effort**
  （§5.8.6 と同じ方針）。**複製に成功した後で keymap_set 本体の保存が失敗した場合は巻き戻さない**ため、
  **孤児となった複製ファイル**と、**メモリ上だけ新しい保存先を指す `hotkey_presets_path`** が残る
  （ディスク上の keymap_set は旧パスを指したままなので、**次回起動時の読み込み先は変わらない**）。
  この状態で続けてプリセットを編集して確定すると、**複製の内容と読み込んだ一覧が一致するため
  上書き確認は出ず**、編集は複製側へ書かれる。**keymap_set を保存し直せば新パスが永続化されて解消する**が、
  保存せずに終了すると編集が反映されていないように見える
  （実体は複製側に残る＝データは失われない）。是正は
  [idea_11](../../../backlog/idea_11_save_as_preset_copy_rollback.md)（優先度低）
* **上書き確認で「既存を読み込む」を選んだ直後、「一覧の出どころ」の表示は追従しない**
  （個別 / グローバル / 組込既定の 3 分類に「保存先の実体を採用中」が無いため）。
  **対象ファイルは個別指定のチェックと保存先の表示で判別できる**ため、状態を増やさない
* **プリセットの読み出しは同期実行**のため、**到達不能な UNC / 切断されたネットワークドライブ /
  極端に大きい JSON** を指していると読み込み中は UI が待たされる
  （config 外に限らず、trigger_set・keymap の読み出しと同じ性質。非同期化はしない）
* **旧「別ディレクトリ保存」で生成された `<保存先>/hotkey_presets/default.json` は参照されない**。
  当該 keymap_set は `hotkey_presets_individual` キーを持たないため §5.10.1 の移行規則で
  常に OFF となり、残置パスも引き継がれない。必要なら手動でライブラリへ移す
* **Export（単一JSON）はプリセットをインラインで含む**が、Import 時はライブラリが読めれば
  そちらで置き換わるため、**Export ファイル中のプリセットは事実上デッドデータ**になる
  （ライブラリが読めないときだけインライン値が残る）
