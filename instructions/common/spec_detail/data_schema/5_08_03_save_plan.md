#### 5.8.3 保存計画（アクションと既定規則）

* 各子ファイルのアクションは **保存（上書き） / 別名保存 / 保存しない** の 3 種
* 決定の優先順位は 1 箇所に集約する: **確認ダイアログでの選択 > 確定済みエントリ > 既定規則**
* **既定規則**（＝ダイアログに出ない子の扱い）:
  **保存先に実体があれば「保存しない」・無ければ「保存」**。
  実体が無いのに保存しないと上位の索引が切れるため、**未実体化の子は未保存でなくても保存対象**とする
* **確認ダイアログの行として出るのは未保存（dirty）の子だけ**。非 dirty の子は
  ダイアログに現れないまま既定規則で決まる
* **source_path を持たない子（keymap / trigger_set / sequence）は常に未保存扱い**で行に出す（phase 34）。
  既定保存先に同名ファイルがあっても黙って「保存しない」にならない（自動作成キーマップ・Import・移行した子が対象）。
  ただしトリガーが 0 件で source_path も持たない trigger_set は行に出さずファイルも作らない（§5.13.5）
* **旧形式からの移行先キーマップ**（§5.13.3）の行は「保存しない」を選べない（保存 / 別名保存のみ）
* keymap を「保存しない」と明示選択した場合（移行先を除く）、その keymap の `trigger_set_path` は旧値のまま・未保存マークも残す
* 保存計画は**表示層が決定し、アプリケーション層が実行する**（表示層のダイアログ都合を
  アプリケーション層へ持ち込まない）
