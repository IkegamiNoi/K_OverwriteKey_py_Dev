#### 5.8.7 個別保存経路

* 各パネルの個別「保存」「別名保存」も §5.7 に従いパスを解決してから書き込む
  （相対表記のまま書き込み層へ渡さない）
* **個別「トリガーセットを保存」も保存計画で実行する**（対象はアクティブなキーマップのトリガー一覧の実体）。dirtyな出力シーケンスがあれば
  **出力シーケンス行のみの一覧ダイアログ**を出し、計画にある子だけを書く（トリガーセット自身は行に出さない）。
  dirtyな出力シーケンスが無ければダイアログを出さない。親参照は §5.8.1（source_path が実在する共有メンバーだけ）。
  フォールバック名は §5.6（親キーマップの保存先 stem → `trigger_set`）
* **個別「キーマップを保存」も保存計画で実行する**。そのキーマップのdirtyなトリガーセット / 出力シーケンス（source なしを含む）があれば
  一覧ダイアログを出す（キーマップ自身は行に出さない）。トリガーセットの保存先が決まってからキーマップの `trigger_set_path` を書く。
  保存後に runtime の `triggers` の list オブジェクトを差し替えない（共有実体とトリガー一覧の表示の参照を保つ）。
  移行先キーマップを個別保存した場合は構成セットを未保存のまま残す
* **個別読込**:
  * トリガーセットの読込は**アクティブなキーマップにだけ**付ける。共有していた場合はアクティブだけが新しい実体を持つ（共有が外れる）。
    同じ解決先の実体を持つキーマップがすでにあればその実体を共有し、**その一覧を未保存にする**（次の保存で `_parent_refs` に新しいキーマップを加えるため）
  * キーマップの読込は参照先のトリガーセット・出力シーケンスも一緒に読み（同じ解決先は共有し、そのトリガーセットを未保存にする）、
    **キーマップの追加として扱う**（`features.md` §4.3 のキーマップ追加の規則: 切替キーの無い既存と読み込んだキーマップの切替キーを 1 つのダイアログでまとめて設定〔0 → 1 個を除く〕/
    キャンセルなら runtime を変えない）。**同じキーマップファイルの二重読込は拒否**（§5.13.2）
* 個別保存・個別読込で子の保存先・参照が変わったときは、**その子の保存先を記録している直接の親ファイルを未保存にする**
  （出力シーケンス→トリガーセット、**トリガーセット→親キーマップ〔共有なら全メンバー〕**、キーマップ→構成セット）。親ファイルを自動保存はしない
