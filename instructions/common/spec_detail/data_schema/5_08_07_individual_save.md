#### 5.8.7 個別保存経路

* 各パネルの個別「保存」「別名で保存」も §5.7 に従いパスを解決してから書き込む
  （相対表記のまま書き込み層へ渡さない）
* **個別「トリガー一覧を保存」も保存計画で実行する**（対象はアクティブキーマップのトリガー一覧の実体）。dirty な sequence があれば
  **sequence 行のみの一覧ダイアログ**を出し、計画にある子だけを書く（trigger_set 自身は行に出さない）。
  dirty な sequence が無ければダイアログを出さない。親参照は §5.8.1（source_path が実在する共有メンバーだけ）。
  フォールバック名は §5.6（親 keymap の保存先 stem → `trigger_set`）
* **個別「キーマップを保存」も保存計画で実行する**。そのキーマップの dirty な trigger_set / sequence（source なしを含む）があれば
  一覧ダイアログを出す（keymap 自身は行に出さない）。trigger_set の保存先が決まってから keymap の `trigger_set_path` を書く。
  保存後に runtime の `triggers` の list オブジェクトを差し替えない（共有実体とトリガー一覧の表示の参照を保つ）。
  移行先キーマップを個別保存した場合は keymap_set を未保存のまま残す
* **個別読込**:
  * トリガー一覧の読込は**アクティブキーマップにだけ**付ける。共有していた場合はアクティブだけが新しい実体を持つ（共有が外れる）。
    同じ解決先の実体を持つキーマップが既にあればその実体を共有し、**その一覧を未保存にする**（次の保存で `_parent_refs` に新しいキーマップを加えるため）
  * キーマップの読込は参照先のトリガー一覧・シーケンスも一緒に読み（同じ解決先は共有し、その一覧を未保存にする）、
    **キーマップの追加として扱う**（`features.md` のキーマップ追加の規則: 切替キーの無い既存を先に設定 / 読み込んだキーマップにも切替キー必須〔0 → 1 個を除く〕/
    キャンセルなら runtime を変えない）。**同じキーマップファイルの二重読込は拒否**（§5.13.2）
* 個別保存・個別読込で子の保存先・参照が変わったときは、**その子を索引する直接の上位を未保存にする**
  （sequence → trigger_set、**trigger_set → 親 keymap〔共有なら全メンバー〕**、keymap → keymap_set）。上位を自動保存はしない
