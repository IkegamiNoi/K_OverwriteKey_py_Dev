# key_input.md — キー入力・フック仕様

## 7. キー入力・フック

### 7.1 グローバルフック

* keyboard によるグローバルフックを必須とする
* `suppress=True` を使用する（元入力を抑制して置換する）
* suppress の副作用を常に考慮する

### 7.2 フックの停止制御

* 停止キー（hook_stop_key）でフックを停止できる。停止トリガーも単キー
* UI 編集中（キャプチャ・ダイアログ等）はフックを停止する（**ネスト対応**: 多重に
  停止要求が重なっても、すべて解除されるまで再開しない）

### 7.3 トリガー

* トリガーは単キーのみ
* トリガーの重複は禁止（停止キーとの重複も含む）

### 7.4 キーキャプチャ

* 停止キー / トグルキーのキャプチャは相互排他とする
  （`SingleKeyCaptureController` が担当。現状は `codebase_map.md` を参照）

### 7.5 安全ルール

* フック暴走を起こさない（暴走防止最優先）
* keyboard の例外は必ず吸収する
* フック処理を UI と競合させない。UI 更新は `after()` で UI スレッドへ委譲する

### 7.6 停止/トグルキーの供給源

* 停止キー / トグルキーは**全体デフォルト（`config/config.json`）**と
  **keymap_set の個別指定**の 2 系統を持つ。データ側の規定は `data_schema.md` §5.9
* **フック実行層が見るのは解決済みの 1 値のみ**。供給源（全体 / 個別）による分岐を
  フック側に持たせない（解決は keymap_set を runtime へ載せる時点で確定する）
* **個別指定 OFF のときのキー取得 / クリアは全体デフォルトを編集する**
  （keymap_set は変更せず、未保存にもしない）。ON のときは keymap_set の個別値を編集する
* **キーの重複検証はカレント keymap_set 内に閉じる**（§7.3）。全体デフォルトは他の keymap_set の
  トリガーとは照合されないため、別の keymap_set でトリガーと重なり得る。
  重なった場合は**停止 / トグルがトリガーより優先**される
* 個別指定のチェックは **FullView で操作**する。CompactView は**状態表示のみ**
  （キー欄も readonly 表示）
