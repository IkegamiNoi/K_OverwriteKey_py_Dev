# key_input.md — キー入力・フック仕様

## 7. キー入力・フック

### 7.1 グローバルフック

* keyboard によるグローバルフックを必須とする
* `suppress=True` を使用する（元入力を抑制して置換する）
* suppress の副作用を常に考慮する

### 7.2 フックの停止制御

* 停止キー（hook_stop_key）でフックを停止できる。停止トリガーも単キー
* UI 編集中（キャプチャ・ダイアログ等）はフックを停止する（**ネスト対応**: 多重に
  停止要求が重なっても、すべて解除されるまで再開しない）
* **停止要求は閉じ方によらず解除される**（OK / キャンセル / Escape / 閉じるボタン /
  プログラムからの破棄のいずれでも、ちょうど 1 回）
* **停止要求が残っている間は置換もアクション実行も行わない**（停止が間に合わず届いた入力は**元のまま素通しする**。飲み込まない）
* **アプリの終了が確定した後はフックを再開しない**

### 7.3 トリガー・入力判定の優先順位・重複（phase 34）

* トリガーは単キーのみ。トリガー一覧はキーマップに従属し（`data_schema.md` §5.13）、入力判定・表示はアクティブキーマップのものを扱う
* **入力判定の優先順位**: **停止 > トグル > 直接切替 > トリガー > 置換**（トリガー・置換はアクティブキーマップのもの）。
  「キーマップ一時停止」中は停止 / トグル以外（直接切替・トリガー・置換）はすべて無効
* **編集時の重複禁止**:

  | 登録するもの | 拒否する相手 |
  |---|---|
  | トリガーキー | 停止 / トグル / 全キーマップの直接切替キー / 同キーマップの既存トリガー / 同キーマップの置換元キー |
  | 置換元キー | 停止 / トグル / 直接切替キー / 同キーマップのトリガーキー |
  | 直接切替キー | 停止 / トグル / 全キーマップのトリガーキー / 全キーマップの置換元キー / 他キーマップの切替キー |
  | 停止 / トグルキー | 互い / 全キーマップのトリガーキー / 全キーマップの置換元キー / 直接切替キー |

  別キーマップのトリガーと置換元キーの重複は許す（別モード）。共有しているトリガー一覧で別キーマップの置換と重なった場合は、
  そのキーマップではトリガーが動き置換が使えなくなる（キーボード表示でトリガーが上に出ることで分かる）
* **読込等で重なった場合（編集時の拒否をすり抜けた重なり）**:
  * トリガーが停止 / トグル / 直接切替キーと重なる → トリガー一覧で**グレー表示＋理由**（「停止キーと重複」/「一時停止/再開キーと重複」/「切替キーと重複」。
    複数なら上位の 1 つ）。入力判定では上位が動く。編集はできる
  * 直接切替キーが停止 / トグルと重なる → キーマップ一覧で**グレー表示＋理由**。キーでは切り替わらないが**一覧からの選択・編集はできる**
  * **置換元キーとの重なりではトリガーをグレーにしない**（トリガーが勝つ）
  * キーボード表示: トリガーを置換より優先して表示し、予約キー（停止 > トグル > 切替）が最後に上書きする
* **重なったキーを押したときの案内**: グレー表示の割り当てに対応するキーが押され上位が働いたとき、**ステータスバー中央の一時メッセージ領域**に
  重複と変更の案内を出す（例「f12 は停止キーと重複しているため、トリガーは実行されません。トリガーのキーを変更してください」/
  「f9 は停止キーと重複しているため、キーマップ <名前> へ切り替えられません。切替キーを変更してください」/
  「f3 は切替キーと重複しているため、トリガーは実行されません。…」）。停止キーでフックが止まる場合は「停止しました」と併記する（上書きしない）。
  置換元キーと停止 / トグル / トリガーの重なりは案内しない。「キーマップ一時停止」中は重なりの案内を出さない
* **重なりの判定は 1 箇所**（`application/key_overlap.py`）に置き、グレー表示・案内・編集時拒否・開始検証が共有する。
  判定結果は**読み取り専用の表**として保持し、データが変わる契機（トリガー / 置換 / 切替キー / 停止・トグルキーの編集・読込・アクティブ切替）で作り直す。
  **キー入力時（フックのスレッド）は表を引くだけ**で全件走査しない。どの割り当てが動くか（上記の優先順位）はキー入力時に判定し、表は案内にだけ使う
* **フック開始を止める重複は「停止キーとトグルキーが同じ」だけ**。停止 / トグルとトリガー・置換元キー・直接切替キーの重なりでは開始を止めない。
  「トリガーが 1 件も無い」判定は全キーマップのトリガー・置換元キーで行う

### 7.4 キーキャプチャ

* 停止キー / トグルキーのキャプチャは相互排他とする
  （`SingleKeyCaptureController` が担当。現状は `codebase_map.md` を参照）

### 7.5 安全ルール

* フック暴走を起こさない（暴走防止最優先）
* keyboard の例外は必ず吸収する
* フック処理を UI と競合させない。UI 更新は `after()` で UI スレッドへ委譲する

### 7.6 停止/トグルキーの供給源

* 停止キー / トグルキーは**全体デフォルト（`config/config.json`）**と
  **keymap_set の個別指定**の 2 系統を持つ。データ側の規定は `data_schema.md` §5.9
* **フック実行層が見るのは解決済みの 1 値のみ**。供給源（全体 / 個別）による分岐を
  フック側に持たせない（解決は keymap_set を runtime へ載せる時点で確定する）
* **個別指定 OFF のときのキー取得 / クリアは全体デフォルトを編集する**
  （keymap_set は変更せず、未保存にもしない）。ON のときは keymap_set の個別値を編集する
* **キーの重複検証はカレント keymap_set 内に閉じる**（§7.3）。全体デフォルトは他の keymap_set の
  トリガーとは照合されないため、別の keymap_set でトリガーと重なり得る。
  重なった場合は**停止 / トグルがトリガーより優先**され、§7.3 のグレー表示と案内で知らせる（フック開始は止めない）
* 個別指定のチェックは **FullView で操作**する。CompactView は**状態表示のみ**
  （キー欄も readonly 表示）

### 7.7 キーの送信

* アプリが送るキー（出力シーケンスの hotkey アクション・キーマップの送信先キー）のうち、
  Windows の**拡張キー**は拡張キーとして送る（テンキーや左側のキーとして扱われないようにする。
  例: 拡張キーとして送らないと `shift+right` がテンキーの 6 と Shift の組み合わせとして扱われ、範囲選択にならない）
* 対象のキー名（別名は keyboard ライブラリの名前の正規化に従う）:
  up / down / left / right / home / end / page up / page down / insert / delete /
  right ctrl / right alt / windows・left windows・right windows / menu（アプリケーションキー）/ print screen / num lock
  * 左右を指定しない `windows` は左の Windows キーとして送る。`ctrl` / `alt` / `shift` は左側（非拡張）のまま
  * 名前で区別できないテンキーの Enter・`/` は対象外（名前は主キーボード側のキーを指す）。`alt gr` は従来どおり
* 組み合わせは記述順に押し、逆順に離す（従来どおり）。テキスト入力（text）・マウス操作は対象外
* hotkey の書式・検証（`codebase_map.md` の hotkey 文法）は変えない
