## §1 目的 / 背景

キーボードUI（`KeyboardWindow`）を、スペースを取らず・前面に置け・大きさを変えても空白が出ない窓にする。
**presentation 層が主（前面の窓の判定は既存の infrastructure を使い、マウスのボタン状態の判定を infrastructure に 1 関数足す・v0.4）。JSON スキーマ変更なし**（前面化の状態は保存しない）。

## §2 確定事項（ユーザー 2026-10-12）

1. **ステータス欄を削除**し、レイアウト名と編集中の案内は**ウィンドウタイトル**へ出す（色分けの説明・操作の案内は出さない）
2. **メインの表示欄に「キーボードUIを常に手前」チェック**を加える
   - 両方を手前にしたときは、Windows の標準動作で**アクティブな方が上**になる（特別な処理をしない）
   - キーボードUIだけ手前のとき、メインをアクティブにしてもキーボードUIが上に残ってよい
   - **保存しない**（起動時 OFF・メインの「常に手前」と同じ）
   - キーボードUIを閉じていても操作でき、開いたときに反映する
   - **アプリのダイアログが前面にある間は、キーボードUIの「手前」を一時的に外す**（前面の窓を監視する方式。ダイアログ側は変更しない）
3. **リサイズは縦横比を固定**（比率はレイアウトのキー配置から決める）。縦 / 横 / 斜めのどの辺を動かしても他方が追従する。
   **ドラッグ中は補正せず、大きさの変化が止まって約 150ms 後に 1 回だけ比率へ合わせる**（ガタつきを原理的に出さない）。
   縦横とも変わったときは今の大きさに収まる最大の形にする。スナップ・配置ツールで置いた後も補正される（形が崩れる）ことは受容する。
   レイアウト切替時も比率を当て直す

## §4 キーボードUIを常に手前

### チェックと適用

- `UiVars` に `keyboard_always_on_top_var`（BooleanVar・既定 False）を加える。保存・読込の対象にしない
- フル / 省略表示の表示欄に Checkbutton「キーボードUIを常に手前」を置く（2 つの表示欄で同じ変数を共有）。
  配置は「キーボードUI」ボタンの下の行（row 3・column 0・`columnspan=2`）
- 適用（実効値 = チェック ∧ ¬一時解除中。§4 一時解除）:
  - チェックの変更時: キーボードUIが開いていれば `-topmost` を実効値にする。閉じていれば何もしない
  - キーボードUIを開いたとき（新規作成・既存窓の再表示の両経路）: 実効値で `-topmost` を当てる
  - 失敗は吸収する（メインの `_apply_always_on_top` と同じ）
- 責務: 適用と一時解除は `LayoutController`（KeyboardWindow のライフサイクル管理）が持つ。表示欄はコールバックを呼ぶだけ

### ダイアログ表示中の一時解除

- 監視: チェック ON **かつ** キーボードUIが開いている間だけ、約 200ms ごとに前面の窓を調べる（UI スレッドの `after`。条件が外れたら止める・窓の破棄で止める）
- 判定: 前面の窓が**自プロセスの窓で、メインの窓でもキーボードUIの窓でもない**とき = 「ダイアログが前面」→ 一時解除中にし `-topmost` を外す。
  それ以外（メイン / キーボードUI / 他プロセス / 前面なし）→ 一時解除を終え、チェックが ON なら `-topmost` を戻す
  - 窓の同一判定は Toplevel の枠の HWND（`wm_frame()`）で行う。自プロセス判定は phase 53 の既存処理を使う（presentation から直接 ctypes を呼ばない）
  - 状態が変わったときだけ `-topmost` を当て直す（毎回当てない）
  - **一時解除で `-topmost` を外した直後に、キーボードUIを前面の窓（ダイアログ）の直下へ置く**（v0.5・task_03 の実機目視で判明）。
    理由: Windows は topmost を外した窓を**非 topmost の窓の最上位**へ置く（`SetWindowPos(HWND_NOTOPMOST)` の仕様）ため、外しただけではダイアログを覆う。
    置き方は infrastructure の関数（`SetWindowPos(キーボードUI, hWndInsertAfter=ダイアログ, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE)`）を App が注入する。
    最背面へ送る（`lower()`）はしない（他アプリの裏に回るため）。失敗は吸収する
- 受容: ダイアログが出てから最大約 200ms はキーボードUIの下に隠れうる / ダイアログを開いたまま他アプリへ移ると「手前」が戻る（ダイアログが前面でないため）
- 前提の実測（task で行う）: キーボードUIがメインの所有窓でないこと（`GetWindow(hwnd, GW_OWNER)` が 0 / メイン以外）。
  成り立たなければ作業を止めてユーザーへ報告する

## §5 リサイズの縦横比固定

### 比率と大きさの計算

- 比率 `r = max_x / max_y`（`redraw` と同じ・キー配置の外接）。キーが無いレイアウトは補正しない（防御）
- 比率を合わせる対象は**キャンバス**。窓の内寸 = キャンバス + 余白（`container` の padding × 2。値は container 生成側と同じ定数を共有し二重定義しない）
- 目標の大きさ: 基準の辺からキャンバス寸法を出し、比率で他方を決め、余白を足す。端数は四捨五入（`round`）
- 最小サイズ: 幅 510 を下限とし、高さの下限は比率から決める。`minsize` は比率が変わるたびに当て直す
- 計算（比率・基準の辺の判定・目標の大きさ）は tkinter に依存しない純関数にし、`tests/` で単体テストする
  （置き場所は前例 `presentation/compact_window_size.py` にならい `presentation/` 直下の専用モジュール）

### 補正（手を離した後に 1 回）

- 窓（Toplevel 自身）の `<Configure>` だけを扱う（**`event.widget is self` のときのみ**。子 widget の Configure は無視）
- 大きさの変化を検知したら補正の予約を **1 件だけ**持つ（新しい変化で取り消して約 150ms 後に置き直す）。予約の発火時に**その時点の大きさ**で計算する
- **マウスのボタンが押されている間は補正しない**（v0.4・実機目視で判明）: 予約の発火時にマウスの左右いずれかの物理ボタンが押されていれば、補正せず約 150ms 後に置き直す。
  理由: Windows の対話的なサイズ変更はドラッグ開始時の枠 + マウスの移動量で大きさを決め続けるため、ドラッグ中に止まった間に当てた補正は次の移動で上書きされ、
  基準 `(w0, h0)` がずれて動かしていない辺を基準に補正してしまう（縮めると大きく・広げると小さくなる）。
  判定は infrastructure の関数（`GetAsyncKeyState` で VK_LBUTTON / VK_RBUTTON の物理状態。左右入れ替え設定に依らないよう両方を見る・取得失敗と非 Windows は「押されていない」）を App が注入する（presentation から ctypes を呼ばない）。
  スナップ（手を離した後に OS が決める）・Win+矢印（ボタン無し）は従来どおり手を離した後 / 直後に補正される。
  つまり**補正はマウスのボタンが（システム全体で）離れた後**に行う。受容: 他アプリでのドラッグ中・ボタンを押したままの放置中は補正が延び、その間は比率がずれたまま（離せば補正される）/
  窓のメニューの「サイズ変更」（`Alt+Space`）から矢印キーで変える操作はボタンを使わないため、確定前に補正が入り基準がずれうる（**保証の範囲外**・ユーザー確定 2026-10-12）
- 基準の辺: 直前に確定した大きさ `(w0, h0)` と今の `(w, h)` を比べる
  - 幅だけ変わった → 幅を基準に高さを決める
  - 高さだけ変わった → 高さを基準に幅を決める
  - 両方変わった（斜め・スナップ・配置ツール） → **今の大きさに収まる最大の形**にする（幅基準と高さ基準のうち、他方が今の寸法を超えない方。
    スナップ等の区画からはみ出さない）
  - どちらも変わらない（移動のみ） → 補正しない
- 収束: 目標が今の大きさと等しければ何もせず `(w0, h0)` を今の大きさにする。当てた後に届いた Configure の大きさが目標と違っても
  （minsize・画面・OS による丸め）、**その大きさを新しい `(w0, h0)` として受け入れ再補正しない**（振動させない）
- 当てるときは `geometry("WxH")`（位置は変えない）
- **補正しない状態**: 最大化中（`state() == "zoomed"`）・最小化中（`"iconic"`）。この間は `(w0, h0)` を更新しない。
  通常状態へ戻った最初の Configure は `(w0, h0)` を取り直すだけで補正しない
- 受容: スナップ（画面端・Win+矢印・スナップレイアウト）や配置ツールは状態が normal のまま OS が大きさを決めるため、ドラッグと区別できず、
  配置後に比率へ補正される（位置は配置先の左上のまま・区画内に収まる形に縮む。区画を埋めない / OS がスナップ状態と扱わなくなりうる）。最大化は対象外 /
  縦長の外部レイアウトで幅の下限から出した高さが作業領域を超える場合は保証の範囲外
- 予約は窓の破棄・最大化 / 最小化への遷移で取り消す

### 初期表示と比率の変化

- 大きさの基準 `(w0, h0)` と今の比率は KeyboardWindow 自身が持つ（新規作成直後は `winfo_width()` が 1 を返すため winfo に頼らない）
- 新規に開くとき: 幅 510、高さは比率から決める
- `update_layout` が呼ばれたとき: **比率が前回と変わったときだけ**、今の幅（`(w0, h0)` の幅）を保って高さを決め直し、`minsize` も当て直す。
  比率が同じ（設定反映による呼び出し）なら大きさに触らない。
  最大化 / 最小化中に比率が変わった場合は比率だけ記録し、通常状態へ戻ったときに 1 回だけ当てる

## §6 受け入れ条件（ドラフト）

1. キーボードUIにステータス欄が無く、キャンバスが上端から描かれる（§3）
2. タイトルが通常は `Keyboard UI — <レイアウト>`、キーの左クリックで `Keyboard UI — 編集中: <キー>（Escでキャンセル）`、Esc / 確定 / 右クリックで通常へ戻る（§3）
3. フル / 省略表示の表示欄に「キーボードUIを常に手前」があり、両方で状態が連動する（§4）
4. チェック ON でキーボードUIが手前に残る。閉じた状態で ON → 開く（ボタン / メニュー / 既存窓の再表示）と手前。OFF で解除（§4）
5. メインとキーボードUIの両方を手前にしたとき、アクティブにした方が上になる（§4・実機目視）
6. 再起動するとチェックは OFF（§4）
7. キーボードUIだけ手前で、独自ダイアログ・messagebox・ファイル選択を開くとダイアログがキーボードUIより上に出て操作でき、閉じると手前に戻る。
   キーボードUIからの割当エラーも同様（§4・実機目視）
8. 縦 / 横 / 斜めのいずれのドラッグでも、手を離した後に縦横比へ合い、キーの周囲に大きな余白が出ない。ドラッグ中のガタつきが無い（§5・実機目視）
9. 設定反映（キーの割当等）で窓の大きさが変わらない。レイアウト切替で比率が当て直される（§5）
10. 最大化中は補正しない。最大化中にレイアウトを切り替えて元に戻すと新しい比率で当たる。最小サイズ付近まで縮めても振動しない（§5）
11. 表示欄に行を足しても、既存の窓サイズの規定（省略表示の最小の高さ・大きさの記録 / フル表示のヘッダ）が崩れない（§4・`features.md` §4.6）
12. 純関数（比率・基準の辺・目標の大きさ）の単体テスト、前面化の UI テスト（既存 `test_keyboard_window_opens_and_closes` の拡張）を含め、既存の単体テスト・tests_ui・smoke が通る
