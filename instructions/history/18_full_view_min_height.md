## §1 目的 / 背景

フル表示のウィンドウは縦方向にいくらでも縮められ、一覧やボタン列・ステータス欄が潰れる。
phase 18 で幅にだけ最小サイズを設け、高さは 1 のまま残した（暫定仕様 16 §6 でスコープ外）。
本フェーズで**フル表示のウィンドウに最小の高さを設ける**。

### 現状監査（2026-09-17・メインで直読み + deep-reviewer 実測）

- 縦方向の構成: `outer`（`app.py:228-229` `padding=12`・`expand=True`）の中に FullView
  = `header_area`（`full_view.py:27-28` `pady=(12,0)`）→ `main_area`（`:43-44` `pady=(12,0)`・`expand=True`）→ `panes`（横並びの `tk.PanedWindow`）。
  `outer` の後に root 直下へステータス欄（`status_bar.py:6-7`・`side="top"`）とステータスバー（`:10-11`・`side="bottom"`）を pack（`app.py:238`）。
- **pack の縮み方（実測）**: 要求高さより低くすると**後から pack した部品から削られ**、`expand=True` の部品は**要求高さより縮まない**（`expand` は余りの配分だけに効く）。
  現行の配置で最小の高さを当てて縮めると、`outer` は要求高さを取り切り、**ステータスバーが消え**、一覧は 12 行のまま。
  枠の中も一覧枠を先に pack しているため（`keymap_box.py` / `trigger_box.py`）、足りない分は**ボタン列・suppress チェックボックスから削られる**。
- ステータス欄の行数: フル表示中は 1 行、省略表示中は 2 行（`trigger_panel_controller.py:253-256`）。
  ただし `show_full_view` は `on_full_view_shown` を `update_status` より**前**に呼ぶ（`app.py:372-376`）ため、戻った直後の測定時点は 2 行。
- ステータスバー中央の一時メッセージ（`status_bar.py` の `flash_message_var` ラベル・行数固定なし）は**改行を含むことがある**
  （`keymap_file_io.py:90-93` の保存先変更時 / `keymap_set_io.py:143` の注意事項）。設定から 4 秒で消える（`app.py:268-270`）。
- 3 枠の中身: キーマップ管理 = 一覧（`Listbox(height=12)`）→ ボタン列 / トリガー一覧 = 一覧（`height=12`）→ ボタン列 → suppress /
  出力シーケンス = 一覧（`height=18`）| スクロールバー | ボタン列（`sequence_box.py`）。
- **実測（Windows・作業領域の高さ 966）**:

  | フォント | 枠の最小の高さ（キーマップ / トリガー / 出力シーケンス） | 出力シーケンスのボタン列 | 一覧 9 行 / 18 行 | メイン領域以外 | ウィンドウの最小の高さ |
  |---|---|---|---|---|---|
  | −3 | 317 / 313 / **407** | 372 | 112 / 220 | 247 | **654** |
  | 標準 | 373 / 369 / **451** | 412 | 148 / 292 | 278 | **729** |
  | ＋3 | 457 / 453 / **517** | 472 | 202 / 400 | 327 | **844**（起動時の 820 を超える） |

  → **出力シーケンスのボタン列は全フォントで 18 行分の一覧より高く、最小の高さを決めるのは常に出力シーケンスのボタン列**。
- Listbox の 1 行の高さ = `linespace + 1`。要求高さ = `height × (linespace+1) + 2×(borderwidth+highlightthickness)`（3 フォントで一致）。
- **高さの基準**: `winfo_reqheight` / `geometry` / `wm minsize` はいずれも**メニューバーを含まないクライアント領域**で揃う（`minsize(w,729)` + `geometry(wx300)` → 729）。
- **Tk は `minsize` の高さを当てるだけで現在の高さを広げ**、それより低い `geometry` 指定は最小へ丸める（実測）。
- `tk.PanedWindow` の要求高さは、中の枠の要求高さが変わっても **`paneconfigure` を呼ぶまで更新されない**（実測）。
- 最小サイズの設定箇所: `pane_layout_controller.py` の `apply_layout`（`minsize(plan.window_min_width, 1)`）/ `_update_window_min_size`（ドラッグ後・高さ 1）/
  `release_window_min_size`（`minsize(1, 1)`）。再計算の契機 = 起動時の初回適用 / フォント変更（省略表示中は印だけ）/ フル表示へ戻ったとき。
- 初期 geometry = `{幅}x820`（`app.py:96`）。高さは保存しない（`features.md` §4.6「ウィンドウ幅の保存と復元」`:75`）。
- 高さに触れる既存テスト: `tests_ui/test_full_view_header_width.py:135-137` / `test_pane_drag_and_window_min.py:201,215`（いずれも解除後の `wm_minsize()` 全体の比較）。
- 正本: `features.md` §4.6「フル表示の幅配分」の「最小幅」項 `:57` に「**高さは制約しない**」（本フェーズで改訂）。

## §2 確定事項（ユーザー 2026-09-17）

1. **暫定仕様先行**で進める（phase 20）。
2. **最小の高さの基準 = 各一覧を既定の行数の半分にしたときの高さ**。キーマップ管理・トリガー一覧 = **6 行**（既定 12）/ 出力シーケンス = **9 行**（既定 18）。
   3 枠のうち最も高いものに、ヘッダ等の縦方向のほかの部分と余白を足した値をウィンドウの最小の高さとする。
   **フォント設定ごとに再計算する（幅と同じ契機）**。
3. **高さは保存・復元しない**（JSON 変更なし。起動時の 820 は変えない）。
4. **省略表示では適用しない**（幅と同様、省略表示へ入るときに解除する）。
5. **案 A**: フル表示の一覧の `height` を **12 → 6（キーマップ管理・トリガー一覧）/ 18 → 9（出力シーケンス）** に変え、
   ウィンドウの要求高さをそのまま最小の高さにする（§3-2）。表示される行数は従来どおり伸びた分で決まる。
6. **最小の高さが画面の高さを超える場合は、はみ出しを受け入れる**（保証の範囲外。幅の規則と同じ扱い）。
7. **ステータスバーの一時メッセージは、表示の有無・行数によらず常に 1 行分として最小の高さを測る**。
   最小の高さ付近まで縮めているときに複数行の一時メッセージが出ると、消えるまで（4 秒）下側が切れることを**受容する**（一時メッセージを出しても測り直さない）。

## §3 設計

### §3-1 用語・原則

- **ウィンドウの最小の高さ**: フル表示中に `wm minsize` の高さとして当てる値（クライアント領域の高さ。幅と同じ基準）。
- **最小の高さまで縮めても何も切れない**: ヘッダ・3 枠の中身（ボタン列・チェックボックス・間隔入力・見出し）・ステータス欄・ステータスバーはすべて表示され、
  一覧はキーマップ管理・トリガー一覧 6 行以上 / 出力シーケンス 9 行以上が見える。
  （実測上、出力シーケンスのボタン列が支配するため、最小の高さでも一覧は 6 / 9 行より多く見える枠がある。これは §2-2 の「最大」の帰結）
  例外 = 複数行の一時メッセージの表示中（§2-7 で切れを受容）。

### §3-2 一覧を縮めさせる方法（案 A・§2-5）

- ビューの一覧の `height` を 12 → **6**（キーマップ管理・トリガー一覧）/ 18 → **9**（出力シーケンス）に変える。
- **ウィンドウの最小の高さ = フル表示中の `app.winfo_reqheight()`**（§3-4 の順序で測る）。要求高さの時点で何も切れないため、§3-1 を満たす。
- 起動時の 820 では `expand` で伸び、**見た目は現状と同じ**（実測: キーマップの一覧 269px で一致）。
- 行の高さの計算・枠ごとの式・新しい純関数は不要。
- 「既定の行数」は**ウィンドウの要求高さを決める値**としての意味に変わる（表示される行数は従来どおり伸びた分で決まる）。
  ビューに「半分の行数 = 最小の高さの基準」である旨のコメントを残す。

- 不採用: 案 B（行数は 12 / 18 のまま pack の順序を変え、最小の高さを式で求める。変更ファイルが多く配置順の検証が要るため）。

### §3-3 変更しない値

- 一覧の `width`（26 文字）・幅の測定（`pane_measure.py` は `height` を参照しない）・既定幅の算出は変わらない。
- 省略表示の一覧（`compact_view/`）の行数は変えない（§2-4・§6）。

### §3-4 適用と再計算の契機・順序

- 幅と**同じ契機・同じ呼び出し**で当てる: 起動時の初回適用 / フォント変更（省略表示中は印だけ立て、フル表示へ戻ったときに測る）/ フル表示へ戻ったとき。
- **測る順序**: 幅の適用（`apply_layout` の `paneconfigure`）の**後**、`update_idletasks` を経てから要求高さを測る
  （`tk.PanedWindow` の要求高さは `paneconfigure` まで古い値のまま）。
- **フル表示へ戻ったときは、ステータス欄をフル表示の文言（1 行）へ更新してから測る**。
  推奨: `show_full_view` で `update_status` を `on_full_view_shown` より前へ移す（他の呼び出し順への影響がないことを実装時に確認）。
- **一時メッセージは 1 行分として測る**（§2-7）: 測定時に一時メッセージが表示中（複数行を含む）でも、ステータスバーは一時メッセージ欄が 1 行の場合の要求高さで数える
  （例: `app.winfo_reqheight()` からステータスバーの要求高さを除き、1 行分の要求高さを足す。1 行分は同じスタイルの 1 行ラベルの要求高さ等から求め、測り方は実装で実測して確かめる）。
  一時メッセージの設定・消去では測り直さない（最小の高さの再計算の契機は上記のまま）。
- フル表示中に `wm minsize` を当てる**すべての箇所**（`apply_layout` / ドラッグ後の `_update_window_min_size`）で、保持した最小の高さを当てる
  （**ドラッグ後に高さの制約が 1 へ戻らない**）。省略表示へ入るときの解除（`minsize(1, 1)`）は変えない。
- 現在の高さが最小未満なら**最小サイズの設定で Tk が広げる**。幅を変える `geometry` を出す場合は、高さに `max(現在の高さ, 最小の高さ)` を渡す
  （途中の値で高さを縮めない）。最小以上なら高さは変えない。
- **画面の高さを超える場合**: 縮めずにはみ出す（保証の範囲外・§2-6）。

### §3-5 保存・既存挙動との関係

- 高さは保存しない。＋3 等で最小の高さが 820 を超えると、起動時に高く開く（保存しない）。
- **ウィンドウ幅の保存判定は変えない**。高さだけの変化は幅の保存を起こさない（`_on_window_configure` は `event.width` の変化だけを見る）。
- 最大化中は OS の扱いに任せる（幅と同じ）。

### §3-6 実装の置き場所

- 状態 = `PaneLayoutController` が `window_min_height: int` を保持（`header_window_width` と同じ扱い）。測定は `pane_measure.py` に関数を足す。
- 純関数の新規ファイルは作らない。
- `codebase_map.md` の該当行を更新する。

## §5 受け入れ条件（ドラフト）

1. フル表示中、ウィンドウを最小の高さより低く指定しても最小の高さで止まり、**その状態で**
   root 直下の pack 部品（`outer`・ステータス欄・ステータスバー）が表示され（mapped）下端がウィンドウの高さ以内 /
   3 枠の各子部品の下端が枠の高さ以内 / 一覧の高さが 6 行（出力シーケンスは 9 行）分の要求高さ以上（§3-1）。
2. フォント設定を変えると最小の高さが再計算される（大きくすると上がり、戻すと下がる）。省略表示中の変更はフル表示へ戻ったときに反映され、
   **戻った直後の値がステータス欄 1 行の状態で測った値と一致する**。**複数行の一時メッセージを表示したまま測っても、一時メッセージが無いときと同じ値になる**
   （フォント変更時 / 表示したまま省略表示を往復した場合の両方）（§2-7・§3-4）。
3. 境界線ドラッグの後も高さの制約が保たれる（§3-4）。
4. 省略表示へ入ると高さの制約も解除され、フル表示へ戻ると再び当たる。戻った高さが最小未満なら広がる（§2-4・§3-4）。
5. 起動時・フォント拡大で最小未満になる場合は高さが広がり、最小以上なら高さは変わらない（§3-4）。
6. 高さは保存されず、ウィンドウ幅の保存挙動は変わらない（§3-5）。JSON の変更なし。
7. 上記を確かめる UI テスト（`tests_ui/`）を追加し、既存テストがすべて通る。
8. 実機目視（ユーザー）: 標準 / ＋3 / −3 で縦に縮めて §5-1 を確認。＋3 で起動時に高く開くことを確認。

## §6 スコープ外

- 高さの保存・復元 / 位置・最大化状態の保存（§2-3）。
- 省略表示の最小サイズ・省略表示の一覧の行数。
- 初期高さ 820 の変更、ボタン列の配置変更（縦に長いボタン列の折り返し等）。
- 一覧の既定の行数の変更（**案 A の `height` 変更は §2-5 の判断による例外**。表示される行数は変わらない）。
- 画面の高さに収めるための縮小規則（§2-6 ではみ出しを受け入れる）。
