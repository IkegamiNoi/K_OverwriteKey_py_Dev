## §3 データモデル

- `op` = `stop`（キーなし）。例: `{"type": "system", "op": "stop", "label": ""}`。`label` を持てる。
- **JSON スキーマ変更あり**（op の追加のみ・既存の種別・キーは不変）。旧ビルド・別実装は「system の操作が不正です」で止まる（受容・§5.11.5 の既存規定と同じ）。

## §4 実行

### 4.1 連続実行

1. 停止の行に達したら**連続実行を終える**。位置は停止の次（停止が最後の行なら末尾 = 位置 0・周回を空に。§4.2.1 の末尾の規則）。**間隔を置かずに**終える。
   - ステップの途中（system の処理中・`advance`）で達した場合も、通常アクションの直後の先行処理（§4.2.2・`settle_after_normal`）で達した場合も同じ。
   - 待機の続きで達した場合（例: `[A, 待機, 停止]`）も同じ。
   - **停止で終えた後も先行処理（§4.2.2）をする**: 停止の次から、続くループの行を処理し、カウンターの行を保留に控える（「次に実行」が次に実際に実行される行を指す）。
     その先行処理で出会った停止の行は通過する。先行処理で末尾に達したら位置 0・周回を空にし、保留をその場で反映する（末尾での停止と同じ）。
     例: `[A, 停止, カウンター+1, B]` → A の後に停止で終え、+1 を保留に控えて「次に実行」は B / 3 周ループ `[ループ, A, 停止, ループ終わり]` の 3 周目 → ループを抜けて末尾で位置 0（次の押下は先頭から）。
     上限 10,000 は停止までの処理と通算する。
   - 境界（受容）: 先行処理が system の上限 10,000 に達して止まった（§4.2.2・黙って止まる）直後の行が停止なら、停止は**次のステップの開始時**に処理する
     （間隔を 1 回置いてから終える。位置は停止の次・戻す履歴は次のステップとして通常どおり）。
2. **読み飛ばし**: その連続実行で**まだ通常アクションを 1 つも実行していない**間に達した停止は読み飛ばす（停止の直後から押し直したとき・一覧で停止の行を選んで開始したときに、何も起きない状態を避ける）。
   - 「その連続実行」= 開始から終了（末尾・停止・エラー・停止操作）まで。**一時停止 → 再開は同じ連続実行**（数え直さない）。
     連続実行中に一覧で位置を変えた・シーケンスを編集した（連続実行は続く）ときも印は変えない
     （既に何か送った後に停止の行へ位置を移すと、そこで終える。まだ何も送っていなければ読み飛ばす）。
   - 「通常アクションを実行した」= hotkey / text / mouse_click の行を実行した（hotkey の検証エラー・座標不正など、**シーケンスが止まらない送信エラーで実際には送らなかった場合も含む**）、
     または file_line の完了（成功。空の行・`empty` で何も送らなかった場合も含む）。シーケンスが止まるエラー（種別不正・file_line のエラー等）で終わったものは数えない。
   - 例: `[A, 停止, 停止]` を停止の後から押すと、最初の停止も次の停止も読み飛ばして末尾に達し、何も送らずに終わる（位置 0）。次の押下で A から（受容）。
3. **保留中のカウンター操作**: 停止で終えるときは**その場で反映する**（停止の手前のカウンターの行は通り過ぎているため。末尾での停止〔§4.2.2〕と同じ）。
   反映した操作は、停止で終えたそのステップの戻す履歴の差分に含める。例: `[A, カウンター+1, 停止, B]` → A を送り、+1 を反映して終える（位置は B）。
4. ループの中に置いてよい（周回は保持され、次の連続実行で続く）。
5. 戻す履歴: 停止で終えたステップも通常どおり 1 段（ステップの開始時の状態）。

### 4.2 単発実行

- 停止は**読み飛ばす**（押下を消費しない・ステップの途中でも先行処理でも止まらずに通過する）。1 ステップの system 上限 10,000 には数える。

### 4.3 実装の方向（参考）

- `advance` / `settle_after_normal` に**連続実行かどうか**と**読み飛ばしの要否**を渡す（どちらも現状は実行モードを知らない）。停止で終えることを `StepOutcome` / 先行処理の結果で runner へ返す。
- runner は連続実行ごとに「通常アクションを実行したか」の印を持つ（開始で消す・一時停止では消さない）。
- 停止は戻す / 先頭への単独登録の制限に含めない（他の行と混ざってよい）。

## §5 表示と編集

- 一覧の表示: `[stop]`（行のラベルがあれば既存の規則どおり `: ラベル` を付ける）。「次に実行」が停止の行を指すことがある（連続実行を停止で終えた直後は停止の次）。
- 編集ダイアログ: system の操作に「停止」を加える（入力欄なし）。挿入・移動は他の system と同じ規則。

## §6 受け入れ条件（ドラフト）

1. 連続実行が停止の行で止まり、位置は停止の次・次の押下で続きから連続実行（§4.1-1）。先行処理・待機の続きで達した場合も同じ。先行処理が上限 10,000 で止まった直後の停止は次のステップの開始時に処理
2. その連続実行で通常アクションを実行する前の停止は読み飛ばす / 一時停止 → 再開をまたいで印が保たれる / file_line の完了も「実行した」に数える（§4.1-2）
3. 停止で終えるとき保留中のカウンター操作をその場で反映し、戻すで打ち消せる / 停止が最後の行なら位置 0・周回を空に（§4.1-1・3）
4. 単発実行で停止を読み飛ばす（ステップの途中・先行処理とも）（§4.2）
5. ループ内の停止で周回が保たれる / 戻す履歴が通常どおり 1 段（§4.1-4・5）
6. 一覧の `[stop]` 表示と編集ダイアログの「停止」（§5）
7. 旧データ（停止を含まない）の実行・保存が従来どおり。既存テスト（tests / tests_ui / smoke）が全 pass

## §9 呼び出し（phase 40）への申し送り

次の暫定仕様で詰める。**以下はユーザー確定済み**（2026-09-26 暫定 26 §13 / 2026-09-27）:
- 同じトリガー一覧のトリガーキーで参照。呼び出し先を先頭から末尾まで一括で連続実行して戻る（呼び出し先の実行位置は変えない・単発でも 1 押下で丸ごと）。
  循環は編集時に拒否し実行時も検出したらエラー停止。参照先なしは一覧で示し実行時エラー。一覧は `[call] <キー>: <呼び出し先のラベル>`。
- **呼び出し中も他のトリガーは動く**（待機と同じ・2026-09-27）。
- **入れ子の呼び出しを許可・深さ 9 まで**（2026-09-27）。
- **呼び出し先の中の停止は読み飛ばす**（2026-09-27）。

v0.1 の起票時レビュー（deep-reviewer）で出た未決論点（次の暫定仕様で扱う）:
- 状態の置き場: `reentry_guard` はキーだけの集合（`app_state.py:44`）・連続実行の途中状態は runner に 1 組。呼び出し文脈は新しい状態として持つ。
- 呼び出し中のキーマップ切替（呼び出し文脈は開始時のトリガー一覧 ID を持ち照合）/ 呼び出し先が連続実行のトリガーで直接押されたとき（他トリガーの連続実行開始 = 全保留の取り消し）/
  呼び出し元が連続実行中は他のトリガーの押下が無視される点 / 単発の呼び出し中に呼び出し先を直接押したときの送信の混在。
- 呼び出し先の無限ループ（呼び出しが終わらない）の扱い。
- 呼び出し先のステップ間の間隔（呼び出し先の「間隔(ms)」は連続実行 OFF だと入力欄が無効〔`trigger_panel_controller.py:283`〕）。
- 取り消し時の位置 / 一時停止時の保持 / キー変更時の参照の書き換え（`mark_sequence_dirty` を伴う）/ 取り消し契機の範囲（行の選択と編集の区別）。
- 「system = 入力を送らない」の正本の定義との整合（呼び出しは入力を送る）。
- 循環・深さの検査の契機（保存時だけか・改名 / 追加 / 読込でも）と深さの数え方 / 一覧の整形（domain）へトリガー一覧を渡す設計 / キーは小文字表示・ラベルの二重区切り。
- 呼び出し先の中の `perform_action` の失敗 / 入れ子の通知の範囲 / 取り消し時の保留の反映。
