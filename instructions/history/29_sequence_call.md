## §3 データモデル

- `{"type": "system", "op": "call", "target": "f5", "label": ""}`。`target` = 呼び出し先のトリガーキー。`label` を持てる。
- `target` は読込時に trim（`normalize_actions` の trim 対象へ追加。他の種別の同名キーは trim されるだけ）。比較は `normalize_key_name`。キーを補完しない。
- **JSON スキーマ変更あり**（op と `target` の追加のみ）。旧ビルド・別実装は「system の操作が不正です」で止まる（受容）。

## §4 実行

### 4.1 呼び出しは「ステップを消費するアクション」

- 呼び出しは system 種別だが、実行の上では**通常アクションと同じく押下（連続実行の 1 ステップ）を消費する**。
  - `advance` は呼び出しの行で止まり（ループ・カウンターのように通過しない）、runner が実行する。先行処理も呼び出しの行で止まる。単発の先頭への回り込み・開始位置で終える規則は通常アクションと同じ。
  - 呼び出しの行自体は system の上限 10,000 に数えない（通常アクションと同じ扱い）。
  - 呼び出しが**成功して**終わったら、通常アクションの後と同じく位置を進めて先行処理をする。停止の読み飛ばしの判定（`features.md` §4.2.8）では「送った」に数える（呼び出し先が空でも）。
    打ち切り・エラーで終わった呼び出しは数えない。
- 正本の分類（`features.md` §4.2 冒頭「system = 入力を送らない」・§4.2.1「system は押下を消費しない」）を、**呼び出しを除く**形へ改める。

### 4.2 呼び出し文脈

- 呼び出しを始めるとき**呼び出し文脈**を作る: 呼び出し元のトリガー一覧 ID / **開始時点のコピー**（呼び出し先から呼び出しの辺を辿れるトリガーを深さ 9 まで集め、
  キー → 〔シーケンスのコピー・間隔(ms)〕の表にしたもの。見つからないキーは「参照先なし」として記録）/ **呼び出しスタック**（段ごとに: キー・位置・周回・文脈の中の保留）。
  - **呼び出しは開始時点のコピーだけで最後まで実行する**（実行中に呼び出し先・入れ子の呼び出し先を編集・削除・改名しても影響しない。入れ子の呼び出し先もコピーの表から引く）。
  - 入れ子の呼び出しは、その行に達したらコピーの表から呼び出し先を引いて段を積む（表で「参照先なし」なら実行時エラー）。**深さ = スタックの段数**（呼び出し元 → 呼び出し先で 1）。9 を超えたら実行時エラー。
  - **循環**: スタック（呼び出し元の根を含む）にあるキーを再び呼んだら実行時エラー。キーは開始時点の名前で比べる（途中の改名で照合し直さない）。
- **呼び出し先トリガー自身の実行位置・周回・保留・戻す履歴は変えない**。カウンターは共有なので呼び出し先のカウンター操作はそのまま効く。
- **文脈の 1 ステップ**（単発・連続実行の両経路から同じ処理で進める）: 最上段の位置から `advance`（先頭へ回らない・停止は読み飛ばす）→ 通常アクション / file_line / 入れ子の呼び出しを実行 →
  先行処理（停止は通過）。待機は待つ・file_line は読込中の保留を経る。**無限ループの始まりに達したら実行時エラー**「呼び出し先に無限ループがあります」。
  最上段が末尾に達したら、その段の保留を反映して段を降ろし、下の段（または呼び出し元）の続きへ戻る。呼び出し先が空なら何もせず成功。
- system の上限 10,000 は、**呼び出しの 1 ステップ全体で入れ子をまたいで通して**数える（v0.5。送るものが無いまま回り続ける呼び出しを止める）。
  超えたら実行時エラー「制御アクションの処理が 10000 回を超えました（通常アクションの無いループ等）」。
- **呼び出し元の存在の照合**: 文脈の各ステップの前に、文脈のトリガー一覧が今のアクティブなトリガー一覧と同じで、かつ呼び出し元のトリガーがあることを照合する。
  違えば呼び出しを**履歴を積まずに**やめる（単発 = 保留を外す / 連続実行 = 停止する。file_line の完了時の照合〔§4.2.7〕と同じ）。

### 4.3 間隔

- 文脈の中のステップの間隔 = **その段の呼び出し先トリガーの「間隔(ms)」**（連続実行 OFF でも欄の値を使う・**開始時点のコピーの値**）。
- 呼び出しの開始直後の最初のステップは間隔を置かずに実行する。待機は待機の時間だけ（間隔を足さない・連続実行の待機と同じ）。
- 呼び出しが終わって呼び出し元へ戻るとき: 単発はそのまま呼び出し元の続き（先行処理）で押下を終える。連続実行は呼び出し元の間隔を置いて次のステップ。
- 連続実行の一時停止からの再開: 呼び出し中なら**最上段の呼び出し先の間隔**の後に文脈の続きから。

### 4.4 呼び出し先の中の各行

| 行 | 扱い |
|---|---|
| 通常アクション（hotkey / text / mouse_click / file_line） | 送る（file_line は読込中の保留を経る） |
| ループ / カウンター | 通常どおり（周回・保留は文脈の中だけ）。**無限ループの始まりに達したら実行時エラー**（「無限ループ + 停止」の形も呼べない・受容） |
| 待機 | 待つ |
| 停止 | 読み飛ばす |
| 戻す / 先頭へ | 実行時エラー（呼び出し先が戻す / 先頭へだけのトリガー。編集でも直接の呼び出し先は拒否・§6） |
| 呼び出し（入れ子） | §4.2 の深さ・循環の規則で実行 |

### 4.5 保留・戻す履歴・打ち切り・エラー

- **単発**: 呼び出し中、呼び出し元のステップは**保留中**（`PendingStep` に文脈を持つ・世代で守る）。位置は呼び出しの行。
  押下・戻す / 先頭への扱いは §4.6・§4.7（v0.6: 同じトリガーで一時停止 / 再開・処理中は他のトリガーを無視・処理中の対象は拒否）。
- **連続実行**: 呼び出しは 1 ステップ。runner の連続実行の途中状態に文脈を持つ（既存の待機と同じく「位置は呼び出しの行・ステップの snapshot と途中の差分を持ち越す」）。
- **戻す履歴**: 呼び出し元の 1 ステップとして、**既存の規則どおり状態（位置・周回・保留・カウンターの差分）が変わったときだけ 1 段**（変わらなければ積まず、直前のトリガーも更新しない）。
  文脈の各ステップのカウンター操作の差分を、保留（単発 = `PendingStep.resume` / 連続実行 = `_run_to_end_resume`）の差分へ**積み増す**
  （既存の確定の 3 箇所は変えずに、打ち切り時も呼び出し先の操作が含まれる）。文脈の中の保留（先行処理で控えた操作）は、打ち切り・エラーでは反映しない。送った入力は戻らない。
  直前のトリガーは呼び出し元（完了した順に更新・受容）。
- **打ち切り**（取り消し・停止操作）: 位置は**呼び出しの行**。戻す履歴は上の規則どおり（積み増した差分があれば 1 段）。次の押下で呼び出しを最初からやり直す（送った入力をもう一度送る・受容）。
- **エラー**（文脈の中の実行時エラー・参照先なし・循環・深さ超過・無限ループ・戻す / 先頭へ・通常アクションの送信が止まるエラー）: 通知し、呼び出し元はそこで止まる
  （位置は呼び出しの行・連続実行は停止・戻す履歴は上の規則どおり。参照先なしですぐ止まり何も変わらなければ積まない）。
  - **通知の連鎖**: runner が検出するエラー（system のエラー・参照 / 循環 / 深さ / 無限ループ・戻す / 先頭へ）の通知に「呼び出し: f5 > f6」を付ける（最初の呼び出し先から最上段まで・**呼び出し元は含めない**〔v0.5〕）。
    ActionExecutor が通知する通常アクション・file_line のエラーには付けない（受容）。二重表示の抑止で入れ子の通知が表示されないことがある（受容）。
- **通知の後の再照合**: エラー通知・送信・file_line の完了はモーダルの通知を挟み得るため、その後に**保留の同一性**（単発 = 世代 / 連続実行 = 世代・キー・読込トークン）を照合し直し、
  変わっていれば状態を変えない（phase 38 の file_line の完了と同じ規則）。これで通知の表示中の停止操作と二重に積まない。
  連続実行の**エラー・送信失敗・file_line の失敗の後**の照合には一時停止を含めない（通知の表示中に一時停止されても停止する・再開で成功扱いや再送にしない。v0.5）。

### 4.7 入力の受け付けと一時停止（v0.6・v0.7）

呼び出しに限らず、トリガーの押下全般の規則を次のとおりに改める（`sequence_runner.py` の `handle_key` と保留の扱い）。

- **処理中 / 止まっている間**
  - 処理中 = 連続実行の実行中（一時停止していない）/ 単発の file_line の読込中 / 単発の呼び出し中（一時停止していない）。
  - 止まっている間 = 単発の待機 / 連続実行の一時停止中 / 単発の呼び出しの一時停止中。
- **押下の扱い**（上から順に判定）
  1. ~~警告のダイアログの表示中~~（v0.7 で廃止）。
  2. 処理中のものがある → そのトリガーのキーは、連続実行・単発の呼び出しなら一時停止、単発の file_line なら無視（既存）。
     **他のキーはすべて無視**（単発・連続実行の開始・一時停止中のものの再開を含む）。
  3. 処理中のものが無い →
     - 一時停止中のもの（連続実行・単発の呼び出し）のキー → 再開。
     - 単発のトリガー → 動く（そのトリガーが待機中なら既存どおり無視）。
     - 連続実行のトリガー → 一時停止中のものがあれば**全部捨てて開始し通知**（v0.7）。単発の待機の保留は既存どおり取り消し（待機を終えた扱い・下記）。
- ~~**単発の待機が明けたときに処理中のものがある場合**~~（v0.8 で不要。待機の明けでは送らず常に次の送る行で押下を終える・§4.8）: 送信が混ざらないよう、その押下を**待機の次の行で終える**（何も送らない・位置は待機の次から**先行処理**〔§4.2.2・通常アクションの後と同じ〕をして「次に実行」を実際に送る行に合わせる・
  戻す履歴は既存の規則で状態が変わっていれば 1 段）。次の押下でそこから続ける。
  連続実行の停止の行（位置は停止の次で終える）に倣った扱い（単発の停止の行は読み飛ばすため「停止の行と同じ」ではない）。一時停止中のものは処理中に数えない。
- **同時に持てる数**: 連続実行（実行中または一時停止中）は 1 つ（既存）。単発の呼び出しの一時停止はトリガーごとに持てる（複数可）。連続実行の一時停止中に単発の呼び出しを一時停止することもある。
- **単発の呼び出しの一時停止**: 次のステップの予約を取り消し、文脈を保持する（文脈の中の待機は残りを捨てる・file_line の読込中は結果を捨てて再開時に読み直す。連続実行と同じ）。
  保留（`PendingStep`）は残る。戻す履歴は一時停止では積まない（呼び出しが終わるか、打ち切り・捨てるときに §4.5 の規則で 1 段）。
  再開は最上段の呼び出し先の間隔の後に続きから（§4.3）。単発の file_line・待機・呼び出し以外の保留には一時停止を設けない。
- **捨てる** = 停止操作による打ち切りと同じ（位置は呼び出しの行 / 連続実行は停止。戻す履歴は §4.5 の打ち切りの規則で、状態が変わっていれば 1 段）。
- **捨てる操作と知らせ方**（v0.7。**ダイアログは使わない**。知らせるのはステータスバーの通知〔既存の `notify_message`〕だけ）
  - 他のトリガーの連続実行の開始 → 一時停止中のもの**すべて**を捨てて開始し、「一時停止中の実行を破棄しました（<キーの一覧>）」と通知する。
  - キーマップの切替（切替キー・一覧での切替・アクティブのキーマップの削除）→ 一時停止中のもの**すべて**を捨てて切り替え、同じく通知する。同じキーマップへの切替（変化なし）は捨てない。
    アクティブの削除は既存の削除の確認だけ（「はい」で捨てて削除）。連続実行が実行中なら今までどおり拒否。
  - 戻す / 先頭へで、対象（直前のトリガー等）が一時停止中の連続実行・単発の呼び出し → **2 回押し**:
    - 1 回目は何も変えず（既存の「保留中の対象の拒否」と同じ扱い）、「一時停止中の <キー> を破棄します。もう一度押すと実行します」と通知し、**その状態を控える**
      （戻す / 先頭へのトリガーのキー・対象のキー・一時停止中のものの集合〔キーと世代〕・処理中の有無・単発の保留の集合）。
    - **続けて**同じトリガーを押し、控えた状態と今の状態が同じなら、**対象だけ**を捨ててから戻す / 先頭へを実行する。
    - 間に他のトリガーの押下があった・状態が変わった場合は控えを捨て、次の押下を 1 回目として扱う（時間の制限は設けない）。
  - 処理中は戻す / 先頭へのトリガーの押下自体を無視する（上の 2。拒否の文言は出ない・v0.9）。
  - 戻す / 先頭へだけのトリガーは、連続実行 ON でも先に一時停止中のものを捨てず、この 2 回押しに従う（v0.9）。
- **待機中に止めたとき**（v0.7。単発・連続実行とも）: 待機を**終えた扱い**にし、位置を待機の次へ進めて**先行処理**をして「次に実行」を実際に送る行に合わせる
  （待機は次の処理との間を空けるためのもので、待機から再開する必要がない）。
  - 対象: 連続実行の一時停止・停止操作・捨てる / 単発の待機の保留の取り消し（他の連続実行の開始・停止操作・キーマップの切替）。
    位置変更・シーケンスの編集（新しい位置が優先）・構成セットの読込等（位置と履歴を消す）は既存どおり。呼び出しの文脈の中の待機はこの規則の対象外（呼び出しは §4.5 の打ち切りで呼び出しの行）。
  - 戻す履歴は既存の規則（状態が変わっていれば 1 段）。先行処理で控えたカウンター操作は既存どおり次のステップの開始時に反映する。
  - 連続実行の一時停止からの再開は、この位置から通常の間隔の後に続ける（既存の「待機の残りを捨てて次から」と同じ結果）。
  - 正本 `features.md` の「待機中に止めたら位置は待機の行」の規定を改める（task_10 で昇格）。
- **表示**: 一時停止の専用の表示は増やさない（連続実行の一時停止と同じ）。

### 4.8 待機の扱い（v0.8）

待機は「直前に送った行と次に送る行の間を空ける」ためのもの（行ごとの個別の間隔）。待機の行を**直前に送った行の後の待ち**として扱う。
呼び出しの文脈の中の待機（§4.4・§4.5）は対象外（従来どおり文脈のステップとして待つ・止めたら打ち切りで呼び出しの行）。

- **送った後の先行処理で待機に達したら、同じステップの中で待つ**（正本 §4.2.2 の「待機の行で止まる」を改める）。
  通常アクション（file_line・成功した呼び出しを含む）を送った後の先行処理で待機の行に達したら待ち、その間の位置（「次に実行」）は**待機の行**。
  明けたら待機の次から先行処理を続け（続く待機も同じく待つ）、既存の規則どおり送る行・戻す / 先頭へ・エラーになる行・呼び出しの行等で止まる（連続実行の停止の行は §4.2.8 のまま）。
  - 単発: 押下はその待機が明けるまで続く。待機中は止まっている間（§4.7: 同じトリガーの押下は無視・他のトリガーは動く・戻す / 先頭への対象なら「待機中」で拒否）。
    **明けても何も送らない**。次の押下で次の送る行から。
  - 連続実行: **待機の前に間隔を置かない**（待機が間隔の代わり）。待ち終えて先行処理を終えたら間隔を足さずに次のステップ（既存の「待機の後は間隔を足さない」）。待機に達しなかったステップの後は通常の間隔。
  - 末尾での先頭への回り込みは既存の先行処理の規則どおり（単発はその押下でまだ回っていなければ先頭から続け、そこで達した待機も待つ / 連続実行は停止）。
  - ms が不正な待機に達したら、先行処理はその行で止まり、次のステップの開始時にエラー（既存の「エラーになる行で止まる」と同じ）。
  - 10,000 の上限（待機をまたいで通算）・カウンター操作の保留（待機をまたいで控え、次のステップの開始時に反映）・戻す履歴（ステップ全体で 1 段）は既存どおり。
- **ステップの中で送る前に達した待機は、待たずに読み飛ばす**（直前に送った行が無いため。一覧で位置を変えた・シーケンスの先頭・連続実行の開始 / 再開の位置が待機、
  カウンター・ループの行の後・続く待機・末尾から先頭への回り込みの後に達した待機を含む。`advance` が送る前に達する待機すべて）。
  単発・連続実行とも。読み飛ばしは他の system の行と同じ扱い（10,000 に数える・ms が不正ならその場でエラー・回り込み後に開始位置へ達したら処理せず終える規則もそのまま）。
- **待つのは「送った後の通常の先行処理」だけ**。止めた後・停止の行の後の先行処理では待たない（待機の行を読み飛ばして次の送る行で止める。続く待機も同じ）:
  - 待機中に止めたとき（§4.7 v0.7: 一時停止・停止操作・取り消し・捨てる）: 待機を終えた扱いで待機の次から先行処理し、**続く待機も読み飛ばして**次の送る行で止める
    （例 `[A, 待機1, 待機2, B]` で待機1の最中に止めたら B）。v0.8 では「次に実行」が待機の行にあるのは待機中だけになるため、止めれば常に次の送る行へ進む。
    連続実行の一時停止・停止も同じ（再開はその位置から通常の間隔の後）。
  - 連続実行が停止の行で終えるとき（§4.2.8 の停止の次からの先行処理）: 待機は読み飛ばす（例 `[A, 停止, 待機, B]` で A の後に終えたら位置は B・待たずにすぐ終える）。
  - カウンター操作の保留・戻す履歴（1 段）の確定時点は既存どおり（止めたとき・停止で終えたときに確定）。
- §4.7「単発の待機が明けたときに処理中のものがある場合」の規則は不要になる（明けで送らないため）。

## §5 参照とキーの変更

- 参照先 = 呼び出しの行に達した時点の、文脈のトリガー一覧で `target` と一致するトリガー（**グレー表示のトリガーも呼べる**）。無ければ実行時エラー「呼び出し先のトリガーがありません（f5）」。
  `target` が空・非文字列なら実行時エラー「呼び出し先が指定されていません」。system エラーの通知の値の欄は `call 呼び出し先=f5`。
- **トリガーのキーを変えたとき**: 同じトリガー一覧の全シーケンスの呼び出しの `target` を新しいキーへ書き換え、書き換えたシーケンスを未保存扱いにする。
  書き換えたトリガーの位置・周回・履歴は**消さない**（シーケンスの編集の契機に当てない）。既に「参照先なし」だった行が新しいキーと一致した場合も、そのまま繋がる（受容）。
- **トリガーを削除したとき**: 参照はそのまま残り、一覧で「参照先なし」になる（実行時エラー）。

## §6 編集と表示

- 編集ダイアログ: system の操作に「呼び出し」を加える。**呼び出し先を同じトリガー一覧から選ぶドロップダウン**（読み取り専用・自分自身は出さない・表示は `キー: ラベル`・グレー表示のトリガーも出す）。
  既存の行が参照先なしのときは、ドロップダウンの先頭に `f5（参照先なし）` を出して選ばれた状態で開く（そのまま OK すると拒否）。
- OK 時に次を拒否する（理由を示して閉じない）: 呼び出し先が未選択・参照先なし / 自分自身 / **循環**（呼び出しの辺をたどって自分へ戻る）/
  **このトリガーから下流の連鎖の深さが 9 を超える**（上流の深さは数えない＝残りは実行時の検出）/ **直接の呼び出し先**が戻す・先頭へだけのトリガー。
  - 検査は**呼び出しの行を保存するときだけ**。それ以外の操作（改名・追加・構成セットの読込・中間のトリガーの編集）で生じた循環・深さ超過・戻す / 先頭へは実行時の検出に任せる。
- 戻す・先頭への単独登録の制限に呼び出しは含めない（他の行と混ぜてよい）。
- 一覧の表示: `[call] f5（呼び出し先ラベル）`（呼び出し先のラベルが空なら `[call] f5`・キーは正規化後の小文字）/ 参照先なし `[call] f5（参照先なし）`。行のラベルは既存の規則どおり後ろに付く。
  一覧の整形（domain）へは「キー → 呼び出し先のラベル（無ければ None）」を引く関数を引数で渡す（`build_action_rows` → `format_action_list_item` → `format_control_value`。「次に実行」の要約も同じ）。
- **間隔の欄**: 連続実行 OFF でも編集可能にする（見出しは「間隔(ms)」のまま）。「呼び出されたときにも使う」旨は、編集ダイアログで「呼び出し」を選んだときの注記で示す（`features.md` §4.1・§4.6）。

## §7 実装の方向（参考・タスク分割の入力）

- domain: `OP_CALL`・`target` の trim・表示（解決関数を引数）/ 呼び出しグラフの循環・下流の深さ・直接の呼び出し先が戻す / 先頭へだけの判定（純関数）。
- application: `advance` / `settle_after_normal` が呼び出しの行で止まる / 呼び出し文脈（スタック）の型と「文脈の 1 ステップ」（単発・連続で共有）/ 単発（`PendingStep`）・連続実行（runner）への組み込み
  （差分の積み増し・再照合・呼び出し元の照合・一時停止の保持・位置変更での続行・file_line の読込中の枠の流用）/ 通知の連鎖。
- presentation: 編集ダイアログ（選択・検査）/ 一覧の表示（解決関数の配線）/ 間隔の欄 / 改名時の参照の書き換え。

## §8 受け入れ条件（ドラフト）

1. 単発 1 押下で呼び出し先が末尾まで実行され、呼び出し先トリガーの位置・周回・履歴は変わらない / 呼び出し元は呼び出しの次へ進み先行処理される（§4.1・§4.2）
2. 呼び出し先の中の待機・file_line・ループ・カウンター・停止・入れ子が §4.4 どおり。深さ超過・循環・参照先なし・無限ループ・戻す / 先頭へで実行時エラーと連鎖つきの通知（§4.4・§4.5）
3. 間隔が §4.3 どおり（最初のステップは待たない・呼び出し先の間隔・再開時の間隔）
4. 保留（戻す / 先頭への拒否）と §4.6 の表の各事象（一時停止 → 再開で続きから・キーマップの切替の拒否 / 打ち切り・停止操作で 1 段・位置変更で続行・構成セットの読込）
4b. §4.7（v0.6・v0.7）: 単発の file_line・呼び出しの実行中は他のトリガーを無視し、待機中は動く / 単発の呼び出しを同じキーで一時停止 → 再開で続きから（同じ入力を二度送らない）/
   連続実行・単発の呼び出しの一時停止中に他の単発のトリガーが動く / 他の連続実行の開始・キーマップの切替で一時停止中のものが捨てられ通知が出る（ダイアログは出ない）/
   一時停止中の対象への戻す / 先頭へは 1 回目が通知だけ・続けてもう一度で捨てて実行・間に他の押下や状態の変化があれば 1 回目に戻る / 削除は既存の確認だけ /
   単発の待機が処理中に明けたら何も送らず待機の次で押下を終え、次の押下で続きから /
   待機中に止めたら（一時停止・停止操作・取り消し・捨てる）位置は待機の次の送る行（先行処理後）
4c. §4.8（v0.8）: 単発で送った直後の待機は同じ押下の中で待ち（待機中の「次に実行」は待機の行・同じトリガーの押下は無視）、明けたら何も送らず次の送る行で押下を終える /
   押下が待機の行から始まったら（カウンター・ループの後の待機・続く待機を含む）待たずに次の送る行を送る / 連続実行は待機の前に間隔を置かず、待機中の「次に実行」は待機の行 /
   待機中に止めたら次の送る行へ（`[A, 待機1, 待機2, B]` で待機1の最中に止めたら B）/ 連続実行が停止の行で終えるとき後ろの待機を待たない（`[A, 停止, 待機, B]` → 位置 B）/
   呼び出しの文脈の中の待機は従来どおり
5. 戻す履歴 1 段に呼び出し先のカウンター操作が含まれ（打ち切りでも）、戻すで打ち消せる / 状態が変わらないエラーでは積まない / 通知の表示中の停止操作で二重に積まない（§4.5）
6. 実行中に呼び出し先・入れ子の呼び出し先を編集・削除・改名しても開始時点の内容と間隔で最後まで実行される / 呼び出し元が消えたら履歴を積まずにやめる（§4.2）
7. 編集ダイアログの選択と OK 時の拒否・一覧の表示と参照先なし・キー変更時の参照の書き換え・間隔の欄（§5・§6）
8. 停止の読み飛ばしの判定で呼び出しの成功が「送った」に数えられる（§4.1）
9. 旧データ（呼び出しを含まない）の実行・保存が従来どおり。既存テスト（tests / tests_ui / smoke）が全 pass
