## §1 目的 / 背景

出力シーケンスの「呼び出し」（`features.md` §4.2.9）は、呼び出し先を開始時点の写しで一括実行し、呼び出し先の中の停止の行は読み飛ばす。
呼び出し元からは呼び出し先の進み具合が見えず、停止が効かない理由も分からない。これを、**呼び出しの行ごとに「ステップ」の動きを選べる**ようにし、
**呼び出し先の写しと位置を表示する枠**を設けて解消する。現行の一括の動きは便利なので既定として残す。

## §2 確定事項（ユーザー 2026-10-04）

- **呼び出しの行ごとに「ステップ」（既定）/「一括」を選ぶ**（編集ダイアログのチェックボックス「一括で実行」・ON で一括）。種別は分けない（v0.5。v0.4 までは一括が既定だった）
- **ステップ**: 単発では **1 回の押下 = 呼び出し先の 1 ステップ**。**停止の行で連続実行全体を止める**。**一時停止は呼び出し先の中の位置で止め、続きから再開する**
- **呼び出し先の表示枠**（Expander）: フル表示は**出力シーケンスの下**、省略表示は**トリガー一覧の下**（省略表示に出力シーケンス欄は作らない）。
  **呼び出し先の中で止まっているときに自動で開き、呼び出しが終わったら閉じる**。中身は呼び出し先の**開始時点の写し**を**読み取り専用**で `▶` 付き表示。
  入れ子は**一番深い段**を表示し、**見出しに経路**（例 `f1 › f5 › f7`）を出す。経路のクリックで段を切り替える機能は付けない
- **上の欄と枠の間に上下を分ける境界線**。位置は**設定ファイルに保存**し、再び開いたときも使う。**トリガーごとなどの個別の設定は持たない**
- **連続実行が呼び出し先の停止の行に達したら「連続実行の一時停止」にする**（§4.3・旧 §9-1 案 A'）
- **枠は止まったときだけ開く**（開いた後は処理中も逐次表示し、文脈が無くなれば閉じる・旧 §9-3 案 A）
- **ダイアログを開いたとき（フック停止）に文脈が打ち切られるのは受容**（旧 §9-4 案 A）
- 「一時停止の再開が最初からになる」はユーザーの勘違いで、本フェーズの対象外（旧 §9-2）

### v0.6 で改める確定事項（ユーザー 2026-10-05・推奨案の採用）

- **表示枠は常設の Expander**（止まったときだけ出して消える形をやめる）。起動時は閉じ、呼び出しで使ったら開く。開閉は**トリガーごと**（メモリ上だけ・保存しない）。見出しのクリックで手で開閉できる（§5.2）
- **境界線の主張を弱める**（出力シーケンス欄の複製・上へボタン程度・§5.1）
- **呼び出しの写し・呼び出し文脈をやめ、呼び出し元と呼び出し先の実行位置を「連動」させる**（§4.5。一括・ステップ共通）:
  呼び出しは呼び出し先の**今の位置から**進め（先頭へ戻さない）、呼び出し先を直接押しても同じものが進み、呼び出し先が末尾に達したら連動している呼び出し元は次へ進む（次の行は実行しない）
- **連動するのは呼び出し元がその呼び出しを始めているときだけ**（`▶` が呼び出しの行にあるだけでは連動しない）
- **戻す履歴は各トリガーが自分の状態だけを持つ**（呼び出し先の中の進みは呼び出し先の履歴に積む）。参照中のトリガーで戻すと、参照先（最上段）の履歴を戻す（§4.5.5）
- 「参照中」= 動作としては連動、処理としては参照（呼び出し先の状態は 1 つで、呼び出し元はそれを参照する）

## §3 呼び出しの種類（一括 / ステップ）

### §3.1 データ（v0.5）

- 呼び出しの行に **`all`**（bool）を足す。**真なら一括 / 無い・偽ならステップ**。真偽は実行時・表示時に `bool(all)` で判定する（`infinite`・`drag` と同じ）。
  **読込時に正規化しない・キーを補完しない**（`data_schema.md` §5.1・§5.11.6 の現行の扱い）
- **既存の呼び出しの行（phase 40〜44 で作った・`all` なし）はステップの動きになる**（ユーザー確定 2026-10-04: 機能が新しく利用が少ないため、読みやすい形式を優先）。一括で動かしたい行は編集で「一括で実行」を ON にし直す
- v0.4 までの `step` キーは phase 45 の中だけで使い、外へ出ていないので扱わない（読込時の置き換えはしない。`step` が残っていても無視）
- 編集ダイアログで OFF のまま確定したら `all` を書かない（ダイアログは結果を新しく組み立てるため、既存の `false` は消える）
- 他の種別の行に `all` があっても無視する（保持はする = `normalize_actions` の現行どおり）

### §3.2 編集と表示（v0.5）

- 呼び出しの編集ダイアログに **「呼び出し先を一括で実行する（停止の行は読み飛ばす）」** のチェックボックス（**既定 OFF = ステップ**・新規追加でも OFF）。呼び出しを選んだときだけ出す
- 一覧の表示: **ステップの行は `[call] f5（呼び出し先ラベル）`・一括の行は `[call all] f5（…）`**（参照先なし・呼び出し先なしの形も同じ接頭辞）。省略表示の次に実行の要約も同じ表示名
- 複製・貼り付け（phase 43）は `all` を含めて写す

## §4 ステップの呼び出しの実行

一括（現行）の規定（`features.md` §4.2.9）からの差分だけを書く。書いていない点は一括と同じ（開始時点の写し・深さ 9・循環・照合・無限ループ / 戻す・先頭へのエラー 等）。

### §4.1 段がステップとして動く条件

- **段がステップとして動くのは、呼び出し元からその段までの呼び出しの行がすべてステップのときに限る**。一括の呼び出しの中にあるステップの行は一括として扱う（段ごとに印を持つ）
- ステップの段の中の一括の呼び出しの行は、その 1 ステップの中で丸ごと実行する

### §4.2 単発

- **呼び出しの行に達した押下**で文脈を始め、呼び出し先の最初の 1 ステップ（system を処理して最初の通常アクションを 1 つ送り、文脈の中の先行処理をするまで）を実行する
- **押下の合間の状態は「単発の呼び出しの一時停止」そのもの**（`features.md` §4.2.10）。そのトリガーの押下は「再開して最上段の 1 ステップを進め、再び一時停止にする」。
  他のトリガーの扱い・**捨てる契機**（他のトリガーの連続実行の開始・キーマップの切替・戻す / 先頭への 2 回押しの対象・停止操作〔フック停止・キーマップ一時停止・UI 編集〕・
  位置の変更・シーケンスの編集・トリガーの削除・キーの変更・構成セットの読込等）・同時に持てる数・並べ替えの禁止は、単発の呼び出しの一時停止の規定に従う。捨てたときの位置は呼び出しの行
- **入れ子の呼び出しの行と空の呼び出し先は押下を消費しない**（同じ押下の中で次の送る行まで進む）。system の上限 10,000 は押下ごとに数える
- **呼び出し先の待機は次の押下の頭で待つ**（現行の文脈の待機と同じ。押下の合間の `▶` は待機の行を指す）。**呼び出し先の間隔は置かない**（押下が間隔の代わり）
- **1 ステップの処理中**（待機中・file_line の読込中・入れ子の一括の実行中）に同じトリガーを押したら**無視**する。単発のステップには途中の一時停止を設けない
- 最上段が末尾に達したら段を降ろし（その段の保留を反映）、下の段の続きへ戻る。**呼び出し元へ戻ったら**（呼び出しの成功）その押下の中で呼び出し元の先行処理をして押下を終える
- 呼び出し先の**停止の行は読み飛ばす**（単発の通常の規定と同じ・`features.md` §4.2.1）
- **戻す履歴と直前のトリガーは一括と同じく呼び出し全体で 1 段**（成功・打ち切り・エラー・捨てるときに §4.2.9 の規則で積む）。押下の合間には積まない

### §4.3 連続実行

- 呼び出し先の各ステップを、その段の呼び出し先の間隔を置いて進める（現行の一括の連続実行と同じ進め方）
- **呼び出し先の停止の行に達したら連続実行全体を止める**。停止の行の判定に使う「送った」は**文脈ごとの印**で数える:
  **ステップの段で呼び出し先の通常アクション（入れ子を含む）を送ったら、その文脈の印を立てる**（文脈の開始時・再開時に下ろさない。文脈が無くなれば消える）。
  印が立っていなければ読み飛ばす（`features.md` §4.2.8 と同じ考え方）。**呼び出し元の「送った」（`_run_to_end_sent`）は従来どおり呼び出しの成功時だけ立て、文脈の印は呼び出し元へ伝えない**
  （一括の呼び出し・打ち切り・位置の変更の挙動は変わらない）
- **停止の後の先行処理は §4.2.8 に従う**（待機を読み飛ばし、保留に控える。末尾に達したら段を降ろしてその段の保留を反映する）。その結果で分ける:
  1. **文脈が残る**（呼び出し先にまだ続きがある）→ **「連続実行の一時停止」にする**（文脈を保持・再開で最上段の続きから・捨てる契機と通知・2 回押しは一時停止の規定のまま。表示は一時停止）
  2. **文脈が無くなった**（段を降ろしきって呼び出しが成功した）→ 呼び出し元の先行処理をし、**呼び出し元の停止の行と同じく連続実行を終える**（§4.2.8。位置は先行処理の結果・
     一時停止にはしない = 続きの無い一時停止を作らない）。履歴は呼び出しの成功として 1 段
  - 呼び出し元の停止の行（§4.2.8）は従来どおり連続実行を終える

### §4.4 一時停止と再開（一括・ステップ共通）

- 呼び出しの文脈がある一時停止（単発の呼び出しの一時停止・ステップの押下の合間・連続実行の一時停止）は**文脈を保持し、再開は最上段の続きから**（`features.md` §4.2.10 を保証する）
- **停止操作（ダイアログを開いたときのフック停止を含む）は文脈を打ち切る**（現行どおり・位置は呼び出しの行に戻る・受容）

### §4.5 連動（v0.6）

v0.5 までの「開始時点の写し・呼び出しスタック・呼び出し先トリガー自身の状態は変えない」（`features.md` §4.2.9）と §4.2〜§4.4 の文脈の記述を、本節で置き換える。一括・ステップ共通。

#### §4.5.1 参照中の印と連動

- 各トリガーは runtime の状態（`features.md` §4.2.3・保存しない）に **「参照中」の印**を持つ。印 = 「`▶` が呼び出しの行にあり、その呼び出しを始めている」
- **印が立つ** = `▶` が呼び出しの行にあるトリガー T が押され（または連続実行がその行に達し）、検査（参照先なし・`target` 空・循環・深さ・無限ループ・戻す / 先頭へ）を通ったとき。
  呼び出し先 U は**U の今の位置・周回・保留から**進める（先頭へ戻さない。末尾まで進んだ U は先頭へ回っているので、次の呼び出しは自然に頭から）
- **連動** = T に印が立っている間、T と U（`target` の有効な行）は連動する。U にも印が立っていれば U の呼び出し先へ続く（**連鎖**）。連鎖の一番深いトリガーを**最上段**と呼ぶ
- **印が立っていなければ連動しない**: T の `▶` が `call U` にあるだけ（T を押していない）なら、U を単独で末尾まで進めても T は動かない。その後 T を押すと U の今の位置（先頭へ回っていれば頭）から呼び出す
- **印が消える**: 呼び出しの完了（§4.5.3）/ T の位置の変更・シーケンスの編集・削除・キー変更・有効な行の交代（既存の規則で T の状態を消す・変える操作）/ 呼び出しのエラー / 構成セットの読込等（状態の全消去）/ 戻す・先頭へ（§4.5.5）。
  **停止操作（フック停止・ダイアログを開く）・キーマップの切替・一時停止では消えない**（状態はトリガーのものとして残る。処理中の予約・待機の残り・読込中の file_line は既存の規則で取り消す）
- 循環・深さは**連鎖**で判定する（印を立てる時点で、T から下る連鎖と T へ上る連鎖を合わせて同じキーが 2 度出る / 深さ 9 を超えるならエラー）。シーケンスは常に今のものを使う（写しを持たない）

#### §4.5.2 押下と実行

- **トリガー P を押したとき、P に印が立っていれば最上段を進める**（P から下る連鎖の一番深いトリガー）。**動かすのは押したトリガー P**（P の単発 / 連続実行の設定で動く）。
  入れ子の呼び出しの行のステップ / 一括は §4.5.4
- **処理中**（`features.md` §4.2.10）は、処理中の実行の連鎖に属するトリガーの押下を、その実行のキーの押下として扱う（連続実行・単発の呼び出しなら一時停止 / 単発の待機中・file_line の読込中なら無視）
- **一時停止中**の連続実行（例 X）がある間に、同じ連鎖の別のトリガー（A・Y）を押したら、**押したトリガーの設定で最上段を進める**。X の連続実行は一時停止のまま（連動で位置は変わり得る）。X を押したときだけ X の連続実行を再開する
  - 押したトリガーが**連続実行**の設定なら、現行（`features.md` §4.2.10）どおり一時停止中のものを**すべて捨てて**（進行中の処理の取り消しだけ・位置と印は残る）開始し通知する。連続実行の同時数 1 は変えない
- 呼び出し先 U が単独で単発の待機中・file_line の読込中のときに、T がそれを呼んだ（印を立てた）場合は、U の押下と同じく**無視**（T の押下は消費しない）
- 複数の呼び出し元 X・Y がともに U に印を立てていてもよい（U の状態は 1 つ）。どれを押しても同じ U が進む

#### §4.5.3 完了

- 呼び出し先 U の実行が **U の末尾に達したら**（誰が押したかによらない）、U に印を立てているすべての呼び出し元 T について: T の印を下ろし、T の位置を呼び出しの次へ進めて**先行処理まで**（次の通常アクションは実行しない。`▶` が次の行を指す）。
  T も末尾に達して連動先の呼び出し元があれば、同じく続けて完了させる
- **T が一時停止中の連続実行のとき**: 位置だけ進め（先行処理まで・送らない）、一時停止のまま。再開するとそこから続く。先行処理で T が末尾に達したら T の連続実行を終える（停止の行・待機は §4.2.8 の終える前の先行処理と同じ扱い）
- **複数の呼び出し元の処理順**: 押下の一括の範囲の内側の呼び出し元を先に（連鎖の深い順）、残りを**トリガー一覧の上から順**に、1 つずつ先行処理（と末尾の保留の反映・さらに上の完了）まで済ませてから次へ進む。
  カウンターは実際に反映した順に効き、差分はそれぞれのトリガーの段に入る
- ただし**押下の一括の範囲の内側**（§4.5.4）にある呼び出し元は、完了の後もその押下の中で続けて実行する（「次の行は実行しない」は範囲の外の呼び出し元だけ）
- 呼び出し先が空・入れ子の呼び出しの行は押下を消費しない（§4.2 のまま）

#### §4.5.4 一括（`all: true`）

- **一括の範囲** = 押したトリガー P から最上段へ下る呼び出しの行のうち、**P に最も近い一括の呼び出しの行**の呼び出し先（例 Q）。1 押下で Q を**今の位置から末尾まで**進める（Q の中の入れ子の呼び出しは、ステップ / 一括によらず完了まで続ける・停止の行は読み飛ばす）。
  P から最上段までがすべてステップなら、1 押下 = 最上段の 1 ステップ（§4.2）
  - 例 X = `[call all A]`・A = `[call U, d]`・U = `[a, b]` → X の 1 押下で a・b を送り、U の完了の後に A を続けて d まで送る
- 途中の一時停止 → 再開は続きから。写しは持たない
- 連続実行では最上段の各ステップの間に、その呼び出し先の間隔を置く（現行と同じ）

#### §4.5.5 戻す履歴・直前のトリガー

- **戻す履歴は各トリガーが自分の状態（位置・周回・保留・参照中の印）だけを持つ**（`features.md` §4.2.3 のキー単位のまま）。1 押下で状態が変わった**各トリガーの履歴に 1 段ずつ**積む
  （呼び出し先の進み = 呼び出し先の履歴・完了で進んだ呼び出し元 = 呼び出し元の履歴）。カウンターの差分は、そのカウンター操作を実行したトリガーの段に入れる。
  同じ押下で積んだ段どうしには**押下の番号**を付ける
- ステップ = 1 押下で最上段に 1 段。一括 = 1 押下で各トリガーに 1 段（範囲内の多数のステップをまとめる）。連続実行は現行どおりステップ単位
- **直前のトリガー = 押したトリガー P**
- **戻す**: 対象 T に参照中の印があれば T から下る連鎖の最上段を、無ければ T を**起点**とし、起点の履歴の一番上の段の押下の番号 N を取る。
  **番号 N の段が履歴の一番上にあるすべてのトリガー**（入れ子の完了で進んだ呼び出し元・段を含む）をまとめて 1 段戻し、それらの段のカウンターの差分をすべて打ち消す。
  番号 N の段が一番上に無いトリガー（後から別の押下で動いた）は戻さない
  - 例 X = `[call A, B]`・A = `[call U, d]`・U = `[+1 n, u]`（ステップ）: X の 1 押下で U が完了し A は d・X は参照中 → 戻すと U・A をまとめて戻し n の +1 も打ち消す
  - 例 X = `[call A, B]`・A = `[a, b, c]`: X で a・b・c を送った後に戻す → X は `call A`・参照中に、A は c の前に戻る → 次の押下で c を送り直す
  - 例 X・Y が交互に A を進めた後に戻す → どちらから戻しても A の履歴を新しい順に戻す（他方の進みを飛び越えない）
- **先頭へ**: 対象の位置・周回・保留・履歴を消し、**対象の印を下ろす**（参照先の状態はそのまま）
- 対象が処理中・一時停止中の連続実行 / 単発の一括の途中（一時停止）なら、現行の 2 回押し（1 回目で通知・2 回目で**進行中の処理だけ**を取り消してから実行。状態は取り消した時点のまま）

#### §4.5.6 連続実行の停止の行と「送った」（§4.3 の v0.6 読み替え）

- 「送った」は**連続実行 1 回ごと**に持つ（`features.md` §4.2.8 の「その連続実行」のまま）。開始から、連鎖のどの段で送った通常アクション・file_line の完了・呼び出しの成功も数える
- その連続実行で送った後に**最上段の停止の行**に達したら、連続実行の一時停止（§4.3 の 1）または、停止の後の先行処理で完了まで進んだら終える（§4.3 の 2）
- 押し直して始めた連続実行（呼び出し先を直接押した場合を含む）は送っていない状態から数える。一時停止 → 再開では数え直さない。単発・一括の範囲の中の停止の行は読み飛ばす
  - 例 A = `[a, 停止, b]`・X = `[call A, B]`: X を単発で押す → a（A の `▶` は停止）→ X を連続実行で押し直すと停止を読み飛ばして b を送る

#### §4.5.7 v0.5 からの扱いの変化（要約）

- **打ち切り**（停止操作・ダイアログ）で位置が呼び出しの行へ戻らない（途中のまま残る。§7 の受容が不要になる）
- 呼び出し先を選ぶと、出力シーケンス欄の `▶` が呼び出しで進んだ位置を指す
- 呼び出し先の編集・削除・キー変更は、連動先の状態として既存の規則がそのまま効く（削除なら次の押下で「参照先なし」）

## §5 呼び出し先の表示枠

### §5.1 置き場所と境界線

- **フル表示**: 出力シーケンスの**一覧の下（右のボタン列の左）**に枠を置き、一覧と枠を上下に分ける境界線で区切る。ボタン列の高さとウィンドウの最小の高さは変えない。
  一覧の最小は 3 行、枠の最小は見出し + 3 行。横の 3 枠の幅の配分（phase 18）は変えない（枠の中身は最小幅に数えない）
- **省略表示**: トリガー一覧の**下**に枠を置き、一覧と枠を境界線で区切る。**枠の開閉でウィンドウの大きさは変えず、トリガー一覧が縮む**。一覧と枠の最小（各 3 行程度）を割る高さなら枠を最小で表示する。
  幅 270 では行の右が切れる（横スクロールなし・受容）
- **（v0.6）枠は常設の Expander**: 閉じているときは見出しの 1 行（`▸ 呼び出し先`）だけを一覧の下に出し、境界線は出さない。開いているときだけ境界線と中身を出す
- **（v0.6）境界線の見た目は控えめにする**: 出力シーケンス欄の複製・上へボタンと同程度の主張（細い線・周囲と近い色）。一覧と枠が区別できる程度に留める

### §5.2 開く・閉じる・どれを出すか（v0.6 で改訂）

- **開閉はトリガーごと**（トリガー一覧ごと・キー単位。メモリ上だけで保存しない）。**起動時・未使用のトリガーは閉じる**。対象 = 一覧で選んでいるトリガー S（その出力シーケンスの下の枠）
- **自動で開く**: S に参照中の印が立ったとき、S の開閉が**一度も手で操作されていなければ**開く。手で閉じたトリガーは自動では開かない。**自動では閉じない**
- **手で開閉**: 見出しのクリック（v0.5 のスコープ外から本フェーズへ移す）
- **表示 = S から下る連鎖の最上段**（§4.5.1）。S に印が無ければ「呼び出し中ではありません」。開いている間は処理中も逐次表示する
- **表示の切替**（フル ⇔ 省略）では同じトリガーの開閉・表示を新しい側の枠に出す（高さはその表示の保存値）
- （v0.5 の「最後に止まった文脈を出す・止まったときだけ開き文脈が無くなれば閉じる・手の開閉なし」は廃止）

### §5.3 中身

- **最上段（一番深い段）の呼び出し先の今のシーケンス**（v0.6。写しではない）を、出力シーケンスと同じ表示形式（`features.md` §4.6「一覧の表示形式」・ループの色分け）で出す。
  周回の表示は段の周回、`(=値)` はカウンターの現在値
- 最上段の位置に `▶` を付ける（出力シーケンスの次に実行の印と同じ・phase 43）。`▶` の行が見える位置へ自動でスクロールする
- **読み取り専用**: 選択・クリック・ダブルクリック・ドラッグ・Ctrl+C / V・編集は何もしない（実行位置は変わらない）。スクロールはできる
- 見出し: **経路** = 呼び出し元のキーから最上段までのキーを ` › ` でつないだもの（例 `f1 › f5 › f7`）。キーは正規化後の小文字。ラベルは出さない
  （エラー通知の連鎖の表記 ` > `〔呼び出し元を含まない〕とは別の用途として分ける）
- **runner からの知らせ方**: `SequenceRunner` に「表示する文脈の要約」を渡すコールバックを注入する（`update_status` と同じ形・application → presentation の依存方向を守る）。
  要約 = 経路のキーの列・最上段の行の列（複製）・位置・周回・**表示に使うカウンターの値の写し**・無ければ None。型は application 側の不変の値。呼び出しは UI スレッドから。
  （v0.6）runner は「表示が変わり得る」ことだけを通知し、presentation が選んでいるトリガー S のキーで**連鎖の要約を問い合わせる**（経路 = S から最上段まで）
- **通知の契機**: 表示する文脈が変わったとき・その位置 / 周回が変わったときに加え、**カウンターの値が変わり得るとき**（どのトリガーのステップの後・戻す / 先頭への後・カウンターの保留の反映の後）。
  文脈が動かず別のトリガーがカウンターを変えた場合も `(=値)` を新しくする

## §10 受け入れ条件（ドラフト）

1. 呼び出しの編集ダイアログで「一括で実行」を選べ（既定 OFF = ステップ）、一覧はステップ = `[call]`・一括 = `[call all]` と出る。`all` のない既存の行はステップで動く（§3）
2. 単発: ステップの呼び出しは 1 回の押下で呼び出し先の 1 ステップずつ進み、入れ子の呼び出しの行と空の呼び出し先は押下を消費せず、最後のステップの押下で呼び出し元の先行処理まで進む。
   合間に他のトリガーが動き、文脈が残る。処理中の同じキーは無視（§4.2）
3. 単発: 呼び出し先の待機は次の押下の頭で待ち、呼び出し先の間隔は置かない。戻す履歴は呼び出し全体で 1 段（§4.2）
4. 連続実行: ステップの呼び出し先の停止の行で（その文脈で送った後なら）連続実行の一時停止になり、再開で停止の次から続く。停止の後に呼び出しが終わる形（例 呼び出し先 `[A, 停止]`）は一時停止にせず連続実行を終える（§4.3）
4a. 既存の一括の呼び出しで、送った後に一時停止 → 呼び出し元の位置を停止の行へ変えて再開しても、従来どおり停止を読み飛ばす（「送った」の互換・§4.3）
5. 入れ子のステップ・一括の組み合わせが §4.1 どおり
6. 一時停止 → 再開で、一括・ステップとも呼び出し先の続きから動く（§4.4）
7. 止まったとき、フル表示は出力シーケンスの一覧の下・省略表示はトリガー一覧の下に枠が開き、写しと `▶`・経路が出る。開いた後は処理中も追従し、文脈が無くなれば閉じる。
   複数の文脈があるときは最後に止まったものを出す。表示を切り替えても同じ文脈が出る（§5.2・§5.3）
8. 枠は読み取り専用で、クリック等で実行位置が変わらない。表示中の文脈が動かず他のトリガーがカウンターを変えても `(=値)` が新しくなる（§5.3）
9. 境界線の位置が、再び開いたとき・再起動後も保たれる。フル表示と省略表示で別の値。不正な値は既定（§5.1・§6）
10. フル表示のウィンドウの最小の高さ・横の幅の配分が変わらない（§5.1）
11. 既存テスト（tests / tests_ui / smoke）が通る
12. （v0.6）X = `[call A, B]`・A = `[a, b, c]`（ステップ）で、X を押す → a、A を押す → b、A を押す → c で X の `▶` が B に移る（B は送らない）（§4.5.2・§4.5.3）
13. （v0.6）X を押していない（`▶` が `call A` にあるだけ）とき、A を単独で末尾まで進めても X は動かない。A を途中まで進めてから X を押すと A の続きから呼ぶ（§4.5.1）
14. （v0.6）X・Y がともに A を呼び出し中なら、どれを押しても同じ A が進み、A の末尾で X・Y がともに次へ進む（§4.5.2・§4.5.3）
15. （v0.6）ステップの呼び出しで c を送った後に戻すと c の前へ戻り、次の押下で c を送り直す。X・Y が交互に A を進めても、戻すは A の新しい順に戻る（§4.5.5）
15a. （v0.6）X = `[call all A]`・A = `[call U, d]`・U = `[a, b]` で X の 1 押下が a・b・d まで送る（§4.5.4）
15b. （v0.6）X の連続実行が A の中で一時停止中に Y（単発・`[call A]`）で A を末尾まで進めると、X は次の行へ進んで一時停止のまま、再開でそこから続く（§4.5.2・§4.5.3）
15d. （v0.6）X = `[call A, B]`・A = `[call U, d]`・U = `[+1 n, u]` で X を 1 回押した後に戻すと、A は `call U`・U は先頭・n は元の値に戻る（§4.5.5）
15e. （v0.6）X の連続実行が A の中で一時停止中に、連続実行の Y で A を押すと、X の一時停止は捨てられ（位置と印は残る）通知が出て Y が動く（§4.5.2）
15c. （v0.6）A = `[a, 停止, b]` を X の単発で a まで進めた後、X を連続実行で押し直すと停止を読み飛ばして b を送る（§4.5.6）
16. （v0.6）呼び出しの途中でダイアログを開いても、呼び出し元・呼び出し先の位置と印が残り、続きから進む（§4.5.7）
17. （v0.6）枠は常設で、起動時は閉じ、印が立つと（手で触っていなければ）開き、自動では閉じない。開閉はトリガーごと。見出しのクリックで開閉できる。印の無いトリガーでは「呼び出し中ではありません」（§5.2）
18. （v0.6）境界線が出力シーケンス欄の複製・上へボタン程度の主張になっている（§5.1）
