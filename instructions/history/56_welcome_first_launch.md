## §1 目的 / 背景

初めて起動した人が、①画面の言語とキーボード配列を選び、②何をするアプリかを短く知り、③サンプルで試してから使い始められるようにする。
あわせて、意味が伝わりにくい今のサンプル（F1 / F2）を、キーマップの切り替え・キー置換・出力シーケンスが見られるサンプルに作り直す。

## §2 確定事項（ユーザー 2026-11-08）

- **Welcome は 1 枚の窓**。上に言語・キーボード配列の選択、下に基本的な使い方の要点とサンプルの案内。言語を選ぶとその場で窓の文言が切り替わる
- **表示は初回だけ**＋**ヘルプのメニューから再表示できる**
- **最初の言語は今の既定のまま（英語）**。項目名は全言語共通の「Language」なので見つけられる
- **既存の利用者を区別しない**（起動設定ファイルが無ければ誰でも同じ Welcome・同じ既定）
- **始め方を選ばせる**（サンプル入りで始める / 空で始める）。**既定 = サンプル入り**
- **サンプルは作り直す**。ユーザー作成のサンプル原案（§1）を元にする
  - **最初に有効なキーマップ = shortcut**
  - **num と right key に h のトリガー**を置き、キーボード表示で割り当てを確かめるよう促す文を入力する（shortcut には置かない）
  - **停止キー = F12**・**一時停止/再開キー（トグルキー）= F1**（ユーザー案「F1 か F3」から F1。§5.1）
  - **書き出し先 = `config/sample/`**（§5.2）
  - **ラベル（キーマップ名・出力シーケンス名・案内文）は言語ごとに用意**する（言語ファイルのキー。ファイル名は全言語共通の英語）
- **コードの既定データ自体を新しいサンプルにする**（ユーザー 2026-11-08。§5.2・§5.3）。サンプルの中身を持つのはコードの 1 か所だけ（言語ごとの原本ファイルは作らない）
- **見本の `jis.json` を `jis_test.json` へ改名し、全キーの JIS を `jis.json` として作る**（§5.4）
- **キーボード配列を Welcome で選ばせる**（US TKL / JIS）。**JIS は全キーの配列ファイルを新しく作り**、選ばれたら外部の配列として構成に登録する
- **minus をキー置換の置換先にするとエラーになる不具合を本フェーズで直し**、サンプルの num も `minus` に戻す
- **本フェーズに入れない**: プリセットが一度編集で開かないと表示されない不具合 / キー名（`bar` 等）の記号表記（§11）

## §3 初回の判定と起動の流れ

- **初回 = 起動設定ファイル（`config/config.json`）も旧 `settings/startup.json` も無い**とき（`resolve_startup_path()` の結果が存在しない）
- **Welcome を出すかは `main.py` から渡す**（v0.5・ユーザー 2026-11-09）: `App(first_launch_welcome=True)` のように引数で渡し、既定は出さない。
  初回の判定（下の 1）は引数が真のときだけ行う。`App()` を直接作る `tests/smoke_app.py` と tests_ui は何も変えずに Welcome が出ない
- 流れ（初回のとき）:
  1. `super().__init__()` の直後に初回を判定し、初回なら Tk ルートを隠す（`withdraw`。空の窓を見せない）
  2. 起動設定の読込・`set_language`・テーマの適用の後、`new_default_data()` の前に Welcome をモーダルで出す（フックはまだ無いので停止・再開は要らない）
  3. Welcome の結果 = **言語・キーボード配列・始め方**の 3 つ。言語は `set_language` し `_startup_settings["ui_language"]` に入れる。配列と始め方は App が起動の間だけ持つ。起動設定ファイルの書き出しはしない
  4. サンプル入りなら、既定データ（＝サンプル・選んだ言語のラベル・選んだ配列）を `config/sample/` へ書き出す（§5.2）。
     成功したら（または完全なサンプルが既にあれば）`_startup_settings["keymap_set_path"]` をサンプルの構成セットにする。失敗したら警告を出し、空で始める
  5. 画面を構築する（`UiVars` は更新後の `_startup_settings` から作るので、メニューの言語の選択も合う）
  6. `load_startup_and_config()`（今の読込の経路）がサンプルの構成セットを読む。
     **空で始めるときは、読込の後に §6 の構成（キーマップ 1 つ・選んだ配列）を作る**（今の読込は構成セットが無いとキーマップ 0 個にするため。読込の失敗で空になる場合とは分けて扱う）
  7. 読込の後、通常の書き出し（`startup_io.write_startup`）で `ui_language` と起動時の構成セットを書く。これで次回からは初回にならない。
     書き出しに失敗したら今の書き出しと同じ警告を出して続ける（次回も Welcome が出る＝受容）
  8. Tk ルートを表示する
- **閉じ方**: 「はじめる」・×・Esc はどれも「その時点の選択で確定」（モーダルの作法 `features.md` §4.6 で Esc = ×。初回に Esc でサンプル入りになるのは受容）

## §4 Welcome の窓（初回）

上から:

1. **Language**: 言語の選択（`available_languages()` の一覧・各言語の自称名）。初期値 = 今の言語（保存値が無いので英語）。
   選ぶとすぐ `set_language` し、窓の文言を作り直す（窓は閉じない）
2. **キーボード配列**: US TKL / JIS を **Language と同じドロップダウン**（読み取り専用）で選ぶ（v0.6・配列が増えても形を変えない）。初期値 = 言語から推定（日本語 = JIS / それ以外 = US TKL）。
   言語を変えたら、配列を利用者が触っていなければ推定値へ追従する（触った後は追従しない）
3. **基本的な使い方**（3〜4 行）: トリガーキーを登録 → 出力シーケンスを作る → 「フック開始」で有効になる、の流れ
4. **始め方**: 「サンプル入りで始める」（既定）/「空で始める」の 2 択。サンプル入りの説明を下に添える
   （§5 の 3 つのキーマップ・1 / 2 / 3 で切替・**まず「フック開始」を押す**・F1 で一時停止/再開・F12 でフックを止める・h で案内・メモ帳などで試す）
5. **ボタン**: 「ヘルプを開く」/「はじめる」（確定して閉じる）
   - 初回の「ヘルプを開く」は、ヘルプの窓を Welcome を親として直接作る（ヘルプの窓口はまだ無い。`open_for_dialog` と同じ作法）。Welcome は閉じない

- 文言はすべて言語ファイルのキー（`ja.json` / `en.json`）。表記は `ui_terms.md` に従う（フックのキーの名前は「停止キー」「一時停止/再開キー」）
- **v0.6**: 折り返す文（`wraplength` の Label）の日本語には半角の空白を入れない（Tk は空白で折り返すため「数字キーで 3」で改行していた）。「数字キーで3つ」「F1で」「hで」のように書く

## §5 サンプル

### 5.1 中身

| キーマップ | 切替キー | 内容 |
|---|---|---|
| shortcut（最初に有効） | 1 | トリガー r = 行を選択（home → shift+end・連続）/ c = コピー / v = 貼り付け / t = アプリの切替（alt+tab）/ a = 行を選択して別のアプリへ貼り付けて戻る（連続） |
| right key | 2 | 左手側のキーを右手側の文字へ置換（原案のとおり）+ **トリガー h = 案内文を入力** |
| num | 3 | 左手側のキーをテンキーの数字・記号へ置換（q → **minus**）+ **トリガー h = 案内文を入力** |

- 構成セット: `hook_keys_individual: true`・`hook_stop_key: "f12"`・`hook_toggle_key: "f1"`・`active_keymap_path` = shortcut・`keyboard_layout` = Welcome で選んだ配列
  （JIS なら `external_keyboard_layouts` に JIS の配列ファイルを登録）。その他は原案のとおり
- トグルキーは F1 を推奨: F12（停止）と左右の端で対になり押し間違えにくい。フック中は F1 のヘルプ（他のアプリ）が使えなくなるが、このアプリのヘルプはメニューから開く
- h の案内文（例・文言はタスクで確定）: 「このキーマップの割り当てはキーボード表示で確かめられます。1・2・3 で切り替え、F1 で一時停止/再開、F12 でフックを止めます。」
  - **v0.6**: 割り当てを確かめる場所は画面の名前どおり「「表示」の欄の「キーボードUI」」と書く（ヘルプと同じ。英語は `Keyboard UI` in the `Display` section）
- キーの重なり（`key_input.md` §7.3）: 切替キー 1 / 2 / 3・F1・F12・h はどのトリガー・置換元とも重ならない（deep-reviewer 確認済）。
  num の置換先 x → 1 等が送るキーを切替キーとして拾い直さないことは受け入れ条件で確かめる（§10）
- サンプルのトリガー・置換のキーは US TKL と新しい JIS の両方にあるキーに限る

### 5.2 既定データ（＝サンプル）と書き出し

- **サンプルはコードの既定データ（`domain/config.py`）として持つ**（ユーザー 2026-11-08）。同梱の原本ファイルは作らない
  - 既定データは**呼び出しのたびに今の言語のラベルで組み立てる**（今の定数 `DEFAULT_CONFIG` を、組み立てる関数に替える。ラベル・案内文は言語ファイルのキー）
  - 中身: キーマップ 3（shortcut・right key・num）とそのトリガー・出力シーケンス 7（行を選択・コピー・貼り付け・アプリ切替・行を別アプリへ・案内文 2〔right key 用・num 用〕）・
    フックのキー（§5.1）・既定のプリセット（今のまま）。`keyboard_layout` は `us_tkl`（Welcome では選んだ配列に差し替える）
- **書き出し先はサンプル専用のフォルダ `config/sample/`**（ユーザー 2026-11-08。利用者のファイルの置き場 `config/user/` と分ける）。
  中の参照パスは `config/` 基準の `sample/...`（構成セット = `sample/keymap_sets/sample.json`。下位フォルダの並びは `config/user/` と同じ）
  - 書き出しは application 層の今の保存の仕組み（分離 JSON の保存）を、ダイアログなし・置き場を決め打ちで使う
  - **書く順 = 子（出力シーケンス → トリガー一覧 → キーマップ）を先に、構成セットを最後に**。途中で失敗したら構成セットは書かれない
  - `config/sample/` に構成セットが既にあれば書き出さず、**全部そろっているかを確かめる**（構成セットから辿れる全ファイルがあり、読める）。
    そろっていればそれを読む（配列の選択は反映されない＝受容）。**欠けていれば手を付けずに警告を出し、空で始める**（利用者の編集を消さない）
  - 構成セットが無く子だけ残っている（前回の途中失敗）ときは、書き出しで上書きしてよい
  - `config/sample/` を置き場の走査（孤児の掃除・保存先の確認など）が扱えるかはタスクで確かめる

### 5.4 JIS の配列ファイル

- **JIS の配列ファイル**（ユーザー 2026-11-08）:
  - 今の一部のキーだけの見本 `config/user/keylayout/jis.json` を **`jis_test.json` へ改名**する（参照しているテスト・ヘルプの本文を追従）

### 5.3 「サンプルを復元」と既定データを使う他の経路

- メニュー「サンプルを復元」は**今のまま既定データをメモリへ入れる**（未保存・パスなし・ファイルは読まず書かない）。これで新しいサンプル（今の言語のラベル）が入る
  - コードから組み立てるので、キーマップ・トリガー一覧・出力シーケンスは**保存先の記録（`source_path`・親の記録）を持たない**。全部を未保存として扱う
  - キーボード配列は今の構成のものを保つ。**フックのキーはサンプルのもの（構成セット側・F12 / F1）にする**（今の復元の後の `apply_global_defaults` が上書きしないことをタスクで確かめる）
- **メニュー「新規」は既定データから作らず、§6 の構成を直接作る**（既定データにキーマップ 3 つと置換が入るため。結果は今と同じ「トリガーなしのキーマップ 1 つ」）
- 既定データの他の利用者は今のままでよい: 分離 JSON の読込の土台（`split_loading.py:104`・キーマップとトリガーを空にし直す）/ `new_empty_data`（キーマップを空にする）/
  プリセット管理（`preset_manager.py:257`・プリセットだけを使う）。起動時の `app.py:139` は読込で上書きされる
- 既定データの F1 / F2 を前提にしたテストは直す

## §6 空で始める

  「新規」と同じ組み立ての関数を使う
- 初回の起動では §3 の手順 6 のとおり、読込の後にこの構成を作る
- 起動時の構成セットは設定しない

## §7 ヘルプからの再表示

- ヘルプのメニューに「Welcome を表示」を足す。通常のモーダルの作法（フックの停止・再開を含む）に従う
- 再表示の窓は §4 から**始め方とキーボード配列を除く**（今の構成を変えない）。上から **基本的な使い方**（§4 の 3 と同じ）/ **サンプル設定**の欄 / ボタン（v0.6。v0.7 で Language を除く）
- **サンプル設定**の欄（v0.6・メニューの場所を案内する一文に替える）: 説明の一文（サンプルの中身は §4 の 4 の説明と同じ文）+ ボタン「サンプル設定に戻す」（メニューの項目と同じ名前）。
  押すと **Welcome を開いたまま**、メニュー「サンプル設定に戻す」と同じ処理（未保存の確認・実行してよいかの確認・§5.3 の復元）を行う。
  確認の窓は Welcome の上に出す（親 = Welcome）。終わったら（取り消しを含む）Welcome に戻る。フックは Welcome が止めたまま（Welcome を閉じたときに再開）
- **v0.7: 再表示に Language は置かない**。窓の文言は今の言語で出し、閉じても言語の保存・再起動の確認は行わない（言語の変更はメニュー「Language」）
- 「ヘルプを開く」は **Welcome の子としてヘルプを開く**（`open_for_dialog` と同じ作法。メニューから開いたヘルプはモーダル中に操作できないため・`features.md` §4.6「ヘルプの窓」）。
  別の窓の子のヘルプがあれば閉じて開き直す。Welcome を閉じたら子のヘルプも閉じる（初回の Welcome も同じ）

## §8 minus の置換エラーの修正

- キー置換の置換先に `minus` を選ぶとエラーになる不具合を直す。原因はタスクで調べる。同じ経路の `plus` / `asterisk` / `slash` 等の記号のキーも調査範囲に含める
- 直した後、サンプルの num の q を `minus` にする

## §9 確認事項（ユーザー判断）

- なし（v0.4 時点で全件確定）

## §10 受け入れ条件（ドラフト）

1. 起動設定ファイルが無い状態で起動すると、メイン画面より先に Welcome が出る。空の窓は見えない（§3）
2. Welcome で言語を変えると窓の文言がその場で変わり、閉じた後のメイン画面とメニューの言語の選択がその言語になる（再起動なし）（§3・§4）
3. 2 回目の起動では Welcome が出ない（§3）
4. 「サンプル入り」で始めると、選んだ言語のラベル・選んだ配列のサンプルが読まれ、shortcut が有効。「フック開始」の後、F1 で一時停止/再開・F12 でフック停止になる。次回の起動でも同じ構成セットが読まれる（§5）
5. JIS を選ぶと、キーボード表示でサンプルのすべてのキーが見える（§5.4）
6. num で x（→ 1）を押してもキーマップが切り替わらない（§5.1）
7. 「空で始める」と、選んだ配列でトリガーなしのキーマップ 1 つで始まる（読込の失敗による空とは別の経路）（§3・§6）
8. `config/sample/` に完全なサンプルがあれば書き出さずに読む。欠けていれば手を付けず警告して空で始める。子だけ残っていれば書き出し直す（§5.2）
9. 「サンプルを復元」で新しいサンプル（今の言語のラベル）が未保存で入る。その後に保存しても `config/sample/` や他の既存ファイルを上書きせず、別名保存になる（§5.3）
10. メニュー「新規」は今と同じくトリガーなしのキーマップ 1 つ（§5.3）
11. 見本は `jis_test.json` の名前で残り、`jis.json` は全キーの JIS になる。ヘルプの本文の見本の名前も合っている（§5.4）
12. ヘルプのメニューから Welcome を再表示でき、再表示に Language は無く、閉じても言語の保存・再起動の確認は起きない（§7・v0.7）
13. Welcome（初回・再表示）の「ヘルプを開く」で開いたヘルプを操作でき、Welcome を閉じるとヘルプも閉じる（§4・§7）
14. キー置換の置換先に minus を選んでもエラーにならない（§8）
15. Welcome を出さない入口を使った既存のテスト（tests / tests_ui / smoke）が通る（§3）
16. （v0.6）配列はドロップダウンで選ぶ。Welcome の日本語の説明が語の途中の空白で改行しない。h の案内文が「表示」の欄の「キーボードUI」を指す（§4・§5.1）
17. （v0.6）再表示の Welcome に基本的な使い方と「サンプル設定に戻す」ボタンがあり、押すと Welcome を開いたままメニューと同じ確認を経てサンプルに戻る（§7）
