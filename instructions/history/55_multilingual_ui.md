## §1 目的 / 背景

画面に出る文言を日本語 / 英語で切り替えられるようにする。言語は利用者が設定で選ぶ。
3 言語目以降を**ファイルを置くだけ**で足せる仕組みにしておく（3 言語目以降の追加自体は本フェーズでやらない）。

## §2 確定事項（ユーザー 2026-11-01）

- **対応言語は日本語（`ja`）と英語（`en`）の 2 つ**。3 言語目以降の追加は別 idea として backlog へ起票する（§10）。
- **言語は設定で切り替える**（OS の言語には合わせない）。
- **文言は言語コードごとのファイルに置く**。ヘルプ本文も言語ごとのファイルにする（`help_ja.json` / `help_en.json`）。
- **訳が足りない文言は英語で表示する**。日本語は元の文言なので欠けない。
- **設定の言語一覧は、置かれている言語ファイルから作る**（言語を足すときはファイルを置くだけ・コードは変えない）。
- **設定ファイルに言語のキーを足す**（後方互換・既存キーは変えない）。
- **言語の変更は次回の起動から反映し、選んだ直後に再起動が必要な旨を知らせる**（§5・旧 Q1）。
- **言語のキーが無いときの既定は英語**。今使っている利用者もアップデート後は英語で開き、メニューで日本語に戻す（§4.2・旧 Q2 = 案 A）。
- **アプリが作って保存する既定の文言は作った時点の言語で作る**（§6.3・旧 Q3。該当は今のところ 1 か所）。
- Codex 敵対的レビューの指摘 2 件を採用（`tr` の最初の引数を位置専用にする §3.2 / 静的検査の許可を内容・場所・理由の組で照合する §9）。

## §3 文言カタログ

### §3.1 ファイルと形式

- 置き場所: `keyseq/shared/i18n/locales/<code>.json`（`ja.json` / `en.json`）。
  全層から使うため Global Shared（`keyseq/shared/`）に置く（`file_organization_rules.md`）。
- **依存ルール**: `keyseq/shared/` は全層から依存してよい。shared は他の層（presentation / application / domain /
  infrastructure）に依存せず、標準ライブラリだけを使う（`architecture.md` §3.2 へ足す・§11）。
- locales の場所は shared/i18n が自分の位置（`__file__`）から引く。exe 化等で変える必要が出たときのために
  場所を差し替える口を置く（本フェーズでは使わない）。
- 形式（UTF-8 の JSON オブジェクト）:
  ```json
  {
    "_meta": {"name": "English"},
    "menu.settings": "Settings",
    "dialog.save_confirm.body": "Save changes to {name}?"
  }
  ```
  - `_meta.name` = 言語一覧に出す名前（その言語自身の表記。`日本語` / `English`）。
  - それ以外のキー = 文言キー → 文字列。キーは `<領域>.<画面や部品>.<用途>` のドット区切り（英小文字・数字・`_`）。
  - 差し込みは `{name}` 形式（`str.format_map`）。`{` `}` 自体は `{{` `}}`。
- **`ja.json` が文言キーの正**（全キーを持つ）。`en.json` も全キーを持ち差し込みの名前が一致することをテストで保証する（§9）。

### §3.2 引き方とフォールバック

- `tr(key, /, **params) -> str` = 今の言語で引く。`tr_in(lang, key, /, **params) -> str` = 指定した言語で 1 回だけ引く（§5 の知らせ用）。
  **`key` / `lang` は位置専用**（文言に `{key}` を差し込む箇所が既にあるため。例 `trigger_row_edit.py:35`・
  `application/keymap_switch_batch.py:35`）。差し込み名に使えない名前は無い（`key` / `lang` を差し込みに使うテストを置く）。
- 探す順: **選んだ言語 → `en` → `ja` → キー文字列そのもの**（重複は飛ばす。`ja` を選んだときは `ja` → `en` → キー）。
  - どの言語にも無いときはキー文字列を返し、キーごとに 1 回だけ `logging.warning` を出す（例外にしない）。
- 差し込みに失敗した（引数の不足・形式の誤り）ときは、差し込み前の文字列を返して warning を出す（例外にしない）。
- **使う言語は起動時に 1 回決め、実行中は変えない**（§5）。カタログはモジュール内に 1 つ持つ。
  **言語を決める前に `tr` が呼ばれたら `ja` を読んで使う**（App を作らない tests/ の application / domain テストも日本語になる。
  利用者の既定〔§4.2 = `en`〕とは別。アプリは画面を作る前に言語を決めるので、利用者にはこの `ja` は出ない）。
- **モジュール定数に訳した文言を入れない**。定数は文言キーを持ち、表示する時点で `tr` する
  （import 時に評価すると言語を決める前の `ja` で固まるため。既存の `KIND_LABELS`・`HOOK_STATE_LABELS` 等も対象）。
- テスト用に言語・カタログを差し替える関数を置く。

### §3.3 言語ファイルが読めないとき

- `ja.json` / `en.json` は同梱物なので通常は読める。テストで同梱の 2 ファイルが読めて §3.1 を満たすことを保証する。
- 読めない / JSON オブジェクトでない / `_meta.name` が文字列でない言語ファイルは**一覧に出さず、引く対象にも入れない**（warning）。
  `ja` が欠けた場合も同じで、§3.2 の順から外れる（`en` → キー）。
- 文言の値が文字列でないキーは、そのキーだけ無いものとして扱う。

### §3.4 ヘルプ本文

- 本文は `help_<code>.json`（`presentation/help/content/`）。読む順: **選んだ言語 → `en` → `ja`**。
  先のファイルが無い / 今の本文の検証で読めないときは次を読む。全部読めなければ今と同じく窓内に理由を出す。
- `help_en.json` は `help_ja.json` と**同じカテゴリ id・項目 id**を持つ（コードと「?」が id で開くため。テストで保証）。
- `help_content.py:139` の `"ja"` 直書きを今の言語へ差し替える。本文の検証エラー文（窓内に出る）は §6.1 の対象。

## §4 言語の一覧と設定

### §4.1 言語の一覧

- `locales/` の `<code>.json` のうち §3.3 で読めたものを一覧にする。`<code>` は英小文字・数字・`-`（例 `ja`・`en`・`pt-br`）。
  これに合わないファイル名（大文字を含む・`_` 始まり 等）は無視する。
- 並び: `ja`、`en`、残りはコード順。表示名は `_meta.name`。

### §4.2 設定ファイルのキー

- `config/config.json` に **`ui_language`**（文字列・言語コード）を足す。
- **キーが無い / 文字列でない / 一覧に無いコード → `en`**（エラー表示なし・ファイルは書き換えない）。
  config.json が無い / 読めないときも `en`。型の判定は App が言語を決めるときに行う。
  ※ 今の利用者（config.json はあるがキーが無い）もアップデート後は英語で開く（ユーザー確定 = 案 A）。
- **言語は画面を作る前に決める**。起動時の config.json 読込失敗の警告などは、言語を決めてから出す（決めた言語で出る）。
- 書き込みは今の起動設定の書き出し経路を通す（§1 の 2 経路とも未知キーを保持するので値は残る）。
  書き込み契機 = メニューで言語を選んだとき（保存済みの言語と違う場合のみ）。config.json がまだ無ければこの時点で作る
  （`data_schema.md` §5.4 の「最初に設定が永続化された時点」の作成契機に足す）。
- **テストでは言語を `ja` に固定する**（tests_ui は実際の config.json を読むため、実機で English を選んだ checkout でも
  日本語で走ること）。固定の方法（環境変数で上書きする口 等）は task で決める。

### §4.3 メニュー

- メニュー「設定」に言語の項目を足す（「フォントサイズ」の下）。項目名は `ja` = **「言語 / Language」**・`en` = **「Language / 言語」**
  （どちらの言語で開いていても、もう一方の利用者が見つけられるように併記する。既定が英語なので、今の日本語の利用者は
  英語のメニューから日本語へ戻すことになる。新規文言なので §6.3「日本語は変えない」の例外に当たらない）。
- 中は §4.1 の一覧のラジオ項目。チェックは**設定ファイルに保存された言語**に付ける（今表示している言語ではない）。
- 選ぶと保存し、§5 のとおり知らせる。

## §5 切り替えの反映

- **次回起動から反映する**（実行中の画面は今の言語のまま）。選んだ直後に情報ダイアログで
  **再起動が必要な旨**（例「言語の変更はアプリを再起動すると反映されます」）を**選んだ言語で**出す（`tr_in`）。文言は task で確定。
- 理由: 文言は窓や部品を作るときに埋め込まれている（約 1,000 か所）。即時反映は全画面の作り直しか、
  全部品の文言の再設定が要り、開いている子窓・編集中の状態の扱いまで広がる。作った後に組み立てる文字
  （ステータス欄・一覧の行・ツールチップ）の差し替え漏れで言語が混ざる不具合も起きやすい。

## §6 対象の文言

### §6.1 対象

`ui_terms.md` §1 の「対象」と同じ範囲（画面に出る文言すべて）。具体的には:

- メニュー・窓のタイトル・ラベル・ボタン・チェックボックス・選択肢・ツールチップ・ステータス欄・一覧の見出し
- messagebox / 確認ダイアログ / エラー文
- **内側の層で作られて画面に出る文**: 内側の層も `tr` で作る（作った時点で今の言語になる。言語は実行中に変わらないので
  表示の時点で訳すのと結果は同じ）。ログ専用の文は対象外（§6.2）。
  ※ 代替案（内側の層は「キー + 引数」を持つ例外を投げ presentation が訳す）は、約 290 か所の例外・戻り値の形を変える
  ことになるため採らない。
- ヘルプ本文・ヘルプの検証エラー文・バージョン情報・ライセンス窓の見出し等（ライセンス本文そのものは対象外）
- **アクションの種類の表示名**: 今は内部名（`hotkey` / `mouse_click` 等）のまま出している。表示名の文言キーを作り、
  画面にはそれを出す（JSON に保存する値は内部名のまま）。日本語の表示名は `ui_terms.md` の用語表に足す（task で確定）。

### §6.2 対象外

- ログ専用の文言（`logging` へ出すだけのもの）・JSON キー・保存されるデータ値・利用者が付けた名前・ファイル / フォルダ名
- キーの名前（`Enter`・`Ctrl`・`変換`・`半角/全角` 等。`keyboard_key_text.py` の表示は今のまま）
- tkinter / OS 標準のダイアログの部品（ファイル選択ダイアログ・messagebox のボタン）。OS の言語に従う
- 同梱のサンプル設定の中身（キーマップ名などはデータ値）
- ライセンス本文・第三者ライセンス

### §6.3 書き方

- 日本語は今の文言を変えない（キーへ移すだけ。文言の変更は本フェーズでやらない）。
- **表示文字列を内部値に使わない**: Combobox / StringVar の値や分岐の比較に使っている表示文字列（§1）は内部コードへ置き換え、
  表示は内部コード → `tr` で写す。言語に依らず同じ動きになること。
- **アプリが作って保存する既定の文言**は、作った時点の言語で作る。保存後はデータ値（§6.2）。
  2026-11-01 の確認で該当は `application/config_service/split_loading.py:381` の `旧トリガーセット（<ファイル名>）`
  （旧形式のトリガーセットを移行するときに作るキーマップ名）だけ。ファイル名・id の既定（`keymap_set.json`・`keymap_1` 等）は
  英語で、新しいキーマップの名前は空・複製は元の名前に番号を付けるだけ。
- 英語は `ui_terms.md` に英語の用語の列を足し、それに従う（task で確定）。英語の表記の規則（大文字の使い方等）も同節に書く。
- 英訳は実装で作り、ユーザーが実機で確認する。

## §7 見え方

- 英語で文言が長くなっても、ボタン・ラベルが切れない / はみ出さないこと（主な画面を実機で確認する）。
- ボタン幅は実測（`font.measure`）なので追従する。文字数基準の最小幅（`pane_width_rules.py`）は英語で足りなければ
  言語に依らない値へ見直す（task で確認し、見直す場合はこの節を改訂する）。

なし（v0.2 の Q1〜Q3 は 2026-11-01 にユーザー確定し §2 へ移した）。

## §9 受け入れ条件（ドラフト）

1. 「設定」→「言語 / Language」で English を選んで再起動すると、メニュー・主画面・全ダイアログ・ステータス欄・エラー文・ヘルプが英語になる（§4〜§6）
2. 日本語を選んだときの文言は今と同じ（§6.3・既存テストが日本語のまま通る）
3. `ui_language` が無い / 不正 / config.json が無いときも起動でき、英語で出る。ファイルは書き換えない（§4.2）
4. 言語を選ぶと保存され、選んだ言語で再起動が必要な旨を知らせる。構成セットの保存後も値が残る（§4.2・§5）
5. `en.json` が `ja.json` の全キーを持ち、差し込みの名前が一致する / `help_en.json` が `help_ja.json` と同じ id を持つ（§3.1・§3.4・テスト）
6. 訳の無いキーは英語 → 日本語 → キーの順で出る / 言語を決める前の `tr` は日本語（§3.2・テスト）
7. 言語ファイルを `locales/` に置くと一覧に出る / 壊れたファイル・規則に合わない名前は一覧に出ない（§4.1・§3.3・テスト）
8. 英語でも、表示文字列を比較していた箇所が日本語と同じに動く（§6.3・テスト）
9. **アプリのソース（`keyseq/`）に、画面に出る日本語の文字列リテラルが残っていない**ことを静的テストで保証する。
   判定: AST の文字列定数と f-string を対象 / docstring を除く / `logging.*` ・ `logger.*` 呼び出しの**メッセージの文字列だけ**を除く
   （その引数の中で画面用の関数へ渡す文字列は除かない）/ §6.2 のキー名等は**文字列の内容・場所（ファイルと関数）・除外理由の組**で
   許可リストに書いて 1 件ずつ照合する。許可リストに無い日本語は失敗、**使われていない許可も失敗**。
   検査自身のテスト（許可した場所の文字列を別の日本語に替えると失敗する / ログ呼び出しの中の画面用の呼び出しを検出する）を置く
10. アクションの種類は表示名で出る（保存値は内部名のまま）（§6.1）
11. テストは実機の言語設定に依らず日本語で走る（§4.2）
12. 英語で主な画面のボタン・ラベルが切れない（§7・実機目視）
13. tests / tests_ui / smoke が通る

## §10 スコープ外（本フェーズでやらない）

- 3 言語目以降の追加（**別 idea を起票する**）
- 実行中の即時切り替え（§5）
- OS の言語に合わせた自動選択
- 日本語の文言そのものの見直し
- tkinter / OS 標準ダイアログの言語
- ログ文言の英語化
- 保存済みデータ（既定名で作られた名前・サンプル設定）の翻訳
