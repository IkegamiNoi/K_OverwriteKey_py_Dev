## §1 目的 / 背景

出力シーケンスに**入力を送らない制御用のアクション**（system 種別）と、**カウンター値で選んだファイルの行を入力する種別**（file_line）を加え、
ループ・回数の把握・誤操作からの復帰を可能にする。

### 現状監査（2026-09-26）

- 実行位置はトリガーごと（トリガー一覧 ID + キー）に `AppState.indices_for()` が持つ（`keyseq/application/app_state.py:39`）。
  runtime 専用で保存しない。
- 単発実行 = 1 押下で 1 アクション・末尾の次は先頭（`sequence_runner.py:65` `_run_single_action`、`% len`）。
  同一キーの再入は `reentry_guard` で弾く。
- 連続実行 = 今の位置から末尾まで `after()` で間隔 `run_to_end_delay_ms` ごとに流し、末尾で位置 0 にして停止
  （`sequence_runner.py:121`）。連続実行中は同じトリガーの押下で一時停止 / 再開し、他のトリガーは無視する（同 `:42`）。
- トリガーの押下は `hook_controller.py:275` から `after()` 経由で **UI スレッド**で `handle_key` に届く（単発実行は UI スレッドで同期実行）。
- アクションの実行は `ActionExecutor.execute`（`action_executor.py:59`）。種別は hotkey / text / mouse_click で、
  それ以外は送信エラーを通知して `False` を返し、runner はそこで止まる（位置は残る。正本 `data_schema.md` §5.11.1）。
- 一覧表示は `format_action_list_item`（`domain/config.py:404`）で `NN. [type] value: label`（正本 `features.md` §4.6「一覧の表示形式」）。
- 一覧の行をユーザーが選ぶと、その行が「次に実行」になる（`trigger_panel_controller.py:561`）。
  追加は末尾に追記（同 `:490`）・移動は隣と入れ替えて位置も移動先の行へ変える（同 `:541`・`:557`）・削除は 1 行（同 `:527`）。
- 一覧の再描画時に位置を補正する（単発実行は `% len`・連続実行は 0..len へ丸める。同 `:160` `refresh_actions`）。
- 実行位置は構成セットの読込等で `reset_indices`（`keymap_set_io.py:68` ほか・`trigger_set_file_io.py:264`）、
  キーマップ削除で `forget_trigger_set` / 代表の変更で `rekey_trigger_set`（`keymap_panel_controller.py:300-302`）、
  トリガー削除で個別に消える（`trigger_panel_controller.py:473`）。
- 同じ trigger_set を参照する複数のキーマップは runtime で 1 つの実体を共有し、実行位置は代表 id 単位（正本 `data_schema.md` §5.13.1）。
- 編集ダイアログの種別は `hotkey` / `text` / `mouse_click` の 3 択（`action_dialog.py:42`）。
- 関連する正本: `data_schema.md` §5.1（後方互換・型不正）/ §5.7（パス保存）/ §5.11（アクション要素）/
  `features.md` §4.2（シーケンス実行）/ §4.6（一覧の表示形式）。

## §2 確定事項（ユーザー 2026-09-26）

1. **system 種別を新設**し、次の操作を持つ: ループの始まり / ループの終わり / カウンター +1 / カウンターを 0 に / 待機 / 戻す / 先頭へ。
2. **system 種別は押下を消費しない**。単発実行では system アクションを即座に処理し、次の通常アクションまで進めてそれを実行する。
3. **ループ**: 始まりに回数を持つ。**既定 1・正の整数のみ**。**無限と回数指定は編集ダイアログのトグル**で切り替える。
   **ネストを許可**する。連続実行の停止・キーマップ切替でも**周回の状態は保持**する。
4. **ループの始まりと終わりは対で追加・対で削除**する。移動で対応が崩れる操作はできないようにする。
   手編集で対応が崩れた場合は、種別が不正なアクションと同じ扱い（エラーを通知してそこで止まる）。
5. **ループの周回は出力シーケンスの一覧に表示**する（ステータス欄ではない）。
6. **カウンター**: **名前付きで複数・アプリ全体で共有**（別のトリガー・別のキーマップのシーケンスからも同じ名前で参照）。
   **初期値 0・再起動で 0**（保存しない）。**現在値は出力シーケンスの一覧に表示**する。操作は **+1 と 0 に戻す** のみ。
7. **file_line 種別を新設**（system ではない独立の種別）: ファイルの「カウンター値の行」を文字列として入力する。
   **行番号は 1 始まり**。**範囲外の動作（エラーで停止 / 空を送る / 折り返し）と文字コード（UTF-8 / Shift_JIS）を編集で選ぶ**。
   実行のたびにファイルを読み直す。行末の改行は除く。空行は空文字。パスは既存と同じ保存規則（config 配下なら相対）。
8. **戻す / 先頭へ の対象は「直前に実行したトリガー」**（戻す・先頭へを置いたトリガー自身ではない。専用のトリガーから押す想定）。
9. **戻す = 直前の 1 ステップ（§4.1。system アクションの処理 + 通常アクション 1 つ）を始める前の状態まで丸ごと戻す**
   （位置・ループの周回・そのステップで動かしたカウンター）。
   押すたびに 1 段ずつ戻れる。位置 0 より前へは戻らない（0 のまま）。用途は単発実行での誤操作（alt+tab の行き先違い等）からの復帰。
10. **先頭へ** を実行したら戻す履歴は消す。
11. **待機**: 指定ミリ秒だけ待つ。単発実行では「押下 → 待機 → 次の通常アクションを実行」。
12. **ネストの色分け**: ループの始まりから終わりまでの行の背景に色を付ける。**色は深さで決め、深さごとに色相を変える
    （青 → 緑 → 橙）。3 色相を一巡したら濃さを 1 段上げる（薄 → 中 → 濃）。上限は 9 段**。**始まり・終わりの行も自分のループの色**。
13. **ジャンプ（任意位置へ）は作らない**（先へ進める操作は利用者の管理が煩雑。分割は第 2 弾の呼び出しで行う）。
14. **2 フェーズに分ける**: 第 1 弾（本フェーズ）= §2-1〜12 / 第 2 弾（次フェーズ）= 停止・他トリガー呼び出し（§13）。
15. カウンター条件の分岐は idea として起票するのみ（本フェーズ・第 2 弾ともスコープ外）。
16. **戻すときのカウンターは「値の書き戻し」ではなく「その操作の分だけ差し引く」**（+1 を戻す = −1 / 0 にしたのを戻す = 0 にする前の値を足す）。
    別のトリガーがその後に同じカウンターを動かしていても、その変更は消えない（§8）。カウンターは名前指定・アプリ全体共有のまま。
17. **単発実行の待機中も他のトリガーは使える**（待機中に他を無視する案は不採用）。同じトリガーの押下は待機が終わるか取り消されるまで無視し、
    取り消した待機の続きは後から動かない（§7）。
18. **file_line は 1 MB を超えるファイルを実行時エラー**にする（UI スレッドを長く塞がないため。§9）。
19. **追加ダイアログに「末尾に追加」のチェック欄**（既定 ON）。OFF なら一覧の選択行の直後へ追加する（全種別・ループは対で）。
    選択行が無ければ末尾。挿入しても「次に実行」の位置は元のアクションのまま・追加した行を選択状態にしない（§11.2）。
20. **通常アクションを実行した直後に、続く system アクションをその場で処理する**（先行処理・§4.1）。一覧の「次に実行」が system の行を指し、
    実際にはその前の通常アクションが実行される、というズレを無くすため（実機目視 2026-09-27）。待機・戻す・先頭へは先行処理しない（次の押下で処理）。
21. **トリガーの無効化（キーマップ一時停止）でも単発の待機を取り消す**（§7 の取り消し契機に追加）。
22. **連続実行を待機の途中で止めた（フック停止・無効化・UI 編集の一時停止）ときは、そのステップを戻す履歴に 1 段積み、位置は待機の行に残す**
    （単発の取り消しと同じ扱い。一時停止 → 再開は従来どおり待機の次から）。
23. **待機の取り消しで積む記録と、位置の変更・編集で履歴を消す規則がぶつかるときは、消す方を優先する**（利用者が位置を変えたら戻す履歴は意味を失うため）。
24. **system の実行時エラーの通知に、操作名と主な値（回数・ミリ秒・カウンター名）とラベルを含める**（§10 の「種類・値・ラベル」を system でも満たす）。
25. **カウンターの +1 / 0 に は、先行処理では位置だけ進め、値の変更は次の押下（そのトリガーの次のステップ）の開始時に反映する**（§4.1）。
    一覧の `(=値)` と file_line が参照する値は、直前に実行した通常アクションの時点の値（現在値）になる。ループの周回表示は v0.4 のまま（次に実行する周回）。
26. **戻す・先頭へ は、出力シーケンスにそれ 1 つだけの登録に限定する**。編集では、空のシーケンスにだけ追加でき、戻す・先頭へのあるシーケンスには他の行を追加できない。
    手編集で他の行と混ざっている場合は、その行に達したとき実行時エラーにする（§8.5・§11.2）。
27. **連続実行が末尾に達して停止するときは、保留中のカウンター操作をその場で反映する**（最後まで通り過ぎたため。§4.1）。
    その反映はその連続実行の最後のステップの差分として戻す履歴に入る。
28. **位置の変更・編集（§4.3）でそのトリガーの戻す履歴を消すとき、そのトリガーが直前のトリガーなら直前も消す**（実装どおり。戻せるものが無いため、
    戻すは「対象がありません」の一時メッセージになる）。
29. **file_line がネットワーク上のパスや応答しないドライブを読むと UI スレッドが止まる**ことは既知の制約とする（1 MB 上限では待ち時間を制限できない）。
    別スレッドでの読込は [idea_38](../backlog/idea_38_file_line_async_read.md) として次フェーズで対応する。

## §3 データモデル（actions[] の要素）

`data_schema.md` §5.11 の表へ種別を 2 つ加える。既存の種別・キーの意味は変えない（新しい種別の追加のみ）。

### §3.1 system

| `op` | キー | 意味 |
|---|---|---|
| `loop_start` | `count` / `infinite` / `label` | ループの始まり。`count` = 周回数（1 以上の整数）/ `infinite` = true で無限 |
| `loop_end` | `label` | ループの終わり |
| `counter_inc` | `counter` / `label` | カウンター `counter` を +1 |
| `counter_reset` | `counter` / `label` | カウンター `counter` を 0 にする |
| `wait` | `ms` / `label` | `ms` ミリ秒（1 以上の整数）待つ |
| `back` | `label` | 直前のトリガーを 1 段戻す（§8） |
| `rewind` | `label` | 直前のトリガーの位置を先頭へ（§8） |

- 形: `{"type": "system", "op": "loop_start", "count": 3, "infinite": false, "label": ""}`。
- `op` / `counter` は §5.1 の型不正の規則に従う（非文字列は空扱い・trim・`op` は大文字小文字を区別しない）。
  **カウンター名は大文字小文字を区別する**（trim のみ。`N` と `n` は別のカウンター）。
- `infinite` の真偽は `bool(infinite)`（ドラッグの `drag` と同じ）。**無限でも `count` は保存に残す**（トグルを戻したとき元の回数に戻すため）。
- `count` / `ms` は `int()` 変換で判定する（`"3"` は受け入れる）。変換不能・1 未満は**実行時エラー**（黙って 1 へ補正しない。§10）。
- 読込時の正規化は既存の §5.11 と同じ（非 dict の除去・未定義キーの無視）で、**新しいキーの補完はしない**。

### §3.2 file_line

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `path` | str | — | 読むファイル。保存・解決は `data_schema.md` §5.7 に従う（config 配下は相対） |
| `counter` | str | — | 行番号に使うカウンター名 |
| `encoding` | str | `utf-8` | `utf-8` / `shift_jis`（大文字小文字は区別しない）。**それ以外は実行時エラー** |
| `out_of_range` | str | `error` | `error` / `empty` / `wrap`。**それ以外は実行時エラー** |
| `label` | str | `""` | 一覧表示用 |

- `path` は**参照元の管理（保存計画・孤児棚卸し・参照元記録）の対象外**。アプリが書き込むファイルではないため。
- キーが無いときは既定値で実行する。キーを補完して保存はしない。

## §4 実行モデル

### §4.1 通常アクションと system アクション

- **通常アクション** = hotkey / text / mouse_click / file_line（入力を送るもの）。**system アクション** = §3.1。
- **1 ステップ** = 今の位置から system アクションを順に処理し、最初に出会った通常アクションを 1 つ実行するまで。
  - 単発実行: 1 押下 = 1 ステップ。
  - 連続実行: 1 ステップごとに間隔 `run_to_end_delay_ms` を置く（system アクションの処理には間隔を置かない）。待機は §7。
- system アクションは、ステップの開始時（今の位置から通常アクションまで）に加え、**通常アクションを実行した直後にも、続く system を先に処理する**（先行処理・§2-20）。
  - 先行処理するのは **ループの始まり / 終わり・カウンター +1 / 0 に** だけ。**カウンターの行は値を変えずに位置だけ進め、その操作を「保留」として
    トリガーごとに控える**（§2-25）。保留した操作は、そのトリガーの次のステップの開始時（system の処理より前）に順に反映し、そのステップの差分として記録する。**待機・戻す・先頭へ・対応崩れ等のエラーになる行**に達したら、処理せずにその行で止める
    （次の押下で通常どおり処理する。エラーはそのとき通知する）。10,000 の上限に達した場合も、そこで黙って止める。
  - 先行処理で末尾に達したら位置 0・周回を空にする。単発実行ではその押下でまだ先頭へ回っていなければ、先頭から同じ規則で続ける
    （先頭の system も処理され、「次に実行」は最初の通常アクションを指す）。連続実行では停止する（先頭は処理しない）。
  - 先行処理はそのステップに含める（戻す履歴の 1 段 = 通常アクション + その直後の先行処理。§8.1）。
  - 先行処理は**次のステップの準備**なので、「この押下の開始位置に達したら終える」規則（下記）の対象外とする（先頭へ 1 度だけ回る制限と 10,000 の上限は適用）。
    例（v0.5）: `[カウンター+1, A]` を単発で押すと、1 回目 = n=1 で A → 先行処理で位置は A・+1 は保留（表示は n=1）/
    2 回目 = 開始時に保留を反映して n=2 で A → 再び保留（表示は n=2）。A を実行するときの n と表示が実行回数と一致する。
    戻すと、位置・周回・保留をステップ開始時に戻し、そのステップで反映した差分を打ち消す（例: 1 回目を戻すと n=0・位置 0・保留なし）。
  - これにより「次に実行」の選択は、通常アクション・待機・戻す・先頭へ・エラーの行のいずれかを指す（初期状態や位置を手で変えた直後は system の行もあり得る）。
- **末尾に達したとき**（位置が len になったとき。通常アクションの実行直後を含む）は、**単発・連続とも位置を 0 にし、周回スタックを空にする**
  （位置 len は持ち越さない）。そのうえで:
  - 単発実行: 通常アクションをまだ実行していなければ、**同じ押下の中で先頭から続ける**（従来の「末尾の次は先頭」と同じ感覚にするため）。
    先頭へ回った後に**この押下の開始位置へ達したら、その行は処理せずに終える**（位置は開始位置のまま）。
    これで、ループによる再訪を除き 1 回の押下で同じ行を 2 度処理しない（例: `[back]` だけのトリガーは 1 押下で 1 段だけ戻す）。
  - 連続実行: 従来どおり停止する。
- **暴走の防止**: 1 ステップで処理する system アクションが **10,000 個**を超えたら実行時エラーにしてそこで止める
  （例: 本体に通常アクションが無い無限ループ）。**待機をまたいでも通算する**。

### §4.2 トリガーごとの runtime 状態

実行位置と同じ単位（トリガー一覧 ID + トリガーキー）で次を持つ。**保存しない**。

- **ループの周回スタック**: 実行中のループごとに「始まりの位置・周回数（何周目か）」。
- **戻す履歴**: §8.1 のスナップショットの列（**上限 100 段**。超えたら古いものから捨てる）。
- **保留中のカウンター操作**: 先行処理で通り過ぎたカウンターの行の操作の列（§4.1・§2-25）。

アプリ全体で次を持つ。**保存しない**。

- **カウンター**: 名前 → 整数。未使用の名前は 0 として扱う。
- **直前のトリガー**: **最後に戻す履歴へ 1 段積んだトリガー**（トリガー一覧 ID + キー。§8.1。エラーで止まったステップも含む）。
  状態を何も変えなかったステップ（例: `[back]` だけのトリガー）は更新しない。

### §4.3 周回スタックの整合

一覧で行を選んで位置を変えた / シーケンスを編集した等で、周回スタックが今の位置・ループの対応と合わなくなることがある。
**ステップの開始時に検証し、合わなければ「今の位置を囲むループを周回 1 周目として張り直す」**。
- **合う** = 周回スタックの始まりの位置の列が、今の位置を囲むループの始まりの位置の列（外側から順）と一致すること。
  **ループの終わりの行はそのループの内側、始まりの行は外側**として数える。
- アクション列の対応が崩れているとき（手編集）は張り直さない（到達した行で §5.3 のエラーになる）。
- **一覧で行を選んで位置を変えたとき**は、そのトリガーの周回スタックを張り直し、戻す履歴を消す。
  同じループの中の行を選んでも周回は 1 周目に戻る（§2-3 の「保持」は実行の中断に対するもので、手で位置を変えた場合は含まない）。
- **シーケンスを編集したとき**（追加・編集・削除・移動）は、編集したトリガーの周回スタックを張り直し、戻す履歴を消す。
- 位置の変更・編集は、**実際に位置や内容が変わったときだけ**扱う（一覧のフォーカス同期などで同じ行が選び直されただけなら何もしない）。
- 待機の取り消しで 1 段積む規則（§7）とぶつかるときは、**履歴を消す方を優先する**（§2-23）。そのトリガーが直前のトリガーなら直前も消す（§2-28）。

### §4.4 runtime 状態の生存期間

- 周回スタック・戻す履歴・**保留中のカウンター操作**（§4.1・§2-25）は、**実行位置（indices）と同じ契機で消す・付け替える**:
  `reset_indices`（構成セットの読込等）/ `forget_trigger_set` / `rekey_trigger_set` / トリガーの削除・キーの変更。
- 直前のトリガーも同じ契機で消す（`rekey_trigger_set` では新しい id へ付け替える）。
- **カウンターだけは消さない**（§6）。
- 保留中のカウンター操作は、位置の変更・編集（§4.3）と先頭へ（§8.3）でも消す。戻す（§8.2）では、そのステップ開始時の保留に戻す
  （ステップの開始時に保留も控え、差分の打ち消しと合わせて復元する）。

### §4.5 表示との分離

- 一覧の表示（§11.3）は周回・カウンターの runtime の値を使うが、`domain` の整形関数は値を**引数で受け取る純粋関数**のままにする
  （domain が application の状態を参照しない）。

## §5 ループ

### §5.1 対応の判定

- 始まりと終わりの対応は**括弧の対応**で決める（始まりに ID は持たせない）。対応はステップのたびにアクション列から求める。
- 深さ = 外側から数えたループの入れ子の数（一番外のループの行 = 深さ 1）。**上限 9**。

### §5.2 動作

- **始まり**に到達: 周回スタックに「この始まり・1 周目」を積み、次の行へ進む。
- **終わり**に到達: 対応する始まりのフレームについて、
  - 周回数 < `count`（または無限）なら周回数 +1 して**始まりの次の行**へ戻る。
  - そうでなければフレームを降ろして**終わりの次の行**へ進む。
- 周回の状態は、連続実行の停止・一時停止・キーマップの切替・エラーで止まったときも保持する（§2-3）。
- 位置が先頭へ戻る（末尾に達した / 先頭へ）と周回スタックは空になる（§4.1）。

### §5.3 実行時エラー（そこで止まる）

- 対応する終わりが無い始まり・対応する始まりが無い終わり（その行に到達したとき）。
- 深さ 9 を超える始まり（その行に到達したとき）。
- `count` が変換不能・1 未満（無限でないとき）。

## §6 カウンター

- `counter_inc` = +1 / `counter_reset` = 0。上限なし。
- カウンター名が空なら実行時エラー。
- 値は**アプリの起動中だけ**保持する（構成セットの読込やキーマップの切替では消さない）。

## §7 待機

- 連続実行: 待機の行を処理したら、その `ms` 後に続きを実行する（間隔 `run_to_end_delay_ms` とは別。待機の直後に間隔は足さない）。
  一時停止すると残りの待機は捨て、再開時は通常の間隔の後に続きから実行する。
- 単発実行: `after()` で待ち（UI スレッドを塞がない）、待ち終わったら同じステップの続きを実行する。
  - **待機中の同じトリガーの押下は無視**する。既存の再入防止（`reentry_guard`）は同期処理の終わりで解除されるため、
    **待機中のステップはトリガーごとに「保留中」として持ち、完了・エラー・取り消しまで同じトリガーの新しいステップを始めない**。
    **他のトリガーの単発実行は通常どおり動く**（§2-17）。
  - 待機の続き（`after()` で予約した処理）は**世代番号**を持ち、取り消し後やトリガーの状態が変わった後に呼ばれても、
    番号が合わなければ何もしない（取り消した待機の続きが後から入力を送らないようにする）。
  - 次のいずれかが起きたら**待機を取り消す**。位置は**待機の行に残る**（次の押下で待機からやり直す）:
    フック停止（停止キー・停止ボタン。**UI 編集中の一時停止も含む**）/ **トリガーの無効化（キーマップ一時停止・§2-21）** / キーマップの切替 /
    対象トリガーの位置の変更（一覧で行を選ぶ）/
    対象トリガーのシーケンスの編集・トリガーの削除 / §4.4 の runtime 状態を消す契機（構成セットの読込等）/
    **他のトリガーの連続実行の開始**（連続実行中は他を無視する現行仕様と交錯させないため）。
  - 取り消しまでに処理した system アクションの影響（カウンター等）は残り、戻す履歴に 1 段積む（§8.1）。
- 連続実行の一時停止では残りの待機を捨てて次へ進み、単発実行の取り消しでは待機の行からやり直す。この非対称は意図どおり
  （連続実行は再開を利用者が明示的に選ぶ操作・単発実行の取り消しは利用者の意図しない中断のため）。
- **連続実行を待機の途中で停止した**（フック停止・トリガーの無効化・UI 編集の一時停止）ときは、単発の取り消しと同じく
  **そのステップを戻す履歴に 1 段積み、位置は待機の行に残す**（§2-22。利用者の意図しない中断のため待機からやり直す）。
- `ms` が変換不能・1 未満なら実行時エラー。

## §8 戻す・先頭へ

### §8.1 戻す履歴

- **ステップの開始時**に、そのトリガーの「位置・周回スタック・保留中のカウンター操作」を控える。ステップ中にカウンターを変えたら、
  **その操作を順に控える**（`counter_inc` = 「+1 した」/ `counter_reset` = 「k を引いた」。k = 0 にする前の値）。
- **ステップの終了時**（通常アクションの実行後・エラーで止まったとき・待機の取り消し時）に、開始時と比べて
  **何か状態が変わっていたら**（位置・周回・保留・カウンターのいずれかに差分がある）、控えを履歴へ 1 段積み、直前のトリガーをこのトリガーにする。
  例: `[A, カウンター+1]` の単発 1 回目は、位置 0→0・カウンターの差分なし・保留だけが増えるが、状態が変わったので積む。
  エラーで止まったステップも積む（止まる前に処理した system アクションの影響も戻せるようにするため）。
- **back / rewind が対象に対して行った変更**（位置・周回・カウンターの書き戻し）は、back / rewind を実行したトリガーの変更として数えない
  （そのトリガーの履歴に積まず、直前のトリガーも変えない）。

### §8.2 戻す（`back`）

- 対象 = **直前のトリガー**。対象の履歴から 1 段降ろし、位置・周回スタック・保留を控えた状態へ戻す。
  - カウンターは**控えた操作を逆順に打ち消す**（+1 した → −1 / k を引いた → +k。§2-16）。
    別のトリガーがその後に同じカウンターを動かしていても、その変更は残る
    （例: A が n を 0→1、B が 1→2、A を戻す → n = 1。A が 5→0、B が 0→1、A を戻す → n = 6）。
  - 打ち消した結果が負になっても、そのままにする（0 へ丸めない。差分の整合を保つため）。
- 履歴が空なら何もしない（位置 0 のまま等）。
- 戻したら対象のトリガーを一覧で選択し、「次に実行」の行を表示する（どこへ戻ったか見えるように）。
  **この選択は、押したトリガー（back を持つトリガー）の選択より後に行う**（runner が押したトリガーを選択して上書きしないように）。

### §8.3 先頭へ（`rewind`）

- 対象 = 直前のトリガー。位置を 0 にし、周回スタック・保留・戻す履歴を消す（§4.4）。**カウンターは変えない**（必要なら `counter_reset` を併用する）。
- 対象を一覧で選択する（§8.2 と同じ）。

### §8.4 対象が無いとき

次の場合は何もせず、**ステータスバー中央の一時メッセージ領域**に「戻す対象のトリガーがありません」等を出す（エラーにはしない・止めない）。
- 直前のトリガーがまだ無い / 直前のトリガーが**戻す・先頭へを実行したトリガー自身**。
- 直前のトリガーが**アクティブなトリガー一覧に無い**（キーマップを切り替えた後・トリガーが削除された後）。
- 直前のトリガーが**単発実行の待機中**（§7）。

※ 連続実行中は他のトリガーの押下が無視される（現行仕様）ため、連続実行中の対象を戻すことは起きない。

### §8.5 単独登録の制限（§2-26）

- 戻す・先頭へ は、出力シーケンスにそれ 1 つだけを登録して使う（専用のトリガーから押す想定）。編集での制限は §11.2。
- 手編集等で、戻す・先頭へ の行を含むシーケンスに他の行がある場合は、**その行に達したとき実行時エラー**（§10。「戻す・先頭へは単独で登録してください」等）にして止まる。
- 受容する挙動: 戻す・先頭へ だけのトリガーを連続実行（run_to_end）にすると、開始時に他のトリガーの単発の待機を取り消す（§7）ため、
  対象が待機中でも取り消しの記録を積んだ直後に戻すことになる。

### §8.6 受容する境界（v0.6）

- 本体に通常アクションが無い無限ループにカウンター操作があると、先行処理が 10,000 の上限まで回って保留が多数たまり、次の押下でまとめて反映した後に上限エラーになる
  （v0.4 でも値は同じだけ増えていた。手編集・誤設定の範囲として受容）。

## §9 file_line（ファイルの行を入力）

- 実行のたびにファイルを読む。**1 MB（1,048,576 バイト）を超えるファイルは読まずに実行時エラー**（§2-18。UI スレッドを長く塞がないため）。
  `encoding` で復号する（`utf-8` は先頭の BOM を除く / **`shift_jis` は cp932 で復号する**。
  Windows で作ったファイルの ①・〜 等の拡張文字を読めるようにするため。表示・保存値は `shift_jis` のまま）。
- 行の分割: **`\r\n` / `\r` / `\n` のみ**を改行として分ける（`str.splitlines()` は他の制御文字でも分けるため使わない）。
  **最後の改行の後ろは行に数えない**。各行の改行文字は含めない。
- 行番号 = カウンター `counter` の値（1 始まり）。行数を L とする。
  - 1 ≦ n ≦ L: その行を送る。
  - 範囲外（n ≦ 0 または n > L）:
    - `error` → 実行時エラー。
    - `empty` → 何も送らずに成功扱いで次へ進む。
    - `wrap` → `((n - 1) mod L) + 1` 行目を送る（n = 0 は L 行目）。**L = 0（空ファイル）は実行時エラー**。
- 送信は text 種別と同じ経路・同じ send guard（`data_schema.md` §5.11.1）。空文字の行は何も送らずに成功扱い。
- 実行時エラー: ファイルが無い・読めない・1 MB 超・復号できない / `counter` が空 / `encoding`・`out_of_range` が不正 / 上記の範囲外。

## §10 実行時エラーの共通規則

- 本書で「実行時エラー」とするものは、**種別が不正なアクションと同じ扱い**（`data_schema.md` §5.11.1）:
  送信エラーを通知（種類・値・ラベルを含める）し、**そこで止まる**（連続実行は停止・単発は次へ進まない）。
  **位置はエラーの行に残る**。
- `system` の `op` が空・未定義の値も同じ扱い。
- system の通知には**操作名（`op`）・主な値（ループは回数と無限、待機はミリ秒、カウンター系はカウンター名）・ラベル**を含める（§2-24。
  system には `value` が無いため、通知の「値」欄が空にならないようにする）。
- 旧ビルド（system / file_line を知らない読み手）は、既存の規定により種別が不正なアクションとして止まる（受容）。

## §11 編集 UI と一覧表示

### §11.1 編集ダイアログ

- 種別に `system` と `file_line` を加える。
- system は操作を選ぶ（表示は日本語: ループ / カウンター +1 / カウンターを 0 に / 待機 / 戻す / 先頭へ）。
  - ループ: 回数（既定 1・1 以上の整数のみ。不正は入力エラーで閉じない）と「無限」のチェック（ON で回数欄を無効化）。
  - カウンター系: カウンター名（空は入力エラー）。**既知の名前を候補に出す**（編集可能なドロップダウン。候補 = 起動中のカウンターと、
    アクティブなトリガー一覧のシーケンスに現れる名前）。
  - 待機: ミリ秒（1 以上の整数のみ）。
- file_line: ファイル（入力欄 + 参照ボタン）/ カウンター名（候補は上と同じ）/ 文字コード（UTF-8 / Shift_JIS）/
  範囲外（エラーで停止 / 空を送る / 折り返し）。ファイルの存在は保存時に検査しない（実行時に判定）。
- **ループの行の編集**: 始まり・終わりのどちらを開いても**対の始まりの設定**（回数・無限・ラベル）を編集する。
  ループの行では種別・操作を変更できない。**他の行をループへ変える操作は選択肢に出さない**（ループは追加でのみ作る）。

### §11.2 追加・削除・移動

- **追加の位置**（全種別・§2-19）: 追加ダイアログの**「末尾に追加」チェック欄（既定 ON・開くたびに ON）**で決める。
  - ON: 末尾へ追加（従来どおり）。
  - OFF: 一覧の**選択行の直後**へ挿入する。選択行が無ければ末尾。
  - 挿入しても**「次に実行」の位置は元のアクションを指したまま**（挿入位置が位置以前なら位置をずらす）。追加した行は選択状態にしない
    （選択行は実行位置を兼ねるため）。編集として §4.3 を適用する（周回の張り直し・戻す履歴の消去）。
  - 編集（既存行の変更）のダイアログにはこのチェック欄を出さない。
  - ネストの作り方の例: `[S1, A, B, E1]` で A を選び、OFF でループを追加 → `[S1, A, S2, E2, B, E1]`。B を内側へ入れるには E2 を 1 つ下へ移動する。
- **ループの追加は、始まりと終わりを対で挿入**する（上の位置規則に従う。対の間は空）。
  **挿入すると深さが 9 を超える場合は追加しない**（理由を示す。実行時エラーに任せない）。
- **ループの行を削除すると、対の行も一緒に削除**する（中の行は残す）。確認文でその旨を示す。
- **戻す・先頭へ は単独登録に限る**（§2-26）: 空でないシーケンスへは追加しない（追加ダイアログで選べても、OK 時に理由を示して追加しない）/
  戻す・先頭へ のあるシーケンスには他の行を追加しない / 既存の行を編集して戻す・先頭へ に変える操作は、シーケンスがその 1 行だけのときに限る。
- **移動**: ループの行（始まり・終わり）は**ループ以外の行とだけ入れ替えられる**（他のループの行と入れ替わる移動はしない）。
  これで始まりと終わりの順序・入れ子の構造は移動で崩れない。通常の行はループの内外へ自由に移動できる。
  - 受容する制約: ループどうしの順序の入れ替えや、入れ子の出し入れは移動ではできない（中身を動かす・作り直す）。
  - 対応が崩れていてもループの行として同じ規則を適用する。
  - 不採用とした代替案: 「対応が崩れない限りループの行どうしの入れ替えを許す」。括弧の対応で組み合わせが入れ替わり、
    回数の設定が別のループへ移ってしまうため。
- **対応が崩れたループの行**（手編集）: 削除はその行だけを消す。編集ダイアログは開かず、対応が崩れている旨を示す
  （対応の無い終わりには編集する設定が無いため。直すには削除して追加し直す）。

### §11.3 一覧の表示

`NN. [<表示名>] <値>: <label>` の形（既存の形式を保つ）。

| 行 | 表示例 |
|---|---|
| ループの始まり（実行中でない） | `[loop] ×3` / `[loop] ×∞` |
| ループの始まり（実行中） | `[loop] 2/3` / `[loop] 2/∞`（周回 / 回数） |
| ループの終わり | `[loop_end]` |
| カウンター +1 / 0 に | `[count+1] n (=5)` / `[count=0] n (=5)`（括弧内は現在値） |
| 待機 | `[wait] 500ms` |
| 戻す / 先頭へ | `[back]` / `[rewind]` |
| file_line | `[file_line] list.txt #n (=5)`（ファイル名 + カウンター名 + 現在値） |

- 周回・カウンターの値は、ステップの実行後と一覧の再描画時に更新する。
- 省略表示のステータス（「次に実行」の要約）も同じ表示名を使う。

### §11.4 ネストの色分け

- ループの始まりから終わりまでの行（始まり・終わりを含む）の背景を、**その行を囲む最も内側のループの深さ**の色にする。ループの外の行は色なし。
- 深さ → 色: 1 青・薄 / 2 緑・薄 / 3 橙・薄 / 4 青・中 / 5 緑・中 / 6 橙・中 / 7 青・濃 / 8 緑・濃 / 9 橙・濃。
  **濃でも黒い文字が読める明るさに留める**。具体的な色値は実装で決めて codebase_map に記録する。
- 選択行はリストボックスの選択色が優先する（既定の見え方のまま）。
- 対応が崩れた行（手編集）には色を付けない。

## §13 第 2 弾の予定（次フェーズ・本フェーズでは実装しない）

対話で方針を合意済み。詳細は次フェーズの暫定仕様で詰める。
- **停止**（system）: 連続実行をそこで止め、位置は停止の次に置く。次の押下で続きをまた連続実行する（区切り）。単発実行では読み飛ばす。
- **他トリガーの呼び出し**（system）: **同じトリガー一覧の中のトリガーキーで参照**する。呼び出し先を**先頭から末尾まで一括で連続実行**して戻る
  （呼び出し先トリガーの実行位置は変えない。単発実行でも 1 押下で丸ごと実行）。**循環は編集時に拒否し、実行時も検出したらエラーで停止**。
  参照先が無くなったら一覧で「参照先なし」を示し、実行時はエラーで停止する。一覧は `[call] F5: <呼び出し先のラベル>`。

## §14 受け入れ条件（ドラフト）

1. system（7 操作）と file_line を JSON で保存・読込でき、既存の種別・既存ファイルの読込結果が変わらない（§3）。
2. 単発実行で system アクションが押下を消費せず、次の通常アクションまで進んで実行する。通常アクションの直後に続く system を先行処理し、
   「次に実行」が system（待機・戻す・先頭へを除く）の行を指さない（§4.1・§2-20。初期状態・手で位置を変えた直後・エラーの行・10,000 の上限・連続実行の終了後の先頭は例外）。末尾から先頭へ回った後は開始位置で終え、
   1 押下で同じ行を 2 度処理しない（§4.1）。周回スタック・戻す履歴・直前が §4.4 の契機で消える / 付け替わる。
3. ループが回数どおり・無限で回り、ネスト（深さ 9 まで）が正しく動く。停止・キーマップ切替の後も周回が保持される（§5）。
4. 対応が崩れた・深さ超過・回数不正のループ、10,000 超の system 処理が実行時エラーで止まり、位置がその行に残る（§4.1・§5.3・§10）。
5. カウンターが名前ごとにアプリ全体で共有され、+1 / 0 に が効き、再起動で 0 になる（§6）。
6. file_line が 1 始まりの行を UTF-8 / Shift_JIS（cp932 の拡張文字を含む）で送り、範囲外 3 種が規定どおり動く（§9）。
7. 待機が連続・単発の両方で UI を塞がずに待ち、単発の待機中の再押下を無視し、§7 の各契機で取り消される（位置は待機の行）。
   連続実行の待機中の停止も 1 段積んで待機の行に残る。一覧のフォーカス同期だけでは取り消されない（§7・§4.3）。
8. 戻すが位置・周回・カウンターを 1 段ずつ戻し、先頭へが位置 0・履歴消去になり、対象が無いときは一時メッセージのみ（§8）。
9. 編集ダイアログで各種別を作成・編集でき、「末尾に追加」の ON / OFF で追加位置が変わり（実行位置は不変）、
   ループの対での追加・削除と移動規則が守られる（§11.1・§11.2）。
10. 一覧に周回・カウンターの値が表示され、ネストの色分けが深さどおりに付く（§11.3・§11.4）。
11. 既存テスト（`tests/` ・ `tests_ui/` ・ smoke）が通る。
12. 先行処理でカウンターの行は保留になり、次の押下の開始時に反映される。一覧の `(=値)` と file_line の参照値が現在値になる。戻す・先頭へ・位置変更で保留も扱われる。
    連続実行の停止時は保留を反映する（§2-25・§2-27）。
13. 戻す・先頭へは編集で単独登録に限られ、混在は実行時エラーで止まる（§2-26・§8.5）。
