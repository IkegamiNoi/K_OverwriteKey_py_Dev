## §1 目的 / 背景

フル表示のメイン領域（**キーマップ管理 | トリガー一覧 | 出力シーケンス**）について、
①アプリ幅を変えたときに伸縮する枠を**出力シーケンスからトリガー一覧へ移す**
②**境界線のドラッグでキーマップ管理・出力シーケンスの幅を変えられる**ようにする
③**変えた幅を保存し、再起動後も復元する**。

## §2 確定事項（ユーザー 2026-09-16）

1. **アプリ幅を変えたときに伸縮するのはトリガー一覧**（キーマップ管理・出力シーケンスの幅は変わらない）。
2. **境界線は 2 本**（キーマップ管理 | トリガー一覧 / トリガー一覧 | 出力シーケンス）。**ドラッグで幅を変える**。
3. **ドラッグの差分はトリガー一覧が吸収**する（ウィンドウ幅は変えない）。
4. **一覧（リストボックス）も枠に合わせて横に広がる**（3 枠すべて）。
5. **各枠の最小幅 = 中身が切れない幅**。**一覧の最小文字数は 10 文字相当**（v0.2）。
   フォントサイズを変えて最小幅が表示幅を上回ったら最小幅へ引き上げる。
6. **フル表示中は、トリガー一覧が最小幅に達したらそれ以上ウィンドウを狭められない**。
   ウィンドウ最小幅 = **両端の表示幅 + トリガー一覧の最小幅**（+ サッシュ・余白）。**両端の枠はウィンドウ縮小で縮まない**（v0.2）。
   **省略表示の幅には影響させない**。
7. **幅を保存し、再起動後も復元する**。保存先は `config/config.json`、**書き込みは `write_startup` を通す**。
8. **保存のタイミングはドラッグを離したとき**。
9. **希望幅と表示幅を分ける**（v0.2）。**保存するのはドラッグした境界線に接する側の枠の希望幅だけ**。
   自動で広げた・縮めた表示幅は保存しない。**条件が戻れば（フォントを戻す等）希望幅で表示する**。
10. **既定幅は現状と同じ見た目**（v0.2）。
11. **収まらない場合はウィンドウを広げる。画面幅を超えるなら出力シーケンス → キーマップ管理の順に表示だけ縮める**
    （保存値は変えない）。起動時・フォント変更時・フル表示へ戻るときに適用（v0.2）。
12. **マウス中ボタンでの境界線ドラッグは無効**（v0.2）。
13. **フル表示時のウィンドウ幅も保存し、再起動後に復元する**（v0.4・ユーザー 2026-09-17 = 案 A）。
    トリガー一覧の幅はウィンドウ幅から決まるため、両端の幅だけでは再起動後に意図した幅にならない。
    **高さ・位置は保存しない**。保存は**ウィンドウ幅が変わったとき（500ms 間引き）**（v0.5。v0.4 の「ドラッグを離したとき・終了時」は廃止）。
14. **ドラッグ中に、幅の変わらない部品（出力シーケンスのボタン列等）を再配置に巻き込まない**（v0.4・ユーザー 2026-09-17）。
    方式は**移動イベントの間引き（案 L・ユーザー確定）**。詳細は §3-2。

## §3 設計

### §3-1 レイアウトの構成

- **`tk.PanedWindow`（横）に 3 枠を入れる**。`paneconfigure` で **両端は `stretch="never"`、
  トリガー一覧は `stretch="always"`**。ウィンドウ幅の増減はトリガー一覧だけが受ける（§2-1）。
  見た目は `sashrelief` / `sashwidth` / 背景色で既存テーマに合わせる（`ttk` 版は無い）。
- 代替（案 B: grid + 自前の仕切り Frame）は押し出し・潰れの制御を自前で持つ点が同じで可動部が増えるため採らない。
- `FullView` は「Widget の生成と配置のみ」の責務を保つ。**幅の算出・可動範囲の制限・保存・復元・
  ウィンドウ最小幅の更新は専用のコントローラ**（例: `controllers/pane_layout_controller.py`）へ置く。
  値の検証・クランプ等の**純粋な計算は tkinter 非依存の関数**に分け、`tests/` で単体テストできる形にする
  （配置は実装タスクで確定）。

### §3-2 ドラッグ（可動範囲の制限・§2-2・§2-3・§2-12）

- `PanedWindow` の標準バインドは、隣の枠が `minsize` に達すると**反対側の枠まで押し縮める**（実測）。
  → **サッシュのドラッグをコントローラの個別バインドで処理し `"break"` で標準処理を止める**。
  - サッシュ 0 の位置 = キーマップ管理の幅。可動範囲 = **[キーマップ管理の最小幅, 出力シーケンスの表示幅と
    トリガー一覧の最小幅を残せる位置]**。サッシュ 1 も対称。**ドラッグ中にウィンドウ幅・反対側の枠は変わらない**。
- **中ボタン（`<Button-2>` / `<B2-Motion>` / `<ButtonRelease-2>`）は `"break"` で無効化**。
- **保存の契機はサッシュ上で始まったドラッグの `<ButtonRelease-1>` だけ**（ドラッグ中フラグで絞る）。
- **ドラッグ中の表示（v0.4・§2-14）**: 現状はマウスの移動ごとに `paneconfigure(width=)` で枠の幅を変えており、
  出力シーケンスの枠（サッシュ 1）は左端が動くたびに見出し・一覧・スクロールバー・ボタン列の子ウィンドウがまとめて再配置される
  （ユーザー観察 = ボタン列が巻き込まれて見える。**原因は推定**: 子の位置は枠の左端基準のため、左端が動くと右寄せのボタン列も毎回動かし直される）。
  **ユーザー確定 = 案 L（ライブ表示のまま移動イベントを間引く）**:
  - `<B1-Motion>` では**最新のマウス位置を記録するだけ**にし、未予約なら `after_idle` で適用処理を 1 回予約する。
    適用処理は記録済みの最新位置から可動範囲（`drag_limits` + `clamp`）で幅を求め `paneconfigure(width=)` する。
    → **アイドル 1 回につき幅の適用は高々 1 回**（連続した移動イベントをまとめる）。
  - `<ButtonRelease-1>` では、予約中の適用があれば**取り消して即時に適用してから**希望幅の更新（§3-5）を行う（最後の位置を取りこぼさない）。
  - 次の押下でドラッグ状態を捨てるとき（task_05b F5）は、予約中の適用も取り消す。
  - 手触り（幅がマウスに追従する）は変えない。子の再配置は残るため、効果は task_05c の実機目視で確認する。
  - 不採用: 案 P（プロキシ表示 = 離したときに幅が変わる）/ 案 S（ボタン列を枠外の独立区画にする = 見た目が変わる）。

### §3-3 一覧を枠に合わせて広げる（§2-4）

- `KeymapBox` / `FullTriggerBox` の**一覧とその親フレーム**を `fill="both", expand=True` へ変える。
  `width=26` は既定幅の算出に使うだけで、最小幅の拘束にはしない（§3-4）。
- `SequenceBox` の一覧は既に伸びる。ボタン列・縦方向の振る舞い（高さ・縦スクロール）は変えない。

### §3-4 最小幅・ウィンドウ最小幅・省略表示との関係

- **枠の最小幅**（v0.3）= **一覧を 10 文字相当にしたと仮定した枠の要求幅**を、**部品の並び方に応じて**算出する:
  - **一覧行の幅** = 一覧 10 文字分（一覧のフォントで `font.measure("0") × 10` + 一覧の枠線・内側余白）+ 縦スクロールバーの要求幅。
  - **縦に並ぶ部品（KeymapBox / FullTriggerBox）**: 最小幅 = **max(一覧行の幅, 他の子〔ボタン群・チェックボックス等〕の要求幅)**
    + LabelFrame の内側余白（`padding`）・枠線。
  - **横に並ぶ部品（SequenceBox）**: 最小幅 = **一覧行の幅 + ボタン列の要求幅 + その間の余白（`padx`）**
    + LabelFrame の内側余白・枠線。
  - いずれも **見出し（LabelFrame のテキスト）の要求幅 + 左右の枠線・余白との max** を取る（見出しを切らない）。
  - **減算で求めない**（v0.2 の「枠の要求幅 − 一覧の要求幅 + 10 文字」は、チェックボックスが最広の枠で切れる幅を許した）。
  - 一覧の width を一時的に書き換えて測らない（ちらつき防止）。**フォント設定ごとに再計算する**。
  - 実測上、トリガー一覧・出力シーケンスはチェックボックス / 見出し・ボタン列で決まり、**実際に現状より狭くできるのは
    キーマップ管理だけ**（§2-5 の確定時に了承済み）。
- **ウィンドウ最小幅**（フル表示中のみ）= **両端の表示幅 + トリガー一覧の最小幅 + サッシュ幅・余白**。
  高さは制約しない（`wm minsize` の高さは 1）。**更新契機** = ドラッグを離したとき / 復元時 / フォント変更後 /
  フル表示へ戻ったとき。
- **省略表示へ入るとき**: `wm minsize` を**解除してから**幅 270 の geometry を当てる（`_apply_compact_geometry` より前）。
- **省略表示中のフォント変更**: 最小幅の再計算・`wm minsize` の設定を**しない**（再計算が必要という印だけ持つ）。
  **フル表示へ戻ったとき**（`_restore_full_geometry` の後）に再計算し §3-7 を適用する。
- ヘッダ領域（フック / 表示 / ファイル操作）の要求幅が上記より大きい場合にヘッダが切れるのは**既存の挙動のまま**（§6）。

### §3-5 希望幅と表示幅（§2-9）

- コントローラは両端の枠について **希望幅**（保存値 or 既定幅。ユーザーの意図）と **表示幅**（実際の幅）を分けて持つ。
- **表示幅** = 希望幅を最小幅以上へ引き上げ、§3-7 の画面幅規則で縮めた値。
- **ドラッグを離したとき**: 動かしたサッシュに接する側の枠（サッシュ 0 = キーマップ管理 / サッシュ 1 = 出力シーケンス）の
  **希望幅だけ**を、その枠の表示幅で更新する。もう一方の希望幅は変えない。
  - **ただし、ドラッグ開始時と離したときでその枠の表示幅が変わっていなければ希望幅を更新しない**（v0.3）。
    最小幅で止まって何も変わらなかったドラッグで、自動で広げた表示幅が希望幅として保存されるのを防ぐ。
- **保存の要否**: 更新後の希望幅の組が**ドラッグ前の希望幅の組と同じなら書かない**。
  **書き込みに失敗しても希望幅（メモリ上）は更新したまま**にする（同じ位置で離すたびにエラーダイアログを出さない）。
- **フォントを戻す等で最小幅が下がれば、表示幅は希望幅へ自動で戻る**（再計算は §3-4 の更新契機）。

### §3-6 保存と復元

- **キー**: `config.json` の **`full_view_pane_widths`** = `{"keymap": <int px>, "sequence": <int px>}`（希望幅）。
  トリガー一覧の幅は保存しない。
- **保存**: `write_startup({"full_view_pane_widths": {"keymap": ..., "sequence": ...}})`。
  失敗時の表示は `write_startup` 既存の `messagebox` に従う。
- **復元**: FullView 構築後、**`update_idletasks()` でレイアウトが確定してから**、表示幅を
  **`paneconfigure(pane, width=...)`** で両端へ適用する（表示前の `sash_place` は反対側の枠をずらす・実測）。
  **現在幅は各枠の `winfo_width()` で読む**（`panecget("width")` はドラッグで更新されない・実測）。
- **値の検証**（`_startup_settings` の生の値に対して行う）: 次のいずれかなら**キー全体を無視して既定幅**を使う
  （エラー表示なし・ファイルは書き換えない）: dict でない / `keymap` / `sequence` のどちらかが欠ける /
  **`bool` を含む非 int** / 0 以下。**正の int だが最小幅未満**は希望幅として保持し、表示幅だけ最小幅へ引き上げる。
- **既定幅**（§2-10・v0.3）: **初回表示時に、現状と同じ構成（一覧 26 文字）の枠を測って決める** —
  - キーマップ管理 = **KeymapBox（LabelFrame 全体）の要求幅**（一覧 26 文字 + スクロールバー + 内側余白・枠線・見出しを含む）。
  - 出力シーケンス = **メイン領域の幅 − KeymapBox の要求幅 − FullTriggerBox（LabelFrame 全体）の要求幅 − 境界線 2 本分の幅**。
  - **境界線と旧余白の差分**: 旧レイアウトは枠の間に `padx=12` の余白が 2 つあった。**境界線 1 本の占有幅
    （`sashwidth` + `sashpad` × 2）を 12px とする**ことで、既定幅での配置を旧レイアウトと一致させる
    （テーマ上 12px にできない場合は、差分を**出力シーケンスの既定幅**で吸収し、キーマップ管理・トリガー一覧の幅と位置を優先して合わせる）。
  - **既定幅は保存しない**（最初のドラッグで希望幅として保存される）。最小幅を下回る場合は最小幅。
  - v0.4: 出力シーケンスの既定幅に使う「メイン領域の幅」は**既定ウィンドウ幅 780 のときの値**に換算する（§3-8）。
- **後方互換**: キーが無い既存の `config.json` は既定幅で動く。既存キーの削除・意味変更なし。
  **keymap_set 保存（書き手 ②）でも `_startup_settings` 由来で値が残る**（§1）。

### §3-7 収まらない場合（§2-11）

起動時の復元・フォント変更後・フル表示へ戻ったときに共通で適用する。
**最終値をすべて計算してから、1 回だけ適用する**（v0.3。途中の値を geometry へ当てない）。

**計算**（tkinter 非依存の純関数。入力 = 希望幅 2 つ・最小幅 3 つ・境界線と余白の幅・現在のウィンドウ幅・画面幅）:

1. 両端の表示幅の候補 = 希望幅を最小幅へ引き上げた値。
2. 必要幅 = 両端の表示幅 + トリガー一覧の最小幅 + 境界線・余白（メイン領域の外側を含むウィンドウ幅に換算）。
3. **必要幅が画面幅（`winfo_screenwidth()`）を超えるなら**、出力シーケンス → キーマップ管理の順に
   **表示幅を最小幅まで縮めて**必要幅を画面幅以下にする（**希望幅・保存値は変えない**）。
   両端とも最小幅にしても超える場合はそこで止める（ウィンドウが画面からはみ出すのは保証の範囲外）。
4. 最終ウィンドウ幅 = max(現在のウィンドウ幅, 必要幅)。**ただし現在のウィンドウ幅が画面幅を超えていても、縮めはしない**（ユーザーの操作による幅を尊重）。
5. ウィンドウ最小幅 = 必要幅（§3-4）。

**適用**（コントローラ）: ①`wm minsize` を必要幅へ ②ウィンドウ幅が変わる場合だけ `geometry` で最終ウィンドウ幅へ
（高さ・位置は変えない）③`update_idletasks()` の後に両端の表示幅を `paneconfigure(width=)` で当てる。

### §3-8 ウィンドウ幅の保存と復元（v0.4・§2-13）

- **キー**: `config.json` の **`full_view_window_width`** = `<int px>`（フル表示時のウィンドウ幅）。
  `full_view_pane_widths` とは**別キー**にする（片方だけ不正でも、もう片方は使える）。
- **保存する値** = フル表示中の `winfo_width()`（v0.5。省略表示中に退避した geometry からは取らない）。
- **保存の契機**（v0.5・ユーザー選択 2026-09-17）: **ウィンドウ幅が変わったとき、間引いて保存する**。
  1. App（トップレベル）への `<Configure>` のうち **`event.widget is app`** のものだけを扱う。
     **前回扱った幅と同じなら何もしない**（高さ・位置だけの変化では予約しない）。
  2. 予約済みの保存があれば `after_cancel` し、**500ms 後**に保存を予約し直す
     （最後に幅が変わってから 500ms 変化がなければ 1 回だけ書く）。500ms は定数 1 か所で持つ。
  3. **予約が実行された時点の状態で**判定し、次のいずれかなら書かない:
     - `wm_state()` が **`"normal"` でない**（最大化 `zoomed`・最小化 `iconic` 等。Tk は最大化中に最大化前の幅を返さない）
     - **省略表示中**
     - **初回適用前**
     - `winfo_width()` が**有効な自動決定幅と同じ**（下記）
     - `winfo_width()` が**メモリ上の保存値（`_startup_settings` の同キー）と同じ**（`write_startup` は成功時にこれを更新する）

     `winfo_width()` が有効な自動決定幅と異なれば、**自動決定幅を無効にする**（ユーザーが幅を変えた後は、自動決定幅と同じ幅へ
     戻したときも保存する。v0.5 敵対的レビュー指摘）。そのうえで保存値と異なれば `write_startup({"full_view_window_width": <幅>})`。
     無効にした自動決定幅は、次に §3-7 の適用で `geometry` を変えたときに記録し直される。
     **最大化中・省略表示中など上の状態条件で書かなかった場合は、自動決定幅を無効にしない**
     （例: 画面幅へ切り詰めて起動 → 最大化 → 解除、で切り詰めた幅を保存しない）。
  - 判定を**予約の実行時**に行うため、最大化・省略表示（幅 270）への切り替えで起きる `<Configure>` の幅は書かれない。
    最大化を解除して元の幅へ戻ったときは、保存値と同じなので書かない。
  - **ドラッグを離したときの書き込みにはウィンドウ幅を含めない**（v0.4 の契機 1 を廃止。ドラッグではウィンドウ幅は変わらない）。
  - **終了時は書かない**（v0.4 の契機 2 を廃止）。`on_close` は**予約中の保存があれば `after_cancel` してから** `destroy` する
    （破棄後に予約を実行させない）。未保存確認 → `begin_shutdown` → キーボードウィンドウ破棄 → フック停止 →
    `finally` で `destroy` の順序は v0.4 のまま維持する。
  - **保存失敗のダイアログ中はフックを止める**（v0.5 敵対的レビュー指摘・正本 `key_input.md` §7.2「ダイアログ中は停止・ネスト対応」への適合）:
    `write_startup` の失敗時の `messagebox` を `suspend_hook_for_dialog()` → 表示 → `finally` で `resume_hook_after_dialog()` で囲む。
    `write_startup` 内で直すため、ドラッグ・フォント変更など**既存の呼び出し元も同じ扱いになる**（既存の抜けの是正）。
    成功時はフックを止めない（リサイズのたびに止め直さない）。
  - **受容する制約**（ユーザー判断 2026-09-17）: 最後に幅を変えてから 500ms 以内に**閉じる・最大化する・省略表示へ切り替える**と、
    その変化は保存されない（人の操作では通常起きない）。保存の失敗が続く環境では、幅を変えるたびに失敗ダイアログが出うる。
  - **自動で決めた幅は保存しない**（v0.4 再レビュー指摘 → ユーザー確定）: コントローラは**アプリが最後に自動で決めたウィンドウ幅**
    を覚える。**初回適用の直後は常に**その `winfo_width()` を記録し、**フォント変更後・フル表示へ戻ったときは §3-7 の適用で
    `geometry` を変えた場合だけ**記録し直す（変えなかった場合に記録すると、ユーザーが縁で変えた幅を「自動」と誤認して保存しないため。
    メインセッションでの明確化 2026-09-17）。
    予約の実行時に**保存するウィンドウ幅がその幅と同じなら `full_view_window_width` を書かない**（ユーザーが縁で変えたときだけ書く）。
    → 例: 1600 を保存した状態で画面幅 1280 の環境で起動しても（画面幅へ切り詰め）、1600 は残る。
- **ウィンドウ幅だけ保存されている場合の既定幅**（v0.4 敵対的レビュー指摘 → ユーザー案 2026-09-17）:
  §3-6 の既定幅を**実際のメイン領域の幅ではなく「既定ウィンドウ幅（780）だったときのメイン領域の幅」**
  （= 初回適用時のメイン領域の幅 −（初回適用時のウィンドウ幅 − 780））で算出する。
  → 780 から広げた（狭めた）分は §2-1 どおり**トリガー一覧が受ける**。「キー無しで起動 → 縁だけ広げる → 終了 → 再起動」で 3 枠の幅が一致する。
  既定幅は引き続き保存しないため、フォント設定が変わっても次回起動時に既定幅として算出し直される。
  780 は `App.__init__` の初期 geometry と**同じ定数**を参照する（二重定義しない）。
- **復元**: `App.__init__` の初期 geometry（`780x820`・`app.py:90`）の**幅だけ**を、検証済みの保存値に置き換える（高さ 820・位置は従来どおり）。
  構築前に当てるので、初回表示で一度 780 になってから広がることはない。その後の初回適用（§3-6 の復元）で §3-7 を
  **現在のウィンドウ幅 = 復元した幅**として適用する（必要幅より狭ければ広がる）。
- **値の検証**: **`bool` を含む非 int / 1 未満**なら無視して 780（エラー表示なし・ファイルは書き換えない）。
  **画面幅（`winfo_screenwidth()`）を超える値は画面幅に切り詰めて当てる**（モニタ構成の変更後に画面外まで開かない。保存値は書き換えない）。
  検証と切り詰めは tkinter 非依存の純関数にする。
- **後方互換**: キーが無ければ従来どおり 780。既存キーの削除・意味変更なし。keymap_set 保存でも §3-6 と同じ経路で値が残る。

## §5 受け入れ条件（ドラフト）

1. フル表示でウィンドウ幅を変えると、**トリガー一覧の幅だけ**が変わる（§2-1）。
2. サッシュ 0 / 1 のドラッグで、キーマップ管理 / 出力シーケンスの幅が変わり、**差分はトリガー一覧が吸収**し、
   **ウィンドウ幅は変わらない**（§2-2・§2-3）。
3. **押し出しが起きない**: どちらのサッシュを限界まで動かしても、**反対側の枠の幅は変わらず**、
   トリガー一覧は最小幅で止まる（§3-2）。
4. **中ボタンのドラッグではサッシュが動かない**（§2-12）。
5. 3 枠とも**一覧が枠幅に合わせて広がる**（§2-4）。
6. **最小幅で中身が切れない**（v0.3）: フォントサイズ −/標準/＋ のそれぞれで、各枠を最小幅にしたとき
   **ボタン・チェックボックス・見出し・間隔入力の要求幅が枠内に収まる**（トリガー一覧の suppress チェック・
   出力シーケンスの見出しとボタン列を含む）（§3-4）。
   どの枠も最小幅より狭くならない。フル表示中にウィンドウを縮めると、**トリガー一覧が最小幅に達した時点で止まり、
   両端の枠は縮まない**（§2-5・§2-6）。
7. **省略表示へ切り替えると幅 270 に寄せられる**（最小幅が邪魔をしない）。**省略表示中にフォントを変えても
   省略表示の幅は変わらず**、フル表示へ戻ると最小幅が再計算・再設定される（§3-4）。
8. ドラッグを離すと `config.json` に `full_view_pane_widths` が保存される。**希望幅が変わらなければ書き込まれない**。
   サッシュ以外の場所でボタンを離しても書き込まれない（§3-2・§3-5）。
9. **希望幅と表示幅**: フォントを上げてキーマップ管理が最小幅へ広がった状態でサッシュ 1 を動かして離しても、
   **保存される `keymap` は元の希望幅のまま**。フォントを戻すとキーマップ管理は希望幅で表示される。
   **同じ状態でサッシュ 0 を縮める方向へドラッグし、最小幅で止まって表示幅が変わらなかった場合も、
   希望幅は更新・保存されない**（v0.3）（§3-5）。
10. 再起動後に保存幅が復元される。**不正値（非 dict / 欠け / bool / 非 int / 0 以下）は既定幅**、
    **最小幅未満は表示だけ最小幅**（§3-6）。
11. **既定幅（キー無し）での初回表示が、現状（変更前）と同じ配置になる**（キーマップ管理・トリガー一覧の枠幅と位置が
    変更前の LabelFrame の要求幅・`padx=12` と一致。境界線を 12px にできない場合の差分は出力シーケンスの幅に出る）（§3-6）。
12. **収まらない場合**: 保存幅が大きくウィンドウに収まらなければウィンドウが広がる。画面幅を超える場合は
    出力シーケンス → キーマップ管理の順に表示だけ縮み、保存値は変わらない。
    **その過程でウィンドウが一時的にも画面幅を超える幅へ設定されない**（v0.3・最終値の一括適用）（§3-7）。
    計算部分は純関数の単体テストで境界（ちょうど画面幅 / 1px 超過 / 両端最小でも超過）を固定する。
13. `full_view_pane_widths` の保存が他の起動設定キー（`ui_font_delta_pt` / `orphan_sweep_scan_dirs` 等）を消さない。
    **keymap_set の保存（`save_runtime_data` 経由）で config.json が書き直されても幅の値が消えない**（§3-6）。
14. 既存の `tests` / `tests_ui` が全て pass し `smoke_app` が通る。**既存アサーションを弱めない**。
    **幅保存のテストは実際の `config/config.json` を書かない**（`write_startup` の差し替え or 一時 config）。
15. **ウィンドウ幅の復元**（v0.4）: 幅を変えて終了 → 再起動すると、同じウィンドウ幅（= 同じトリガー一覧の幅）で開く。
    保存値が必要幅より狭ければ広がり、画面幅より広ければ画面幅で開く。不正値（bool / 非 int / 1 未満）は 780（§3-8）。
16. **ウィンドウ幅の保存契機**（v0.5）: 縁でウィンドウ幅を変えると、**最後の変化から 500ms 後に 1 回だけ**
    `full_view_window_width` が書かれる（連続したリサイズの途中では書かない）/ 高さ・位置だけの変化では書かない /
    **幅を変えて 500ms 以上待ってから最大化 → 閉じる → 再起動で、変えた幅で開く** / 最大化中・最小化中・省略表示中は書かない
    （最大化・省略表示への切り替えで画面幅や 270 が保存されない）/ 保存値と同じ幅なら書かない /
    ドラッグを離したときの書き込みにウィンドウ幅を含まない / **終了時は書かない**（予約中の保存は取り消され、閉じた後に実行されない）/
    保存に失敗してもアプリは動き続ける（§3-8）。
    **キー無しで起動 → ウィンドウの縁だけ広げる → 500ms 以上待って終了 → 再起動で、3 枠の幅が終了前と同じ**（既定幅を 780 基準で算出するため）。
    **自動で決まった幅は書かない**: 保存幅より狭い画面で起動（画面幅へ切り詰め）→ 何もせず終了 → 保存値は変わらない /
    フォントを上げてウィンドウが自動で広がった → 保存値は変わらない /
    **起動時の幅 → 別の幅へ変えて保存 → 起動時の幅へ戻して保存 → 再起動で、起動時の幅で開く** /
    画面幅へ切り詰めて起動 → 最大化 → 解除 → 保存値は変わらない /
    **保存失敗のダイアログ表示中はフックが停止しており、閉じると元の状態へ戻る**（ドラッグ・フォント変更時の保存も同じ）。
    間引きのテストは実時間の待機に依存せず、予約した処理を直接実行して検査する。
17. **ドラッグ中の間引き**（v0.4・案 L）: 連続した移動イベントでも、アイドル 1 回につき枠の幅の適用は高々 1 回。
    離したときは最後の位置が必ず適用されてから希望幅が更新される。ドラッグの結果（§5-2・§5-3・§5-8・§5-9）は変わらない（§3-2）。
18. 既定（キー無し）の起動が従来どおり 780x820 で開き、§5-11 の配置になる（§3-8）。
