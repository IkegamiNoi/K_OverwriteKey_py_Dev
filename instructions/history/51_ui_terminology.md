## §1 目的 / 背景

UI の文言で**同じ概念を複数の語で呼んでいる**・**別の概念を同じ語で呼んでいる**箇所を、1 概念 1 語に揃える。
ヘルプ（用語の説明）と多言語化（訳語の対応表）の土台になる用語表を先に確定させるのが狙い。

## §3 適用規則

### §3.1 対象

- **対象**: 利用者の目に触れる文字列 = 画面のラベル・ボタン・メニュー・ダイアログの題と本文・ステータスバー / フラッシュ通知・
  messagebox・入力検査のエラー文・一覧の表示文字列。application / domain 層で作られ UI に表示される文言（例外文が「〜保存失敗: {e}」の形で画面に出るもの・
  `keymap_switch_batch.py` の重複エラー等）も含む。
- **対象外**: JSON キー・コード識別子・ログ専用の文言（`logging` へ出すだけのもの）・テスト名・**docstring・コメント**・
  **JSON に保存されるデータ値**（例外: §2.1 Q5 の移行ラベルは今後作る値だけ変える）。
- **ファイル・フォルダ名**: 特定のファイルやフォルダそのものを指す表記（パス表示・`startup.json`・`config.json`・`global/`・
  `keymaps / trigger_sets / sequences` のフォルダ名）は**対象外で据え置く**。
  一方、**種類を指して使っている `keymap_set.json` / `keymap_set` は A1 で置き換える**
  （例: 「起動時に読み込む keymap_set.json を選択」→「起動時に読み込む構成セットを選択」・「この keymap_set を読み込みます」→「この構成セットを読み込みます」）。
- **内部名の線引き**: 文中で**語として**使っている内部名（「sequence の保存先変更には trigger_set の保存が必要です。」・
  「押したキーが hotkey として反映されます」）は A1/A2/A7/A8 で置き換える（hotkey は §2.1 Q1）。
  コンボの値・エラー中の**種類の値**（`mouse_click` 等）の表示名化は本フェーズ対象外（§2.1 Q1）。
- **意味を変えない**: 語を置き換えるだけで、文の情報量・挙動・ダイアログの選択肢の数は変えない。
  語の置換に伴う助詞・語順の最小限の調整は可。

## §4 実装の方針
