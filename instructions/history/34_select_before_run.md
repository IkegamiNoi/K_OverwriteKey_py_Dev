## §1 目的 / 背景

今はトリガーのキーを押すと即実行される。**一覧で選んでいない（フォーカスされていない）トリガーを押したときは、1 回目は一覧でそのトリガーを選ぶだけにし、選ばれた状態でもう一度押したら実行する**モードを加える。
シーケンス欄でそのトリガーの次に実行の位置と中身を確かめてから実行するため。
**domain / application / presentation。keymap_set と sequence の JSON にキーを 1 つずつ追加（後方互換）。**

## §2 確定事項（ユーザー 2026-10-07）

1. **フォーカス = トリガー一覧で選んでいるトリガー**。選んでいないトリガーのキーを押したら、**1 回目は一覧でそのトリガーを選ぶだけで実行しない**。選んでいるトリガーのキーを押したら従来どおり実行する
2. 設定は 2 つ: **フック欄に全体のチェックボックス**（構成セットごとに保存）/ **出力シーケンス欄の「連続実行」の下にトリガーごとのチェックボックス**（そのトリガーのシーケンスに保存）。**どちらかが ON なら対象**
3. **対象はトリガー一覧のトリガーだけ**。キーマップの直接置換（置換元キー → 送るキー）は対象にならない（従来どおり即送る）。停止キー・一時停止 / 再開キー・キーマップ切替キーも対象外
4. **処理中は従来どおり**: 正本 §4.2.10 の判定（処理中のものがある / 一時停止中のものの再開 / 待機中の無視）を先に行い、選ぶだけの扱いは**何も処理しない押下（実行を始める押下）にだけ**効く
5. 1 回目（選ぶだけ）は**ステータスバーの一時メッセージで知らせる**。文言 = 「<K> を選びました（もう一度押すと実行します）」（K は正規化後の小文字・ラベルは出さない）（2026-10-08）
6. **省略表示**: フック欄に全体のチェックを**無効状態で表示**（個別指定チェックと同じ作法）。トリガーごとのチェックは出さない。設定の操作はフル表示（2026-10-08）
7. **戻す・先頭へだけのトリガー（単独登録）は選んでから実行の対象外**（押すと対象を選んで見せる既存の動きが確認の役目を果たす・一時停止中の破棄の 2 回押しと重ねない）（2026-10-08）
8. **単発の待機が明けたとき、待機の間に一覧の選択が変わっていたら（選ぶだけの押下・一覧のクリック等の手段によらず）、待機していたトリガーを選び直さない**（2026-10-08・v0.4 で「選ぶだけの押下のときだけ」から改訂）。**機能の ON / OFF によらない既存の挙動の変更**（今は待機中に一覧をクリックしても待機明けに戻される）
9. **長押し（キーリピート）**: 選ぶだけになった押下は、**そのキーを離すまでのリピートを無視する**（実行も選ぶだけもしない）。実行は、いったん離してから次に押したとき。選ばれているトリガーの長押しは従来どおり（2026-10-08・Codex 敵対的 high）

## §3 判定（押下の扱い）

**判定の位置**: 正本 §4.2.10「トリガーの押下の扱い」2.（処理中のものが無い）のうち、一時停止中のものの再開・押したトリガー自身の保留（待機中の無視・一時停止中の呼び出しの再開）・アクションが空の判定の**後**、
連続実行のトリガーの開始（一時停止中のものを捨てる・単発の待機の保留を取り消す）・単発の実行の**前**（`input_acceptance.py:187` と :188 の間）。

- 押したキー K のトリガーが**選んでから実行の対象**（§4）で、かつ **K の有効な行が一覧で選ばれていない**とき → **選ぶだけ**:
  - 一覧で K の有効な行を選ぶ（フル・省略の両方の一覧・シーケンス欄・ステータスを更新する。押下でトリガーを選ぶ既存の処理と同じ）
  - 一時メッセージ「<K> を選びました（もう一度押すと実行します）」（§2-5）
  - **それ以外は何もしない**: 実行しない・位置 / 周回 / 保留 / 戻す履歴 / 直前のトリガー（§4.2.6）を変えない・**一時停止中のものを捨てない**・**他のトリガーの単発の待機の保留を取り消さない**（連続実行のトリガーでも）
  - 戻す / 先頭への 2 回押しの控えは、別キーの押下なら既存の規則どおり捨てる（K が控えのキーと同じになるのは §4 の除外により起きない）
- それ以外 → 従来どおり
- **「選ばれている」の判定**: `App._selected_trigger_idx` の行（フル表示の範囲選択の帯ではない）が **K の有効な行**であること。キーが K でもグレーの重複行を選んでいるときは選ばれていない扱い（1 回目で有効な行へ選択を移す）。一覧が空なら選ばれていない
  - 起動直後・読込直後は先頭の行が選ばれている（既存）。そのため先頭の行のトリガーだけは 1 回目から実行される（受容）
- **リピートの無視**（§2-9）: 選ぶだけにしたキー K について、K の up（離す）が来るまでの K の down は無視する（実行・選ぶだけ・一時メッセージのいずれもしない。suppress の決定は従来どおり）。K の up、または K 以外のキーの押下で無視は終わる。フックの停止・キーマップの切替で押下状態が失われた場合も無視は終わる（次の down は通常の押下）
- 判定に時間の制限は設けない。1 回目と 2 回目の間に一覧のクリック等で選択を変えたら、2 回目の時点の選択で判定する（控えは持たない）
- **呼び出しが絡む場合**: 呼び出しの開始で判定する「待機中の呼び出し先は無視」「一時停止中の呼び出し先は捨てて進める」（正本 §4.2.9）は判定の位置より奥にあるため、**選ぶだけが先に効く**（1 回目 = 選ぶだけ・2 回目 = 従来どおり無視 / 破棄して実行）。
  単発のステップの呼び出しの押下の合間に呼び出し元を押した場合も判定の対象になるが、runner が選ぶのは常に押したキー（呼び出し元）なので、**同じ呼び出し元を続けて押す限り選ぶだけは挟まらない**。連鎖の別のトリガー（呼び出し先・別の呼び出し元）を押すと 1 回目は選ぶだけ（規則どおり）
- suppress が OFF のトリガーは、1 回目もキーが前面のアプリへ素通しされる（実行されずに文字だけが入る・suppress の決定は変えない＝§7）

## §4 対象の決定

- 対象 = **全体の設定が ON**（アクティブな構成セットの値）**または そのトリガーの設定が ON**
- 全体の設定はトリガー一覧のトリガーに効く（直接置換・停止 / トグル / 切替キーには効かない・§2-3）
- **戻す・先頭へだけのトリガー（単独登録・`_is_standalone_control` と同じ判定）は対象外**（§2-7）。手編集で他の行と混ざったものは対象に残る
- 呼び出し（§4.2.9）で呼ばれたトリガーは押下ではないので対象外

## §5 UI

- **フル表示のフック欄**: チェックボックス「選んでから実行」（全体）。置き場は個別指定チェックの近く（配置は実装時に決め、実機目視で確認）。
  操作で構成セットを未保存（dirty）にする（`hook_keys_individual` と同じ扱い）。フックの ON / OFF・キーマップ一時停止とは独立。
  **読込・新規作成・例を復元・Import のときに構成セットの値へ同期する**（`_sync_control_vars_from_data` の経路）
- **出力シーケンス欄**: 「連続実行」の行の下（「間隔(ms)」の行がその下にあるなら、その位置関係は実装時に決め実機目視で確認）にチェックボックス「選んでから実行」（トリガーごと）。
  選択の切替で選んでいるトリガーの値へ同期し、操作でそのシーケンスを未保存にする（「連続実行」と同じ扱い）。トリガー未選択・グレーの行の扱いは「連続実行」のチェックと同じ。
  ボタン列の幅が変わる場合はフル表示の最小幅の計測（`pane_measure.py`）に従う
- **省略表示**（§2-6）: フック欄に全体のチェックを**無効状態で表示**（同じ変数・個別指定チェックと同じ作法）。トリガーごとのチェックは出さない。判定自体は省略表示でも同じに効く（省略表示の一覧の選択 = 同じ `_selected_trigger_idx`）

## §6 保存（後方互換）

- **keymap_set**: 新しいキー `select_before_run`（bool・既定 false）。**bool 型でなければ false**（`hotkey_presets_individual` と同じ・キーの有無や他の値からの推論はしない）
- **sequence**: 新しいキー `select_before_run`（bool・既定 false）。`run_to_end` と同じ解釈（キーが無ければ false・値があれば `bool()`）
- **trigger_set 内の trigger / 単一 JSON のインラインの trigger**: `run_to_end` と同じく trigger 内の `select_before_run` も読む。trigger_set 内と sequence の両方にあれば sequence 側が優先（既存の `run_to_end` と同じ・`split_loading.py:510`）
- 読み書きの漏れ口（§1 の列挙）すべてにキーを足す: keymap_set の読込・保存 / sequence の保存（一括・個別）・読込（`_normalize_sequence_payload`）/ trigger_set 内 / `normalize_triggers`
- false のときも書くか / 省略するかは既存の `run_to_end`（sequence）・`hotkey_presets_individual`（keymap_set）の書き方に合わせる
- 往復で値が保たれること: 保存 → 再読込 / Import → Export / シーケンスの個別保存 → 個別読込 / 複製・貼り付け

## §7 責務の置き場（実装の方針）

- 判定（§3・§4）は application（`SequenceRunner` の押下の受付）で行う。presentation からは「今一覧で選ばれている有効な行のキー（無ければ None）」を返す口を注入し、選ぶのは既存の `select_trigger` の口を使う
- 全体の設定値は構成セットのデータ（runtime の `data`）から application が読む（presentation の Tk 変数を application へ持ち込まない）
- 新しい注入口は**省略可能**にし、省略時は機能 OFF（常に従来の動き）とする（既存テストは注入なしで `SequenceRunner` を作っている）
- InputRouter の suppress の決定は変えない
- リピートの判定材料: その down の前にキーが既に押下中だったか（`KeyStateManager` の押下状態）を、TriggerAction に添えて runner へ渡す（例: `repeat` の印）。runner は選ぶだけにしたキーを覚え、印付きの down を無視する。印の付け方は実装で決めてよい（フックの down の前の押下状態で判定）
- 待機明けの判定材料: 単発の待機を積む時点の「選ばれている有効な行のキー」を保留（PendingStep）に控え、待機明けに今の選択と比べる（注入口が無いとき＝機能の注入なしの既存テストでは従来どおり選び直す）

## §8 状態・表示

- 選ぶだけの押下は実行状態（§4.2.3）を一切変えない。ステータス欄の表示は選択の変化どおりに更新される
- 実行の後に runner が実行したトリガー（戻す・先頭へは対象）を選ぶ既存の動きは変えない
- **単発の待機が明けたときの選び直し**（`send_wait.py:66`・§2-8）: 待機を始めた時点で選ばれていたトリガー（通常は待機している K。runner が実行後に K を選んでいる）が、待機が明けた時点でも選ばれているときだけ K を選び直す（実質は表示の更新）。待機の間に選択が変わっていたら（手段によらず）選び直さない。待機が続けて積まれる（連続する待機・`send_wait.py:26-30`）ときは、それぞれの待機の始まりの選択で判定する。待機が取り消された・捨てられた場合は選び直しそのものが起きない（既存）

## §10 受け入れ条件（ドラフト）

1. 全体 OFF・トリガーの設定 OFF なら従来どおり即実行（§4）
2. 全体 ON で、選んでいないトリガーを押すと一覧でそのトリガーが選ばれ、実行されず、一時メッセージが出る。続けて同じキーを押すと実行される（§3）
3. 全体 OFF でトリガー T の設定だけ ON なら T だけが選ぶだけになり、他のトリガーは即実行（§4）
4. 直接置換のキー・停止 / 一時停止・再開 / キーマップ切替キーは常に即効く（§2-3）
5. 処理中（連続実行の実行中・単発の呼び出し中など）・一時停止中の再開・押したトリガー自身の待機中の扱いは従来どおり（§2-4）。選ぶだけの押下では一時停止中のものを捨てず、他のトリガーの単発の待機も取り消さない（§3）
6. グレーの重複行を選んでいるとき、そのキーを押すと有効な行へ選択が移り実行されない（§3）
7. 単発のステップの呼び出しの呼び出し元を続けて押しても選ぶだけは挟まらない。待機中 / 一時停止中の呼び出し先を呼ぶトリガーは 1 回目 = 選ぶだけ・2 回目 = 従来どおり（§3）
8. 単発の待機中に他のトリガーを選ぶだけで押したとき・一覧をクリックしたとき、待機が明けても選択はその時点のまま（§2-8・§8）。選択を変えなければ従来どおり待機していたトリガーが選ばれている
8a. 選ばれていないトリガーを長押しすると、1 回目で選ぶだけになり、離すまでのリピートでは実行されない。離して押すと実行される（down / down / up / down・§2-9）。選ばれているトリガーの長押しは従来どおり
9. 戻す・先頭へだけのトリガーは全体 ON でも即実行される（§2-7）
10. 全体の設定は構成セットに、トリガーの設定はシーケンスに保存され、§6 の往復で値が保たれる。キーが無い古い JSON は OFF で読める。読込・新規作成・Import で全体のチェックの表示が構成セットの値に合う（§5・§6）
11. 全体のチェックの操作で構成セットが、トリガーのチェックの操作でシーケンスが未保存になる（§5）
12. 既存テスト（tests / tests_ui / smoke）が通る
