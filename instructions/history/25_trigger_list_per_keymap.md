## §1 目的 / 背景

1 つの構成セット（keymap_set）で複数のトリガー一覧を使い分けられるようにする。
**トリガー一覧をキーマップに従属させ、「キーマップ＝モード」として置換キーとトリガーを一括で切り替える**。
出力シーケンスはトリガー一覧に従属しているため、トリガー一覧と連動して切り替わる。

### 現状監査（2026-09-24・コード実測）

- **トリガー一覧は構成セットに 1 つ**: keymap_set の `trigger_set_path` を読み、runtime のトップレベル
  `triggers` に格納する（`split_loading.py:306`）。sequence の内容は各 trigger 要素へ結合して持つ
  （`split_loading.py:435-487`）。split 読込の土台は `new_default_data()`（`split_loading.py:280`）で、
  例データのトップレベル `triggers` を含む。
- **キーマップ要素はトリガーへの参照を持たない**: runtime / 単一 JSON の `keymaps[]` は `id` / `label` / `mappings`
  （+ 内部キー）のみで、**正規化（`ensure_config_compatibility`）が未知キーを落とす**（`domain/config.py:277-291`）。
  `active_keymap_id` / `keymap_switch_keys` はトップレベル。切替キーは keymap_set の `keymaps[].switch_key` に保存される（§5.5）。
- **キーマップ 0 個の補完が既にある**: `KeymapService.ensure_active_keymap` が id=`default` / label=`Default` で作る
  （`keymap_service.py:260-269`）。
- **入力判定の優先順位**: 停止 > トグル > 直接切替 > トリガー > 置換（`input_router.py:83-110`）。
  トリガーと置換元キーの重複は**登録時にどちらからも拒否されない**（トリガーが黙って勝つ）。
  直接切替キーは トリガー・置換元キーの双方と登録時に排他（`keymap_panel_controller.py:111-149` /
  `trigger_panel_controller.py:382,420` / `keymap_panel_controller.py:371`）。停止 / トグルの取得時の重複検証は
  表示中の `triggers` のみを見る（`app.py:140-158`）。
- **「通常トリガー無効化」（`custom_input_enabled=False`）は直接切替・トリガー・置換をすべて止める**
  （停止 / トグルのみ生存。`input_router.py:91`）。
- **フックは全キー一括の単一グローバルフック**（`hook_coordinator.py:45-58`）。アクティブ切替でフック再登録は不要。
- **アクティブ切替**: 一覧の選択ではアクティブにならず「選択」ボタン（`keymap_panel_controller.py:230`）で切り替え、
  keymap_set を dirty にする。直接切替キー経由（`SelectKeymapAction`）は dirty にしない。
- **連続実行中**: 実行中のトリガー自身以外は無視される（`sequence_runner.py:33-42`）が、
  **直接切替キーは router でトリガーより先に判定されるため連続実行中でも効く**。
  シーケンスの実行位置・選択行は trigger key 単位で保持（`trigger_panel_controller.py:126-177` / `sequence_runner.py:64-68`）。
- **保存計画**: trigger_set は key 空の 1 行に固定（`child_save_plan.py:37` / `save_plan_execution.py:266`）。
  **sequence の識別子は trigger key**（`child_save_plan.py:83-87`）。**一覧ダイアログの行は dirty な子のみ**
  （`child_save_rows.py:126-129`）で、**行に出ない子は既定保存先が実在すれば「保存しない」**
  （`child_save_plan.py:72`）→ 索引は source_path が実在すればそれ、無ければ空（`split_payloads.py:164-171`）。
  書込順は sequences → trigger_set → keymaps → keymap_set → startup（`save_plan_execution.py:117`）。
  保存先の衝突回避は trigger_set 内に閉じる（`split_payloads.py:205`）。依存（上位の保存必須）の検出は
  sequence → trigger_set のみ（`save_plan_execution.py:214-225`）。
- **`_parent_refs`**: keymap / trigger_set の親 = keymap_set、sequence の親 = trigger_set（`split_payloads.py:44,64,264,272`）。
  参照元の掃除が除去するのは実在しない上位のみ（正本 5_08_01）。
- **参照辿り**: keymap_set → trigger_set → sequence の 2 段固定。keymap は参照収集のみ（`reference_scan.py:108,129`）。
  keymap_set の判別はキーの有無で行う（`reference_scan.py:98-105`）。
- **既定ファイル名**: keymap = （`user/keymaps` 配下の source_path stem）→ `id` → `label` → `keymap`
  （`save_path_resolution.py:126-141`・`id` が常に非空のため実質 `keymap_N`）。trigger_set = keymap_set の stem 由来（§5.6）。
- **Import は子を dirty にしない**（`keymap_set_io.py:589`）。**例の復元**は `DEFAULT_CONFIG`
  （トップレベル `triggers` あり・`keymaps` 空。`domain/config.py:23,70`）のコピー。
- **キーマップの個別読込は runtime へ「追加」**し、切替キーは付かない（`keymap_file_io.py:102-133`）。
- **トリガー一覧 UI / キーボードウィンドウは `app.data["triggers"]` を直参照**（`trigger_panel_controller.py` 各所 /
  `keyboard_window.py:95`）。trigger_set の dirty / source_path は単一トラッカー（`dirty_state.py`）。

## §2 確定事項（ユーザー 2026-09-24）

1. **トリガー一覧はキーマップに従属する**（タブ方式は採らない）。トリガー一覧を持たないキーマップに切り替えると、
   トリガー一覧は空になり置換のみ効く。
2. **全キーマップ共通のトリガー層は作らない**（将来案は [idea_36](../backlog/idea_36_common_trigger_layer.md)）。
3. **出力シーケンスはトリガー一覧に従属**し、トリガー一覧の切替に連動して入れ替わる。
4. **トリガー一覧への参照はキーマップファイルに持たせる**。キーマップファイルを複数の構成セットで共有すれば
   トリガー一覧も共有される（現行の「trigger_set を複数の構成セットで共有すると sequence も共有される」と同じ構図を 1 段上に適用）。
5. **旧形式の移行**: 構成セットの `trigger_set_path`（旧形式）は、**アクティブなキーマップ**にだけ付ける。
   キーマップ側に参照があればそちらを優先する。
6. **後方互換は「古い JSON を読めること」のみ**。新しいファイルを旧版アプリで開けること（前方互換）は考慮しない。
7. **構成セットには常にキーマップが 1 つ以上ある**。新規作成・読込でキーマップが 0 個なら自動で 1 つ作る。
   キーマップが 1 つだけの間は切替キー不要。
8. **キーマップの追加（2 つ目以降）は切替キー必須**。追加しようとしたとき切替キーの無い既存キーマップがあれば、
   エラーダイアログでそのキーマップを示し、切替キーを付けさせてから追加に進む。
9. **既定ファイル名**: ラベルが既定（空）のキーマップは構成セットのファイル名由来。それ以外はラベル由来。
   **トリガー一覧は親キーマップのファイル名と同じ stem**。
10. **トリガー一覧はアクティブなキーマップのものを表示**する。**キーマップ一覧で選択したものを自動でアクティブにする**。
11. **アクティブの変更では構成セットを未保存にしない**（保存時にその時点のアクティブを書き込む）。
12. **連続実行中（一時停止中を含む）はキーマップを切り替えられない**。切替を試みたらステータスバーの一時メッセージ領域に表示する（§2-21）。
13. ~~置換をトリガーより優先する~~ → **v0.6 で撤回: トリガーを置換より優先する（旧版と同じ）**（ユーザー 2026-09-26）。
    同じキーマップ内のトリガーと置換元キーの重複は**編集時に双方向で禁止**する（v0.4 どおり）。読込・共有一覧で重なった場合は
    トリガーが動き、その置換が使えなくなる（キーボード表示でトリガーが上に出ることで分かる）。トリガーのグレー表示の対象から「置換」を外す。
    理由: 重なっても置換が使えなくなるだけで競合を考えなくてよい・旧版データの挙動が変わらない・共有一覧の重複チェックに追加対策が要らない。
14. **Import / Export（単一 JSON）も対象に含める**。
15. **旧形式の構成セットを開くと未保存表示になる**（移行先キーマップを確実に新形式で書くため。§4.2）。
16. **グレー表示の対象を広げる**: 読込時にトリガーが置換元キーだけでなく**直接切替キー / 停止 / トグル**と重なる場合も
    グレー表示＋理由を出す（§7.3）。**v0.6 で置換元キーとの重なりは対象外**（§2-13・トリガーが勝つため）。
17. **「通常トリガー無効化」を改名する（A 案）**: ボタンは **「キーマップ一時停止」⇔「キーマップ再開」**。
    関連表示も揃える（ステータス欄の「通常トリガー: ON/OFF」/「有効/無効トグルキー」のラベル。§8.4）。
    挙動（止める範囲＝直接切替・置換・トリガー）は変えない。
18. **フック開始を止めるのは「停止キーとトグルキーが同じ」場合だけ**。停止 / トグルと置換元キー・トリガー・
    直接切替キーの重なりは開始を止めず、停止 / トグルを優先する（置換元キーはキーボード表示の色で、
    トリガー・直接切替キーはグレー表示で知らせる）。
19. **直接切替キーが停止 / トグルと重なるキーマップは、キーマップ一覧でグレー表示**する（キーでは切り替わらない）。
    **一覧からの選択（アクティブ化）・編集はできる**（直す手段を残す。キーマップが 1 つでも同様に選択されトリガー一覧等を表示する）。
20. **グレー表示の割り当てに対応するキーを押したら、ステータスバーの一時メッセージ領域で重複と変更を案内する**（§8.5・§2-21）。一覧の行のグレー表示と理由は一覧に残す。
21. **一時的な案内（§8.2 の切替不可・§8.5 の重複案内）の表示先は、画面下のステータスバー中央の一時メッセージ領域**（`_set_flash_message`・既定で自動消去）。上部の「ステータス」枠（フック・キーマップの状態表示）には出さない（ユーザー 2026-09-26・実機目視）。
22. **キーマップの追加ダイアログは、切替キーが空・不正などの入力エラーで閉じない**。エラーを示したうえでダイアログを開いたまま入力し直せる（ユーザー 2026-09-26・実機目視）。
23. **旧参照を移行できなかったときは、そのトリガー一覧用のキーマップを自動で作って移す**（ユーザー 2026-09-26・統合レビュー H-2 を受けて）。
    ラベルは旧一覧のファイル名由来（例「旧トリガー一覧（work）」）・置換は空・切替キー未設定。移行と同じく未保存表示にし、保存すれば構成セットの旧値は `""` になる。
    どれかのキーマップが旧一覧と同じファイルを既に参照していれば作らない（使用済み扱い）。「使われていない」まま旧値が残り続ける状態は無くす（§4.4・§4.5）。
24. **旧形式を移行する対象は、キーマップファイルに `trigger_set_path` の項目が無い（旧いキーマップファイル）ときだけ**（ユーザー 2026-09-26）。
    新しい版で書いたキーマップファイルは一覧が無くても `trigger_set_path: ""` を持つので移行されない（単一 JSON の「`triggers` キーの有無」と同じ規則）。
25. **移行先のキーマップを削除したら、構成セットと旧トリガー一覧の関係を切ったものとして扱う**（ユーザー 2026-09-26）。移行の記録を消し、保存すると構成セットの旧値は `""`。
    旧一覧のファイルは残る（孤児ファイルの棚卸しで見つけられる）。
26. **同じキーマップファイルの二重読込を禁止する**（ユーザー 2026-09-26）。個別読込で、既に同じ解決先パスのキーマップがあれば「このキーマップは既に読み込まれています」と表示して読み込まない。
    別々のキーマップファイルが同じトリガー一覧を共有するのは引き続き許す（置換が違いトリガーが同じモードを作れる）。
27. **重なりの判定結果は、グレー表示の再判定の時点で読み取り専用の表として保持し、キー入力時はその表を引くだけにする**（ユーザー 2026-09-26・統合レビュー L-3）。
    フックのスレッドで全件走査しない・画面側の編集と競合しない。データが変わる契機（トリガー / 置換 / 切替キー / 停止・トグルキーの編集・読込・アクティブ切替）で作り直す。
    どの割り当てが動くか（§7.1 の順）はキー入力時に従来どおり判定し、表は案内（§8.5）にだけ使う。
28. **アクティブのキーマップが `trigger_set_path` の項目を持つ（値が `""` を含む）ために旧参照を移行できないときも、新しいキーマップを自動作成して移す**
    （ユーザー 2026-09-27・完了判定前レビュー H-1）。旧一覧を黙って捨てない（§2-23 の趣旨）。例: 同じキーマップファイルを共有しアクティブだけが違う 2 つの旧構成セット。
29. **移行した trigger_set の行も、一括保存で「保存しない」を選べない**（移行先キーマップと同じ扱い。ユーザー 2026-09-27・M-2）。
30. **アクションが空のトリガーは、入力判定では無いものとして扱う**（置換元キーと重なれば置換が動く。phase 34 以前と同じ挙動。ユーザー 2026-09-27）。
31. **切替中の受け付け停止**（ユーザー 2026-09-27・codex 指摘を受けたユーザー提案）: 判定（フックのスレッド）で直接切替を決めた瞬間に「切替中」の印を立て、
    印がある間に届いたキーは停止 / トグル以外を**処理せず素通しする**（元のキーのまま OS へ渡す・待ち行列に入れない・`key_input.md` §7.2 と同じ扱い）。
    UI スレッドで切替が終わったら（アクティブの変更・再描画・重なりの表の作り直しまで。連続実行中などで拒否された場合も）印を下ろして受け付けを再開する。
    これで「切替キーの直後のキーが、切替前の状態で判定され切替後の状態で実行される」ずれを無くす。

## §3 データモデル

### §3.1 分離 JSON

- **keymap ファイルに `trigger_set_path`（str）を追加**する。意味は「このキーマップのトリガー一覧」。
  型不正は §5.1 の共通規則（非文字列は空＝トリガー一覧なし）。表記は §5.7。
- **keymap_set の `trigger_set_path` は「旧形式の読込元（移行用）」に意味を据え置く**。書く値は §4.4。
  共通トリガーへの転用はしない（idea_36 は新キーを使う）。
- trigger_set / sequence のファイル形式は変更しない。
- **keymap_set の判別**（参照辿り・孤児棚卸しの候補判定）は `trigger_set_path` の有無に頼らない
  （keymap ファイルも同キーを持つようになるため。`keymaps` 参照の有無など keymap_set 固有のキーで判別する）。

### §3.2 単一 JSON（Import / Export）

- **`keymaps[]` 要素に `triggers`（list）を追加**する。要素の形は現行トップレベル `triggers[]` と同一
  （インライン `actions` を含む・§5.2 / §5.11）。**list 以外なら `[]`**（§5.1）で、その場合も「キーあり」とみなす。
- トップレベル `triggers` は**旧形式の読込元（移行用）**。**Export 時は `[]` を書く**。
- 最古形式（`trigger_key` 等・`domain/config.py:168-182`）の変換は §4.1 の移行より**先に**行う。

### §3.3 runtime

- **runtime はキーマップごとにトリガー一覧を保持する**。各 `keymaps[]` 要素が `triggers` と trigger_set の内部キー
  （source_path / parent_refs / dirty / imported）を持つ。**正規化はこれらを保持する**（未知キー除去の対象外にする）。
- **同じ trigger_set ファイルを参照する複数のキーマップは、runtime で 1 つの実体（同一オブジェクト）を共有する**
  （ファイル共有の意味と一致させる。片方の編集はもう片方にも見える）。
- runtime のトップレベル `triggers` は**常に `[]`** とし、読まない（旧形式の判定は §4.1 のとおり**読込元ファイルの内容**で行い、
  runtime の土台〔既定データ〕を見ない）。Export 時は入れ子の内部キーも除く。
- UI・入力判定・フック開始検証は**アクティブキーマップのトリガー一覧を service 経由で取得**する（`app.data["triggers"]` の直参照をやめる）。
- シーケンスの実行位置・選択行は**トリガー一覧の実体ごと**に保持する（別キーマップの同じキーと混ざらない）。

## §4 読込と移行

### §4.1 読込規則（split / 単一 JSON 共通）

1. 各キーマップのトリガー一覧は、**キーマップ側の参照（split: keymap ファイルの `trigger_set_path` /
   単一: `keymaps[].triggers` キーの有無）**から読む。参照先の trigger_set が読めない場合は、
   現行の trigger_set 読込失敗時の扱いをキーマップ単位で適用する（旧形式では補わない）。
2. **アクティブなキーマップがキーマップ側の参照を持たない**とき（split: keymap ファイルに `trigger_set_path` の**項目が無い**〔v0.6・§2-24。値が `""` なら参照ありの「一覧なし」〕 /
   単一: `triggers` キーが無い）に限り、**旧形式の読込元（keymap_set の `trigger_set_path` / 単一 JSON の
   トップレベル `triggers`）をアクティブなキーマップに付ける**（＝**移行**）。
   アクティブが参照を持っていて移行できない場合は §4.5（v0.6: 新しいキーマップを作って移す）。
3. アクティブ以外のキーマップには旧形式を付けない。
4. **キーマップが 0 個なら 1 つ自動作成**（`id` は既存採番 / `label`=`""` / `mappings`={} / 切替キーなし）し、
   アクティブにしてから 2. を適用する。既存の `ensure_active_keymap`（id=`default` / label=`Default`）はこの規則に統一する。
5. 読込ではファイルを書き換えない。

### §4.2 移行したキーマップは未保存にする

- **移行（§4.1-2）が起きたら、移行先キーマップを未保存（keymap の dirty）にし、構成セットも未保存にする**
  （旧形式の構成セットを開くと未保存表示になる）。
  理由: 移行先を書かないまま保存すると、次回読込で旧形式が「その時点のアクティブ」に付き直り、
  別のキーマップへ移ったり（アクティブ変更後）、参照が消えたりする（v0.1 の H1）。
- **移行先キーマップは、構成セットの保存（一括保存）で「保存しない」を選べない**（保存 / 別名保存のみ）。
  移行先は構成セットと同じ保存で必ず書かれるため、移行先をファイルへ記録する仕組みは要らない。
  移行先の書込みが失敗した場合は既存の書込み順（子 → 親）により keymap_set を書かず、ファイルは旧形式のまま残る。
- 個別「キーマップを保存」で移行先だけを書いた場合は、keymap_set を未保存のまま残す（§4.4 の空文字化は keymap_set の保存時）。

### §4.3 適用する入口

§5.8.8 の runtime 入口台帳（E1〜E5 / L1〜L3 / P1）の**すべて**に §4.1 を適用する。
特に: 新規作成（キーマップ 1 つを自動作成・トリガー一覧は空）/ 起動時読込 / 通常読込 / 読み込み履歴からの読込 / Import。
**例の復元は移行として扱わない**: `DEFAULT_CONFIG` を新形式（`keymaps[0].triggers` に例のトリガー）へ書き換える。

### §4.4 keymap_set の `trigger_set_path` に書く値

- 読込時の状態を runtime の内部キー（状態 + 旧値 + 移行先 keymap id）で保持し、保存時に次の決定表で書く:

  | 読込時の状態 | 書く値 |
  |---|---|
  | 旧参照なし（空・新形式・新規作成） | `""` |
  | 旧参照を移行した（§4.1-2） | `""`（移行先は同じ保存で必ず書かれる・§4.2） |
  | ~~旧参照があるが、アクティブキーマップが別ファイルの参照を持っていたため使わなかった~~（v0.6 で廃止: §4.5 で新しいキーマップへ移すので「移行した」に含まれる） | — |
  | 旧参照があり、**いずれかのキーマップ**が同じファイルを参照していた（v0.6: アクティブに限らない） | `""`（新形式側で参照済み） |
  | 移行先のキーマップが保存前に削除された（v0.6・§2-25） | `""`（関係を切ったものとして扱う・移行の記録も消す） |

- 書込失敗時は keymap_set 自体が書かれない（既存の書込み順）ため、ファイルの値は変わらない。

### §4.5 旧参照をアクティブへ移行できなかったとき（v0.6 で改訂・§2-23）

§4.1-2 で、旧形式の読込元が**非空**なのに、アクティブキーマップが `trigger_set_path` の**項目を持つ**（別のファイルの参照、または v0.7 で `""` を含む・§2-28）ため
移行できない場合（例: キーマップファイルを共有する別の構成セットが先に移行した / 共有しアクティブだけが違う別の構成セットを保存した）:

- **いずれかのキーマップが旧一覧と同じファイルを参照していれば**何もしない（使用済み・§4.4 の `""`・通知しない）。
- そうでなければ、**新しいキーマップを 1 つ自動作成して旧一覧を付ける**（`id` は既存採番 / `label` = 旧一覧のファイル名由来〔例「旧トリガー一覧（work）」〕/
  `mappings` = {} / 切替キー未設定）。移行（§4.2）と同じく**移行先として未保存**にし、一括保存で「保存しない」を選べない。アクティブは変えない。
- 読込完了時に**情報ダイアログ**で「旧形式のトリガー一覧 <パス> を、キーマップ『<名前>』に移しました（切替キーは未設定です）」と通知する（読込完了メッセージの後・起動時の自動読込でも 1 回）。
- 単一 JSON（Import）はトップレベル `triggers` とアクティブの `triggers` が併存する手編集時だけの状況なので対象外（従来どおり旧値を使わない）。

## §5 保存

### §5.1 保存計画・カスケード

- 保存計画は**trigger_set の実体ごとに 1 行**（識別子 = その実体を参照する最初のキーマップの id）。
- **sequence の識別子は（trigger_set 行の識別子, trigger key）の組**に変える。
- **保存先の衝突回避は保存計画全体**で行う（別キーマップの新規 `f1` 同士が同じ `user/sequences/f1.json` を狙わない。
  trigger_set 同士も同様）。
- 書込順は子→親を維持: sequences → trigger_sets → keymaps → keymap_set → startup。
  payload の組立順は keymap の保存先確定 → trigger_set の既定名・`_parent_refs` 確定 → keymap の内容。
- **トリガーが 0 件で source_path も持たない（空文字）トリガー一覧はファイルを作らない**（keymap の `trigger_set_path` は `""`）。
  source_path を持つもの（実在は問わない）は 0 件でも保存する（削除を反映するため）。

### §5.2 未保存のファイルを持たない子（全種共通）

- **source_path を持たない子（keymap / trigger_set / sequence）は常に未保存扱い**とし、一覧ダイアログの行に出す
  （既定保存先に同名ファイルがあっても黙って「保存しない」にならない）。自動作成キーマップ・Import・移行した子が対象（v0.1 の H2）。

### §5.3 依存（上位の保存必須）の 3 段化

- **trigger_set の保存先が変わる（新規作成を含む）なら、親 keymap の保存が必須**（§5.8.6 を 1 段下へ拡張。
  依存確認の既存の選択肢も同じ扱い）。
- keymap を別名保存したら、ファイル未作成の trigger_set の既定名を再計算する（§5.8.5 の上書き確認を適用）。
- keymap を「保存しない」と明示選択したら（移行先を除く・§4.2）、その keymap の `trigger_set_path` は旧値のまま・未保存マークも残す。

### §5.4 `_parent_refs`

- **trigger_set の親 = keymap ファイル**（従来は keymap_set）。sequence の親 = trigger_set（不変）。keymap の親 = keymap_set（不変）。
- 共有状況判定（§5.8.4）は「直接の親」との比較のまま（trigger_set の比較対象が keymap になる）。
- **移行した trigger_set の初回保存**（§4.4 の内部キーで判定）:
  - 判定では、`_parent_refs` に移行元 keymap_set があれば「現在の親」として扱う（「別の構成」に倒さない）。
  - trigger_set の書込み時は**移行先 keymap を加えるだけ**（移行元 keymap_set は残す）。
  - **移行元 keymap_set 自身への上書き保存が成功した後の後処理**でのみ、trigger_set の `_parent_refs` から
    移行元 keymap_set を除去する（§5.8.1「除去は掃除のみ」への例外として明記）。後処理の失敗・途中の書込み失敗では
    除去しない（共有を多めに見積もる安全側に倒れる）。
  - 別名保存なら移行元 keymap_set を残す（元の構成セットは旧形式で参照し続けるため）。

### §5.5 既定ファイル名

| 対象 | 既定のファイル名（初回保存時のみ・source_path があればそれを使う） |
|---|---|
| keymap（`label` が空） | 構成セットの stem（自動作成分に限らない。複数あれば連番）。構成セット未設定なら `id` |
| keymap（`label` あり） | `label` |
| trigger_set | **親 keymap の保存先ファイルの stem** |

- stem の正規化は現行（§5.6）。衝突回避は §5.1 のとおり計画全体。
- **keymap の既定名の優先順位**: source_path（現行条件）→（label 空なら構成セット stem / label あれば label）→ `id` → `keymap`。
- **「同名の既存ファイルがあれば既定を別名保存へ倒す」規則（§5.8.4）の trigger_set 除外を撤廃**し、keymap / sequence と同じく適用する
  （既定名がラベル由来になり他の構成セットのファイルと衝突し得るため）。帰結として、
  §5.8.4 の「同名 keymap_set を保存先に指定すると trigger_set は上書きされる」は無くなり、
  除外の理由だった「単独所有なら確認を出さない」が trigger_set で空振りし得ることを受け入れる。
- 個別「トリガー一覧を保存」のフォールバック名は 親 keymap の保存先 stem → 無ければ `trigger_set`（一括保存経路の親既定名とは異なる）。

### §5.6 個別保存・個別読込

- 個別「トリガー一覧を保存 / 別名保存 / 読込」は**アクティブキーマップのトリガー一覧**が対象。
  保存先・参照が変わったら**親 keymap を未保存にする**（従来は keymap_set）。
- 個別「キーマップを保存」は保存計画で実行し、**そのキーマップの dirty な trigger_set / sequence があれば一覧ダイアログを出す**。
- 個別「キーマップを読込」は**参照先のトリガー一覧・シーケンスも一緒に読み**、**キーマップの追加として §8.1 の追加規則に従う**
  （切替キーの無い既存があれば先に設定 / 読み込んだキーマップにも切替キー必須〔キーマップが 0→1 個になる場合を除く〕）。

## §6 周辺機能

- **Export**: `keymaps[].triggers` にキーマップごとのトリガー一覧（インライン）を書く。トップレベル `triggers` は `[]`。
  共有実体は各キーマップへ同内容を書く（単一 JSON では共有関係は保存しない）。
- **読み込み履歴**: 変更なし（keymap_set 単位の記録）。
- **参照辿り・孤児棚卸し**:
  - 参照辿りを **keymap_set → keymap → trigger_set → sequence の 3 段**に変える（keymap ファイルの内容を読む）。
  - **旧形式の keymap_set `trigger_set_path` も参照として数え続ける**（未移行の構成セットのトリガー一覧を孤児にしない）。
  - 読めなかった keymap は既存の「読めなかった参照側（理由コード付き）」として扱う。
  - 保護対象に、現在の全キーマップの trigger_set と、その sequence を含める。

## §7 入力判定

### §7.1 優先順位

**停止 > トグル > 直接切替 > トリガー > 置換**（v0.6 で旧版と同じ順へ戻す・§2-13。v0.5 までの「置換 > トリガー」は撤回）。
トリガー・置換はアクティブキーマップのもののみ。「通常トリガー無効化」中は現行どおり直接切替・置換・トリガーすべて無効。
~~既知の制約: 判定はフック時点・実行は UI スレッドのため、切替キー直後のキーが切替後の内容で実行され得る~~ → v0.7 で §2-31（切替中の受け付け停止）により解消。
アクションが空のトリガーは無いものとして扱う（§2-30）。

### §7.2 重複の禁止（編集時）

| 登録するもの | 拒否する相手（追加分を**太字**） |
|---|---|
| トリガーキー | 停止 / トグル / 全キーマップの直接切替キー / 同キーマップの既存トリガー / **同キーマップの置換元キー** |
| 置換元キー | 停止 / トグル / 直接切替キー / **同キーマップのトリガーキー** |
| 直接切替キー | 停止 / トグル / **全キーマップのトリガーキー** / 全キーマップの置換元キー / 他キーマップの切替キー |
| 停止 / トグルキー | 互い / **全キーマップのトリガーキー / 全キーマップの置換元キー** / 直接切替キー |

- 別キーマップのトリガーと置換元キーの重複は許す（別モード）。

### §7.3 読込時の重複（グレー表示）

- アクティブキーマップのトリガーのうち、入力判定で上位に負けるものはトリガー一覧で
  **グレー表示＋理由**を出し、入力判定では使わない（§7.1 の順序で上位が勝つ）。理由の文言:
  | 重なる相手 | 理由 |
  |---|---|
  | 停止キー | 「停止キーと重複」 |
  | トグルキー | 「一時停止/再開キーと重複」 |
  | 直接切替キー（全キーマップ） | 「切替キーと重複」 |
  複数に当たる場合は上位（表の上）の理由を 1 つ出す。停止 / トグルは全体デフォルトと個別指定の解決済み値で判定する。
  **置換元キーとの重なりではトリガーをグレーにしない**（v0.6・トリガーが勝つ。使えなくなる置換はキーボード表示で分かる）。
- **キーマップ一覧**: 直接切替キーが停止 / トグルと重なるキーマップの行はグレー表示＋理由（「停止キーと重複」/
  「一時停止/再開キーと重複」）。キーでは切り替わらない（§7.1 で停止 / トグルが勝つ）が、**一覧からの選択・編集はできる**。
- **キーボード表示**: 置換元キーとトリガーが重なるキーは**トリガーの表示を優先**する（v0.6 で旧版の表示へ戻す）。
  予約キー（停止 > トグル > 切替）が最後に上書きする現行の順は維持。
- 編集（キー変更・削除）はできる。重複が解消すれば通常表示に戻る。

### §7.4 フック開始の検証

- 「トリガーが 1 件も無い」判定は**全キーマップのトリガー・置換元キー**で行う（切替で使えるため）。
- **開始を止める重複は「停止キーとトグルキーが同じ」だけ**。停止 / トグルとトリガー・置換元キー・直接切替キーの重なりは
  開始を止めない（現行の `hook_controller.py:193-222` のトリガー / 置換元キーとの検証を外す）。
  重なりは §7.3 のグレー表示・キーボード表示の色・§8.5 の案内で知らせる。
- 編集時の拒否（§7.2）は維持する（新たな重なりを作らせない。重なりが生じるのは全体デフォルトの変更等で他の構成セット側から
  持ち込まれる場合のみ・`key_input.md` §7.6）。

## §8 UI

### §8.1 キーマップ管理

- **一覧の選択 = アクティブ化**。「選択」ボタンは削除する。ダブルクリックの編集は維持。
  帰結: 矢印キーで移動するだけで切り替わる / 編集・削除・個別の保存・読込の対象は常にアクティブなキーマップ /
  連続実行中は他のキーマップを選べない（＝編集できない）。
- アクティブ変更で構成セットを未保存にしない（直接切替キー経由と統一）。
- **追加**:
  1. 切替キーの無い既存キーマップがあれば、一覧順に 1 つずつ「<名前> に切替キーを設定してください」の
     エラーダイアログ → OK でそのキーマップの編集ダイアログを開く → 設定されたら次へ / キャンセル・空のままなら追加を中止。
  2. 追加ダイアログで**ラベル（任意）と切替キー（必須・空は拒否）**を入力して作成する。**切替キーが空・不正・重複のときはエラーを示してダイアログを開いたままにする**（閉じて追加を中止しない。§2-22）。キャンセルしたときだけ追加を中止する。
- **編集**: キーマップが 2 つ以上のときは切替キーを空にできない（拒否）。1 つだけのときは空にできる。
  読込済みデータで切替キーの無いキーマップが複数あっても、読込は拒否しない（追加時に 1. で拾う）。
- **削除**: キーマップが 1 つだけのときは削除できない。未保存のトリガー一覧・シーケンスを持つキーマップの削除確認では、
  それらが破棄されることを明示する。
- アクティブ切替時にトリガー一覧・シーケンス欄・キーボードウィンドウ・CompactView の表示を再描画する。

### §8.2 連続実行中の切替禁止

- 対象: 一覧の選択 / 直接切替キー / アクティブなキーマップの削除。
- 連続実行中（一時停止中を含む）は切り替えず、**ステータスバーの一時メッセージ領域**に「連続実行中のためキーマップを切り替えられません」を表示する（§2-21）。
  一覧の選択はアクティブの行へ戻す。

### §8.3 トリガー一覧

- アクティブキーマップのトリガー一覧を表示する（空もあり得る）。§7.3 のグレー表示。
- アクティブ以外のキーマップの未保存の編集は切替で失わない（runtime に保持）。

### §8.4 一時停止の表示（改名）

- ボタン（FullView / CompactView）: 「通常トリガー無効化」⇔「通常トリガー有効化」→ **「キーマップ一時停止」⇔「キーマップ再開」**。
  ボタン幅を文言で揺らさない既存規定（`features.md` の対の文言の幅）に新しい対を載せる。
- ステータス欄の「通常トリガー: ON/OFF」→ **「キーマップ: 動作中 / 一時停止」**に改め、既存の「キーマップ: <名前>」表示と
  1 項目に統合してよい（形は実装時に決める。例「キーマップ: <名前>（一時停止）」。現行の「(待機)」表記はこれに置き換える）。
- 「有効/無効トグルキー」のラベル・エラーメッセージ → **「一時停止/再開キー」**（「モード切替キー」表記の箇所も揃える）。
- 「通常トリガーと重複しています」等、トリガー一覧を指す「通常トリガー」の表記は変えない。
- 内部名（`custom_input_enabled` / `TRIGGER_*_TEXT` 等）の改名はしない（表示文言のみ）。

### §8.5 重複キーを押したときの案内

- グレー表示の割り当て（トリガー一覧の行 / キーマップ一覧の行）に対応するキーが押され、上位の割り当てが働いたとき、
  **ステータスバーの一時メッセージ領域に重複と変更の案内を出す**（§2-21）。例:
  - 「f12 は停止キーと重複しているため、トリガーは実行されません。トリガーのキーを変更してください」
  - 「f9 は停止キーと重複しているため、キーマップ <名前> へ切り替えられません。切替キーを変更してください」
  - 「f3 は切替キーと重複しているため、トリガーは実行されません。トリガーのキーを変更してください」
  - ~~「a は置換と重複しているため、トリガーは実行されません…」~~（v0.6 で廃止・トリガーが勝つため）
- **上位の動作の表示を消さない**: 停止キーでフックが止まる場合は「停止しました」と案内を併記する（上書きしない）。
- 置換元キーと停止 / トグル / トリガーの重なりは案内しない（キーボード表示で分かる）。
- 「キーマップ一時停止」中は直接切替・置換・トリガーがすべて無効なので、**重なりの案内は一切出さない**（停止 / トグルの動作自体の表示は従来どおり）。
- 案内の判定には §2-27 の表（グレー表示の再判定時に作る読み取り専用の結果）を使う。

## §10 受け入れ条件（ドラフト）

1. キーマップごとに別のトリガー一覧・シーケンスを持ち、アクティブ切替で入力判定と表示が切り替わる（§3.3 / §8.1）
2. 旧形式の構成セット・単一 JSON を読むと旧トリガー一覧がアクティブキーマップに付き、未保存表示になる（§4.1 / §4.2）
3. **旧形式を読込 → 無編集で保存 → 再読込**でトリガーが残る。アクティブを変えてから保存しても移行先が変わらない（§4.2 / §4.4）
4. 移行先キーマップは一括保存で「保存しない」を選べない。移行後 A → B に切り替えて保存 → 再読込しても旧トリガー一覧は A に付いたまま（§4.2）
5. 保存後の keymap ファイルが `trigger_set_path` を持ち、移行済みなら keymap_set の `trigger_set_path` は `""`（§3.1 / §4.4）
6. 新規作成・キーマップ 0 個の読込・例の復元で、キーマップが 1 つある（§4.1-4 / §4.3）
7. 自動作成キーマップ・Import した子が、既定保存先に同名ファイルがあっても黙って保存されずに終わらない（§5.2）
8. 同じ trigger_set を複数のキーマップが参照する構成で、編集が共有され、保存で二重化・上書き競合しない（§3.3 / §5.1）
9. 別キーマップの同名新規シーケンスが互いに上書きしない（§5.1）
10. 2 つ目以降の追加・キーマップの個別読込で切替キーが必須、切替キー無しの既存があれば先に設定させる。2 つ以上で切替キーを空にできない（§8.1 / §5.6）
11. キーマップが 1 つのときは削除できない（§8.1）
12. 一覧の選択でアクティブになり、構成セットは未保存にならない（§8.1）
13. 既定ファイル名が §5.5 に従う
14. トリガーと置換元キー等の重複が §7.2 どおり拒否され、読込時の重複（切替・停止・トグル）はグレー表示＋理由・入力判定で使われない。置換元キーと重なるトリガーはグレーにならずトリガーが動く（§7.2 / §7.3 / v0.6）
15. 連続実行中（一時停止中を含む）はキーマップを切り替えられず、ステータスバーの一時メッセージ領域に表示される（§8.2・§2-21）
16. 移行後初回保存で trigger_set が別名保存に倒れず、`_parent_refs` の移行元除去は keymap_set 上書き保存の成功後のみ（§5.4）
17. 旧参照をアクティブへ移行できない場合、旧一覧を付けた新しいキーマップが作られ通知され、保存後は構成セットの旧値が `""` になる。いずれかのキーマップが同じファイルを参照していれば作られない（§4.4 / §4.5 / v0.6）
18. 孤児棚卸しが新旧両方の参照を辿り、未移行の構成セットのトリガー一覧を孤児にしない。keymap ファイルを keymap_set と誤判別しない（§6 / §3.1）
19. Export → Import → 保存 → 再読込でキーマップごとのトリガー一覧が保たれる（§3.2 / §6）
20. 一時停止の表示が §8.4 の文言になり（ボタン・ステータス・トグルキーのラベル）、挙動は変わらない（§8.4）
21. 停止 / トグルとトリガー・置換元キー・直接切替キーが重なってもフックを開始でき、停止 = トグルのときだけ開始できない（§7.4）
22. 切替キーが停止 / トグルと重なるキーマップは一覧でグレー表示され、一覧から選択・編集できる（§7.3）
23. グレー表示の割り当てのキーを押すとステータスバーの一時メッセージ領域に案内が出て、停止時は「停止しました」も残る（§8.5・§2-21）
24. キーボード表示で置換元キーとトリガーが重なるキーはトリガーが表示される（§7.3 / v0.6）
25. 既存テスト全通過（必要な期待値更新を含む）・smoke 通過
26. 追加ダイアログで切替キーが空・不正でもダイアログが閉じず、入力し直して作成できる（§8.1・§2-22）
27. `trigger_set_path` の項目を持つ（値が `""` の）キーマップには旧形式が移行されない（§4.1-2 / v0.6）
28. 移行先のキーマップを保存前に削除して保存すると、構成セットの旧値が `""` になり移行の記録も残らない（§4.4 / v0.6）
29. 同じキーマップファイルを個別読込で二重に読めない（§2-26）
30. キー入力時の重なりの案内は保持した表を引き、表はデータの変更時に作り直される（§2-27）
31. 保存の前後でトリガー一覧の選択行・シーケンスの実行位置が保たれる（統合レビュー H-1・§3.3）
32. アクティブが `trigger_set_path: ""` を持つ構成セットの旧一覧も新キーマップへ移され通知される（§2-28）
33. 移行した trigger_set の行で「保存しない」を選べない（§2-29）
34. アクションが空のトリガーと置換元キーが重なるキーでは置換が動く（§2-30）
35. 切替キーの直後、切替が終わるまでに届いたキーは停止 / トグル以外素通しされ、切替後に受け付けが再開する（§2-31）
36. 構成セットの読込・例の復元の後、全キーマップの実行位置・選択行が初期化される（完了判定前レビュー H-2）
37. 既存の一覧の共有に加わったキーマップが、次の保存でその一覧の `_parent_refs` に記録される（完了判定前レビュー codex High）
