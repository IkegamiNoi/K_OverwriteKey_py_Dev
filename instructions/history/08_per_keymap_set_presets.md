## §1 目的 / 背景

phase 08 で hotkey プリセットは **`config/config.json` が指すアプリ全体のライブラリ**になった
（正本 `data_schema.md` §5.10）。これに対し、**「この構成セット専用のプリセットを持ちたい」**という
需要へ応えるのが本フェーズ。**グローバル既定 + keymap_set 側の個別指定（上書き）**という、
hook キー（§5.9）と同型の構造を導入する。

**挙動変更 + スキーマ変更**を伴う。影響レイヤは
**application（解決順序・保存先の算出）+ presentation（切替 UI・保存先の切替）+
スキーマ（keymap_set のキー復活 + フラグ追加 / グローバル既定パスの変更）**で、
**domain のプリセット構造そのものは変えない**。

### 現状監査（2026-08-09・phase 08 完了時点）

- **読み出し**: `split_loading.load_global_hotkey_presets(service, *, config_root) -> list | None`。
  config.json の `hotkey_presets_path`（既定 `user/hotkey_presets/default.json`）から読み、
  **読めた＝`list`（空を含む）/ 読めない＝`None`（置き換えない）**。戻り値は正規化済み
  （`domain/config.py::normalize_hotkey_presets`）。
- **供給の 2 経路**（正本 §5.8.8 の入口台帳）:
  - **注入 API `ConfigService.apply_global_defaults(runtime, *, config_root)`** …
    入口台帳 **E1〜E5**。**keymap_set を引数に取らない**。
  - **通常読込 `split_loading.build_runtime_data_from_split(service, keymap_set, *, config_root)`** …
    **L1〜L3**。**keymap_set の dict を持っているが、そのファイルパス（stem）は知らない**
    （パスを持つのは呼び出し元の `load_split_config`）。
- **書き手は 1 本のみ**（§5.10.3）: `PresetManagerDialog.on_ok` → `App.save_hotkey_presets` →
  `HotkeyPresetsIo.write_global_presets`（成否 bool）→ `ConfigService.save_global_hotkey_presets`。
  **保存カスケードは書かない**。失敗時は runtime を更新せずダイアログも閉じない。
  プリセット編集は **keymap_set を dirty にしない**。
- **keymap_set の `hotkey_presets_path`** は phase 08 で**生成停止・読込時無視**にした
  （§5.1 の「削除禁止の例外＝生成停止」）。**既存ファイルには残っている可能性がある**。
- **`build_keymap_set_payload` は固定キー集合で payload を生成する**ため、keymap_set の未知キーは
  再保存で必ず落ちる（「生成停止」より強い性質）。→ 新キーの追加箇所は一意に定まる。
- **Export は runtime を丸ごと出力**し（`export_runtime_data`）、**Import は未知キーを保全**する
  （`ensure_config_compatibility` が `safe_deepcopy`）。→ 個別指定キーが外部ファイル経由で
  runtime へ載り得る（§2 で強制 OFF を規定）。
- 同型の先行実装 = **hook キー（§5.9）**: `hook_keys_individual`（bool・既定 false）+ 既存キー 2 本。
  移行判定 `resolve_hook_keys_individual` は **フラグがあればその値 / 無ければ「非空なら ON」**（§5.9.3）。
  **本フェーズはこの「無ければ非空で ON」を採らない**（§2）。

## §2 確定事項（ユーザー確定 2026-08-09）

### 構造

- **グローバル既定は残す**。個別指定は**上書き（オーバーライド）**であり、グローバルを置き換えない。
- **個別指定の有無は keymap_set 側が持つ**。**後方互換必須**（既存 keymap_set は個別指定なし＝
  グローバル利用として動く）。
- **【G】ファイル配置を変更する**:
  - **グローバル既定パスを `user/hotkey_presets/global/default.json` へ移す**（config.json の
    `hotkey_presets_path` の**既定値**を変更）。
  - **個別ファイルは `user/hotkey_presets/<keymap_set の stem>.json`**（直下）。
    命名・フォールバック・「衝突を避けて別名へ逃がさない」は **trigger_set と同じ流儀**（§5.6）。
  - **【v0.7】`user/hotkey_presets/global/` は「グローバル専用の予約ディレクトリ」**とする。
    **グローバルライブラリはこの配下に置く**（config.json の `hotkey_presets_path` はここを指す想定）。
    **個別ファイルをこの配下へ保存しない**（【O4】で拒否する）。
    → 名前空間を分けることで、**生成される個別パスとグローバルが構造的に衝突しない**。
  - **移行は手動**（互換フォールバック読みは実装しない）。**移行手順は 2 段**で、正本へ明記する:
    1. `user/hotkey_presets/default.json` を `user/hotkey_presets/global/default.json` へ**移す**
    2. **config.json に `hotkey_presets_path` を明示保存している場合は、その値も新パスへ書き換える**
       （**v0.4・敵対的レビュー H1**。既定値の変更は明示値には効かないため、①だけでは旧パスを
       読み続けて失敗し、**マネージャ保存で旧パスが再生成される**ループになる）
  - **移行しないと組込既定が表示される**（ファイルは失われない）。
  - **起動時のディレクトリ骨格作成（`ensure_split_config_dirs`）へ `user/hotkey_presets/global/` を追加**する。
- **【A】個別パスのキーは旧 `hotkey_presets_path` を再利用する**（keymap_set 側）。
  **フラグが真のときだけ読む**。新キーは増やさない。
- **【新キー】`hotkey_presets_individual`（bool・既定 false）** を keymap_set へ追加する。

### 解決と供給

- **【§3-5】移行規則: `hotkey_presets_individual` を持たない keymap_set は常に OFF**。
  **hook キーの §5.9.3（フラグ無し + 非空なら ON）を採ってはならない**
  （phase 08 の残置 `hotkey_presets_path` が個別指定として復活してしまうため）。
  フラグの判定は**キーの有無ではなく値**で行う（キーが無ければ false）。
- **【§3-5・v0.8】フラグキーを持たない keymap_set は `hotkey_presets_path` も引き継がない**
  （runtime へ載せず**未設定＝空文字として扱う**。Import の強制 OFF【K】と同じ落とし方）。
  - 理由: phase 08 以前の keymap_set には**旧グローバルパス `user/hotkey_presets/default.json`** が
    残っており、config 配下＝有効なパスと判定されるため、**初回 ON + OK の保存先がそのまま残置パス**に
    なっていた（stem 由来の名前にならない / 同じ残置パスを持つ複数セットが 1 ファイルを無警告共有する
    ＝【M】の事故が既定で起きる / `global/` 配下でも現行グローバルと同一でもないため【O4】も素通りする）。
  - **判定はフラグキーの有無**で行う（値ではない）。phase 09 以降の keymap_set は 2 キーを常に出力するため、
    「フラグキーがある」＝ アプリが書いたパスとみなせる。**フラグが false でもキーがあればパスは保持する**
    （【N】の再 ON 復帰を壊さない）。
  - これにより **v0.7 の既知の制約「残置パスの初回 ON」は撤回**する。
- **【C】個別ファイルが読めない（`None`）ときはグローバルへフォールバックする**。
  グローバルも読めなければ従来どおり**置き換えない**（runtime の既定を維持）。
- **【I・v0.8 で再採用】トグルで一覧を切替先から読み直す**（v0.4 の【I 撤回】を反転）。
  マネージャ内の切替は「次の OK でどこへ書くか」と「いま編集している一覧」の**両方**を切り替える。
  - **OFF → ON**: 個別ファイルが**読めればその内容へ差し替える** / **読めなければ現在の一覧を引き継ぐ**【E】
    （＝ 実質のコピー。初回 ON の導線はこれまでどおり）。
  - **ON → OFF**: グローバルが**読めればその内容へ差し替える** / **読めなければ組込既定へ差し替える**
    （**現在の一覧を持ち越さない**。読み出し規則で「置き換えが起きない＝組込既定のまま」になるのと同じ状態を作る）。
    → **個別の内容が OFF 状態へ持ち越されないため、グローバルへ流出する経路が無くなる**
    （v0.4【H2】の狙いをここで担保する）。**OK ではその組込既定がグローバルとして書かれる**
    ＝ **失われた / 壊れたグローバルを組込既定で作り直す導線**になる。
  - **編集中の内容が破棄される場合は確認ダイアログを出す**（破棄してよいか）。**キャンセルならチェックを
    元の状態へ戻し、一覧も保存先表示も変えない**。**一覧が未編集なら確認せずに差し替える**。
  - **runtime への反映は OK を押したときだけ**（トグルでは runtime を変更しない）。
    → **プリセット単独の注入 API は作らない**（読み直しは読み出し関数の呼び出しで足りる）。
- **【O2・v0.8 で改訂】個別パスが config 配下でなくても、読み出しではそのファイルを読む**。
  読めなければ【C】でグローバルへフォールバックする。**キーの値は書き換えない**。
  - **書き込みは従来どおり管理下の既定パスへ寄せる**【O3】。＝ **外部パスは「初回に内容を拾うための
    移行導線」**であり、**次の保存で `hotkey_presets_path` が管理下の値へ置き換わる**（v0.6 の dirty 規則）
    ため、外部参照は残り続けない。手編集・別実装由来の外部パスを**マネージャの保存先にしない**という
    【O】の狙いは書き込み側だけで担保する。
  - **UI には「config 外のファイルを読み込み中・次の保存で管理下へ移る」旨と、これから書く既定パス**を
    表示する【R】（v0.7 までの「無効」表示は廃止）。
  - **別名保存の複製【L】は対象外**（複製元の解決は書き込み側と同じ判定を使うため、config 外からは
    複製しない）。新しい既定パスを指すだけで、次のマネージャ確定で実体が作られる。
  - **外部パスが管理下の値へ置き換わるのは「個別 ON での保存が成功したとき」だけ**。
    **OFF で保存した場合は書込先がグローバルなので置き換わらず、外部パスが保持される**【N】
    （次に ON へ戻したときに【O3】で寄せられる）。受入条件 15 はこの区別込みで判定する。
  - **【既知の制約】読み出しは同期実行**のため、**到達不能な UNC / 切断されたネットワークドライブ /
    極端に大きい JSON** を指していると、読み込み中は UI が待たされる（config 外に限らず、
    trigger_set・keymap の読み出しと同じ性質。本フェーズで非同期化はしない）。
- **【O3・v0.6】config 外のパスのまま個別へ書こうとした場合は、書込先を管理下の既定パスへ寄せる**
  （**グローバルへ倒さない / 拒否もしない**）。書き込みでグローバルへ倒すと
  **グローバルライブラリを破壊する**ため、書込先は必ず個別側に取る。
  - **「書き込みに使えないパス」は「使えるパスが記録されていない」と同一視する**。
    ＝ **ON + パス未設定と同じ扱い**で既定パス `user/hotkey_presets/<stem>.json` を算出し、
    **その時点の一覧を書いて新規作成する**【E】。既存の分岐を増やさない。
  - **保存先はチェックに追従して OK 前に表示される**【R】ため、これは「黙って別の場所へ書く」に
    当たらない。**表示は「記録されていた保存先が config 外のため書き込みには使わない」旨を添える**
    （**v0.8**: 内容の読み出しには使う。【O2】）。
  - 対象は**その保存の実効的な書込先が個別のとき**だけ（＝ ON のまま OK / OFF → ON の確定）。
    **OFF での確定は書込先がグローバルなので対象外**。
  - **config 外の元ファイルへは書かない・消さない**（**v0.8**: 読み出しだけは行う【O2】。
    書く内容は表示中の一覧から作る＝【E】）。
  - **【N】との関係**: OFF で保持するのは**使えるパス**であり、**書き込みに使えないパスは
    保存成功時に管理下の値へ置き換える**（下記の dirty 規則に従う）。
- **【O4・v0.7】保存先ガード: 次のいずれかに当たる個別の保存先へは書かず、保存を拒否する**
  （理由を表示し、**ダイアログを閉じない・runtime を変更しない・dirty を汚さない**。
  **キーの値も書き換えない**）。**【O3】のリダイレクトより後の最終関門**として、
  書き込み直前に判定する。
  1. **保存先が `user/hotkey_presets/global/` 配下**（予約ディレクトリ違反）
  2. **保存先がグローバルの読み先（config.json の `hotkey_presets_path` 解決値）と同一ファイル**
     — 判定は**比較専用の canonical identity**（`canonical_path`）で行う
  - 2 は **1 だけでは防げない**。config.json が `user/hotkey_presets/` 直下を指し、その名前が
    構成セットの stem と一致すると、**保存先は `global/` の外にありながらグローバルの実体と同一**になる。
    このとき**専用プリセットとグローバルが同一ファイルの別名**になり、
    **専用側の編集が全構成セットのグローバルへ漏れ続ける**（一度きりの損失ではなく継続的なエイリアス）。
  - **文言は 2 種類に分ける**。1 = 「`global/` はグローバル用のため専用の保存先にできない」/
    2 = **「config.json の `hotkey_presets_path` を `global/` 配下へ直す」案内**（＝移行手順②への誘導）。
  - **【O3】と同居する**: 書き込みに使えないパス → 既定パスへ寄せる → **その結果が上記に当たれば拒否**。
  - **読み出しは対象外**（グローバルと同一ファイルでも読めてしまうが、内容は同じなので実害がない）。
- **【既知の制約として明記する】**（正本 §5.10.4 へ昇格させる）
  - **~~残置パスの初回 ON~~（v0.8 で撤回）**: フラグキーごと残置パスを落とすようにしたため解消。
    ただし**フラグキーを持つ keymap_set（phase 09 以降）で `hotkey_presets_path` を手編集した場合**は、
    引き続き**記録済みパスがそのまま個別ファイルの保存先になる**（アプリ由来かを値から判別できないため）。
  - **複製の失敗**: 別名保存時の複製（【L】）に失敗した場合は、**keymap_set 本体の保存ごと中止**する。
    中途半端に成功させると「専用のはずが元と共有」状態が黙って生まれるため。
  - **OFF へ戻す時にグローバルが読めない場合**（v0.8 で解消 + 制約の中身を差し替え）:
    一覧は**組込既定へ差し替わり**、OK で**グローバルが組込既定として作成 / 修復される**【I】。
    **個別の内容がグローバルへ流出する経路は残らない**（再オープン後も同じ結果になる）。
    残る制約は「**壊れた既存のグローバルファイルは退避されずに上書きされる**」こと
    （読めないファイルも上書きするのは §5.10.4 の既定規則どおり。破損検知・退避は §6 でスコープ外）。
- **【P】解決の入力は keymap_set に保存されたパス**とする（stem からの再導出はしない）。
  stem は**新規に保存先を決めるときの既定名算出**にだけ使う。
  → `build_runtime_data_from_split` のシグネチャは変えない。
- **入口台帳のうち個別指定が効くのは L1〜L3 だけ**。**E1〜E4 は常にグローバル**
  （`apply_global_defaults` のシグネチャは変えない）。
- **【K】Import（E5）では個別指定を強制的に OFF にする**。Export 側は現状のまま（runtime 丸ごと出力）。
  **外部指定の任意パスへ書く経路を作らない**。
  - **落とす場所**: `load_legacy_runtime_data` の**直後・`apply_global_defaults` を呼ぶ前**
    （Import 経路 1 箇所。`ensure_config_compatibility` には入れない＝通常読込へ波及させないため）。
  - **落とし方（v0.4・M5）**: `hotkey_presets_individual` を **`False`**、
    `hotkey_presets_path` を **`""`（空文字）**にする。以後の保存でも §3-1 のとおり
    **2 キーは常に出力**されるため、値が一意に決まる。

### 保存と UI

- **【B】書き手は引き続きプリセットマネージャの 1 本**（正本 §5.10.3 を維持）。
  個別指定 ON のときは**書き込み先が個別ファイルへ切り替わる**だけ。成否契約
  （失敗時は確定せずダイアログを閉じない）は不変。**保存カスケードはプリセットを書かない**。
  → **個別プリセットは keymap_set の子ファイルにしない**（§5.8 の保存計画に載せない）。
- **【H】個別ファイルは ON 操作では作らない**。**マネージャの確定（OK）で初めて作られる**
  （書き手 1 本を維持）。実体が無い間は【C】のフォールバックが効く。
- **【E・v0.8 で縮小】ON 直後の内容は、個別ファイルが無い（読めない）ときだけ
  「その時点の一覧」を引き継ぐ**（＝グローバル由来の内容から始まり、OK で個別ファイルへ書かれる
  ＝実質のコピー）。**個別ファイルが読めるならその内容へ差し替える**【I】。
  **OFF に戻しても個別ファイルは削除しない**。
- **【H2・v0.8 で撤回】OFF へ戻した OK も書き込む**（表示中の一覧をグローバルへ書く）。
  v0.4 の【H2】は「編集中の一覧でグローバルを上書きしない」ための規定だったが、**v0.8 では
  トグル時にグローバルを読み直す**【I】ため、**書かれる内容はグローバル自身の内容**（読めなければ
  **組込既定**）になり、事故の前提が消える。**例外を作らず常に書く**（＝グローバルが失われている
  場合はここで組込既定として作り直される）。
- **【I2・v0.9】ダイアログを開いた時点でも、OFF なら表示元へ合わせて一覧を確定させる**
  （グローバルが読めればその内容 / 読めなければ**組込既定**）。v0.8 は読み直しを**トグル時のみ**に
  置いたため、**runtime が個別由来の一覧を持ったまま OFF になっている状態**（グローバル欠損 +
  個別 ON セットの Import。Import は【K】で強制 OFF にするが、**グローバルが読めなければ
  `apply_global_defaults` は置き換えない**）で開いてそのまま OK すると、**個別由来の内容が
  グローバルとして書かれた**（ラベルは「組込既定を表示中」と出るのに内容が違う＝表示と実体の乖離）。
  **ON のときは確定させない**（【E】の「個別ファイルが読めなければその時点の一覧を引き継ぐ」を壊さないため）。
- **【S・v0.9】個別ファイルへ書く直前の上書き確認**。次の 3 条件を**すべて**満たすときだけ確認する:
  ① **個別として書き込む**（OFF ＝ グローバルへの書き込みは対象外）
  ② **【O3】で寄せた後の最終的な保存先に実体がある**
  ③ **その実体の内容が、ダイアログが直近に読み込んだ一覧と異なる**
  （＝ダイアログを開いた時点の一覧、またはトグル【I】で差し替えた内容。**編集後の一覧とは比較しない**）。
  **保存先が読めない（破損）ときも異なるものとして扱う**
  - **③を「出どころ（読み出し元パス）の比較」にしない**理由: 別名保存【L】でコピー先の実体を採用した
    場合、keymap_set のパスだけが新しくなり**一覧は別名保存前のファイル由来のまま**になるため、
    現在の状態から出どころを導くと**保存先と一致してしまい確認が素通りする**
    （v0.9 の敵対的レビュー High）。**内容比較なら出どころの追跡なしで正しく発火する**。
  - **【v0.10】確認は 3 択**（**上書きする / 既存を読み込む / キャンセル**）。
    - **上書きする** … そのまま書き込む。
    - **既存を読み込む** … **保存先の実体の内容へ一覧を差し替え、保存せずダイアログも閉じない**。
      **`_loaded_temp` 相当（破棄確認の比較基準）も同時に更新する**。**明示的な選択なので
      追加の破棄確認は出さない**。差し替え後に改めて OK すると内容が一致するため確認は出ず、
      **既存の内容が保たれたまま保存が通る**。
    - **キャンセル** … 何もしない（下記の不変契約）。
    - **保存先が読めない（破損）ときは「既存を読み込む」を出さない**（読む対象が無いため 2 択）。
  - 「キャンセル」なら**保存せず、ダイアログを閉じない**。`data`・dirty・ファイルの**いずれも変更しない**
    （【O4】の拒否と同じ契約）。ユーザーはチェックを戻すこともできる。
  - **【v0.10・この 3 択が必要な理由】** 2 択だと**既存ファイルの内容を採る手段が UI に存在しない**。
    記録パスが空のときは【I】のトグル読み直しが空振りし（読み出しは**記録パス**のみを見る）、
    **`hotkey_presets_path` が記録されるのはプリセットの保存が成功した後**なので、
    確認を断り続ける限りその実体には二度と到達できない。
  - **通常運用では発火しない**: 初回 ON で新規作成（②で除外）/ 記録パスのある再 ON・ON のままの
    内容編集（保存先の実体＝読み込んだ一覧なので③で除外。**編集した内容は比較対象ではない**）/
    OFF での OK（①で除外）/ 内容がたまたま一致している共有【M】（③で除外）。
  - **発火する**: 記録パスが空のままの ON（別名保存で既存の構成セットを上書きした後など）/
    **別名保存でコピー先の実体を採用した後の ON**【L】/ config 外パスからの移行【O2】/
    保存先が破損して読めないとき。
  - **【L】との関係（v0.9）**: 別名保存でコピー先の実体を採用した場合、**一覧は別名保存前のファイル
    由来のまま表示される**（【I2】は OFF 限定のため差し替えない＝**手編集された外部パスを読むのと同じ扱い**）。
    **保存先は管理下の既定パスのまま**で、内容が違えば本条項の確認が挟まる。
  - **【M】との関係**: 【M】が許容するのは**共有そのもの**であり、本条項は**共有が始まる瞬間の
    データ損失**だけを止める関門。**【L】の「別名保存では上書き確認を新設しない」とは矛盾しない**
    （そちらは実体があれば**複製しない＝内容が失われない**経路）。
- **【N】OFF で保存しても個別パスは消さない**（フラグだけ false）。再 ON で同じファイルへ戻る。
- **【D】切替 UI はプリセットマネージャ内**（「この構成セット専用にする」チェック + 保存先パス表示）。
- **【J】チェックの確定も OK ボタンで行う**（キャンセルなら**フラグも dirty も変えない**）。
- **【F】keymap_set が未保存（パス空）のときは ON にできない**（UI で無効化し理由を表示）。
  **【Q】**この可否表示は**保存 / 読込 / 新規作成の後に再評価**する。
- **個別指定の切替は keymap_set を未保存（dirty）にする**（`hotkey_presets_individual` は
  keymap_set に保存される値のため。§5.9.4 と同型）。**プリセットの内容編集は dirty にしない**。
- **【R】マネージャに保存先パスを表示**する。状態に応じて次を出し分ける（**v0.4・M6**）:
  - 個別が読めた … 個別のパスを表示
  - 個別が読めずグローバルへフォールバック中 … **「グローバルを表示中」**
  - **個別もグローバルも読めない** … **「読み込めませんでした（既定を表示中）」**
    （置き換えが起きず組込既定が出ている状態。「グローバルを表示中」と誤表示しない）
  - **個別パスが config 外（v0.8）** … **「config 外のファイルを読み込み中。次の保存で管理下へ移る」旨 +
    これから書く既定パス**（【O2】【O3】。v0.7 までの「無効」表示は廃止）
  - **OFF でグローバルが読めない（v0.8。ON → OFF のトグル直後を含む）** …
    **「グローバルを読み込めませんでした。組込既定を表示中（OK でグローバルを作成します）」**
  - **（v0.8）表示はチェックの切替に追従して更新する**（一覧の差し替えと同時に行う【I】）

### パスと制約

- **【O・v0.8 で範囲を限定】個別パスは config 配下に限定する**（**書き込み側の制約**。
  アプリが `hotkey_presets_path` へ書く値は必ず config 配下になる）。**読み出しは config 外も許容する**
  【O2】。表記は正本 §5.7 に従う（config 配下は相対・区切りは `/` 正規化）。
- **【M】同一 stem の複数 keymap_set が同じ個別ファイルを共有し得る**ことは
  **既知の制約として許容**する（`_parent_refs`・共有状況判定・誤爆保護は効かない）。正本へ明記する。
- **【L・v0.4 で反転】keymap_set を別名保存したら個別ファイルも追随させる**（複製する）。
  - 新しい保存先の stem から**個別パスを再計算**し、keymap_set の `hotkey_presets_path` を新パスへ更新する。
  - **コピー先に実体が無ければ複製する / 既にあれば複製せずそれを使う**
    （§5.8.3 の既定規則「保存先に実体があれば保存しない」と同じ思想。**上書き確認を新設しない**）。
  - **コピー元が存在しない場合（ON だが未確定でまだ実体が無い）は複製しない**。新パスを指すだけで、
    次のマネージャ確定で作られる。
  - **「書き手 1 本」との整合**: ここで行うのは**既存ファイルの複製**であり、
    **プリセットの内容を決める書き手は引き続きマネージャだけ**（runtime の内容を書き出さない）。
- **正規化の規則は正本 §5.10.2 のまま**（読み出し側 1 箇所・`list | None`・非文字列要素の除去）。
- **【O 補足】個別ファイルの中身の形は共通**（根キー `hotkey_presets` の配列）。

## §3 設計本文

### §3-1 データモデル

| 置き場 | キー | 型・既定 | 意味 |
|---|---|---|---|
| `config/config.json` | `hotkey_presets_path` | str・既定 **`user/hotkey_presets/global/default.json`** | **グローバルライブラリ**のパス（**アプリは書かない＝読むだけ**）|
| keymap_set | `hotkey_presets_individual` | bool・**既定 false** | 個別指定のフラグ（**新規**）|
| keymap_set | `hotkey_presets_path` | str | **個別ファイル**のパス（**旧キーの再利用**。フラグが真のときだけ読む）|

- keymap_set の 2 キーは **payload で常に出力する**（`build_keymap_set_payload` は固定キー集合のため）。
  OFF のときも**パスは空文字化しない**（【N】）。
- **【v0.7】`hotkey_presets_path` は payload 出力時に §5.7 の表記へ正規化する**
  （config 配下は相対・区切りは `/`。同じ payload の `trigger_set_path` と同じ扱い）。
  手編集・別実装由来の `user\hotkey_presets\main.json` や config 内絶対パスを**そのまま書き戻さない**。
- 個別ファイルの既定パス: `user/hotkey_presets/<stem>.json`（stem 規則とフォールバック名は §5.6 準拠）。

### §3-2 解決順序（runtime へ載せる時点で確定する）

**keymap_set を runtime へ載せる時点の 1 回**で確定させる（hook キー §5.9.2 と同型）。

1. `hotkey_presets_individual` が**真** … **個別パスから読む**
   - 読めた（`list`・空を含む）… **それを採用**
   - 読めない（`None`）… **グローバルへフォールバック**【C】。グローバルも `None` なら**置き換えない**
2. **偽**（キー無しを含む）… **グローバルから読む**（現行どおり。`None` なら置き換えない）

- **（v0.8）個別パスが config 外でもそのまま 1. で読む**【O2】。読めなければ【C】でグローバルへ倒れる。
- **（v0.8）`hotkey_presets_individual` キーを持たない keymap_set は、`hotkey_presets_path` も
  未設定として runtime へ載せる**（§3-5）。したがって残置パスは 1. にも保存先算出にも現れない。
- **E1〜E4 は常にグローバル**、**E5（Import）は個別指定を落としてグローバル**【K】。
- **（v0.8）マネージャのトグルでは一覧を読み直す**【I】が、**runtime へ反映されるのは OK を押したとき**
  （ON なら個別へ書いた内容が runtime へ / OFF なら読み直したグローバルの内容が runtime へ）。
  読み直しはダイアログ内の表示更新であり、runtime の解決順序（1./2.）は変えない。

### §3-3 保存先と書き込み

- **書き手はプリセットマネージャの 1 本**【B】。個別指定 ON なら個別ファイルへ即時保存する。
- **保存先の算出は application 側**に置く（trigger_set の `save_path_resolution` と同じ流儀。
  presentation と二重化しない）。
- **実体は OK で初めて作る**【H】。ON にしただけではファイルを作らない。
- **書込先が個別で、そのパスが config 外なら既定パスへ寄せて新規作成する**【O3】。
  **これを理由にグローバルへ倒さない**（読み出しの【O2】と非対称なのは意図どおり
  ＝ **読むのは外部でもよいが、書くのは必ず管理下**）。
- **（v0.8）OFF での OK はグローバルへ書く**（【H2】撤回・例外なし）。**ON → OFF のトグルで
  グローバルを読み直せなかった場合は一覧が組込既定へ差し替わっている**ため、
  書かれるのは**組込既定**であって個別の内容ではない【I】。
- **【v0.7】寄せた結果を含め、最終的な保存先が `global/` 配下またはグローバルと同一なら拒否する**【O4】。
- **【v0.9】判定の順序は 【O3】寄せ → 【O4】拒否 → 【S】上書き確認 → 書き込み**。
  【S】は**最終保存先の実体を読んで比較する**ため、寄せた後でなければ判定できない。
  読み出しは**正本 §5.10.2 の正規化を通した結果どうし**で比較する（読み出し側 1 箇所の規則を再利用し、
  比較専用の別経路を作らない）。**確認と書き込みの間の競合（別プロセスによる作成・置換）は対象外**
  （§5.8.3 の「保存先に実体があれば保存しない」等と同水準の既知の性質）。
- **【dirty・v0.6】`hotkey_presets_path` の値が実際に変化したときだけ keymap_set を dirty にする**
  （同じ値の再確定では立てない）。`hotkey_presets_path` は **keymap_set に保存される値**のため、
  変化はそのまま keymap_set の変更にあたる。
  - **通常運用（ON + 有効パスあり → 内容を編集して OK）は値が変わらないので dirty は立たない**
    ＝「**プリセットの内容編集は dirty にしない**」は維持される。
  - 従来は**フラグ変更（OFF → ON）への相乗り**でパスが永続化されており、
    **「最初から ON でパス未設定」の経路では dirty が立たず永続化されない穴**があった。
    本規則はその穴と【O3】のリダイレクトを**同じ 1 つの規則で塞ぐ**。
  - OFF（グローバルへ書く）ときは `hotkey_presets_path` を反映しないので無関係。
- **保存カスケードは引き続きプリセットの内容を書かない**（正本 §5.10.3 を維持）。
- **別名保存時のみ、既存の個別ファイルを新しい保存先へ複製する**【L】。
  複製は**内容の生成ではなくファイルのコピー**であり、コピー先に実体があれば行わない。

### §3-4 UI（プリセットマネージャ）

- 「**この構成セット専用にする**」チェック + **保存先パスの表示**【D】【R】。
- **（v0.8）チェックは「次の OK でどこへ書くか」と「編集中の一覧」を同時に切り替える**【I】。
  切替先が読めなければ**現在の一覧を引き継ぐ（ON）/ 組込既定へ差し替える（OFF）**。
  表示中のパスもチェックに追従して更新する。
- **（v0.8）一覧が編集済みのときだけ、差し替え前に確認ダイアログを出す**
  （「編集中の内容は破棄されます」。**キャンセルならチェックを元に戻し、一覧も表示も変えない**）。
  未編集なら確認しない。**判定は「直近に読み込んだ一覧」との比較**で行う
  （＝ダイアログを開いた時点の一覧、または直前のトグルで差し替えた内容）。
- **OK で確定・キャンセルで何も変えない**【J】（フラグ・dirty・ファイルのいずれも変更しない）。
  **（v0.8）トグルで一覧を差し替えた後にキャンセルした場合も、runtime・ファイル・フラグは変わらない**
  （トグルはダイアログ内の表示にしか影響しない）。
- **（v0.9）ダイアログを開いた時点でも、OFF なら一覧を表示元へ合わせて確定させる**【I2】
  （トグルと同じ処理を初期化にも通す）。**ON では行わない**（【E】の引き継ぎを維持するため）。
  この確定は**ダイアログ内の表示にとどまり、runtime へは OK まで反映しない**（【J】不変）。
- **（v0.9）個別へ書く直前に、条件を満たす場合だけ上書き確認を出す**【S】。
  **（v0.10）確認は 3 択**（**上書きする / 既存を読み込む / キャンセル**）。
  「既存を読み込む」は**一覧と比較基準を差し替えるだけで保存しない**（ダイアログは開いたまま）。
  「キャンセル」なら**保存せずダイアログを閉じない**（【O4】の拒否と同じ契約）。
  **保存先が読めない（破損）ときは「既存を読み込む」を出さない**。
- **OK の挙動**: ON なら個別ファイルへ書いて runtime へ反映 /
  **OFF なら表示中の一覧をグローバルへ書いて runtime へ反映**（v0.8。読み直しに失敗していた場合は
  表示中＝**組込既定**が書かれ、グローバルが作り直される）/
  **ON だが個別パスが config 外なら既定パスへ寄せて新規作成する**【O3・v0.6】。
- keymap_set 未保存なら**チェックを無効化し理由を表示**【F】。表示は保存 / 読込 / 新規作成後に再評価【Q】。
- 切替の確定は keymap_set を **dirty にする**。内容編集は dirty にしない。
  **`hotkey_presets_path` の値が変わった保存も dirty にする**（v0.6。§2 の dirty 規則）。
- フォールバック中は「**グローバルを表示中**」を明示【R】。

### §3-5 移行規則（後方互換）— **重要**

- **`hotkey_presets_individual` を持たない keymap_set は常に OFF**（フラグは値で判定する）。
- **（v0.8）`hotkey_presets_individual` キーが無い keymap_set は `hotkey_presets_path` も引き継がない**
  （runtime へ載せず空文字として扱う。**この判定だけはキーの有無で行う**）。
  → phase 08 の**残置 `hotkey_presets_path` が、フラグとしても保存先としても復活しない**。
  v0.7 までは**保存先としては復活していた**（初回 ON + OK が残置パスへ書いていた）。
- **グローバル既定パスの移行は手動**【G】。旧既定 `user/hotkey_presets/default.json` は
  **自動では読まない**（フォールバック読みを実装しない）。移行しない場合は組込既定が表示されるだけで、
  **ファイルは失われない**。
- **旧版アプリ（phase 08 実装）が本フェーズ後のファイルを読んだ場合**: `hotkey_presets_individual` は
  未知キーとして無視され、`hotkey_presets_path` も読込時無視のため、**グローバルへ安全に倒れる**。

| 17 | **移行手順（ファイル移動 + config.json の明示値の書き換え）**が正本に明記され、`global/` が起動時に作成される | §2【G】|
| 21 | **（v0.10）上書き確認は 3 択**（上書きする / 既存を読み込む / キャンセル）。**「既存を読み込む」で一覧と比較基準が保存先の実体の内容へ差し替わり、保存されずダイアログも閉じない**（`data`・dirty・ファイルは不変）。**続けて OK すると確認が出ずに保存が通り、既存の内容が保たれる**（**一覧を編集せず、保存先が外部から変更されていない場合**。変更・削除されていれば【S】の判定規則どおりに再評価される＝**確認と書き込みの間の競合は対象外**という v0.9 の除外と同じ扱い）。**保存先が読めない（破損）ときは「既存を読み込む」が出ない** | §2【S】/ §3-4 |
| 19 | **（v0.9）個別として書く直前に、保存先に実体があり かつ その内容がダイアログの読み込んだ一覧と異なる（または読めない）なら上書き確認が出る**。「キャンセル」なら**保存されずダイアログも閉じず**、`data`・dirty・ファイルが変わらない。**初回 ON の新規作成 / 記録パスのある再 ON / ON のままの内容編集 / OFF での OK / 内容が一致している共有では出ない**。**記録パスが空のままの ON・別名保存でコピー先の実体を採用した後の ON【L】・config 外からの移行【O2】では出る** | §2【S】/ §3-3 |

| 14 | `tests` / `tests_ui` / smoke が更新後の期待値で pass。解決順序・移行規則・保存先切替・上記を特性テストで固定 | 全体 |

## §6 スコープ外（本フェーズでやらない）

- **プリセット編集 UI の刷新**（追加/編集/削除/並べ替えの操作体系は変えない）
- **グローバルの multi-library 化**（config.json が指すのは引き続き 1 本）
- **個別プリセットの保存計画ダイアログ（§5.8）への統合**（【B】で不採用）
- **グローバル既定パス変更の自動移行**（【G】で手動と確定）
- 破損プリセットファイルの**検知・警告・退避**（正本 §5.10.4 の既知の制約のまま）
