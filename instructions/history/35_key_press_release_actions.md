## §1 目的 / 背景

出力シーケンスに**キー（またはマウスのボタン）を押したままにする行と、離す行**を加える。例: shift を押す → 矢印を何回か → shift を離す / ctrl を押したままクリックする。
今の hotkey は押して離すまでを 1 回で送るため、押したまま他の行を送る組み立てができない。押したままのキーが残ると OS 全体の入力が壊れるため、**止まる経路で必ず離す安全策**を同時に入れる。
**domain・application・infrastructure・presentation。JSON にアクションの種類を 1 つ追加（後方互換）。**

### 現状監査（2026-10-09〜10・codex-explorer + deep-reviewer + メイン実測）

- 種別: 通常アクションは `hotkey` / `text` / `mouse_click`（文字列比較・定数なし）、制御は `system` / `file_line`（`domain/sequence_control.py:9`）。読込の正規化 `domain/config.py:152-169` の `normalize_actions` は種別ごとのキーを検証せず未知の種類も残す（`value` も正規化しない）。
  実行 `application/action_executor.py:95` の `execute` は未対応の種類をエラー通知して False。`sequence_steps.advance` は system 以外を通常アクション（送る行）として返すため、新しい種類も自動で 1 ステップに数えられる
- 実行時エラーは 2 系統: **止まる系**（種別不正・system・file_line。`execute` が False）/ **止まらない系**（hotkey の検証エラー・mouse_click の座標不正。`execute` が True で「送った」に数える）。送信の例外は `execute` でも runner でも捕まえていない
- 一覧の書式 = `domain/config.py` の `format_action_list_item`（system・file_line）と `presentation/controllers/action_list_rendering.py:58-75`（他の種類は自前で整形）。ダイアログ = `presentation/dialogs/action_dialog.py`（493 行・種類の候補 :49）
- 送信: `infrastructure/input_gateway.py` の `press_key` / `release_key`（:85・:92。拡張キーは拡張キーフラグ付き `keybd_event`・それ以外は `keyboard.press/release`）・キー名の検査 `validate_key_name`（:131）。
  マウスは `pyautogui`（ドラッグ `drag_mouse` :150-163 は **FAILSAFE を外して** mouseDown → 移動 → finally で mouseUp）。**マウス操作は send_guard の対象外**（`data_schema.md` §5.11.2）
- text の送信 `keyboard.write` は Windows では各文字を Unicode のパケットで送り、**送る前に `stash_state()` で keyboard が押下中と記録しているキーをすべて離し、最後に修飾キーだけを押し直す**（`.venv/Lib/site-packages/keyboard/__init__.py:783-792`・:840-871）
- 自己入力: 送信は `ActionExecutor` の send_guard（`action_executor.py:215-226`）の間だけフックが無視する（`input_router.py:75-77`）。トリガーの判定はスキャンコードから引く（`input_router.py:143-153`・layout に無いキーだけ `event.name`）
- **押したままのキーを記録して離す仕組みは今は無い**。止まる経路はいずれも実行状態を止めるだけ
- 戻す履歴は位置・周回・保留・参照中の印・カウンターの差分だけを持ち、送信は取り消さない（`application/sequence_history.py`）

## §2 確定事項（ユーザー 2026-10-09〜10）

1. **押したキーは 1 回の押下（単発の 1 ステップ）をまたいで押したままにしてよい**（例: 1 回目の押下で shift を押す → 次の押下以降で矢印 → 最後に shift を離す）
2. **押したままのキーは止まる経路すべてで自動で離す**（詳細は §5。ただし 6〜8・11 の例外を除く）
3. **アクション編集では種類「キーの押下 / 解放」を 1 つ足し、ダイアログの中で「押す / 離す」を選ぶ**
4. **対象 = キーボードの単キー（修飾キーを含む）とマウスのボタン**（左 / 右 / 中）。組み合わせ（`ctrl+shift` 等）は行を分けて書く
5. **マウスのボタンは座標を指定することもできる**（指定なし = 今のカーソル位置・指定あり = そこへ移してから押す / 離す）（2026-10-10）
6. **押したトリガー（最上段）のシーケンスの末尾に達したら、そのトリガーの押下中のキーを離す**（2026-10-10）。**呼び出し先の末尾（呼び出しの完了）では離さない**（v0.2・押すだけの下請けを呼ぶ組み立てを許す）
7. **一時停止（連続実行・単発の呼び出し）で離す。再開で押し直さない**（一時停止中にユーザーが他の操作をするため）（2026-10-10）
8. **戻すでは離さない・先頭へでは離す**（v0.2 で改訂。戻しても押したままを保つので、範囲選択の行き過ぎを 1 段戻して続けられる。先頭へは最初からやり直すので離す）（2026-10-10）
9. **押下中のキーをステータス欄に「押下中: shift, マウス左」と出す**（押したままに気づけないと OS 全体が誤作動するため）（2026-10-10）
10. **連続実行の停止の行（区切り・4.2.8）では離さない**（単発の押下の合間と同じ扱い）（v0.2・2026-10-10）
11. **`key_hold` の行の実行時エラー（キー名・ボタン・座標の不正・送信の失敗）では、そのトリガーを止め、先にその分の押下中のキーを離してからエラーを知らせる**（止まる系・v0.2・2026-10-10）
12. 押下中の扱いは §4.3（押すは毎回送る・持ち主 = トリガーのキー）とする（レビューの代替案の採用・メイン判断）
13. **確定前の Codex 敵対的レビューの 5 件をすべて反映**（v0.3・2026-10-10）: 同じキー = 実際に送る対象が同じもの（左右の ctrl / alt は別）・押すは送る前に記録し失敗したら離す・実行を終えるエラーすべてで知らせる前に離す・連動で末尾に達した呼び出し元の分も離す・text / file_line への影響は task_01 の probe で確定
14. **押したままの間の text / file_line は、送る間だけ押下中のキーボードのキーをすべて（shift を含む）離し、送り終えたら押し直す**（文字どおり入力する・v0.4 で ctrl / alt / windows・v0.5 で shift を含むすべてへ改訂・ユーザー判断 2026-10-10）
15. **本機能で押したキーは keyboard ライブラリの押下記録に載せない**（右 ctrl が左 ctrl として残る不具合の防止・v0.4・probe で判明した安全上の必須事項・メイン判断）
16. **text / file_line の送信で keyboard に修飾キーを押し直させない**（手で右 ctrl を押している間の text で左 ctrl が残る既存の不具合をこのフェーズで直す・v0.5・ユーザー判断 2026-10-10）
17. **text / file_line の送信が失敗したら押し直さず、実行を終えるエラーとしてそのトリガーの押下中のキーを離してから知らせる**（v0.5・ユーザー判断 2026-10-10）。**一時的に離した他のトリガーのキーボードのキーも離した扱いにする**（v0.6・ユーザー判断 2026-10-10）
18. **連続実行の停止の行がシーケンスの最後の行にあるときは、末尾として離す**（位置が先頭へ戻るため。途中の行の停止〔区切り〕では従来どおり離さない・§2-10）（v0.7・task_04 のレビューで見つかった §2-6 と §2-10 の境界・ユーザー判断 2026-10-10）
19. **キーマップの切替・アクティブなキーマップの削除で押下中のキーをすべて離す**（`reset_indices` とは別の独立した入口。キーマップの切替では実行状態は一覧ごとに保たれ `reset_indices` は呼ばれないため。同じキーマップへの切替では離さない）（v0.8・task_06 の deep-reviewer H1・M1・ユーザー判断 2026-10-10）
20. **ダイアログの「1 キーを記録」は修飾キーの左右を区別して記録する**（右 ctrl → `right ctrl` 等・§4.3 の同じキーの判定とそろえる）（v0.8・task_06 の Codex レビュー・ユーザー判断 2026-10-10）
21. **フックが止まっている・キーマップ一時停止中に、予約済みの入力（トリガー・直接置換）を実行しない**（停止の直前に押されて UI スレッドへ予約された入力が、全部を離した後に押し直すのを防ぐ。hotkey 等の既存の種類にも効く既存の挙動の変更。停止の直前の押下は捨てる）（v0.9・完了判定前の Codex 敵対的 high・ユーザー判断 2026-10-11）
22. **自動で離す（§5）・押すの補償の離すで送信が例外になったものは集合に残す**（次の自動の解放で送り直す。表示も押下中のまま＝OS の実態に近い側）。例外は従来どおり集めて知らせる。text の失敗時の他のトリガーの分の離すの例外も知らせに含める（v0.9・完了判定前の Codex 敵対的 high・deep-reviewer M2 / L1・ユーザー判断 2026-10-11）
23. **呼び出し先の中の停止の行で連続実行が一時停止になる場合（features 4.2.8 の 1）は、停止の行の区切りとして離さない**（§2-10 にそろえる。通常の連続実行の一時停止〔一時停止の操作〕は従来どおり離す）（v0.9・完了判定前の deep-reviewer M1・ユーザー判断 2026-10-11）

## §3 データモデル（JSON）

新しい種類 **`key_hold`**（§5.11.1 に 1 行追加）:

| キー | 型 | 意味 |
|---|---|---|
| `edge` | str | `down` = 押す / `up` = 離す（実行時に trim + 小文字で判定）。**それ以外・非文字列は実行時エラー** |
| `button` | str | マウスのボタン `left` / `right` / `middle`（大文字小文字は区別しない）。**`button` が空でない文字列ならマウスの行**、それ以外（キー無し・空・非文字列）ならキーボードの行 |
| `value` | str | キーボードの行のキー名（単キー 1 つ）。実行時に trim + 小文字で判定。マウスの行では無視 |
| `x` / `y` | int | **マウスの行だけ・任意**（`x` と `y` は両方そろえて書く）。指定があればカーソルをその画面の絶対座標へ移してから押す / 離す（§2-5）。変換の規則は mouse_click の `x` / `y` と同じ（`int()` で判定）。キーボードの行では無視 |
| `label` | str | 一覧表示用（他の種類と同じ） |

- 例: `{"type": "key_hold", "edge": "down", "value": "shift", "label": ""}` / `{"type": "key_hold", "edge": "up", "button": "left", "x": 400, "y": 200, "label": ""}`
- 読込の正規化は**既存のまま**（`edge` / `value` / `button` / `x` / `y` は読込で書き換えず、実行時に判定する。`value` を全種類で正規化すると hotkey・text の既存の挙動〔数値の value を文字列にして送る〕が変わるため）。`type` / `button` / `label` の型不正は §5.1 の共通規則どおり
- **実行時エラー**（§2-11・§4.5）: `edge` 不正 / キーボードの行で `value` が空・非文字列・`+` や `,` を含む・`validate_key_name` で不正 / マウスの行で `button` が 3 つ以外 / `x` と `y` の片方だけ・変換不能。mouse_click の「不正なら left」とは扱いを分ける（押したままの対象を取り違えると離せないため）
- 種類を 2 つ（`key_down` / `key_up`）にせず 1 つ + `edge` にする理由: §2-3 の UI と JSON を対応させ、一覧・ダイアログ・検証の分岐を 1 か所にする
- 旧版アプリは `key_hold` を未知の種類として読み、実行時にエラー通知する（既存の未知の種類の扱い・phase 31）

## §4 実行

### 4.1 送る行としての数え方
- `key_hold` は**通常アクション（送る行）1 行**として数える（単発の 1 ステップ・連続実行の 1 ステップ・呼び出しのステップ / 一括とも、hotkey と同じ扱い）。戻す履歴の段も hotkey と同じ規則で積む。停止の行の読み飛ばしの判定（4.2.8 の「送った」）にも数える
- 待機（4.2.5）の「直前に送った行」に `key_hold` も含む（押した後 / 離した後の待ちを置ける）

### 4.2 送信
- キーボード: 押す = `press_key`・離す = `release_key`（拡張キーの扱いは既存の送信経路どおり）。send_guard の中で送る（フックが自分の送信を拾わない）
- マウス: `x` / `y` があれば**カーソルをそこへ移して**から押す / 離す、無ければ今のカーソル位置で押す / 離す（§2-5）。移動は瞬時（速度は持たない）。**FAILSAFE を外して送る**（画面の隅で例外になり離し損ねないため・`drag_mouse` と同じ）。send_guard の対象外（既存のマウス操作と同じ）
  - 座標つきで押す → 座標つきで離す を並べると、離すときの移動の間ボタンを押したままなのでドラッグになる（例: `[押す 左 (100,200), 待機, 離す 左 (400,200)]`）
- IME の操作はしない（text / file_line だけの規則のまま）

### 4.3 押下中の記録（runtime・保存しない）
- アプリ全体で **押下中の集合**（キーボードのキー / マウスのボタン → **持ち主 = トリガーのキー**）を持つ。キーマップの切替・アクティブの削除・構成セットの読込等ですべて離すため（§5。キーマップの切替は v0.8 で独立した入口に訂正）、押下中のものは常にアクティブなトリガー一覧のもの（持ち主に一覧の id は持たない）
- 持ち主 = **押したトリガー（最上段）のキー**。呼び出し先の行で押したものも呼び出しを始めた最上段のトリガーが持ち主（§2-6 で呼び出し先の末尾では離さないため、離す単位を押したトリガーにそろえる）
- **同じキーとみなす**: キーボードは**実際に送る対象（スキャンコード + 拡張フラグ）が同じもの**（`ctrl` と `left ctrl` は同じ・`left ctrl` と `right ctrl`・`left alt` と `right alt` は別。shift・windows も左右は別）。マウスはボタン名（v0.3・Codex 敵対的 high 1）
- 押す: **毎回送る**（既に押下中でも送り直す。OS 上は無害で、物理で離された後や hotkey で離れた後でも押し直せる）。**送る前に集合へ入れる**（持ち主は今のトリガーへ上書き）。
  送信が例外になったら（押す信号が OS に届いたかは分からない）、**そのキーにも離すを送ってから**集合から外す（v0.3・Codex 敵対的 high 2）
- 離す: 集合に無くても**送る**（手で押されて残ったキーの後始末に使えるように）。送ってから集合から外す。
  離すの送信が例外になったら集合に残す（OS 上離れたか分からないので、次の自動の解放で送り直す＝安全側）（v0.8・注記）
- 同じキーをユーザーが物理的に押して離した場合、OS 上は離れるが集合には残る（次の自動の解放で離す・余分な up は無害）＝受容

### 4.4 他の送信との関係
- **hotkey・直接置換**は押下中のキーの影響を受ける（例: shift を押したまま `right` → 範囲選択）。これが本機能の目的
- **text・file_line は押したままのキーに関係なく文字どおり入力する**（v0.4〜0.5・task_01 の probe とユーザー判断 2026-10-10）:
  - 文字は Unicode のパケットで送るが、改行・バックスペースは通常のキーとして送る（`keyboard.write` が `send` を使う）ため、押したままの修飾キーと組み合わさる（probe: ctrl を押したまま `p\nq` → 改行だけ・文字は Ctrl+P / Ctrl+Q。shift なら Shift+Enter / Shift+Backspace）
  - そのため **text / file_line を送る間だけ、押下中の集合にあるキーボードのキーをすべて（shift を含む）離し、送り終えたら押し直す**（v0.5・§2-14 の改訂）。マウスのボタンは離さない。集合は変えない。押し直した後の扱いは §4.3 の押すと同じ
  - **送信が失敗したら押し直さない**: 送信の例外は「実行を終えるエラー」（§4.5）として、そのトリガーの押下中のキーを離してから知らせる（v0.5・§2-17）
    - 一時的に離した**他のトリガーのキーボードのキーも押し直さず、離した扱いで集合から外す**（OS の実態と集合をそろえる。マウスのボタンは離していないので残す）（v0.6・task_03 のレビュー・ユーザー判断 2026-10-10）
    - **送る前の一時的な離すが途中で失敗した場合も同じ**に扱う（送信の失敗と同じく、押し直さず、離した扱いで集合から外してから知らせる）（v0.8・task_06 の Codex レビュー・ユーザー判断 2026-10-10）
  - 送り終えた後の**押し直しが失敗した場合**は、text は送れているが「実行を終えるエラー」（止まる系・§4.5）として扱う（押したままの前提が崩れたまま続けないための安全側）（v0.8・注記）
- **本機能で押したキーは keyboard ライブラリの押下記録に載せない**（v0.4・§2-15）: keyboard が送信の前後に押下中のキーを離して修飾キーを押し直す処理（`stash_state` / `restore_modifiers`）は、
  フックが動いている間に記録したキーを対象にする。拡張キー（right ctrl 等・`keybd_event` で送る）は記録に載るため、**右 ctrl を押したまま text を送ると左 ctrl として押し直され、右 ctrl を離しても左 ctrl が OS 上に残った**（probe）。
  押す / 離す・自動で離す・text の前後の離す / 押し直すの送信は、keyboard の記録に載らない送り方にする（実装の方法は task_03 で決める）
- **text / file_line の送信で keyboard に修飾キーを押し直させない**（v0.5・§2-16・既存の不具合の修正）: 上と同じ処理で、**ユーザーが手で右 ctrl を押している間に text が送られると左 ctrl が残る**（本機能と関係なく今もある）。
  text / file_line の送信は keyboard の送信後の押し直しをしない形（`keyboard.write(..., restore_state_after=False)`）にする。変わる点: 手で修飾キーを押したまま text が送られると、送信後は OS 上離れた扱いになる（押し直したければ一度離して押す）＝受容
- hotkey がそのキー自身を含む場合（shift を押したまま `shift+right`）、hotkey の送信の終わりで OS 上は離れる。集合には残る＝受容（次の押す行で押し直せる・§4.3）
- 押したままの間のユーザーの物理入力も影響を受ける（shift を押したままなら打鍵が大文字）

### 4.5 エラー（§2-11）
- §3 の実行時エラー・送信の例外（キーボード・マウスとも）は、**その行を送らず（送信の例外は送れたかどうか不明・押すなら §4.3 の補償の離す）、そのトリガーを止め**（`execute` が False を返す止まる系。連続実行は停止・単発はその押下で終わる）、
  **先にその持ち主の押下中のキーを離してから**エラーを知らせる（知らせのダイアログがモーダルで、開いている間に押したままにならないよう）
- **`key_hold` 以外の行のエラーで実行が終わる場合も同じ**（v0.3・Codex 敵対的 high 3）: 制御の行・file_line・未知の種類・**text / file_line の送信の例外**（v0.5・§2-17）など**実行を終える実行時エラー**（単発の `_run_single_action` の `outcome.error` / `execute` が False・単発の呼び出しの失敗・連続実行のエラー停止）では、**知らせる前に**そのトリガー（持ち主 = 最上段）の押下中のキーを離す。
  送信を続けるエラー（hotkey の検証エラー・mouse_click の座標不正。`execute` が True）では離さない（実行が続くため）
- 送信の例外は ActionExecutor で捕まえて実行時エラーとして扱う（`key_hold` の行だけ。他の種類の扱いは変えない）
- hotkey の送信の例外（`execute` の外へ抜ける既存の挙動）は扱いを変えず、押下中のキーも離さない（本フェーズの対象外・v0.8・注記）

## §5 自動で離す（安全策）

**集合の該当分を離す送信をしてから集合から外す**。1 つの送信の例外で残りを離し損ねないよう、例外は集めて**すべて離し終えてから**まとめて知らせる。
契機は**入口の関数の単位**で決める（経路を列挙すると漏れるため）。下の入口を通るすべての経路で離す。

| 契機（入口） | 離す範囲 |
|---|---|
| フック停止 `HookController.stop_hook`（停止キー・ボタン・**UI 編集中の一時停止**〔ダイアログ〕・アプリ終了の前処理を含む） | すべて |
| キーマップ一時停止 `toggle_custom_input_enabled`（一時停止にするとき） | すべて |
| 実行状態を消す契機 = runtime の位置・周回の作り直し（`reset_indices` 等。構成セットの読込等） | すべて |
| **キーマップの切替**（アクティブが実際に変わるとき。同じキーマップへの切替を除く）・**アクティブなキーマップの削除**（v0.8・§2-19。`reset_indices` を通らない独立した入口） | すべて |
| アプリ終了 `App.on_close`（finally で・フック停止が失敗しても） | すべて |
| 連続実行が終わる（`stop_run_to_end` を通るすべて: 停止操作・末尾・エラー・トリガーの消失・他の連続実行の開始による破棄。**停止の行の区切りは除く**〔§2-10〕） | そのトリガーの分 |
| 連続実行の一時停止・単発の呼び出しの一時停止（§2-7） | そのトリガーの分 |
| 一時停止中のものを捨てる（`discard_paused`・4.2.10） | そのトリガーの分 |
| 単発の待機の取り消し（`_cancel_pending_steps`・4.2.5 の契機） | 待機していたトリガーの分 |
| 先頭へ（対象 T・§2-8）。**戻すでは離さない** | T の分 |
| トリガーの削除・キー変更・有効な行の交代・シーケンスの編集・一覧で位置を変えた（4.1・4.2.3 で状態を消す契機） | そのトリガーの分（キー変更は旧キーの分） |
| 押したトリガー（最上段）のシーケンスの末尾に達した（§2-6・下記の時点） | そのトリガーの分 |
| **連動で末尾に達した**（呼び出し先を直接押して完了させ、参照中の呼び出し元 T が末尾まで進んだ・4.2.9）（v0.3・Codex 敵対的 high 4） | 末尾に達した各呼び出し元 T の分（押したトリガーと違っても） |
| 実行を終える実行時エラー（§4.5・`key_hold` 以外の行を含む） | そのトリガーの分（知らせる前） |

- **末尾の時点**（§2-6）: 最上段のシーケンスが末尾に達した時点で、**先頭へ回って次の行を送る前に**離す（単発で末尾の制御行から同じ押下の中で先頭へ回る〔4.2.1〕場合も、先頭の `key_hold` 押すより先に離す）。
  末尾の後に待機があって押下が待機明けまで続く場合は、末尾に達した時点（待機の前）で離す。呼び出し先の末尾（呼び出しの完了）では離さない
- 単発の 1 ステップの終わり・押下の合間・停止の行の区切り・戻すでは離さない（§2-1・§2-8・§2-10）。ただし**最後の行の停止は末尾として離す**（§2-18）
- ダイアログを開く操作（キー変更等）はフックの一時停止ですべて離れるため、表の一部は実質重なる（重なっても余分な up は無害）
- **離す処理は UI スレッドで行う**。キーボードの送信は send_guard の中（フックが自分の解放を拾わない）。フック停止の後でも送る（フックの有無に関係なく OS へ送る）

## §6 フック・入力判定との関係

- 押したままの間もトリガー・直接置換の判定は従来どおり（判定はスキャンコードから引く・自分の押下は send_guard の中で送るので押下状態の管理に入らない）
- **task_01 の probe の結果（2026-10-10・テスト用の Tk の入力欄・合成の入力で近似）**:
  1. 合成の shift を押したままでも、キーのスキャンコードは変わらない（キー名は `a` → `A`・`1` → `!`）。判定はスキャンコードから引くので**トリガーとして判定される**。layout に無いキーは名前で引くため shift で変わり得る（受容）。物理の押下での確認は task_06 の実機目視
  2. text は §4.4 のとおり（shift は影響なし・ctrl / alt は文字がショートカットになる → 送る間だけ離す。右 ctrl は左 ctrl として残る → 記録に載せない）
  3. 左右の ctrl は別々に押し離しできる。`ctrl` で押して `left ctrl` で離すと離れる（§4.3 の同じキーの判定どおり）
- 押したままのキーがトリガー・置換元キー・停止キーと同じでも、送るのは send_guard の中なので判定は起きない

## §7 UI

- **アクション編集ダイアログ**: 種類の候補に「キーの押下 / 解放」（`key_hold`）を加える（hotkey 等と同じく、ダイアログを開くすべての文脈で出す）。
  入力欄 = 「押す / 離す」の選択（既定 押す）・対象の選択「キー / マウスのボタン」・キー名の入力（hotkey の「記録」と同じ要領で 1 キーを取得できる。**修飾キーは左右を区別して記録する**〔v0.8・§2-20〕）/ ボタンの選択（左 / 右 / 中）と「座標を指定する」チェック + X / Y（mouse_click と同じ入力欄と座標の取得手段を流用）
  - OK 時の検証: §3 の実行時エラーに当たる入力を拒否（理由を表示）
- **一覧の書式**: `[押す] shift` / `[離す] shift` / `[押す] マウス左` / `[押す] マウス左 (100, 200)` のように種類と向きが分かる表示（ラベルがあれば他の種類と同じ規則で併記）。
  フル表示の一覧（`action_list_rendering.py`）・省略表示のシーケンス欄・呼び出し先の表示枠の**すべてで同じ書式**（書式は domain の 1 関数にまとめて各所から使う）
- **押下中の表示**（§2-9）: ステータス欄に「押下中: shift, マウス左」（押した順・同じキーは 1 つ）。押下中が無ければ出さない。フル表示・省略表示とも

## §8 責務の置き場（実装の方針）

- 押下中の集合と解放の口 = application（例: `application/held_inputs.py` の `HeldInputs`。送信は InputGateway に任せる）。
  **runner が持ち主（最上段のトリガーのキー）を ActionExecutor へ渡す**（`perform_action` の引数を足す。呼び出し元 = 単発・連続実行・呼び出しの各経路）
- 解放の呼び出しは**なるべく runner / application の入口**に置く（§5 の表の入口）。presentation から呼ぶのはフック停止・キーマップ一時停止・アプリ終了・**キーマップの切替 / アクティブの削除**（v0.8。いずれも application の解放の口を呼ぶだけ）
- 種類の定数・検証（`edge` / `value` / `button` / `x` / `y`）・一覧の書式 = domain
- 送信（マウスのボタンの押す / 離す・座標への移動）= infrastructure の InputGateway に足す
- ダイアログの `key_hold` の入力欄は別モジュールに分ける（`action_dialog.py` が 493 行のため。既存の `action_control_fields.py` と同じ作り）
- 押下中の表示は、集合の変化を presentation へ知らせる口（既存のステータス更新の口）で行う

## §10 受け入れ条件（ドラフト）

自動テスト（偽の gateway で送信を記録）:
1. `key_hold` の行を追加・編集・保存・再読込でき、旧ファイル（キーの無いもの）は従来どおり読める（§3）
2. 単発で `[押す shift, right, right, 離す shift]` を 4 回押すと、押す / right / right / 離す の順に送り、最後に集合が空（§2-1・§4）
3. §5 の表の各入口で、該当範囲の押下中のキーが離れ集合から外れる（すべて / そのトリガーの分の区別を含む）。停止の行の区切り・戻す・単発の押下の合間・呼び出し先の末尾では離れない（§2-6・§2-8・§2-10）
4. 末尾の時点: 単発で末尾から同じ押下の中で先頭へ回るとき、先頭の押すより先に離す（§5）
5. 実行時エラー（§3）でその行を送らず、トリガーが止まり、押下中のキーを離してからエラーを知らせる（§4.5）
6. 押すは押下中でも送り直す・離すは集合に無くても送る・同じスキャンコードは同じキー（§4.3）
7. 一覧・省略表示・呼び出し先の表示枠で同じ書式・ステータス欄の押下中の表示（§7）
7a. 左右の ctrl を別々に押して片方を離すと、もう片方は集合に残る。押すの送信が例外のとき、そのキーにも離すを送り集合に残らない（§4.3）
7c. ctrl・shift を押したまま text を送ると、送る前にそれらを離し、送った後に押し直す（マウスのボタンは離さない）。送信が例外なら押し直さず、トリガーが止まり、押下中のキーを離してから知らせる。本機能の送信が keyboard の押下記録に載らない。text の送信で keyboard が修飾キーを押し直さない（§4.4）
7b. 押す行の次の制御の行のエラーで単発の実行が終わるとき、知らせる前に押下中のキーを離す。連動で呼び出し元が末尾に達したとき、呼び出し元の押下中のキーを離す（§4.5・§5）
7d. キーマップを実際に切り替える / アクティブなキーマップを削除すると押下中のキーがすべて離れる。同じキーマップへの切替では離れない。送る前の一時的な離すが途中で失敗しても、離した他のトリガーのキーが集合に残らない。「1 キーを記録」で右 ctrl / 右 shift / 右 alt / 右 windows が左右を区別した名前になる（v0.8・§2-19〜20）

実機目視（ユーザー）:
8. テキストエディタで単発の `[押す shift, right, right, 離す shift]` が範囲選択になり、shift が残らない（§2-1）
9. 押したままの状態で、フック停止・ダイアログを開く・キーマップ一時停止 / 切替・構成セットの読込・アプリ終了のそれぞれで shift が離れる（§5）
10. マウスの左ボタンを押す → 物理でマウスを動かす → 離す でドラッグになる。座標つきの押す → 座標つきの離す で指定の 2 点間のドラッグになる（§4.2）
11. §6 の probe の結果（押したままの間のトリガー判定・text）が §4.4・§6 どおり

12. 既存テスト（tests / tests_ui / smoke）が通る
