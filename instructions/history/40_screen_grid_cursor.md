## §2 確定事項（ユーザー 2026-10-12）

1. **キーマップの追加 / 編集ダイアログに「枠」の ON / OFF チェック**。枠 ON のキーマップが**アクティブな間だけ**枠を表示する（直接切替キーで出し入れする）。
   その間、そのキーマップの**トリガーと置換は効かず、枠の操作キーだけが効く**
2. **操作**: 枠のキー = その枠を選び、カーソルを枠の中心へ / **Enter = 左クリック**・**Shift+Enter = 右クリック** / **Space = 選んだ枠を細分化** /
   **Esc・BackSpace = 細分化を一段戻す**（最上段では Esc は素通し・BackSpace は何もしない・§2-12）/ **Tab = 枠を出す画面を次のモニタへ**（複数画面への同時表示はしない）
3. **クリックの後は最上段へ戻り、枠は出したまま**（続けて別の場所をクリックできる）
4. **最上段の枠は自由に編集できる**: 段（横の帯）の数と高さ・**段ごとに**列の数と幅（×ボタン・検索欄・タスクバー等に合わせるため）。境界はドラッグで編集し記録する。
   **既定の最上段 = 3 段 × 4 列**（キー `Q W E R / A S D F / Z X C V`）
5. **細分化後の段は等分**。既定 3 × 3（キー `Q W E / A S D / Z X C`）。**分割数とキーは任意に指定できる**（境界のドラッグはしない）
6. **枠のキーは任意に指定できる**。枠を増やしたときは自動で割り当て、後から個々に変えられる
7. **境界は比率で記録**し、**画面（モニタ）ごと**に持つ。記録先は keymap の JSON（任意キー `grid`・後方互換）
8. 枠の編集は**専用の編集モード**（キーマップのダイアログの「枠を編集…」から）。普段の枠はクリックが下の窓へ素通りする
9. DPI（画面ごとの拡大率）の扱いは**実機で検証してから**決める（アプリ全体の DPI 対応は避ける方向）
10. **キーマップの追加でも枠を設定できる**: 切替キーのまとめて設定のダイアログの**新規の行にだけ**「枠を使う」チェック（既定 OFF・形は組み込みの既定）。形の編集は追加後にダブルクリックの編集から（v0.3）
11. **枠 ON のキーマップがあればフックを開始できる**（トリガーも置換も無くてよい・v0.3）
12. **最上段では Esc を素通し**（アプリの Esc が使える）。**BackSpace は最上段でも suppress して何もしない**（誤って届くと文字を消すため。v0.3・v0.6 で再確認）
13. **枠のキーの表示位置を keymap ごとに「中央」（既定）/「枠の左上」で切り替えられる**。編集の窓のチェックで切り替え、最上段・細分化後の両方と編集の窓の表示に効く。左上のときの文字はアプリの UI フォントの大きさで、暗い下地を敷く（v0.7・2026-10-13 ユーザー判断）

## §3 用語とデータモデル

- **領域**: 枠を出す画面（モニタ）の矩形（作業領域ではなくモニタ全体。タスクバーにも合わせるため）
- **最上段の形（top layout）**: 段の並び。段 = 高さの比率 + 列の並び。列 = 幅の比率 + キー
- **細分化の形（sub layout）**: 行数 R・列数 C・キー R×C 個（読む順）。どの段の細分化にも同じものを使う
- **段（level）**: 0 = 最上段。Space で 1 段深くなる。各段の「今の領域」は 1 つ上の段で選んだ枠の矩形

### JSON（keymap の任意キー `grid`）

```json
"grid": {
  "enabled": true,
  "monitors": {"1920x1080+0+0": {"rows": [{"h": 0.3333, "cells": [{"w": 0.25, "key": "q"}, ...]}, ...]},
               "2560x1440-2560+0": {"rows": [...]}},
  "sub": {"rows": 3, "cols": 3, "keys": ["q","w","e","a","s","d","z","x","c"]},
  "label_position": "top_left"
}
```

- `enabled`: bool（bool 以外は false）
- `label_position`: `"center"`（既定）/ `"top_left"`。それ以外・無いときは `"center"`（v0.7・§7）。**正規化後の `grid` には `"top_left"` のときだけ書き、`"center"` のときは書かない**（v0.6 までの `grid` を読んで保存しても差分が出ない・JSON の例は `top_left` のとき）
- `monitors`: 画面の識別子 → 最上段の形。**記録の無い画面は組み込みの既定（3 段 × 4 列・§2-4）**を使う（既定は JSON に持たない）。
  **識別子 = `<幅>x<高さ><左><上>`・左と上は符号付き**（`+0` / `-2560`。§6 の検証で得る座標系の値）。
  解像度や配置が変わった画面は別の画面として扱い既定を使う（古い記録は残す・受容）
- `sub`: 細分化の形。無い / 不正なら既定（3×3・`q w e / a s d / z x c`）
- `h` / `w` は正の数。**読込時に段の `h` の和・各段の `w` の和を 1 へ正規化**する
- `key`: キー名（`key_input.md` の正規化に従う・テンキーの区別を含む）
- **読込時に形を既定へ戻すのは、形の不正（段 0・列 0・比率が正でない・形の中でのキーの重複・空のキー）と固定の予約キー（§5）だけ**（その形だけ・ログ 1 回）。
  設定で変わる予約キー（停止 / トグル / 直接切替キー）との重なりでは戻さない（振り分けで上が勝つ・§5）。`grid` が dict でなければ無いものとして扱う
- **`grid` が無い keymap は枠 OFF**。保存は **dict に `grid` があれば書く**。`grid` はダイアログでチェックを ON にしたとき、または形を編集したときに作る（OFF に戻しても消さない・形を失わない）。
  既存の keymap は触らない限り差分が出ない
- 読込 / 正規化 / 保存の全経路（§1 の 4 経路）で `grid` を保持する。複製 / 貼り付けは既存のまま丸ごと写る（追加実装なし）
- 正本 `data_schema.md` §5.6「keymap」・§5.2 に追記する（「未定義キーは無視」の例外として `grid` を定義済みキーに加える）

## §4 枠の表示と操作

### 4.1 表示の条件

枠を出す = **アクティブな keymap の `grid.enabled` が真** ∧ フック動作中 ∧ キーマップ一時停止でない ∧ フックの一時停止（ダイアログ表示中等・ネスト）でない。
条件が偽になったら隠し、状態（段・選択・画面）を捨てる。真になったら**マウスカーソルのある画面**の最上段・選択なしから始める。

- **世代**: 枠の状態は「表示を始めたキーマップの id + 世代番号」に結び付ける。次のとき**条件が真のままでも**世代を進めて状態を捨て、カーソルのある画面の最上段・選択なしからやり直す:
  アクティブの変更（枠 ON → 別の枠 ON を含む）/ フックの停止 → 開始 / 一時停止 → 再開 / ダイアログを閉じた後 / そのキーマップの `grid` の確定（ダイアログの OK）。
  フックのスレッドが振り分けた枠の操作には**その時点の世代**を付け、UI スレッドで実行するとき今の世代と違えば何もしない

- **表示の同期は 1 か所**: 条件が変わりうる契機（フックの開始・停止・一時停止の切替・ダイアログの開閉・アクティブの変更〔一覧・直接切替キー・削除・読込〕・ダイアログの OK）は
  既存の `refresh_keyboard_window` の呼び出しと同じ所で枠の表示も同期する（呼び出し元を散らさない）
- **UI スレッドで実行するとき枠が表示中でなければ何もしない**（フックのスレッドで振り分けた後に停止・切替が入った場合。`features.md` §4.5 の予約済み入力と同じ考え方）
- **モニタ構成の変化**: 状態は画面を**列挙の番号ではなく §3 の識別子と列挙時の矩形**で持つ。モニタの列挙は表示の開始・Tab・クリックの直前にやり直し、
  今の画面の識別子が見つからない（抜かれた・解像度や配置が変わった）なら、**クリックせず**状態を捨て、カーソルのある画面の最上段・選択なしへ戻す（窓と suppress する集合も作り直す）
- **フックの開始・再開の条件**（§2-11）: 共通の判定（`hook_coordinator.py:78` `_can_process_input`。呼び出し元 = 開始と `can_enable_custom_input`〔一時停止からの再開・`hook_controller.py:201`〕）で、
  `grid.enabled` が真のキーマップがあれば「トリガーまたは置換がある」と同じに扱う（両方の呼び出し元から渡す）

### 4.2 状態

- 画面（§3 の識別子と列挙時の矩形・§4.1）・段の積み（各段の領域と、その段の形）・今の段の選択（枠 1 つ or なし）
- 保存しない（runtime のみ）

### 4.3 キーの意味（枠の表示中）

| キー | 動作 |
|---|---|
| 今の段の枠のキー | その枠を選ぶ（強調表示）+ カーソルを枠の中心へ |
| Space | 選んでいる枠を今の領域にして 1 段深くする（選択なし・カーソルは動かさない）。選択なし / 枠が小さすぎる（細分化した 1 枠が **4px 未満**になる）なら何もしない |
| Esc / BackSpace | 1 段戻る（戻った段で、細分化した枠を選んだ状態にしカーソルをその中心へ）。最上段では BackSpace は何もしない・**Esc は素通し**（§2-12） |
| Enter（`num enter` を含む）/ Shift+Enter | 選んでいる枠の中心（選択なしで段 ≥1 なら今の領域の中心）へカーソルを置いて左 / 右クリック → 最上段・選択なしへ戻る。最上段で選択なしなら何もしない |
| Tab | 次の画面へ（列挙順で循環）・最上段・選択なし。カーソルは動かさない。画面が 1 つなら何もしない |
| 今の段では意味の無い操作キー（下の「suppress する集合」に入るが今の段の枠に無いキー） | 何もしない |
| 上記以外 | 素通し（他のアプリへ届く）。トリガー・置換は効かない（§2-1） |

- 停止キー・トグルキー・**直接切替キー**は従来どおり先に効く（枠を抜ける手段）
- **suppress する集合 = 全画面の最上段のキー ∪ 細分化のキー ∪ Enter・num enter・Space・BackSpace・Tab**。この集合のキーは**状態に関係なく常に suppress**（リピート・「何もしない」場合を含む）
- **Esc だけは段で分ける**: フックのスレッドが見る「段 ≥1 か」の印が真なら suppress して 1 段戻る、偽なら素通し（§2-12）。
  印は UI スレッドが段の変化のたびに更新する。**Space の直後（UI スレッドが細分化を処理する前）に押した Esc はアプリへ届きうる**（受容。逆に段 1 から戻した直後の Esc が suppress されて何もしないことも受容）
- **ctrl / alt / windows（左右）を押している間は素通し**（Alt+Tab・Ctrl+C 等を妨げない）。shift は Enter のときだけ右クリックとして見て、shift+枠のキーは枠のキーと同じに扱う。修飾キー単独の押下は素通し
- Shift+Enter の判定は**物理的に押している shift**（フックのキーの状態）で、**Enter の押下を振り分けた時点**に行い、左 / 右とリピートかどうかを枠の操作のアクションに入れる（UI スレッドで実行するときに修飾キーの状態を見直さない）。key_hold で押下中の shift は見えないため左クリックになり、OS 上は Shift+クリックになる（受容）
- キーリピート（押しっぱなし）: 枠のキー・Space・Esc/BackSpace・Tab は**リピートを無視**、Enter はリピートでクリックしない（いずれも suppress はする。Esc は最上段なら素通し）

### 4.4 入力の振り分けへの組み込み

`input_router.handle` の **直接切替キーの判定の後・トリガーの前**に「枠の表示中か」を判定し、表示中なら suppress する集合のキーは枠の操作のアクションを返して suppress、
それ以外は**素通し**（トリガー・置換へ進まない）。フックのスレッドで見るのは「表示中か」「世代」「suppress する集合」「段 ≥1 か（Esc 用）」と、Enter のときの shift の押下状態だけ。
集合は **UI スレッドが表示の開始・終了と形の確定のときにだけ更新する**（段・選択に依存しないので、Space の直後に次の枠のキーを打っても漏れない）。今の段での意味づけは UI スレッドで行う。

### 4.5 クリックとカーソル移動

- カーソル移動とクリックの手段（pyautogui か Win32 の `SetCursorPos` + `SendInput` か）は §6 の検証で決める。
  pyautogui を使う場合は `PAUSE`（既定 0.1 秒の待ち）で UI スレッドを止めないこと・FAILSAFE（画面の隅で例外）を外すことを条件にする（既存の `_send_mouse_button` と同じ扱い）
- 枠の窓は**クリックを素通しする**ため、自分の枠をクリックすることはない
- クリック後に最上段へ戻すのは送信の後

## §5 キーの規則

- **固定の予約キー**（枠のキーにできない・読込時も検査）: enter / num enter / space / esc / backspace / tab / 修飾キー（shift・ctrl・alt・windows の左右）
- **設定で変わる予約キー**: 停止キー / トグルキー / **全キーマップの直接切替キー**。**編集の窓の OK でだけ拒否**する。
  後から切替キー等を枠のキーと同じにするのは拒否しない（`key_input.md` §7.3 の表に枠のキーを足さない）。そのときは振り分けで上が勝ち、その枠は選べない（受容）
- 1 つの形（最上段の 1 画面分 / 細分化）の中でキーは重複不可。最上段と細分化は段が違うので同じキーを使ってよい（既定がそう）
- キー名は**フックの振り分けが返す正規化名**（`key_input.md`）。編集の窓のキーの取り込みは、押したキーを**フックと同じ名前**にする（テンキー → キーボード配列のスキャンコード → 修飾なしの文字 → `normalize_tk_key_event` の順。既存の `normalize_tk_key_event` だけでは記号キーが `period` 等の Tk の名前になりフックの `.` と一致しないため・v0.7。既存のキー取得〔トリガー等〕は変えない）
- **自動割当**: 枠を足したときは、その形で未使用のキーを次の順で最初に見つかったものにする（予約キーは飛ばす）:
  `q w e r t y u i o p a s d f g h j k l ; z x c v b n m , . / 1 2 3 4 5 6 7 8 9 0`（正規化名で記す。実装時に `key_input.md` の名前へ合わせる）。見つからなければ空
- **振り直し**（編集の窓のボタン）: 段 k（上から 1〜3）に Q 段 / A 段 / Z 段を左から、4 段目に数字段を割り当て、足りない分・5 段目以降は上の自動割当の順の未使用キーで埋める
- 空のキー・重複・予約キー（固定・設定で変わる）は**編集の窓の OK で拒否**（理由と枠を示す）

## §6 画面（モニタ）と座標の検証（task_01・スパイク）

本機能の座標系は実機の結果で確定する。**検証の結果が下の既定案で成り立たなければ止めてユーザーへ確認**する。
**検証は本番の起動経路（`main.py` と同じ import 順・Tk の初期化後）で行う**（pyautogui の import が DPI の状態を変えるため・§1）。

- 確かめること（**検証環境 = VirtualBox のゲストに仮想モニタ 2 台・縦並び〔2 枚目を主モニタの上 = 負の y〕・拡大率 100%**。
  実構成〔2026-10-12 ユーザー報告〕: モニター 1 = 主・1920×966 / モニター 2 = 主の上・1024×768〔解像度が違うため仮想画面は矩形にならない。EnumDisplayMonitors の実測〔DPI 未対応の素のプロセス〕= (0,0)-(1920,966) と (0,-768)-(1024,0)・左端揃え。本番の起動経路での値は 1 で確かめる〕。ユーザーの実環境〔ホスト〕も縦並び・全画面 100% のため、**拡大率の混在は検証せず受容**〔2026-10-12 ユーザー判断〕）:
  0. 起動後のプロセス・UI スレッドの DPI awareness の実際の値（`GetThreadDpiAwarenessContext` 等）
  1. モニタの列挙（Win32 `EnumDisplayMonitors` / `GetMonitorInfo`）が返す矩形
  2. その矩形へ tkinter の枠なし・最前面の窓を置いたときに画面全体をちょうど覆うか
  3. その座標へのカーソル移動（`SetCursorPos` / pyautogui）とクリックが、窓に描いた位置と一致するか（**負の座標の画面**を含む）
  4. 窓を出すとき・別の画面へ移すときに**フォーカスを取らない**こと（拡張スタイルは表示前に、Tk のラッパーの HWND = `GetParent(winfo_id())` へ付ける）とクリック素通し
  5. カーソル移動とクリックの手段（§4.5）で UI スレッドが止まらないこと
- **既定案**: プロセスの DPI の状態は今のまま（既存 UI の見た目を変えない）。その状態の座標で 1〜3 が一致すれば採用（主モニタと拡大率の違う画面で枠の線が少しぼやけるのは受容）
- 一致しない場合の選択肢（ユーザー判断）: (a) 枠の窓だけ Per-Monitor 対応の文脈で作る / (b) アプリ全体を Per-Monitor DPI 対応にする（既存 UI の大きさが変わる）/ (c) 主モニタと拡大率の違う画面では枠を出さない
- 検証には、表示中の画面の抜き差し・配置の変更（§4.1 のモニタ構成の変化）と、Space / Enter の直後の連打（§4.4）を含める

## §7 枠の窓（表示）

- 画面ごとではなく**今の画面に 1 枚**の窓（枠なし・最前面・**クリック素通し**・**フォーカスを取らない**）。Tab で窓を次の画面へ移す
- 透過: 背景を透過色にして、線・キーの文字・強調だけを描く（tkinter の `-transparentcolor` + Win32 の拡張スタイルでクリック素通し / 非アクティブ化）
- 描くもの: 今の段の枠の線とキー（`label_position` が `center` なら枠の中央・`top_left` なら枠の左上〔少し内側〕に文字）/ 選んだ枠の強調 / 段 ≥1 では今の領域の外を薄く暗くする
- 配色・線の太さは固定値（設定にしない）。文字の大きさは、中央のときは枠の大きさに合わせた固定の段階、**左上のときはアプリの UI フォント（`TkDefaultFont`）の大きさ**（フォントの拡大縮小の設定に従う）。
  **文字の下地**: 左上のときだけ、背景の画面の上でも読めるよう文字の大きさぶんの暗い四角を文字の下に敷く（枠の線のすぐ内側の左上の角に付ける・枠の窓・編集の窓とも・色は固定・フォントの大きさの変更で描き直す）。中央のときは下地なし（実機目視で 2 倍の太字・全体の下地を試した上で 2026-10-13 ユーザー判断）。
  **文字の収まり**: 使うフォントで文字の実際の幅と高さを測り、内側の余白（各辺 4px）を含めて枠に収まらなければ、その枠の文字は描かない（中央・左上・編集の窓のすべてで同じ規則。§4.3 の細分化できるかの 4px の判定とは独立）
- Win32 の呼び出しは infrastructure に置き、presentation から ctypes を直接呼ばない（phase 55 の方針）

## §8 枠の編集（編集モード）

### 8.1 入口とダイアログ

- `KeymapEditDialog`（ダブルクリックの編集）に「**枠を使う**」チェックと「**枠を編集…**」ボタンを足す（チェックが偽でもボタンは押せる）
- `KeymapSwitchBatchDialog` の**新規の行（区別 = 新規）にだけ**「枠を使う」チェック（既定 OFF）を足す（§2-10）。ON で OK なら組み込みの既定の形で `grid` を作る（`{"enabled": true}` + 既定の `sub`。`monitors` は空）。
  既存・読込・貼り付けの行と 1 つ目の追加（ダイアログなし）には足さない。行が 1 つのときの見た目（通常の編集ダイアログに近い）にもチェックを出す
- チェックと形の変更は**ダイアログの OK で確定**（キャンセルで捨てる）。確定で keymap を未保存にする

### 8.2 編集の窓

- 「枠を編集…」で編集の窓を開く。対象画面 = マウスカーソルのある画面。編集の窓の間もフックは停止中（ダイアログの子として扱う）
- **重なり順: 操作パネル（最前面）→ 編集の窓 → 他のアプリ・本アプリの窓**（v0.7。開いた直後・画面の切替の後もこの順を保つ）
- 全画面・半透明の窓（クリックを受ける）に最上段の形を描く + 小さな操作パネル（最前面）:
  画面の切替（列挙順の選択肢）/ 段の追加・削除 / 選んだ段の列の追加・削除 / 振り直し / この画面を既定に戻す / 細分化の設定（行数・列数・キー）/ **キーを枠の左上に表示（チェック・`label_position`・§2-13）** / OK / キャンセル
- 操作:
  - 段の境界（横線）・列の境界（段の中の縦線）を**ドラッグ**で動かす。隣の枠が **8px 未満**にならない範囲に止める
  - 枠のクリックでその枠（とその段）を選ぶ。選んだ枠でキーを押すとその枠のキーにする（Esc で中止）
  - 段の追加 = 選んだ段を上下に等分 / 列の追加 = 選んだ枠を左右に等分（新しい枠に自動割当）。削除 = 選んだ段 / 枠を消し隣が広がる。最後の 1 段・段の最後の 1 列は消せない
- 編集した画面の形は `monitors[<識別子>]` に入る（未記録の画面は組み込みの既定の写しから始める）。「既定に戻す」= その画面の記録を消す
- 細分化の設定: 行数・列数（各 1〜9・R×C ≥2）とキー（**操作パネルに R×C の小さなボタンの並びで細分化の形を出し、ボタンをクリックしてキーを押すとその枠のキーにする**〔最上段の枠と同じ取り込み方・§5 のフックと同じ名前。空白を含む `num 1` 等のキー名も扱える〕。行数・列数を変えたら並びを作り直し自動割当で埋め直す・v0.7）
- OK で §5 の検査 → 編集の窓を閉じて結果をダイアログへ返す。キャンセル（Esc を含む）で捨てる

## §9 他機能との関係

- **連続実行・保留中のステップ等**: 枠 ON の keymap へ切り替えても既存の切替の規則（§4.3 連続実行中は切り替えない等）に従う。枠の表示中はトリガーが効かないので新たな実行は起きない
- **キーボード表示**: 枠 ON の keymap がアクティブのとき、キーボード表示は従来どおりその keymap の割当（置換・トリガー）を色分けする（枠の操作キーは表示しない・受容）
- **重なりの表（`key_input.md` §7.3）**: 枠のキーはトリガー・置換・停止 / トグル / 直接切替キーと重なってよい（表に足さない・グレー表示の対象にしない）。
  停止 / トグル / 直接切替キーとの重なりは振り分けで上が勝ち、編集の窓の OK でだけ拒否する（§5）
- **key_hold の押下中**（phase 51）: 枠の表示へ切り替えても押下中のものは従来の規則のまま（自動で離す等は変えない）

## §11 受け入れ条件（ドラフト）

1. 枠 ON の keymap へ切り替えると、カーソルのある画面に既定 3×4 の枠が出る。別の keymap へ切り替える・フック停止・一時停止・ダイアログ表示で消える（§4.1）
2. 枠のキーで枠が強調されカーソルが中心へ動く / Space で 3×3 に細分化 / Esc・BackSpace で一段戻る / Enter・Shift+Enter で左・右クリックして最上段へ戻る（§4.3）
3. 枠の表示中、操作キーは他のアプリへ届かず、それ以外のキーと ctrl / alt / windows を押しながらのキーは届く。トリガー・置換は効かない。停止・トグル・直接切替キーは効く。Space の直後に打ったキーも漏れない（§4.3・§4.4）
4. Tab で次の画面へ枠が移る（2 画面以上）（§4.3・§7）
5. 編集の窓で段・列の追加 / 削除・境界のドラッグ・キーの変更ができ、OK → 保存 → 再読込で形が保たれる。画面ごとに別の形を持てる（§8・§3）
6. 細分化の分割数とキーを変えられる（§8.2）
7. `grid` の無い既存 keymap は読込・保存で差分が出ない（§3）。不正な `grid` で起動が止まらない
8. 予約キー・重複・空のキーを編集の OK で拒否する（§5）
9. §6 の検証で、枠の線とクリック位置が一致する（ユーザーの実機目視）
10. 最上段の Esc はアプリへ届き BackSpace は届かない。段 ≥1 ではどちらも一段戻る（§4.3）
11. 追加のダイアログで「枠を使う」を ON にしたキーマップは既定の形で枠が出る。枠だけの構成でフックの開始 → 一時停止 → 再開ができる（§8.1・§4.1）
12. 枠 ON のキーマップから別の枠 ON のキーマップへ切り替えると最上段・選択なしからやり直し、切替の前に押した操作は切替の後に実行されない（§4.1 の世代）
13. 表示中の画面を抜く・解像度を変えると、クリックせずにカーソルのある画面の最上段へ戻る（§4.1）。Shift+Enter の直後に Shift を離しても右クリックになる（§4.3）
14. 既存テスト（tests / tests_ui / smoke）が通る

## §12 スコープ外（本フェーズでやらない）

- 中クリック・ダブルクリック・ドラッグ・ホイール
- 枠の配色・線の太さの設定（文字の大きさは §7 の規則で決まり、個別の設定は持たない）
- 切替キーのまとめて設定のダイアログでの枠の形の編集（チェックのみ・§8.1）
- 枠の操作をトリガーのアクション（出力シーケンス）から呼ぶこと
- キーボード表示での枠の操作キーの表示（§9）
