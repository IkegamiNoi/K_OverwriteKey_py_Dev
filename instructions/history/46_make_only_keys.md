## §1 目的 / 背景

外付けの JIS キーボードの無変換・変換のように、**離しを送らず押下（DOWN）だけが届くキー**を、フックで普通のキーと同じく扱えるようにする。
具体的には「押した / 押し続けたときのリピート / 離した」の 3 つに組み直す。
主な目的は、キーボードUI（直接置換）で無変換・変換を近くにあると便利な別のキー（BackSpace・矢印 等）に置き換えて使うこと（ユーザー 2026-10-18）。

### 現状監査（2026-10-18〜19）

**実測**（Windows 11・JIS・外付けキーボード・低レベルフックの生の値）

- 無変換: `DOWN vk=0x1A(VK_IME_OFF) scan=241 flags=0x01(拡張)`
- 変換: `DOWN vk=0x16(VK_IME_ON) scan=242 flags=0x01`
- UP は一度も届かない
- 環境: MS-IME のキーの割り当てはオフ / `Scancode Map` 無し / キーを置き換える常駐ツールは無し

**届き方**

| 操作 | 届く押下の並び |
|---|---|
| 1 回押して離す | 押した瞬間に 1 回 → 離したときに**約 11〜13 ms 間隔の 2 回組** |
| 押し続ける | 押した瞬間に 1 回 → 約 0.5 秒後から OS のキーリピート（約 33 ms ごと・実測の間隔は 21〜46 ms）→ 離したときに 2 回組 |
| 素早く 3 回連打 | 「1 回」の並びが約 0.12 秒あけて 3 回（2 回組の後の静かな間は 89 ms 以上） |

半角/全角（41）・かな（112）は従来どおりで、今回は対象外。

**今の不具合**（phase 62 で確認・task_03b を戻した理由）

- 2 回目の押下が送信ガードの最中に届き、抑止されずに OS へ素通りする（`keyseq/application/input_router.py:88-90`）
  - 変換で IME が ON になる
- 3 回目の押下で再び置換され、二重送信になる
- 離しが届かないので、押下状態（`KeyStateManager`）に残る

**関連コード**

| 役割 | 場所 |
|---|---|
| フックの入口 | `presentation/controllers/hook_controller.py:289` `on_input_event` → `input_router.handle(event)` → `route.accept` を返し、actions は `after(0)` で実行（:293-298） |
| 判定 | `application/input_router.py:87-149` `handle`（送信ガード・一時停止 → 名前 → リピート判定 `is_pressed`（:96）→ 押下状態の更新 → 停止 / トグル / 切替 / 画面の枠 / トリガー / 直接置換） |

| 名前 | `presentation/keyboard_layouts.resolve_layout_key_id_from_scan_code`（レイアウトの `scan_code` だけ・phase 62） |

### 実機目視の NG の計測（2026-10-20・v0.4 の根拠）

task_03（v0.3 = リピートあり）の実機目視で「リピートの途中で IME が切り替わる」「離してもリピートがすぐ終わらない」が出た。task_03c のデバッグ出力（`make_only_trace.txt`・jis.json・無変換 → BackSpace）で測った結果:

- **原因 = 送信の最中に届いた物理の押下が、アプリのフックに届かず OS へ素通りする**
  - keyboard は送信の間 `_listener.is_replaying` を立て、その間のイベントは**物理の入力も含めて**フックへ渡さず通す（`.venv/Lib/site-packages/keyboard/__init__.py:233`・`:377-389`）。アプリの送信（`infrastructure/input_gateway.py:141`・`:183`）も同じ旗を立てる
  - 素通りした無変換（`VK_IME_OFF`）で IME が切り替わる
- リピートの最中は、約 33 ms ごとに届く押下のたびに BackSpace を送るので、送信と押下が重なる
  - 押下の間隔が 64.9 ms に開いた所が 2 回 = 押下が 1 回ずつ抜けている（OS へ素通り）
  - 離しの 2 回組の 2 回目も抜けた → 1 回目をリピートと取り違え、離した後に BackSpace が 2 回余分に出て、押したままの扱いが次の押下まで残った（次の押下で「古い押下」として直った）
- リピートの出ない短い押下（押した瞬間に 1 回だけ送る）では、2 回組は 1〜2 ms 間隔で届き、全て正しく「離した」になった（送信が押した直後の一瞬だけで、0.4 秒以上後の 2 回組と重ならない）
- タイマーは 16 ms の予約が 21〜32 ms で満了した（Windows のタイマーの粒度。§3.1 の「判定は時刻で行う」で吸収済み）
- 送信の最中の物理の入力の取りこぼしは、正本で既存の性質として受容済み（`key_input.md:170`・`:175`）。押下だけのキーでは「取りこぼした 1 回で IME が切り替わる」「2 回組が崩れる」ので、受容できない

### 実機目視の NG の計測（2026-10-20・v0.5 の根拠）

task_03d・03e（v0.4 = リピートなし）の実機目視で「押し続けるとリピートする」が出た（IME の切り替えも出たが、計測では 241 / 242 は全て抑止で、原因は未特定・§9 #7）。デバッグ出力（jis.json・変換 / 無変換 → BackSpace・2 秒ほどの長押し）で測った結果:

- 押し続けている途中のある時点で、フックの処理が約 30 ms 止まった（`dur_ms` = 31.2 / 29.5 ms。原因は未特定・デバッグ出力の書き出しを含む）
  - その間に届いた OS のリピート 2 回が 15.7 / 10.3 ms 間隔で処理され、離しの 2 回組と取り違えた（§3.3 の受容「フックのスレッドが詰まると、処理した間隔で測られる」）
- **連鎖**: 取り違えの次のリピート（28 / 32 ms 後）が「押した」になって BackSpace を 1 回送る → その次のリピート（約 33 ms 後）は「押した」から 400 ms より前の単独の押下なので、§3.2 の案 A で「離した」→ その次が「押した」…を手を離すまで繰り返す
  - 結果、リピート 2 回ごとに BackSpace 1 回（約 66 ms 間隔）が出続けた。v0.4 の §3.3 は取り違えを「1 回余分に出る」と見ていたが、案 A と組み合わさると連鎖する（v0.4 の想定外）
- 取り違えの前のリピートは全て正しく捨てていた（`discarded-hold`）。1 回押しは正しく「押した」1 回 →「離した」1 回

## §2 確定事項（ユーザー 2026-10-18〜19）

- **押下だけのキーは、走査コード 241 / 242 の表で見分ける**
  - Windows で離しを送らないキーとして決まっている値（韓国語キーボードのハンジャ / ハングルと同じ）
  - 名前の表ではなく「届き方」の表なので、phase 62 の「名前はレイアウトが決める」と矛盾しない
- **押下と離しの見分け方（案 B）**
  - 押していないときの押下 = 「押した」
  - 押している間の押下は抑止して、すぐには使わない
  - 16 ms 以下の間隔の 2 回組 = 「離した」
  - 保険: 押している間に一定時間（§3.3）何も届かなければ、離した扱いにする
- **リピートなし**（v0.4 で変更・ユーザー 2026-10-20。v0.3 の「リピートあり」を撤回）
  - 押している間の押下は抑止して捨てる（何も実行しない）。16 ms 待って、次の押下が来れば離しの 2 回組とみなす（離しの見分けは v0.3 のまま）。加えて、「押した」から OS のリピートの待ち時間 − 100 ms より前の単独の押下は 2 回組の片方 =「離した」とみなす（§3.2・§9 #3）
  - 理由: リピートのたびに送ると、送信の最中に届いた物理の押下が OS へ素通りして IME が切り替わり、2 回組も崩れる（§1「実機目視の NG の計測」）。送信を押した瞬間の 1 回だけにすれば、BackSpace のような短い置換先では重ならない（長い送信のトリガー等では残る・§3.3）
  - リピートありへ戻すのは、送信の見直し（[idea_53](../backlog/idea_53_send_without_dropping_physical_input.md)）の後
  - **離した直後の押下は押し続けの続き**（v0.5 で追加・ユーザー 2026-10-20）: 次のどちらかで「離した」とした後、16 ms を超え「離しの直後の時間」（§3.3・60 ms）以内に届いた押下は、押し直しではなく押し続けの続きとみなす。押している状態へ戻して何も実行しない（§3.2 注 5）
    - 長押しの途中の 2 回組の「離した」（「押した」から「片方の離しの時間」〔§3.3・既定 400 ms〕以上たってから）
    - 片方の「離した」（案 A）
    - 理由: 押し続けている途中の「離した」の取り違えから、案 A と組み合わさってリピートのように出続ける連鎖を、最初の 1 歩で止める（§1「実機目視の NG の計測（v0.5 の根拠）」）。取り違えは OS のリピートが届いている間にしか起きず、案 A の「離した」は 2 回組の片方の取りこぼし（まれ）か連鎖の途中にしか起きないので、この 2 つに絞る
    - 短い押下の後の 2 回組（連打）には当てない: 0.1 秒間隔の連打では離しから押し直しまでが 40 ms 前後になり得るので、続きとみなすと打鍵が消える（Codex 敵対的レビュー high）
- **キーボードUI の色**（v0.4 で追加・ユーザー 2026-10-20）: 押下だけのキーに直接置換を割り当てた枠は、リピートしないことが分かるように**灰色がかった緑**で出す（§3.4）
- **名前は `extra_scan_codes` で付ける**
  - 暫定 45 v0.4 §3.1 の設計に、Codex 敵対的レビューの指摘 2 件（修飾キー等の禁止の適用・受け取り専用の行の送信）を反映した形を使い直す
  - 見本の jis.json の `muhenkan` に 241、`henkan` に 242 を足す
- **送信は変えない**（`muhenkan` / `henkan` は `scan_code` の 123 / 121 で送る。2026-10-18 に実機で物理キーと同じ動きを確認済み）

## §3 押下だけのキーの組み直し

### §3.1 置き場所と依存の向き

- **application 層の新しいモジュール**（例: `application/make_only_keys.py`）に状態機械を置く
  - 状態はキーごと（走査コードごと）: 「押している / いない」・覚えた決定・最後の押下の時刻・保留の時刻・「古い押下」の印
  - 走査コードの表（241 / 242）は domain の定数（例: `domain/make_only_keys.py` の `MAKE_ONLY_SCAN_CODES`）
- **作るイベント**: application の小さな dataclass（`event_type` / `scan_code` / `name` / `is_keypad`）。keyboard の `KeyboardEvent` を import しない
  - `name` は元のイベントの値を写す（無変換・変換は `None`）。`is_keypad=False`
- **時刻**: 単調で高分解能の時計（`time.perf_counter` 相当）を外から受け取る
  - フックのスレッドがイベントを受けた時点で取る
  - keyboard の `event.time`（壁時計）は使わない
- **タイマー**: 「16 ms 後に呼ぶ」を外から受け取る（テストで差し替える）
  - 実装は 1 本のワーカーのスレッドで回し、リピートのたびにスレッドを作らない
  - Windows のタイマーは約 15.6 ms 単位で遅れ得るので、**判定はタイマーの状態ではなく時刻で行う**（§3.2）
- **直列化**: 状態機械は 1 本のロックを持つ。フックのスレッド・タイマーのスレッド・UI スレッド（消去）から呼ばれる
  - **ロックの中で行うのは、判定・状態の更新・押下状態の更新・`input_router.handle` の呼び出し（戻り値の受け取り）まで**。`handle` は Tk を呼ばない（設定の読み出しと押下状態だけ）
  - **Tk の呼び出し（`after` 等）はロックの中で行わない**（タイマーのスレッドがロックを持ったまま UI スレッドを待ち、UI スレッドが消去でロックを待つ相互待ちを防ぐ）
- **世代**: 消去（§3.2 末尾）のたびに世代を上げる。タイマーは保留を立てた時の世代を持ち、違えば何もしない
- **呼び出し口**: `hook_controller.on_input_event`
  - 押下だけのキーのイベント（走査コードが表にある）は、状態機械を通す
  - それ以外は今と同じ経路
  - デバッグ出力（`should_debug_special_key_event`）は生のイベントだけが対象（作ったイベントは対象外）
- actions の実行: ロックの外で、今の経路（`after(0)` → `_execute_reserved_action`）へ**世代つきで**予約する。実行時（UI スレッド）に世代が今と違えば捨てる（消去の後に予約が残っていた場合）
  - タイマーのスレッドから `after` を呼んで失敗した場合（アプリの終了後の `TclError` 等）は、ログに残して捨てる

### §3.2 状態と遷移

**押下（`down`）が時刻 t に届いたとき**（押下だけのキー・キーごと）:

| 状態 | 条件 | すること | フックへの戻り値 |
|---|---|---|---|
| 押していない | 直前の「離した」から 16 ms 以内 | 離しの 2 回組の続きとして捨てる | 前の押下の決定 |
| 押していない | 直前の「離した」が続きの対象（注 5）で、そこから 16 ms を超え「離しの直後の時間」（§3.3）以内（v0.5） | **押し続けの続き**: 押している状態へ戻す（覚えた決定は元の押下のまま・**「押した」の時刻は t に置き直す**）。そのうえで、この押下を「押している・保留なし」の行と同じく保留にする（t）。`input_router.handle` は呼ばない（注 5） | 前の押下の決定 |
| 押していない | それ以外 | **「押した」**: `input_router.handle(down)` へ渡し、戻り値を「このキーの決定」として覚える。押している状態へ | `handle` の戻り値 |
| 押している・保留なし | 最後の押下から t までが「古い押下の時間」（§3.3）より長い | 「古い押下」の印をつけて保留にする（t） | 覚えた決定（§3.2 の注 1） |
| 押している・保留なし | それ以外 | 保留にする（t） | 同上 |
| 押している・保留あり（時刻 p） | t − p ≤ 16 ms（16 ms ちょうどを含む） | **「離した」**: 保留を取り消す。押下状態から外す（下の注 3）。押していない状態へ（離した時刻 = t） | 同上 |
| 押している・保留あり（時刻 p） | t − p > 16 ms（タイマーが遅れた） | その場で保留を確定してから（下の「保留の確定」）、新しく保留にする（t）。**確定で「離した」になったら（v0.4）、この押下は「押していない」の行で扱い直す**（t − p > 16 ms なので「押した」） | 同上（扱い直したら「押していない」の行の戻り値） |

**保留の確定**（タイマーの満了時、または上の「遅れた」とき。どちらもロックの中で、**保留の時刻から 16 ms を厳密に超えているときだけ**〔16 ms ちょうどは「離した」の側・同じ時刻列ならタイマーと押下の処理順によらず同じ結果になる〕。早く満了したら待ち直す）:
- 「古い押下」の印が無く、保留の時刻 p が「押した」の時刻から「片方の離しの時間」（§3.3）**より前** → **2 回組の片方 =「離した」**（v0.4・§9 #3 の案 A）: 押下状態から外す（注 3）。押していない状態へ（離した時刻 = p）。`input_router.handle` は呼ばない
  - 根拠: OS のリピートは「押した」から待ち時間が過ぎるまで始まらないので、それより前に届く単独の押下は、2 回組の片方か押し直しのどちらか。片方とみなせば、続く押し直しは「押していない」状態に届いて「押した」になる
- 「古い押下」の印が無く、それ以外 → **押し続けている間の押下として捨てる**（v0.4・リピートなし）: `input_router.handle` を呼ばず、何も実行しない。押下状態は押したまま
- 「古い押下」の印がある → 前の押下の離しを取りこぼしていたとみなす。**「離した」→「押した」**の順に処理する（「押した」の決定を覚え直す）。出力は 16 ms 遅れる
- 保留を外す

**`up` が届いたとき**（押下だけのキーに離しが届いた場合。離しを送るキーボード・将来のキー）: ロックの中で、保留を取り消し、押していない状態へ戻し、**押下状態から外す（`KeyStateManager` へ直接 `up`・送信ガード・停止要求に関係なく）**。そのうえで今の経路（`input_router.handle`）へ渡し、戻り値をフックへ返す

**注**
1. **覚えた決定を返す**: 「押した」の後に届く押下は、**送信ガードの最中でも**覚えた決定で返す（2 回目が素通りして IME が切り替わる不具合の直し）
   - ただし**停止要求が残っている間（`get_hook_pause_count() > 0`）は素通し**にする（`key_input.md` §7.2「停止が間に合わず届いた入力は元のまま素通しする。飲み込まない」に従う）
2. **覚えるのはフックへの戻り値（抑止 / 素通し）だけ**（v0.4。v0.3 の「`handle` が actions を出したか」はリピートの判断にだけ使っていたので不要）
   - 押している間は、「押した」の決定によらず `handle` を呼ばず何も実行しない
   - 戻り値が素通し（送信ガード・停止要求・キーマップの切替中・割り当て無し・`suppress: false` のトリガー）なら、押している間の押下も素通しで OS に任せる
3. **「離した」は押下状態だけを更新する**（`KeyStateManager` に `up` を渡す）。`input_router.handle(up)` は actions を出さないので呼ばない。送信ガードの最中でも押下状態から外れる
4. **消去**: フックの開始・停止（`KeyStateManager.clear` と同じ時点・`hook_controller.py:138` / :166。停止要求のダイアログも `stop_hook` を通る）で、保留を取り消し、全キーを押していない状態にし、世代を上げる
5. **押し続けの続き**（v0.5）
   - 続きの対象の「離した」は 2 つ:
     - 長押しの途中の 2 回組の「離した」: 離した時刻 r（2 回目の t）−「押した」の時刻 ≥「片方の離しの時間」。「押した」の時刻は、押している間の最後の「押した」（古い押下の「押した」を含む）。続きでは続きの時刻に置き直す
     - 片方の「離した」（案 A・離した時刻 = 保留の時刻 p）
   - 対象外: 短い押下の 2 回組（連打）・`up` による離し・「古い押下」の「離した」→「押した」。対象外の「離した」の後は v0.4 のまま（16 ms 超の押下は「押した」）
   - 遅れた保留の確定で案 A の「離した」になり、その押下を「押していない」の行で扱い直す場合（§3.2 の表の最後の行）も、この行が先に当たる（t − p が 60 ms 以内なら続き）
   - 続きとみなしたら、「離した」の時刻を消す（同じ「離した」で 2 回続きにならない。続きの後の本物の離しは、2 回組で改めて「離した」になる）
   - **押下状態（`KeyStateManager`）は戻さない**。「離した」で外れたまま、本物の離しまで外れている（`is_pressed` を見るのはリピートの判定と画面の枠の修飾キーの判定だけ・押し続けの間は `handle` を呼ばないので影響しない）
   - **「押した」の時刻を続きの時刻に置き直す**（v0.5・Codex 敵対的レビュー 2 回目 high）。元の時刻を残すと、長押しの後の連打で続きの後の 2 回組が全て「長押しの途中」になり、以後の打鍵が全て続きとして消える（例: 0 ms 押下・1050 / 1063 ms 離し・1100 ms 押し直し・1150 / 1163 ms 離し・1200 ms 押し直し…）
     - 置き直すと、続きの後の 2 回組は短い押下の 2 回組（対象外）になり、消えるのは最初の 1 打だけ（上の例は 1100 ms だけが消え、1200 ms 以後は「押した」）
     - 押し続けている途中では、続きの保留の確定が案 A の「離した」になり、次の OS のリピートが 60 ms 以内で再び続き…を繰り返す（出力なし・押下状態は外れたまま）。本物の 2 回組で「離した」になって止まる（短い押下の 2 回組なので続きの対象外）

### §3.3 時間の値

| 値 | 決め方 |
|---|---|
| 離しの 2 回組の間隔 | **16 ms 以下**（実測の 2 回組は 11〜13 ms、OS のリピートの間隔は最短 21 ms） |
| 片方の離しの時間（v0.4） | **OS のリピートの待ち時間 − 100 ms**（既定 500 ms → 400 ms。待ち時間 250 ms なら 150 ms）。「押した」の時刻から測る。実測の最初のリピートは待ち時間ちょうど付近（0.501 s）なので、揺れで最初のリピートを「離した」と取り違えないよう 100 ms の余裕をとる |
| 離しの直後の時間（v0.5） | **60 ms**（続きの対象の「離した」の時刻から測る・16 ms を超え 60 ms 以内が対象）。OS のリピートの間隔の実測は 21〜46 ms（フックの詰まりの後も 28〜32 ms）に余裕をとった値。長押しを離した後・片方の取りこぼしの後の押し直しがこれより早いことはまれとみなす（受容・下記） |
| 古い押下の時間 | **OS のリピートの待ち時間 + 300 ms**（`keyboard_repeat_timing()` の待ち時間・既定 500 ms → 800 ms）。押し続けている間は、待ち時間の後に約 33 ms ごとに押下が届くので、これより長く静かなら離しを取りこぼしたか、別のキーを押してリピートが止まっている |

- 保険（§2 の「一定時間何も届かなければ離した扱い」）は、**次の押下が届いた時点で経過時間を見て判断する**形で行う（タイマーを持たない）
  - 押下状態は、次の押下までは押したまま残る（`is_pressed` を見るのはリピートの判定と画面の枠の修飾キーの判定だけで、影響は小さい）
- 「古い押下」は、押し続けている途中で別のキーを押した場合（OS のリピートは最後に押したキーだけを繰り返すので、無変換の押下が止まる）にも起きる。この場合、後の本物の離しの 2 回組は「古い押下 → 16 ms 以内に 2 回目」で「離した」になり、余計な出力は出ない

**受容**
- OS のリピートの間隔のばらつき・フックの詰まり: 間隔が 16 ms 以下に縮むと、押し続けている途中で「離した」と取り違える
  - 次の押下は 60 ms 以内に届くので、押し続けの続きに戻り、**余計な出力は出ない**（v0.5。v0.4 では「押した」になり、案 A と組み合わさって連鎖した・§1）
  - 次の押下が 60 ms を超えて届くと（取り違えの直後にさらに詰まる・リピートの間隔を 60 ms より遅く設定している等）、「押した」になって**置換先が 1 回余分に出る**。その後のリピートは、案 A の「離した」→ 60 ms 以内の続き、を繰り返すだけで出力は出ない（ただしリピートの間隔が 60 ms より遅い設定では続きにならず、v0.4 と同じ連鎖が残る・受容）
- 長押し（「片方の離しの時間」以上）を離してから 60 ms 以内に押し直す・2 回組の片方を取りこぼした後 60 ms 以内に押し直すと、押し続けの続きとみなされ、**その 1 打が実行されない**（v0.5。短い押下の後の連打には当てないので、取りこぼしの無い連打は消えない）
- OS のリピートの最後の押下（保留）から 16 ms 以内に 2 回組の 1 回目が来ると、1 回目で「離した」、2 回目は「離した直後の 16 ms 以内」として捨てる（余計な出力なし）
- 2 回組の片方を取りこぼした場合（v0.4・§9 #3 の案 A）:
  - 「押した」から「片方の離しの時間」より前に届いた片方 → 「離した」になる。続く押し直しは「押した」（例: 0 ms 押下・45 ms に片方だけ・120 ms に押し直し → 120 ms は「押した」・165 / 176 ms の 2 回組は「離した」）
  - それ以後（押し続けた後の離し）に届いた片方 → 押し続けている間の押下として捨て、押したままの扱いが残る（余計な出力は出ない）。次の押下が「古い押下の時間」（既定 800 ms）より後なら「古い押下」として「離した」→「押した」になる。それより前の押し直しは捨てられ、**その 1 打が実行されない**
- 「片方の離しの時間」より前の 2 回組の間隔が 16 ms を超えて届くと（フックのスレッドの詰まり等）、1 回目で案 A の「離した」、2 回目は 60 ms 以内なら続き → その保留の確定で再び案 A の「離した」になり、**余計な出力は出ない**（v0.5。v0.4 では 2 回目が「押した」になって 1 回余分に出ていた）。60 ms を超えると v0.4 と同じく 1 回余分に出る
- 2 回組が「片方の離しの時間」をまたいで 16 ms を超えて伸びても（例: 既定値で 0 ms 押下・390 / 420 ms に 2 回組）、390 ms で案 A の「離した」・420 ms は続き（「押した」の時刻 = 420 ms）→ 420 ms の保留の確定で再び案 A の「離した」になり、押したまま残らない。次の 509 ms の押下は「押した」（Codex 敵対的レビュー 1 回目 medium・注 5 の置き直しで解消）
- 2 回組を**両方**取りこぼした直後に「片方の離しの時間」より前に押し直すと、押し直しが「片方 =「離した」」とみなされ、**その 1 打が実行されない**（片方の取りこぼしより起きにくい・§9 #3 の案 A の弱み）
- 「押した」から「片方の離しの時間」より前に OS の最初のリピートが届くと（待ち時間の揺れが 100 ms を超える）、案 A の「離した」とみなされる。次のリピートは 60 ms 以内なので続きになり、「片方の離しの時間」を過ぎるまで「離した」と続きを繰り返す（出力なし・押下状態は外れたまま・v0.5。v0.4 では次のリピートが「押した」になって 1 回余分に出た）
- 「古い押下」の後の「押した」は 16 ms 遅れる（最初の「押した」は遅れない）
- 送信の最中に届いた物理の押下の素通り（§1）は、押下だけのキーでも残る。リピートなしで**頻度が下がるだけで、無くはならない**。直すのは [idea_53](../backlog/idea_53_send_without_dropping_physical_input.md)
  - 同じ押下の「押した」の送信自身が長い場合（text・file_line のトリガー〔`action_executor._write_text` は送信全体を送信ガードの中で行い、`keyboard.write` は送信の間 `is_replaying` を立てる〕・長い hotkey の列）: その間に届く OS のリピート・離しの 2 回組が素通りして、IME が切り替わり・2 回組が崩れ得る
  - 他の送信と重なる場合（key_hold のキーリピート・連続して実行されるトリガー・他のキーの直接置換 等）
- フックのスレッドが詰まると、間隔はキーボードが送った間隔ではなく、処理した間隔で測られる（OS の `KBDLLHOOKSTRUCT.time` は keyboard が渡さない）
- 停止キーを押下だけのキーにした場合、停止の actions は `after(0)` で後から動くので、フックが外れるまでに 2 回組が届き得る（覚えた決定で返す・二重には止まらない見込み・未確認）

### §3.4 キーボードUI の色（v0.4 で新設）

  - 案: 地 `#e4ebe1`・枠 `#7f9a74`・文字 `#2f4429`（最終の値は実機目視で決め、正本反映で `codebase_map.md` に書く）

- トリガーの枠（§9 #2）: 押下だけのキーのトリガーも押し続けて繰り返さないが、色は青のまま

## §4 名前（受け取り用の追加の走査コード `extra_scan_codes`）

暫定 45 v0.4 §3.1 の設計を、Codex 敵対的レビューの指摘 2 件を反映した形で使う。

- レイアウトの行に任意キー `extra_scan_codes`（整数の配列）を足せる（JSON スキーマの追加・既存キーは不変）
- 受け取り（フックの実行時・画面の枠の編集の窓・キーボードUI の取得・デバッグ出力の判定）:
  - イベントの走査コードが `scan_code` か `extra_scan_codes` のどれかに一致する最初の行の `id` を名前にする
  - 行の順に見て、行ごとに `scan_code` → `extra_scan_codes` の順に照合する
  - テンキーの名前を採らないガードは同じに効く
- 送信は `scan_code` だけを使う（`extra_scan_codes` は送信・検査・同じキーの判定に使わない）
  - `scan_code` が無く `extra_scan_codes` だけの行は、レイアウト由来の送信の候補にならない（その `id` がテンキー・拡張キー・keyboard で決まる名前ならそれで送る）
- 修飾キー・Caps Lock・Windows キー・AltGr の行に `extra_scan_codes` を書かない。これらのキーの走査コードを別の行の `extra_scan_codes` に書くことも同じ（`features.md` §4.6 の `scan_code` の禁止と同じ・規定のみ）
- 同じ走査コードを複数の行が持つときは、行の順で最初の行。読込で拒否しない
- 読込の検証:
  - 無い・`null` → 空
  - 配列でなければ読込エラー
  - 要素は整数にする（できなければ読込エラー）
  - 範囲は問わない
- 見本の jis.json: `muhenkan` に `"extra_scan_codes": [241]`、`henkan` に `[242]`
- `features.md` §4.6 の「押下だけで届く走査コード（241 / 242 等）を `scan_code` に書かない」はそのまま（受け取り用は `extra_scan_codes` に書く）

## §5 影響する機能の確認

- **直接置換**（キーボードUI・キーマップ）: 「押した」で置換先を 1 回送る。押し続けても繰り返さない（v0.4）。キーボードUI の枠は灰色がかった緑（§3.4）
- **トリガー**: 「押した」で 1 回実行。押し続けても `TriggerAction(repeat=True)` は出ない（v0.4・普通のキーのトリガーのリピートとは違う）
- **停止キー・トグルキー・切替キー**: 「押した」で 1 回動く（v0.4。押している間の押下では何も実行しない）
- **画面の枠**: 押下だけのキーを枠の操作キーにした場合も、上と同じ組み直しを通る
- **押下状態**: 「押した」で載り、「離した」で外れる
- **「キーを個別にフックする」設定**（`register_key_hook`・`hook_keys_individual`）: 今回は対象外（keyboard が `muhenkan` の名前を知らないため、もとから使えない・§7）

## §6 受け入れ条件（ドラフト）

1. 状態機械の単体テスト（時刻とタイマーを差し替え）
   - 1 回押して離す（押下 → 45 ms → 押下 → 11 ms → 押下）: 「押した」1 回・「離した」1 回・リピート 0 回（§3.2）
   - 押し続ける（押下 → 500 ms → 33 ms ごとに押下 × N → 22 ms → 押下 → 13 ms → 押下）: 「押した」1 回・**リピート 0 回**（押している間の押下は `handle` を呼ばない）・「離した」1 回（v0.4）
   - 素早く 3 回連打: 「押した」3 回・「離した」3 回
   - 古い押下: 押下の後に「古い押下の時間」より長く何も届かず、次に 2 回組が来る → 「離した」1 回・余計な出力なし（押したまま別のキーを押した場合）/ 次に単独の押下が来る → 16 ms 後に「離した」→「押した」（離しを取りこぼした場合・§3.3）
   - 最後のリピートの保留から 16 ms 以内に 2 回組 → 「離した」1 回・2 回目は捨てる・余計な出力なし
   - タイマーが遅れて満了する（保留から 16 ms を超えて次の押下）→ 古い押下でない保留は**捨ててから**新しい保留（`handle` を呼ばない・actions が増えない・v0.4）/ 早く満了する → 待ち直す / 古い押下の保留が遅れて確定する → 「離した」→「押した」（別の条件として確かめる）
   - 2 回組の片方を取りこぼした後の押し直し（0 ms 押下 → 45 ms に 1 回だけ → 120 ms に押下 → 165 / 176 ms に 2 回組）: 「押した」2 回・「離した」2 回（45 ms の片方で「離した」）・`handle` の呼び出しは「押した」の 2 回だけ
   - 片方の離しの時間の境目（待ち時間 500 ms → 400 ms）: 「押した」から 399 ms の単独の押下 → 「離した」/ 401 ms の単独の押下 → 捨てる（押したまま）/ 待ち時間を差し替えると境目が動く
   - 押し続けた後に片方だけ届く（押下 → 500 ms → 33 ms ごとに押下 × N → 22 ms → 押下 1 回だけ）→ 捨てて押したまま。次の押下が古い押下の時間より後なら「離した」→「押した」
   - 「押した」の決定が抑止なら、続く押下も抑止を返す（送信ガード中でも）/ 停止要求の間は素通し / 「押した」の決定が素通しなら、続く押下も素通しで、リピートの actions を実行しない
   - `up` が届いたら保留を取り消し、押していない状態へ / 「離した」は送信ガードの最中でも押下状態から外す
   - フックの開始・停止で保留が取り消され、状態が消える / 消去の後に満了したタイマー（古い世代）は何もしない
   - フックのスレッドとタイマーのスレッドから同時に呼んでも、押下状態が「離した」の後に残らない（ロック）
   - 保留から 16 ms ちょうどに次の押下とタイマーが重なっても、処理の順によらず「離した」になる
   - 送信ガードの最中に実の `up` が届いても、押下状態から外れる
   - `suppress: false` のトリガー（素通しで actions あり）は、押し続けても「押した」の 1 回だけ動き、押している間の押下は素通し / 割り当て無し（素通しで actions なし）も、押している間 `handle` を呼ばない（v0.4）
   - 消去の後に実行された予約（古い世代）は捨てられる
   - ロックの中で Tk を呼ばない（タイマーの確定の actions はロックの外で予約される）
   - 押し続けの続き（v0.5・§3.2 注 5）:
     - 実機の連鎖の再現（押下 → 500 ms → 33 ms ごとに押下 × N → 途中で 2 回を 15 ms 間隔 → 続けて 30 ms ごとに押下 × M → 22 ms → 押下 → 13 ms → 押下）: 「押した」1 回・`handle` の呼び出しは最初の「押した」の 1 回だけ・最後の 2 回組で「離した」・離した後に押していない状態
     - 片方の「離した」（案 A）の後の続き: 押下 → 400 ms より前に単独の押下 → 遅れた確定で「離した」→ 30 ms 後の押下は続き（`handle` を呼ばない）
     - 境目: 「離した」から 60 ms ちょうどの押下 → 続き / 61 ms → 「押した」/ 16 ms ちょうど → 2 回組の続きとして捨てる（v0.4 のまま）
     - 続きで「押した」の時刻が続きの時刻に置き直され、続きの保留の確定は案 A の「離した」になる（押し続けの途中は、この「離した」と次のリピートの続きを出力なしで繰り返す）
     - 続きの後の本物の 2 回組で「離した」になり、その 80 ms 後の押下は「押した」
     - 続きは同じ「離した」で 2 回起きない（続きとみなした時点で「離した」の時刻を消す。続きの保留が再び「離した」になった場合は、その新しい「離した」の時刻から測る）
     - 連打には当てない（Codex 敵対的レビュー high）: 押下を 0 / 100 / 200 ms・2 回組を 50 / 63・150 / 163・250 / 263 ms → 「押した」3 回・「離した」3 回（100 / 200 ms の押下は 2 回組から 37 ms でも「押した」）
     - 2 回組が「片方の離しの時間」をまたぐ（Codex 敵対的レビュー 1 回目 medium）: 0 ms 押下 → 390 / 420 ms に 2 回組 → 390 ms で「離した」・420 ms は続き・420 ms の保留の確定で「離した」→ 509 ms の押下は「押した」
     - 長押しの後の連打（Codex 敵対的レビュー 2 回目 high）: 0 ms 押下 → 33 ms ごとのリピート → 1050 / 1063 ms に 2 回組 → 1100 ms 押下 → 1150 / 1163 ms に 2 回組 → 1200 ms 押下 → 1250 / 1263 ms → 1300 ms 押下 → 1350 / 1363 ms: 1100 ms は続き（`handle` を呼ばない・受容の 1 打）/ 1200・1300 ms は「押した」/ 最後に押していない状態
     - 停止要求の間は続きの押下も素通し（注 1）
2. `input_router` を通した結合テスト: 直接置換の元キーが `muhenkan`（jis.json + 241）のとき、1 回押して離すと置換先が 1 回だけ送られる / **押し続けても置換先は 1 回だけ**（v0.4）/ 離した後に押下状態に残らない
3. `extra_scan_codes` の読込・受け取りの照合・送信に使わないこと・デバッグ出力の判定（§4。暫定 45 v0.4 §7 #13 と同じ項目）
4. 241 / 242 以外のキーの判定が変わらない（既存テストが全て通る）
5. キーボードUI の色（§3.4・v0.4）: jis.json で `muhenkan` に直接置換を割り当てると灰色がかった緑 / 割り当てが無ければ白 / `muhenkan` をトリガーにすると青のまま / 押下だけの走査コードを持たない行（例: `kana`）の直接置換は緑のまま
6. 実機目視（ユーザー・JIS 外付けキーボード・jis.json）
   - キーボードUI で無変換を BackSpace に置き換え、1 回押すと 1 文字消える / **押し続けても 1 文字だけ消える・離した後に余計に消えない**（v0.4）/ 2 秒以上の長押しを 3 回以上くり返しても、途中でリピートのように消え続けない（v0.5・デバッグ出力で `released` の後に `down accept` が続かないことも確かめる）
   - 素早く連打（約 0.1 秒間隔）しても、打った回数だけ消える（v0.5 の「離しの直後の時間」で 1 打が消えない）
   - 無変換・変換を置き換えて押し続けて離しても、IME が切り替わらない（2〜3 回・1 秒以上の長押しを含む）
   - キーボードUI で無変換・変換の枠が灰色がかった緑になり、緑・灰色の枠と見分けられる（§3.4）
   - （任意・受容の確認）無変換に長い text のトリガーを割り当てて押し続けると、IME が切り替わり得る（§3.3 の受容。直すのは idea_53）
   - 無変換を押したまま別のキー（例: Shift）を押し、無変換を離す → 余計な出力が出ない（届き方は未測定。目視で確かめる）
