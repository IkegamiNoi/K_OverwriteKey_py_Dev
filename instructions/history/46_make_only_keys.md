## §1 目的 / 背景

外付けの JIS キーボードの無変換・変換のように、**離しを送らず押下（DOWN）だけが届くキー**を、フックで普通のキーと同じく扱えるようにする。
具体的には「押した / 押し続けたときのリピート / 離した」の 3 つに組み直す。
主な目的は、キーボードUI（直接置換）で無変換・変換を近くにあると便利な別のキー（BackSpace・矢印 等）に置き換えて使うこと（ユーザー 2026-10-18）。

### 現状監査（2026-10-18〜19）

**実測**（Windows 11・JIS・外付けキーボード・低レベルフックの生の値）

- 無変換: `DOWN vk=0x1A(VK_IME_OFF) scan=241 flags=0x01(拡張)`
- 変換: `DOWN vk=0x16(VK_IME_ON) scan=242 flags=0x01`
- UP は一度も届かない
- 環境: MS-IME のキーの割り当てはオフ / `Scancode Map` 無し / キーを置き換える常駐ツールは無し

**届き方**

| 操作 | 届く押下の並び |
|---|---|
| 1 回押して離す | 押した瞬間に 1 回 → 離したときに**約 11〜13 ms 間隔の 2 回組** |
| 押し続ける | 押した瞬間に 1 回 → 約 0.5 秒後から OS のキーリピート（約 33 ms ごと・実測の間隔は 21〜46 ms）→ 離したときに 2 回組 |
| 素早く 3 回連打 | 「1 回」の並びが約 0.12 秒あけて 3 回（2 回組の後の静かな間は 89 ms 以上） |

半角/全角（41）・かな（112）は従来どおりで、今回は対象外。

**今の不具合**（phase 62 で確認・task_03b を戻した理由）

- 2 回目の押下が送信ガードの最中に届き、抑止されずに OS へ素通りする（`keyseq/application/input_router.py:88-90`）
  - 変換で IME が ON になる
- 3 回目の押下で再び置換され、二重送信になる
- 離しが届かないので、押下状態（`KeyStateManager`）に残る

**関連コード**

| 役割 | 場所 |
|---|---|
| フックの入口 | `presentation/controllers/hook_controller.py:289` `on_input_event` → `input_router.handle(event)` → `route.accept` を返し、actions は `after(0)` で実行（:293-298） |
| 判定 | `application/input_router.py:87-149` `handle`（送信ガード・一時停止 → 名前 → リピート判定 `is_pressed`（:96）→ 押下状態の更新 → 停止 / トグル / 切替 / 画面の枠 / トリガー / 直接置換） |

| 名前 | `presentation/keyboard_layouts.resolve_layout_key_id_from_scan_code`（レイアウトの `scan_code` だけ・phase 62） |

## §2 確定事項（ユーザー 2026-10-18〜19）

- **押下だけのキーは、走査コード 241 / 242 の表で見分ける**
  - Windows で離しを送らないキーとして決まっている値（韓国語キーボードのハンジャ / ハングルと同じ）
  - 名前の表ではなく「届き方」の表なので、phase 62 の「名前はレイアウトが決める」と矛盾しない
- **押下と離しの見分け方（案 B）**
  - 押していないときの押下 = 「押した」
  - 押している間の押下は抑止して、すぐには使わない
  - 16 ms 以下の間隔の 2 回組 = 「離した」
  - 保険: 押している間に一定時間（§3.3）何も届かなければ、離した扱いにする
- **リピートあり**
  - 押している間の押下は 16 ms 待つ。次の押下が来なければリピートとして扱い、来れば離しの 2 回組とみなす
  - 理由: 直接置換で BackSpace・矢印などに置き換えるときに、普通のキーと同じくリピートが要る
- **名前は `extra_scan_codes` で付ける**
  - 暫定 45 v0.4 §3.1 の設計に、Codex 敵対的レビューの指摘 2 件（修飾キー等の禁止の適用・受け取り専用の行の送信）を反映した形を使い直す
  - 見本の jis.json の `muhenkan` に 241、`henkan` に 242 を足す
- **送信は変えない**（`muhenkan` / `henkan` は `scan_code` の 123 / 121 で送る。2026-10-18 に実機で物理キーと同じ動きを確認済み）

## §3 押下だけのキーの組み直し

### §3.1 置き場所と依存の向き

- **application 層の新しいモジュール**（例: `application/make_only_keys.py`）に状態機械を置く
  - 状態はキーごと（走査コードごと）: 「押している / いない」・覚えた決定・最後の押下の時刻・保留の時刻・「古い押下」の印
  - 走査コードの表（241 / 242）は domain の定数（例: `domain/make_only_keys.py` の `MAKE_ONLY_SCAN_CODES`）
- **作るイベント**: application の小さな dataclass（`event_type` / `scan_code` / `name` / `is_keypad`）。keyboard の `KeyboardEvent` を import しない
  - `name` は元のイベントの値を写す（無変換・変換は `None`）。`is_keypad=False`
- **時刻**: 単調で高分解能の時計（`time.perf_counter` 相当）を外から受け取る
  - フックのスレッドがイベントを受けた時点で取る
  - keyboard の `event.time`（壁時計）は使わない
- **タイマー**: 「16 ms 後に呼ぶ」を外から受け取る（テストで差し替える）
  - 実装は 1 本のワーカーのスレッドで回し、リピートのたびにスレッドを作らない
  - Windows のタイマーは約 15.6 ms 単位で遅れ得るので、**判定はタイマーの状態ではなく時刻で行う**（§3.2）
- **直列化**: 状態機械は 1 本のロックを持つ。フックのスレッド・タイマーのスレッド・UI スレッド（消去）から呼ばれる
  - **ロックの中で行うのは、判定・状態の更新・押下状態の更新・`input_router.handle` の呼び出し（戻り値の受け取り）まで**。`handle` は Tk を呼ばない（設定の読み出しと押下状態だけ）
  - **Tk の呼び出し（`after` 等）はロックの中で行わない**（タイマーのスレッドがロックを持ったまま UI スレッドを待ち、UI スレッドが消去でロックを待つ相互待ちを防ぐ）
- **世代**: 消去（§3.2 末尾）のたびに世代を上げる。タイマーは保留を立てた時の世代を持ち、違えば何もしない
- **呼び出し口**: `hook_controller.on_input_event`
  - 押下だけのキーのイベント（走査コードが表にある）は、状態機械を通す
  - それ以外は今と同じ経路
  - デバッグ出力（`should_debug_special_key_event`）は生のイベントだけが対象（作ったイベントは対象外）
- actions の実行: ロックの外で、今の経路（`after(0)` → `_execute_reserved_action`）へ**世代つきで**予約する。実行時（UI スレッド）に世代が今と違えば捨てる（消去の後に予約が残っていた場合）
  - タイマーのスレッドから `after` を呼んで失敗した場合（アプリの終了後の `TclError` 等）は、ログに残して捨てる

### §3.2 状態と遷移

**押下（`down`）が時刻 t に届いたとき**（押下だけのキー・キーごと）:

| 状態 | 条件 | すること | フックへの戻り値 |
|---|---|---|---|
| 押していない | 直前の「離した」から 16 ms 以内 | 離しの 2 回組の続きとして捨てる | 前の押下の決定 |
| 押していない | それ以外 | **「押した」**: `input_router.handle(down)` へ渡し、戻り値を「このキーの決定」として覚える。押している状態へ | `handle` の戻り値 |
| 押している・保留なし | 最後の押下から t までが「古い押下の時間」（§3.3）より長い | 「古い押下」の印をつけて保留にする（t） | 覚えた決定（§3.2 の注 1） |
| 押している・保留なし | それ以外 | 保留にする（t） | 同上 |
| 押している・保留あり（時刻 p） | t − p ≤ 16 ms（16 ms ちょうどを含む） | **「離した」**: 保留を取り消す。押下状態から外す（下の注 3）。押していない状態へ（離した時刻 = t） | 同上 |
| 押している・保留あり（時刻 p） | t − p > 16 ms（タイマーが遅れた） | その場で保留を確定してから（下の「保留の確定」）、新しく保留にする（t） | 同上 |

**保留の確定**（タイマーの満了時、または上の「遅れた」とき。どちらもロックの中で、**保留の時刻から 16 ms を厳密に超えているときだけ**〔16 ms ちょうどは「離した」の側・同じ時刻列ならタイマーと押下の処理順によらず同じ結果になる〕。早く満了したら待ち直す）:
- 「古い押下」の印が無い → **「リピート」**: 「押した」が actions を出したキーなら（注 2）、`input_router.handle(down)` へ渡す（押下状態にあるのでリピート扱い）。出た actions を実行する（ロックの外で予約）
- 「古い押下」の印がある → 前の押下の離しを取りこぼしていたとみなす。**「離した」→「押した」**の順に処理する（「押した」の決定を覚え直す）。出力は 16 ms 遅れる
- 保留を外す

**`up` が届いたとき**（押下だけのキーに離しが届いた場合。離しを送るキーボード・将来のキー）: ロックの中で、保留を取り消し、押していない状態へ戻し、**押下状態から外す（`KeyStateManager` へ直接 `up`・送信ガード・停止要求に関係なく）**。そのうえで今の経路（`input_router.handle`）へ渡し、戻り値をフックへ返す

**注**
1. **覚えた決定を返す**: 「押した」の後に届く押下は、**送信ガードの最中でも**覚えた決定で返す（2 回目が素通りして IME が切り替わる不具合の直し）
   - ただし**停止要求が残っている間（`get_hook_pause_count() > 0`）は素通し**にする（`key_input.md` §7.2「停止が間に合わず届いた入力は元のまま素通しする。飲み込まない」に従う）
2. **覚えるのは 2 つ**: フックへの戻り値（抑止 / 素通し）と、「押した」の `handle` が actions を出したか
   - actions を出していない（送信ガード・停止要求・キーマップの切替中・割り当て無し）なら、押している間は `handle` を呼ばず何も実行しない（OS に任せる）
   - actions を出したなら、戻り値が素通し（`suppress: false` のトリガー・`input_router.py:138-141`）でもリピートで `handle` を呼ぶ（普通のキーのトリガーのリピート〔`key_input.md` §7.3〕と同じ）
3. **「離した」は押下状態だけを更新する**（`KeyStateManager` に `up` を渡す）。`input_router.handle(up)` は actions を出さないので呼ばない。送信ガードの最中でも押下状態から外れる
4. **消去**: フックの開始・停止（`KeyStateManager.clear` と同じ時点・`hook_controller.py:138` / :166。停止要求のダイアログも `stop_hook` を通る）で、保留を取り消し、全キーを押していない状態にし、世代を上げる

### §3.3 時間の値

| 値 | 決め方 |
|---|---|
| 離しの 2 回組の間隔 | **16 ms 以下**（実測の 2 回組は 11〜13 ms、OS のリピートの間隔は最短 21 ms） |
| 古い押下の時間 | **OS のリピートの待ち時間 + 300 ms**（`keyboard_repeat_timing()` の待ち時間・既定 500 ms → 800 ms）。押し続けている間は、待ち時間の後に約 33 ms ごとに押下が届くので、これより長く静かなら離しを取りこぼしたか、別のキーを押してリピートが止まっている |

- 保険（§2 の「一定時間何も届かなければ離した扱い」）は、**次の押下が届いた時点で経過時間を見て判断する**形で行う（タイマーを持たない）
  - 押下状態は、次の押下までは押したまま残る（`is_pressed` を見るのはリピートの判定と画面の枠の修飾キーの判定だけで、影響は小さい）
- 「古い押下」は、押し続けている途中で別のキーを押した場合（OS のリピートは最後に押したキーだけを繰り返すので、無変換の押下が止まる）にも起きる。この場合、後の本物の離しの 2 回組は「古い押下 → 16 ms 以内に 2 回目」で「離した」になり、余計な出力は出ない

**受容**
- リピートの間隔のばらつき: 間隔が 16 ms 以下に縮むと、押し続けている途中で「離した」と取り違える
  - 次の押下は「押した」として届くので、出るキーの数はほぼ変わらない（リピート 1 回分が「押した」1 回に置き換わる）
- 最後のリピートの保留から 16 ms 以内に 2 回組の 1 回目が来ると、1 回目で「離した」、2 回目は「離した直後の 16 ms 以内」として捨てる（余計な出力なし）
- 2 回組の片方を取りこぼすと、保留がリピートとして余計に 1 回出る
- リピートは 16 ms 遅れて実行される（最初の「押した」は遅れない）。「古い押下」の後の「押した」も 16 ms 遅れる
- フックのスレッドが詰まると、間隔はキーボードが送った間隔ではなく、処理した間隔で測られる（OS の `KBDLLHOOKSTRUCT.time` は keyboard が渡さない）
- 停止キーを押下だけのキーにした場合、停止の actions は `after(0)` で後から動くので、フックが外れるまでに 2 回組が届き得る（覚えた決定で返す・二重には止まらない見込み・未確認）
- リピートの `TriggerAction(repeat=True)` の扱いは、普通のキーのリピートと同じ

## §4 名前（受け取り用の追加の走査コード `extra_scan_codes`）

暫定 45 v0.4 §3.1 の設計を、Codex 敵対的レビューの指摘 2 件を反映した形で使う。

- レイアウトの行に任意キー `extra_scan_codes`（整数の配列）を足せる（JSON スキーマの追加・既存キーは不変）
- 受け取り（フックの実行時・画面の枠の編集の窓・キーボードUI の取得・デバッグ出力の判定）:
  - イベントの走査コードが `scan_code` か `extra_scan_codes` のどれかに一致する最初の行の `id` を名前にする
  - 行の順に見て、行ごとに `scan_code` → `extra_scan_codes` の順に照合する
  - テンキーの名前を採らないガードは同じに効く
- 送信は `scan_code` だけを使う（`extra_scan_codes` は送信・検査・同じキーの判定に使わない）
  - `scan_code` が無く `extra_scan_codes` だけの行は、レイアウト由来の送信の候補にならない（その `id` がテンキー・拡張キー・keyboard で決まる名前ならそれで送る）
- 修飾キー・Caps Lock・Windows キー・AltGr の行に `extra_scan_codes` を書かない。これらのキーの走査コードを別の行の `extra_scan_codes` に書くことも同じ（`features.md` §4.6 の `scan_code` の禁止と同じ・規定のみ）
- 同じ走査コードを複数の行が持つときは、行の順で最初の行。読込で拒否しない
- 読込の検証:
  - 無い・`null` → 空
  - 配列でなければ読込エラー
  - 要素は整数にする（できなければ読込エラー）
  - 範囲は問わない
- 見本の jis.json: `muhenkan` に `"extra_scan_codes": [241]`、`henkan` に `[242]`
- `features.md` §4.6 の「押下だけで届く走査コード（241 / 242 等）を `scan_code` に書かない」はそのまま（受け取り用は `extra_scan_codes` に書く）

## §5 影響する機能の確認

- **直接置換**（キーボードUI・キーマップ）: 「押した」で置換先を送り、リピートで繰り返し送る（普通のキーと同じ）
- **トリガー**: 「押した」で実行。リピートは `TriggerAction(repeat=True)`（今の普通のキーのリピートと同じ扱い）
- **停止キー・トグルキー・切替キー**: 「押した」で動く。リピートでも今の普通のキーと同じ扱い
- **画面の枠**: 押下だけのキーを枠の操作キーにした場合も、上と同じ組み直しを通る
- **押下状態**: 「押した」で載り、「離した」で外れる
- **「キーを個別にフックする」設定**（`register_key_hook`・`hook_keys_individual`）: 今回は対象外（keyboard が `muhenkan` の名前を知らないため、もとから使えない・§7）

## §6 受け入れ条件（ドラフト）

1. 状態機械の単体テスト（時刻とタイマーを差し替え）
   - 1 回押して離す（押下 → 45 ms → 押下 → 11 ms → 押下）: 「押した」1 回・「離した」1 回・リピート 0 回（§3.2）
   - 押し続ける（押下 → 500 ms → 33 ms ごとに押下 × N → 22 ms → 押下 → 13 ms → 押下）: 「押した」1 回・リピート N 回・「離した」1 回
   - 素早く 3 回連打: 「押した」3 回・「離した」3 回
   - 古い押下: 押下の後に「古い押下の時間」より長く何も届かず、次に 2 回組が来る → 「離した」1 回・余計な出力なし（押したまま別のキーを押した場合）/ 次に単独の押下が来る → 16 ms 後に「離した」→「押した」（離しを取りこぼした場合・§3.3）
   - 最後のリピートの保留から 16 ms 以内に 2 回組 → 「離した」1 回・2 回目は捨てる・余計な出力なし
   - タイマーが遅れて満了する（保留から 16 ms を超えて次の押下）→ 保留をリピートとして確定してから新しい保留 / 早く満了する → 待ち直す
   - 「押した」の決定が抑止なら、続く押下も抑止を返す（送信ガード中でも）/ 停止要求の間は素通し / 「押した」の決定が素通しなら、続く押下も素通しで、リピートの actions を実行しない
   - `up` が届いたら保留を取り消し、押していない状態へ / 「離した」は送信ガードの最中でも押下状態から外す
   - フックの開始・停止で保留が取り消され、状態が消える / 消去の後に満了したタイマー（古い世代）は何もしない
   - フックのスレッドとタイマーのスレッドから同時に呼んでも、押下状態が「離した」の後に残らない（ロック）
   - 保留から 16 ms ちょうどに次の押下とタイマーが重なっても、処理の順によらず「離した」になる
   - 送信ガードの最中に実の `up` が届いても、押下状態から外れる
   - `suppress: false` のトリガー（素通しで actions あり）は、押し続けるとリピートで動く / 割り当て無し（素通しで actions なし）は、押している間 `handle` を呼ばない
   - 消去の後に実行された予約（古い世代）は捨てられる
   - ロックの中で Tk を呼ばない（タイマーの確定の actions はロックの外で予約される）
2. `input_router` を通した結合テスト: 直接置換の元キーが `muhenkan`（jis.json + 241）のとき、1 回押して離すと置換先が 1 回だけ送られる / 押し続けると繰り返し送られる / 離した後に押下状態に残らない
3. `extra_scan_codes` の読込・受け取りの照合・送信に使わないこと・デバッグ出力の判定（§4。暫定 45 v0.4 §7 #13 と同じ項目）
4. 241 / 242 以外のキーの判定が変わらない（既存テストが全て通る）
5. 実機目視（ユーザー・JIS 外付けキーボード・jis.json）
   - キーボードUI で無変換を BackSpace に置き換え、1 回押すと 1 文字消える / 押し続けると続けて消える / 離すと止まる
   - 変換を別のキーに置き換えて押しても、IME が切り替わらない
   - 無変換を押したまま別のキー（例: Shift）を押し、無変換を離す → 余計な出力が出ない（届き方は未測定。目視で確かめる）
