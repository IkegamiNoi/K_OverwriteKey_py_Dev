## §1 目的 / 背景

ヘルプを開いたあとに別のダイアログ（`grab_modal`）を開くと、Mac・Windows ともヘルプが操作できなくなる（ユーザー報告の場面: メニューから開いたヘルプ → アクションの追加 /「?」から開いたヘルプ → プリセット編集）。
ヘルプが、新しく grab を持ったダイアログの「子」でないため（Windows = grab の部分木の外・Mac = grab の窓以外にクリックが届かない）。
本書は、**ヘルプを常に「いちばん手前のダイアログ（なければ App）」の子として持つ**ことで、ダイアログの間もヘルプを操作できるようにする。

### 現状監査（2026-11-26・deep-reviewer の実測を含む）

- ヘルプは `HelpWindow(tk.Toplevel)`（`help/help_window.py`）・単一は `HelpWindowController`（`help/help_window_controller.py`）。メニュー = `open(tab)`（親 = App・`controller:34-38`）/「?」= `open_for_dialog`（親 = そのダイアログ・親が違えば `close()` して作り直す・`controller:60-70`）。窓を作るたびに `load_content()` で本文を読み直す（`controller:43`）。
- Tk には窓の親を後から変える機能がない → 付け替え = **作り直し**。
- ヘルプの状態（実装と照合済み）: 窓の位置と大きさ / 選択中のタブ（`notebook`）/ 絞り込みの文字（`filter_var`）/ タブごとの開いた見出し（`HelpTabView._open`）・選択中の見出し（`_selected`）・本文のスクロール位置（`text.yview()`）/ 本文の選択範囲 / 窓の表示状態（通常・最小化）。`apply_filter` は `_open` を空にする（`help_tab_view.py:100`）。本文の読込に失敗した窓には Notebook もタブもない（`help_window.py:53-59`）。作った直後に `after_idle` で Notebook へフォーカスを入れる（`help_window.py:38・124-128`）。
- モーダルの台帳は `modal.py` の `_active_modals`（`grab_modal` で開いた窓・開いた順）。外へ知らせる口は `set_modal_presence_listener`（ある / ないの変化だけ・登録先は 1 つ・`modal.py:23-25`）。閉じるときの処理 `restore_grab`（`modal.py:354-391`）は、台帳から外して存在を知らせたあと、`previous is None` などで早期 return し、そうでなければ前の持ち主へ grab を戻す。メッセージボックスは台帳に入らない。
- **破棄の順（Mac・素の tkinter で実測）**: ダイアログが破棄されると、子のヘルプの `<Destroy>` が先に来て、そのあとダイアログの `<Destroy>`（`restore_grab`）が来る。ヘルプの `<Destroy>` の時点では親はまだ `winfo_exists()` が真。**台帳から外れた直後に同期で作り直すと、入れ子の外側がまだ破棄の途中だったり App の終了中だったりして、作った窓がすぐ消える**。`after_idle` に回せば作れる。
- `choice_dialog._grab_holder`（`controllers/config_io/choice_dialog.py:66-73`）は grab の持ち主を新しいダイアログの親にする。Mac でヘルプが grab を持つ間に開くと、ヘルプが親になり得る。
- カーソルグリッドの編集窓は `overrideredirect`・`-topmost`・`-alpha 0.5` で画面全体を覆う `grab_modal`（`dialogs/grid_editor_window.py:53-55・70`）。
- 正本「モーダルダイアログの作法」は「開いた時点では、窓の前面化・フォーカス強制は行わない」「閉じた後のフォーカスの戻り先は規定しない」（`features.md` 1142〜1153 行付近）。
- Mac の grab の受け渡し（task_02）= `help/grab_handoff.py`（相手 = 作った時の親）。
- 実測（`task01_measurement.md` §10）が裏付けるのは**開くときの付け替え**（新しい窓を先に出してから古い窓を消す・66〜150 ms・状態は保たれる）まで。目視用スクリプトは閉じるときもダイアログを破棄する**前**に付け替えており、本書 §3.5 の「破棄されたあとに作り直す」経路と §3.6 の重なり・フォーカスは、task_03 で実測した（`task01_measurement.md` §11・§12・Mac は操作・Windows はユーザーの報告で問題なし）。

関連する正本: `features.md` §4.6「ヘルプの窓」（1049〜1082 行）・「モーダルダイアログの作法」（1138 行〜）/ `key_input.md` 28〜29 行。

## §2 確定事項（ユーザー 2026-11-26）

- **案 E を採る**: ヘルプを、いちばん手前のダイアログの子へ作り直して付け替える。状態を引き継ぐ。ダイアログが閉じたら 1 つ前のダイアログ（なければ App）の子へ戻す。
- 「親でないダイアログが開いたらヘルプを閉じる」案は採らない。
- Mac の grab の受け渡し（task_02・案 D）は残し、相手を「その時点の親」にする。Windows は受け渡しをしない。
- （v0.3・確認事項 1）**「?」から開いたヘルプも、そのダイアログを閉じたあと残す**（持ち主の子へ移る。メニューから開いたヘルプと同じ扱い）。
- （v0.3・確認事項 2）**閉じるときの一瞬の消え方（§3.5）は実装後の目視で許容を確かめる**。気になるなら、ダイアログを閉じる前に付け替える口を別タスクで検討する。
- （v0.3・確認事項 3）**本文の選択範囲は引き継がない**。
- （v0.3・確認事項 4）**カーソルグリッドの編集窓は付け替えの対象外**（§3.1）。
- （v0.6・task_06 の統合レビュー）**付け替えのあとのフォーカスの戻しの判定は「このアプリ（プロセス）の窓が前面か」**（§3.6）。**Tk 9.1 の deiconify の対策は Mac（aqua）だけ**（§3.7）。**App が最小化されている間は付け替えを待ち、元に戻したときに行う**（§3.2）。**最後のダイアログを閉じたあとの入力先は、task_06 の目視で確かめてから決める**（§3.6）。

## §3 付け替えの規則

### §3.1 持ち主（親）

- ヘルプの親（**持ち主**）= 台帳 `_active_modals` を末尾から見て、**存在していて付け替えの対象外でない**最初の窓。無ければ App。
- **付け替えの対象外**（持ち主にならない）: カーソルグリッドの編集窓（画面全体を覆う最前面の半透明の窓で、その下のヘルプはどのみち操作できず、最前面のヘルプは覆いの上に出てキャンバスを隠すため）。編集窓の間、ヘルプは前の持ち主の子のまま（操作できない・受容）。
- 台帳に入らない窓（メッセージボックス・OS のファイルの窓・右クリックのメニュー）は付け替えない（開いている短い間だけヘルプは操作できない・受容）。
- **初回起動の Welcome のヘルプは対象外**: 初回の Welcome はヘルプをコントローラの外で作り（`welcome_window.py:169-172`）、App の画面ができる前で知らせる口も未登録のため。今どおり Welcome の子で、Welcome を閉じると閉じる。**メニューから開き直した Welcome**（`reopen`）はコントローラ経由なので対象に入る。

### §3.2 知らせる口（modal.py）

- 台帳の末尾が変わったことを外へ知らせる口 `set_modal_front_listener(callback | None)` を足す（`set_modal_presence_listener` と同じ形・登録先は 1 つ・例外は記録して吸収）。
- （v0.5）台帳の窓ごとに**最後の入力先**を覚え、外から読めるようにする（§3.6）。開いたときは `grab_modal` の初期の入力先、以後はその窓の中の部品が `<FocusIn>` を受けるたびに更新する（窓そのものは数えない）。
- 呼ぶ時点: ①`grab_modal` で台帳に入れ、存在の通知（`_notify_modal_presence_changed`）を済ませたあと ②`restore_grab` で台帳から外し、grab を前の持ち主へ戻したあと（**どの return の経路でも通る**）。存在の通知を先にするのは、App の最前面の再評価（`effective_always_on_top`）を付け替えの前に済ませるため。
- 呼ばれた側（コントローラ）は、その場では何もせず **`after_idle` に回す**。実行時に持ち主を §3.1 で選び直す。**終了が確定したあと**（保存の確認を通り `hook.begin_shutdown()` へ進んだあと）は付け替えない。終了の確認の窓が出ている間は通常どおり付け替える（確認を取り消して App が続いても、ヘルプは正しい持ち主の子に居る。`App._closing` は確認の取り消しで戻るため、これを条件にしない）。
- （v0.6）**App が最小化・非表示の間は付け替えない**。待っていることを覚え、App が元に戻ったとき（App の `<Map>`）に付け替えを 1 回行う（最小化の間に通常表示のヘルプが出ないように・deep-reviewer M4）。

### §3.3 付け替える条件

- ヘルプが開いていて（利用者が閉じていない・§4.3）、選び直した持ち主が今の親と違うとき。
- （v0.6）作り直しの最中（表示を待つ間）に付け替えの知らせが来たときは、作り直しが終わったあとで、**作り始めたときの持ち主と今の持ち主が違えば**付け替えを予約し直す。成功・失敗どちらでも同じ（失敗したときも同じ持ち主への再試行はしない）。「?」で持ち主でないダイアログを明示して開いたときは、持ち主が変わっていない限り予約し直さない（codex P2・deep M2）
- ヘルプが親と一緒に破棄されていたとき（§3.5）は、持ち主の子として作り直す。
- 「?」（`open_for_dialog(dialog, …)`）: `dialog` が持ち主ならヘルプを持ち主の子として再利用する（無ければ作る）。`dialog` が持ち主でない（最小化の預かりで grab が外れている間など）なら `dialog` の子として作り直す（新しい窓を先に作ってから古い窓を消す・§3.4 と同じ順。失敗したら古い窓を残す）。タブ・飛び先・絞り込みを空にする今の動きは変えない。
- メニュー（`open(tab)`）: 親を App 固定でなく**持ち主**にする（Mac のメニューバーがダイアログの間は使えないことは task_01 で確認済みだが、使える経路があっても破綻しないため）。

### §3.4 開くとき（ダイアログが台帳に入った）

1. 新しい窓を隠して作る（作った直後の Notebook への初期フォーカスは**入れない**）→ 2. 状態を戻す（§4.2）→ 3. 表示する → 4. 古い窓を消す（利用者の閉じとは扱わない）→ 5. 前面とフォーカス（§3.6）。
何も映らない間を作らない。付け替えの間だけ一瞬ヘルプが 2 つになる（「同時に 1 つだけ」の例外）。
付け替え中に例外が出たら記録して吸収する。**新しい窓の準備（作成・状態の復元・表示）が済むまで、古い窓と控えはそのまま残す**。準備の途中で失敗したら、作りかけの新しい窓を消し（§4.3 の「作り直しの失敗」）、古い窓を残す。**控えは成功するまで書き換えない**（v0.6・codex P3）。

### §3.5 閉じるとき（ヘルプの親が破棄された）

- ヘルプは親と一緒に Tk に破棄される。コントローラはそれを「親と一緒に消えた」と記録し（§4.3 の利用者の閉じと区別する）、控え（§4.2）を残す。
- 知らせる口（§3.2 ②）からの `after_idle` で、持ち主の子として控えから作り直し、§3.6 を行う。
- ヘルプは**一瞬消えてから出直す**（何も映らない間が生じる・§2 確認事項 2）。
- 破棄されたのがヘルプの親でない窓（開いた順と違う順で閉じた・Tk の子でない窓）なら、ヘルプは消えていないので §3.3 の条件どおり（持ち主が変わったときだけ付け替える）。

### §3.6 重なりとフォーカス

- 付け替えたあと、新しいヘルプは**表示されるのを待ってから**（`wait_visibility` 相当・表示前の `lower` は効かない = task_03 の実測）**持ち主のすぐ下**に置く（`lower(持ち主)` 相当。ダイアログを覆わない・ダイアログを前面化しない）。持ち主が App ならこの手順はしない。ダイアログを開いたときにダイアログがヘルプの上に出る今の重なりと同じ。
- ヘルプがダイアログに完全に隠れたときは、ダイアログを動かせば出せる（ふつうの窓の重なりと同じ・受容）。「最前面に表示」が ON のときのヘルプの topmost の同期（§4.6「ヘルプの窓」）は今のまま（Windows ではモーダルの間も解除しないので、ヘルプがダイアログの上に出ることがある・今と同じ）。
- **フォーカス（v0.5 で改訂）**: OS は新しく出したヘルプを前面の窓にするため、何もしなければ打った文字がどこにも入らない（task_03 の実測 = `task01_measurement.md` §11）。そこで付け替えでは、上の「すぐ下に置く」のあと、**持ち主が覚えている入力先へ `focus_force` で戻す**（同 §12 で入力先が保たれることを確認）。
  - 入力先 = 開いた直後なら `grab_modal` の初期の入力先（`focus` 引数・省略時はダイアログ自身）。以後はダイアログ内で最後にフォーカスを受けた部品（ダイアログの窓そのものへのフォーカスは数えない）。`modal.py` が台帳の窓ごとに覚える（§3.2）。
  - **戻さない場合**: 持ち主が App のとき / **このアプリ（プロセス）の窓が前面にないとき**（v0.6 で改訂。`WindowBackend.foreground_own_window()` が `None` でないか、`is_own_process_foreground()` で判定する。`modal.py` の `is_app_foreground`〔メイン窓が前面か・最小化から戻したときのフォーカスの規則用〕は使わない＝ダイアログの間はいつも偽になるため・deep H1・codex P1）/ 入力先が既に無いとき。
  - （v0.6）**下に置く・入力先を戻すのは付け替え（§4.3 の ②④）のときだけ**。新しく開くとき（メニュー・「?」）と最小化から前に出すとき（§3.7）は行わない（開いたヘルプへ入力先が行く今の動きを保つ・deep M1）。
  - （v0.6）最後のダイアログを閉じて持ち主が App に戻ったあとの入力先は、task_06 の目視で確かめてから決める（deep M5）。
  - 正本の作法「開いた時点では、窓の前面化・フォーカス強制は行わない」の**例外**になる（ヘルプの付け替えで奪われた入力先を戻すだけで、ダイアログの前面化はしない）。
- 作り直したヘルプは初期フォーカス（Notebook）を入れない（§3.4）。

### §3.7 前面化と最小化からの復帰（v0.6・task_05 の Tk の対策）

- ヘルプを前に出す（メニュー・「?」で開いているヘルプを再利用する）とき、**表示中の窓には `deiconify` しない**（`lift` だけ）。最小化・非表示のときだけ解除する（正本 §4.6「最小化を解除して前面へ出す」）。
- **Mac（Tk の aqua・`presentation/tk_platform.is_aqua`）では、最小化・非表示のヘルプに `deiconify` せず、控えから同じ持ち主の子として作り直して出す**。Tk 9.1（macOS）は、このヘルプに `deiconify` すると内部（`WmDeiconifyCmd` → `TkWmMapWindow`）で落ちることがあるため（task_05 の probe）。作り直しの控えは「通常の表示」として扱い、作り直しに失敗したら古い窓（最小化のまま）と控えを残す。Windows は今どおり `deiconify`（本文の選択範囲・カーソル位置を保つ・deep M3）。

## §4 状態

### §4.1 引き継ぐもの

| 窓の位置と大きさ | する（「位置と大きさは記録しない」は**保存しない**の意味で、付け替えの引き継ぎはこれに当たらない） |
| 窓の表示状態（利用者がヘルプを最小化していたら最小化のまま） | する |
| 選択中のタブ | する |
| 絞り込みの文字 | する（付け替えでは消さない） |
| タブごとの開いた見出し・選択中の見出し | する |
| タブごとの本文のスクロール位置 | する |
| 本文の選択範囲 | しない（§2 確認事項 3） |
| 絞り込み欄のフォーカスとフックの停止 | しない（フォーカスはヘルプへ移さないので、古い窓の破棄で停止は解除される・`key_input.md` の規則どおり） |
| 最前面・フォント | 作り直した時点の設定で作る（今の `_create_window` と同じ） |

本文は付け替えのたびに読み直さない（最初に読んだ結果をコントローラが持つ）。本文の読込に失敗した窓は、位置と大きさ・表示状態・絞り込みの文字だけを引き継ぐ。

### §4.2 戻す順

位置と大きさ → 絞り込みの文字（`apply_filter` が `_open` を空にするため先）→ タブごとの開いた見出し・選択中の見出し → 表示の更新 → 選択中のタブ → 描画を済ませてからスクロール位置 → 表示状態。
**状態を戻している間（窓を作り始めてから戻し終えるまで）は控えへ書き込まない**（作った窓が初期化の途中で「スクロール = 先頭」などを控えに書き、控えを上書きするため = task_03 の実測）。

### §4.3 控えと、窓の消え方

- ヘルプの状態は**変わるたびに控える**（破棄の時点で読みに行かない）。控えは `HelpWindowController` が持つ。拾う口の例: 絞り込みの変更・タブの切り替え・見出しの開閉（`toggle` / `reveal`）・スクロール（`yscrollcommand`）・窓の移動と大きさ（`<Configure>`）・最小化と復元。
- （v0.6）**控える時点**: 絞り込みの文字・タブ・見出しの開閉と選択は、変わったその場で控える（ダイアログを閉じる直前の変更を落とさない・codex P2）。**窓の位置と大きさ・表示状態・スクロールは `<Map>` / `<Configure>` の中では読まず、処理が一段落してから（`after_idle`）1 回にまとめて控える**（Tk 9.1〔macOS〕で `deiconify` の途中の問い合わせが落ちる原因になったため・task_05）。スクロールは割合に加えて**先頭に見えている行**も控え、画面に出ていないタブは前に控えた行を使う。
- ヘルプの窓が消える理由を、**窓ごとに次の 4 つに分ける**（窓を消す前に、コントローラがその窓に理由を付ける。理由の無い破棄は ④。ただし付け替えの時点で**元の親がまだ生きていれば ④ ではない**＝親と一緒に消えたのではないので、作り直さず控えを捨てる・v0.6・deep M7）:

| 理由 | 例 | そのあと |
|---|---|---|
| ① 利用者の閉じ | ×・Escape・`close()`（終了時・利用者の操作） | 控えを捨てる。付け替えない |
| ② 付け替えで古い窓を外す | §3.4 の手順 4・「?」の作り直し | 何もしない（新しい窓が残る） |
| ③ 作り直しの失敗 | §3.4 の準備の途中の失敗 | 作りかけの窓を消す。古い窓と控えは残す |
| ④ 親と一緒に消えた | 持ち主のダイアログが破棄された | 控えを残し、§3.5 で作り直す |

- どの理由でも、絞り込み欄で止めたフックの再開はちょうど 1 回（`key_input.md` の規則・今の `HelpWindow` の作りのまま）。

## §5 Mac の grab の受け渡し（task_02 の変更）

- 付け替えで作った窓の持ち主がモーダルなら、その持ち主を相手に `install_grab_handoff` を掛ける。持ち主が App なら掛けない。
- 規則（前面で grab をヘルプへ・前面でなくなったら親へ・grab を持ったまま閉じたら親へ）は task_02 のまま。親が破棄の途中のとき、`_destroy` の `grab_set` は破棄途中の親へ向かうことがある（実害は小さい・付け替え後に新しい持ち主が grab を持つ）。
- **共通の規則: grab の持ち主がヘルプなら、ヘルプの親（持ち主のダイアログ）を grab の持ち主とみなす**。ヘルプは台帳の外の一時的な grab の持ち主で、付け替えで消えるため、grab の戻し先・預かり先にしない。この規則を次の 3 か所で使う（解決する関数は `modal.py` に 1 つ置き、ほかから使う）:
  - `grab_modal` の前の持ち主（新しいダイアログを閉じたときの grab の戻し先）
  - 最小化の預かり（`_deferred_check` が `_custody_window` に入れる窓・`_return_grab` が戻す窓）。Mac でヘルプが grab を持ったまま App を最小化しても、復元ではダイアログへ grab とフォーカスが戻る
  - `choice_dialog._grab_holder`（新しい選択ダイアログの親）
