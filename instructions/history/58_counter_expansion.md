## §1 目的 / 背景

カウンターを「ファイルの行」の行番号以外にも使えるようにする。
①カウンターの行で任意の量（負も可）を足せる ②カウンターに名前ごとの開始値を持たせ、リセットはそこへ戻す
③カウンターの現在値を文字として入力するアクションを加える。

## §2 確定事項（ユーザー 2026-11-22）

1. **「カウンター +1」→ 名称「カウンター」**。**任意の整数の増やす量**を持つ（負も可・0 も可〔何もしない行〕）。
2. **開始値はカウンター（名前）ごとに 1 つ**。同じ名前のカウンターはどこにあっても値を共有する（現行どおり）。
   開始値は「カウンター」の行の編集ダイアログで設定し、**ダイアログには今の開始値が入っていて、それを上書きできる**（食い違いを拒否する方式にしない）。
3. **開始値の範囲は構成セット全体**（値がアプリ全体で共有のため。キーマップごとにしない）。
4. **「カウンターを0に」→ 名称「カウンターリセット」**。開始値へ戻す。
5. **新規「カウンターの値を入力」**: カウンターの現在値をそのまま文字として入力する。**ゼロ埋め等の書式指定はしない**。
6. **負の値を許す**（file_line は既存の範囲外の規則で扱う）。
7. 表示用の別機能は作らない（一覧の行の `(=値)` で足りる）。
8. **開始値を変えても、すでに値が入ったカウンターは今の値のまま**（次のリセットから効く）。未使用の名前に足してから戻すと「値が入った」扱いになり、以後の開始値の変更に追従しない（受容）。
9. **「カウンターの値を入力」は独立した種類**（`counter_text`・hotkey / ファイルの行と並ぶ。system は呼び出しを除き入力を送らないため）。
10. **増やす量 0 を許す**（`[count+0]` と表示・何もしない行）。
11. **構成セットの書き込みだけが失敗したとき、`amount` と開始値が別の版で残るのを受容する**（§3.6・既存のまたがる保存に共通の制約）。
12. **手で `amount` を書き足した既存の行が、更新後にその値で動くのを受容する**（§3.5・未定義キーに意味を与える互換の例外）。

## §3 データモデル

### §3.1 カウンターの行（`counter_inc`）に増やす量 `amount`

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `amount` | int | `1` | 足す量。負は減らす・0 は何もしない |

- `op` 名 `counter_inc` は据え置く（既存キーの意味変更をしない。「+1 する」は「amount を足す・既定 1」の特別な場合）。
- **`op` が `counter_inc` の行だけが読む**。他の op・他の種別の行に `amount` があっても無視する（保持はする。mouse_scroll の `amount` は別の種別の別のキー）。
- **キーが無ければ 1**（既存データの互換）。読込時に補完しない。
- 判定は `count` / `ms` と同じく `int()` 変換（`"3"` は受け入れる・`2.5` は 2・bool は `int()` に任せる。いずれも受容）。**変換不能は実行時エラー**「増やす量が正しくありません」（黙って補正しない）。
- 編集ダイアログで OK するときは常に `amount` を書く（1 でも書く）。

### §3.2 カウンターリセット（`counter_reset`）

- キーは従来どおり `counter` のみ。**意味を「0 にする」→「開始値にする」へ変える**。
  開始値を設定していない名前は開始値 0 のため、**既存データの挙動は変わらない**。

### §3.3 開始値 `counter_starts`（構成セット）

- **構成セット（`keymap_set.json`）の最上位キー `counter_starts`** = `{"<カウンター名>": <int>, ...}`。単一 JSON（Import / Export）でも最上位キーとして同じ規則で持つ（`select_before_run` と同じ置き方・`data_schema.md` §5.3）。
- 読込: dict でなければ空。**キーは trim し、空なら捨てる（大文字小文字は区別する）。値は bool を除く int のみ。0 の要素も捨てる**（それ以外の要素も捨てる・エラー表示なし・ファイルは書き換えない）。
  **正規化の順序**: ①型が有効な要素（bool を除く int）だけを取る（0 を含む）→ ②trim 後の名前で**後に現れた要素が勝つ**（JSON の並び順）→ ③最後に値 0 の要素を除く
  （例 `{"n": 7, " n ": 0}` → 開始値なし〔0〕）。分離読込と Import は同じ正規化の関数を使う。
  ※ 値を `amount` より厳しく見る（int のみ）のは、`amount` は手書きの行の互換を `count` / `ms` に合わせるため・開始値はダイアログでしか書かない新しいキーのため。
- 保存: 構成セットの保存で**常に出力する**（空なら `{}`）。**開始値 0 の名前は書かない**。
- 開始値を持たない名前の開始値は **0**。
- **どの行からも使われなくなった名前の開始値も残す**（掃除しない・受容。同じ名前を使えば以前の開始値がダイアログに入る）。
- キーを持たない既存の構成セットは全名前 0（互換）。
- 新規作成した構成セットは空。別名保存はそのまま写す。

### §3.4 カウンターの値を入力（新しい種別 `counter_text`）

| キー | 型 | 意味 |
|---|---|---|
| `counter` | str | 入力するカウンター名（大文字小文字を区別・trim のみ） |
| `label` | str | 一覧表示用 |

- 例: `{"type": "counter_text", "counter": "n", "label": ""}`
- **通常アクション**（入力を送る・1 押下 1 ステップを消費・停止の行の読み飛ばしの判定で「送った」に数える・呼び出し先の中でも通常アクションと同じ）。
  `features.md` §4.2 の通常アクションの列挙（§4.2 冒頭・§4.2.8 の「送った」の列挙・§4.2.9 の呼び出し先の行の表）に加える。
- 送る文字列 = **実行時点のカウンターの実効値**（§4.1）を 10 進の文字列にしたもの（`5` / `-3` / `0`）。**text と同じ経路・send guard**。
  実行は `ActionExecutor.execute` の 1 分岐で行い、既存の `get_counter`（§4.1 の実効値）を使う（runner の経路は変えない。file_line と違い読込の保留を経ない）。
- 実行時エラー: `counter` が空（非文字列を含む）→「カウンター名が空です」（file_line と同じ止まる系・`data_schema.md` §5.11.8）。通知の値の欄はカウンター名。送信の例外は text と同じ扱い（止まる系）。
- `counter` は `normalize_actions` の trim 対象（既存）。
- 種類の表示名: 日本語「カウンターの値を入力」/ 英語「Type counter value」（`ui_terms.md`「アクションの種類の表示名」に 1 行足す）。
  種類の候補での出し方は system / file_line と同じ（それらを隠す文脈では隠す・`presentation/dialogs/action_dialog.py:58-63`）。
- 種別不正の文言（`data_schema.md` §5.11.1「hotkey / text / … / key_holdのいずれか」・`ja.json` / `en.json`）に `counter_text` を足す。
- 旧ビルド・別実装は種別不正で止まる（受容・file_line と同じ）。

### §3.5 旧ビルドとの互換（受容）

- 旧ビルドは `amount` を知らず、カウンターの行を +1 として動かす（止まらない）。
- 旧ビルドで構成セットを保存すると `counter_starts` が消える（構成セットの保存が出力するキーを列挙しているため・`config_service/split_payloads.py`）。
- 旧ビルドは `counter_reset` を 0 にする（開始値を知らない）。
- **手で `amount` を書き足した既存の `counter_inc` の行**（従来は未定義キーとして無視・`data_schema.md` §5.1）は、更新後にその値で動く（変換不能なら止まる）。
  未定義キーに意味を与える互換の例外として受容する（§2.12・アプリはこのキーを書いたことがない）。

### §3.6 構成セットと子ファイルにまたがる保存（受容）

- 一度の OK で行の `amount`（出力シーケンスのファイル）と `counter_starts`（構成セットのファイル）の両方が変わることがある。
  保存は子ファイル → 構成セットの順に書く（`config_service/save_plan_execution.py:135-151`）ため、**構成セットの書き込みだけが失敗すると、2 つが別の版で残る**。
- これは既存の「子ファイルと構成セットにまたがる保存」すべてに共通する制約（トリガーキーの変更で複数の出力シーケンスの `target` を書き換える場合など）で、本フェーズで新たな仕組みは入れない（§2.11）。
  失敗の通知は既存のまま。未保存の印は既存の規則どおり残るので、もう一度保存すれば揃う。
- `counter_text` は §3.4 のとおり止まる。

## §4 実行の規定

### §4.1 開始値の持ち場所と実効値

- **実行時の開始値は `AppState` が持つ**（`counter_starts: dict[str, int]`）。差し替える契機 = **構成セットのデータを置き換えるすべての経路**
  （起動時の読込・読込・Import・新規作成・**サンプル設定に戻す**〔`keymap_set_io.py` の復元は読込の経路を通らない〕）と、編集ダイアログでの開始値の確定（§5.2）。
  差し替えは構成セットの置き換えの共通の処理に 1 か所で入れる（`select_before_run` の同期〔`features.md` §4.6〕と同じ契機の集合）。
  application から presentation の構成セットのデータを直接読まない（依存方向）。
- **実効値は application の 1 関数で求める**: `counters` にあればその値 / 無ければ `counter_starts` の値 / それも無ければ 0。
  **カウンターを読む・動かすすべての経路がこの関数を通る**: §1 の操作の経路すべて（保留の反映・先行処理・呼び出し・連続実行・待機の続き・file_line の一時停止からの読み直しを含む）/ file_line の行番号（読込開始時点）/ counter_text の送る値 / 一覧・簡易表示・呼び出し先の表示枠の `(=値)`。
- 「値が入った」= `AppState.counters` にキーがある（カウンター・リセットの反映、戻すでの打ち消しを含む）。
- **開始値を変えたとき**: まだ値が入っていない名前には即座に効く。値が入った名前の今の値は変えない（次のリセットから効く・§2.8）。
- 構成セットを読み込み直しても値は消えない（現行どおり）。読込後の未使用の名前・リセットは新しい構成セットの開始値を使う。
- 戻す・先頭へ・保留の規則（`features.md` §4.2.2・§4.2.6）は変えない。ユーザー操作の**戻す**で差分を打ち消した名前は「値が入った」ままになる（開始値と同じ値でも以後の開始値の変更には追従しない・受容・§2.8）。
- **無視された押下の巻き戻し**（呼び出しの連動で押下をなかったことにする `linked_call.py` の `_rollback_linked_press`）は、ユーザー操作の戻すと違い**押下の前の状態へ完全に戻す**:
  差分を引いたうえで、**その押下で初めて `counters` に入った名前のキーを消す**（その押下の前に無かった名前を押下の文脈で記録しておく。差分 0 のリセットで入った名前を含む）。
  押下の間に他の押下が入らない（巻き戻しは同じ押下の中で起きる）ため、他の更新を消すことはない。

### §4.2 カウンターの行（`counter_inc`）

- 値 = 実効値 + `amount`。差分 `(name, amount)` を戻す履歴に入れる。
- **保留**（先行処理・`features.md` §4.2.2）: 控える内容を **`(op, name, amount)`** にする（`amount` は控えた時点の行の値。リセットは `amount = None`）。
  保留の型が出てくる箇所（`app_state.py:33-34`・`sequence_history.py`・`sequence_steps.py`・`call_context.py`・`linked_call.py`・`call_wait.py`・`call_run_to_end.py`・`run_to_end.py`・
  待機の再開と停止の確定 `send_wait.py`・`wait_stop.py`・`sequence_runner.py`）をすべてこの形にし、**保留の生成・反映・履歴の復元は同じ型と同じ反映の関数を使う**（負の `amount` が 1 回だけ反映されること）。
- `amount` が不正な行は先行処理で控えず、その行で止まり、次のステップの開始時にエラー（ループの回数不正・待機の `ms` 不正と同じ扱い）。
- 実行時エラーの通知の値の欄: 日本語 `counter_inc カウンター=n 増やす量=abc` / 英語 `counter_inc Counter: n, Amount: abc`（`en.json` の既存の `Counter: {counter}` に合わせる）。

### §4.3 カウンターリセット（`counter_reset`）

- 値 = 今の開始値。差分 = 開始値 − 反映前の実効値（0 なら差分を積まない・現行どおり）。保留の規則は現行どおり（反映時点の開始値を使う）。

## §5 UI

### §5.1 名称（`ja.json` / `en.json` の両方）

| キー | 日本語 | 英語 |
|---|---|---|
| `action_dialog.system.op.counter_inc` | カウンター | Counter |
| `action_dialog.system.op.counter_reset` | カウンターリセット | Reset counter |

ヘルプ（`help_ja.json` / 英語版のカウンター・アクションの種類の記述）も合わせて直す。

### §5.2 編集ダイアログ

- **カウンター**: カウンター名（既存のドロップダウン）+ **増やす量**（整数・既定 1・負可）+ **開始値**（整数・負可）。
  - 欄の解釈は待機の ms の欄と同じ（`int(strip())`・`action_control_fields.py:286`）。
  - **名前の欄が変わるたびに**（候補の選択・打鍵のどちらでも）、その名前の今の開始値を開始値の欄に入れ直す。未知の名前・空の名前は 0。
  - 既存の行の `amount` が不正なら、欄にはその値をそのまま出す（直すための初期値・OK で拒否される）。
  - OK 時: 増やす量・開始値が整数でないなら理由を出して拒否。
  - ダイアログは**開始値を結果として返すだけ**で、構成セットは書き換えない。
- **開始値の確定**: **行の追加・置換が成立した時点で**（コントローラの `standalone_violation` 等の拒否を通った後）、コントローラが **OK 時点の名前**に欄の値を書く。
  今の開始値と違うときだけ、構成セットの `counter_starts` と `AppState` の開始値を書き換え、構成セットを未保存にする（その名前を使うすべての行に効く）。
  キャンセル・拒否では変えない。op を「カウンター」以外にして OK したら開始値は書かない。
- **カウンターリセット**: カウンター名のみ（現行どおり）。
- **カウンターの値を入力**: カウンター名のみ（file_line と同じドロップダウン）。OK 時に空なら「カウンター名を入力してください。」（既存の文言）。開いたときの入力先は種類のドロップダウン（値の欄が無いため・`features.md` §4.6）。
- 「既知の名前」の候補（`action_edit.py:355-370`）に、`counter_text` の行の名前と `counter_starts` の名前も含める。

### §5.3 一覧の表示形式（`features.md` §4.6）

| 行 | 表示 |
|---|---|
| カウンター | `[count+3] n (=5)` / `[count-2] n (=5)`（`amount` が無ければ `+1`・不正なら `[count?] n (=5)`） |
| カウンターリセット | `[count=10] n (=5)`（`=` の後は今のその名前の開始値） |
| カウンターの値を入力 | `[counter_text] n (=5)` |
| file_line（既存） | 変えない（`(=値)` が実効値になるだけ） |

- `(=値)` はすべて §4.1 の実効値。表示の書式の関数（`sequence_control.format_control_value` と `domain/config.py` の一覧の値の分岐・`action_list_rendering.py` の要約）は、実効値と開始値を引数で受け取る（domain は AppState を読まない）。
