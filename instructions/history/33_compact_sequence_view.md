## §1 目的 / 背景

省略表示（幅 270）でも、選んでいるトリガーの出力シーケンスと「次に実行」の位置を見て、クリックで次に実行を変えられるようにする。
**presentation 限定・domain / application 不変。`config/config.json` にキーを 2 つ追加（`compact_sequence_view`・`compact_window_size`・後方互換）。省略表示のウィンドウの大きさの記録と最小の高さを加える（v0.5）。keymap_set の JSON スキーマは不変。**

## §2 確定事項（ユーザー 2026-10-06）

1. **操作 = 見る + 次に実行の変更**。選んでいるトリガーのシーケンスを `▶` 付きで出し、クリックで次に実行の位置を変える。
   **編集・並べ替え・コピー / 貼り付け・範囲選択はしない**
2. **開閉 = 全体で 1 つ・保存する**。トリガーを選び替えても開閉は変わらない。開閉と高さを `config.json` に保存し、次回起動時も同じ
3. **並び = 上から トリガー一覧 / シーケンス欄 / 呼び出し先の枠**。境界はそれぞれドラッグできる。
   **開閉でウィンドウの大きさは変えず、トリガー一覧が伸び縮みする**（呼び出し先の枠と同じ規則）。シーケンス欄の高さは保存する
4. **選択の帯とキー操作はフル表示と同じ**（v0.2 §9-1 案 B）: 選択の帯を出し、クリックでフォーカスを取り、↑↓ で次に実行を動かす。キー操作でも呼び出し先の実行中は拒否する（§4）
5. **収まらないときは呼び出し先の枠 → シーケンス欄の順に縮める**（v0.2 §9-2 推奨）: 各欄の最小は 呼び出し先の枠 → シーケンス欄 → トリガー一覧 の順に確保（下の欄ほど優先）。希望の高さが入りきらなければ呼び出し先の枠から先に最小へ縮め、次にシーケンス欄を縮めて、トリガー一覧の最小を残す。3 つの最小も入らないときは §2-8
6. **初回（保存値なし）は開いた状態**（v0.2 §9-3 推奨）。今の省略表示ではトリガー一覧が初回からおよそ 3 分の 1 短くなる
7. **押している間に対象が変わったら取り消す**（v0.3 Codex 敵対的レビュー high・ユーザー確定）: 押したときの構成セット（トリガー一覧）・トリガー・行を覚え、離したときにどれかが違えば何もしない。押している間に一覧が描き直された・欄が閉じた場合も取り消す（実行の進行で runner が選択を切り替える〔`_select_trigger`〕ため）
8. **縦が足りないときは下の欄の最小を優先し、見出しを残す**（v0.3 Codex 敵対的レビュー medium → v0.6 Codex 敵対的レビュー high をユーザー判断で改訂）: 各欄の最小は §2-5 の順（呼び出し先の枠 → シーケンス欄 → トリガー一覧）に確保し、**トリガー一覧は 3 行を割って縮んでよい**（開いた欄があると窓の最小の高さでもトリガー一覧が 3 行未満になる＝受容）。トリガー一覧が尽きてもなお足りなければ、呼び出し先の枠 → シーケンス欄 の順に一覧の部分が最小を割って詰まる。**各欄の見出し（開閉の操作先）は残す**。万一それも入らなければ下から見切れる（受容）
9. **省略表示のウィンドウの幅と高さを記録する**（v0.5・ユーザー要望 2026-10-06）: 省略表示中に幅・高さを変えたら保存し、省略表示へ入るたびにその幅・高さで開く（§7.2）
10. **省略表示のウィンドウに最小の高さを設ける**（v0.5・ユーザー要望 2026-10-06「縦を短くしたときにステータスバーやステータス欄が消える」）:
    上部（フック・表示の枠）・ステータス欄・ステータスバーは常に出す。最小の高さ = それらと、トリガー一覧の最小 3 行 + シーケンス欄と呼び出し先の枠の**見出し**が入る高さ。
    **開閉で最小は変わらない**（欄を開いたときは §2-8 のとおり下の欄の最小を優先し、トリガー一覧が 3 行を割ることがある）。**最小の高さが主モニタの高さより大きくても最小を優先**し、画面からはみ出すのは受容（v0.6・フル表示の幅の規則と同じ考え方）（§7.3）
11. **省略表示中のステータス欄は常に 2 行・ステータスバーは常に 1 行**（v0.6・Codex 敵対的レビュー medium をユーザー判断で反映）: 省略表示中は表示する文言の改行を空白へ置き換える（改行を含む値の「次」表示・複数行の完了メッセージ等）。フル表示の表示は変えない。これで省略表示中は中身で高さが変わらず、最小の高さを測る契機は §7.3 のとおりで足りる

## §3 置き場所と見た目

- 省略表示のトリガー欄（`CompactTriggerBox`）の縦の PanedWindow に、トリガー一覧と呼び出し先の枠の**間**へシーケンス欄を置く
- **常設の Expander**（呼び出し先の枠と同じ作法）: 閉じているときは見出しの 1 行（`▸ シーケンス`）だけ、開いているときは `▾ シーケンス` と一覧
  - **閉じた見出しはトリガー一覧のペインの下端に置く**（PanedWindow の中・トリガー一覧のペインの一部。ペインの間に見出しだけのペインは作らない）。
    このときトリガー一覧のペインの最小 = 一覧の最小 + 見出し 1 行。開いたときは見出しをシーケンス欄の本体の上端へ移す（呼び出し先の枠と同じ）
  - したがって境界は、シーケンス欄を閉じていれば呼び出し先を開いているときの 1 本だけ、開いていれば 1 本（呼び出し先を閉じている）または 2 本
  - 境界線の見た目は呼び出し先の枠と同じ（細い平らな線・控えめな色）
- 中身は**フル表示の出力シーケンス欄と同じ表示形式**（`▶` / 行の文字列 / ループの色分け / 周回・カウンターの現在値・呼び出し先の表示）。
  有効でない（グレーの）トリガーを選んでいるときは `▶` を出さない（フル表示と同じ）。シーケンスが空・トリガー未選択なら空の一覧
- 部品は呼び出し先の枠（`CallViewFrame`）を見出しの文字を引数にして流用してよい（実装の選択）
- 幅 270 で行の右が切れるのは受容（横スクロールなし）。描き直したとき `▶` の行が見える位置へスクロールする
- 枠の見出し「トリガー一覧」（`LabelFrame`）は変えない（中にシーケンス欄・呼び出し先の枠が入るのは受容）

## §4 操作

- **クリック**: **押した行で離したときだけ**、その行を次に実行にする（押した行と離した行が違えば何もしない・押している間に選択を動かさない）。押している間に構成セット・トリガーが変わった・一覧が描き直された・欄が閉じた場合も何もしない（§2-7）
- 次に実行の変更は**フル表示と共有する 1 つの処理**（行番号を受け取る）で行う: 有効でないトリガーでは何もしない / 呼び出し先の実行中は拒否 /
  ループの周回のリセット / 描き直し。**フル表示の経路（範囲選択・ドラッグ・`on_selection_commit`）は変えない**。省略表示の一覧はフル側の一覧の選択・ドラッグ状態を読まない
- **選択の帯**: フル表示と同じく、次に実行の行に選択の帯を置く（単一選択）。描き直したときも帯は次に実行の行
- **フォーカス**: クリックで一覧がフォーカスを取る（Tab での移動は Listbox の既定のまま）
- **キー操作（↑↓ ほか `on_focus_index_change` と同じキー: Up / Down / Prior / Next / Home / End・Shift 付きは除く）**: フォーカスを動かした行を次に実行にする（フル表示と同じ）。
  **キー操作でも呼び出し先の実行中は拒否する**（上の共有処理を通す。フル表示のキー操作の経路は変えない＝§11）
- 省略表示の一覧の選択の同期・イベントは省略表示の一覧の中で閉じる（フル側の `on_action_list_select` を経由しない・`_programmatic_action_select` のような描き直し中の抑止は省略表示の一覧にも効かせる）
- ダブルクリック（編集）・ドラッグ（移動・範囲）・Ctrl+C / V・Delete は**何もしない**

## §5 大きさ

- 最小: シーケンス欄 = 見出し + 3 行程度（呼び出し先の枠と同じ）。トリガー一覧の最小 = 3 行程度（シーケンス欄を閉じているときは + 見出し 1 行）
- **開閉でウィンドウの大きさは変えず、トリガー一覧が伸び縮みする**
- シーケンス欄の**希望の高さ**を 1 つ持ち、`config.json` に保存する（§7）。
  **既定 = 3 段を並べる高さ全体（PanedWindow の高さ）の 3 分の 1**。呼び出し先の枠の既定も同じ基準（PanedWindow の高さの 3 分の 1）で、意味は変えない。
  既定は省略表示の幅にした後・レイアウトが落ち着いた後に決める（呼び出し先の枠と同じ）
- 最小を割る希望値・表示しきれない希望値は保存値を保ち、表示だけ収める
- **収まらないとき**: §2-5 のとおり
- **高さの配置・ドラッグ・保存は省略表示の PanedWindow ごとに 1 か所が受け持つ**（呼び出し先の枠の制御とシーケンス欄の制御が別々に `sash_place` しない）。
  境界は上から順に置く。ドラッグ中は配置しない
- **境界のドラッグ**: どの境界を動かしても、**離したときの各欄（シーケンス欄・呼び出し先の枠）の実際の高さが押す前と違えば、その欄の希望の高さにする**
  （境界ごとの規則は置かない。Tk が隣の境界を押し動かした場合も同じ規則で拾う）
- 省略表示中にフォントを変えたら、シーケンス欄の最小も測り直す（呼び出し先の枠と同じ契機）

## §6 開閉

- 見出しのクリックで開閉。**全体で 1 つ**（トリガーごとではない・トリガーを選び替えても変わらない）
- 開閉のたびに `config.json` へ保存する（§7）。保存値が無いときは開いた状態（§2-6）
- 呼び出し先の枠の開閉（トリガーごと・自動で開く）は従来どおりで、シーケンス欄の開閉と独立
- フル ⇔ 省略の切替: シーケンス欄の開閉・高さは省略表示の中だけのもので、フル表示の出力シーケンス欄には影響しない

## §7 保存（`config/config.json`）

- 新しいキー **`compact_sequence_view`** = `{"open": <bool>, "height": <int px>}`
  - `open`: bool 以外・欠けていれば既定（開く・§2-6）/ `height`: bool を含む非 int・0 以下・欠けていれば既定（§5）。**値ごとに判定**し、片方が不正でももう片方は使う。値が dict でなければ両方既定
  - 書き込み契機 = 見出しのクリックで開閉したとき / 境界のドラッグを離して希望の高さが変わったとき
  - **変わったキーだけを書き、キーの中は今の値をすべて書く**（`height` がまだ決まっていなければ `height` は書かない）。
    1 回のドラッグで `compact_sequence_view` と `call_view_heights` の両方が変われば **1 回の `write_startup` にまとめる**。`call_view_heights` の中身の規則（もう片方の今の希望値も一緒に書く等）は従来どおり
  - **値の dict の中の未知のキー（`open` / `height` 以外）は保持しない**（トップレベルのほかのキーは従来どおり保持される）。キーが無ければ既定で動く（後方互換）
- `call_view_heights` の意味・形は変えない（`compact` は呼び出し先の枠の希望の高さのまま）

### §7.2 省略表示のウィンドウの幅と高さ（v0.5）

- 新しいキー **`compact_window_size`** = `{"width": <int px>, "height": <int px>}`。**値ごとに判定**し、bool を含む非 int・1 未満・欠けていれば、その値は保存値なしとして扱う。値が dict でなければ両方なし。値の dict の中の未知のキーは保持しない
- **書き込み**: 省略表示中にウィンドウの幅または高さが変わってから **500ms 変化がなければ**、今の幅・高さを両方書く（フル表示のウィンドウ幅の保存と同じ作法・`pane_layout_controller.py:228-250`）。
  **書かない**: 最大化中・最小化中・フル表示中 / アプリが決めた大きさ（省略表示へ入ったときに当てた大きさ・最小の高さへの引き上げ）/ 保存済みと同じ大きさ。
  省略表示から出る・終了する直前 500ms 以内の変更は保存されない（受容・フル表示の幅と同じ）
- **適用**: 省略表示へ入るたび、保存値があればその幅・高さで開く。値ごとに、保存値が無ければ今の動き（幅 = 270 / 高さ = 今の高さ・最低 360）。
  高さが最小の高さ（§7.3）より低ければ表示だけ最小へ引き上げる（保存値は変えない）。主モニタの幅・高さより大きければ主モニタの大きさへ切り詰める（保存値は変えない）。ただし切り詰めた高さが最小の高さより低ければ最小を優先する（はみ出しは受容・§2-10）
- フル表示の幅の保存（`full_view_window_width`）・フル表示へ戻るときの大きさ（省略表示へ入る前の大きさへ戻す）は変えない

### §7.3 省略表示のウィンドウの最小の高さ（v0.5）

- 省略表示中はウィンドウの最小の高さを §2-10 の高さにする（幅の最小は設けない・今のまま）。フル表示へ戻るときは従来どおりフル表示の最小サイズへ戻す
- 測る契機 = 省略表示へ入ったとき / 省略表示中のフォント変更。そのときウィンドウが最小より低ければ最小まで伸ばす（アプリが決めた大きさ・保存しない）
- 省略表示中のステータス欄（2 行）・ステータスバー（1 行）は行数が固定（§2-11）なので、中身の変化では測り直さない

## §8 更新の契機

- `refresh_actions` が描くたびに、省略表示のシーケンス欄にも同じ内容を描く（範囲の選択 `select` は当てない）
- 省略表示中は `refresh_actions` を呼ばない次の経路を、**呼ぶように改める**:
  `set_selected_trigger_index`（トリガーの選び替え）/ `hook_controller.py:206`（フックの状態の変化）/ `show_compact_view`（省略表示への切替）
  - これにより省略表示中にも `refresh_actions` の次に実行の位置の補正（`_indices` の範囲合わせ）が走る。挙動の変化として**受容**する（フル表示では同じ補正が既に走っている）
- 実行の進行の通知（runner → `refresh_actions`）は従来どおりで、そのまま省略表示の欄にも届く

## §9 確認事項（ユーザー判断）

なし（v0.2 の 3 点は 2026-10-06 にユーザー確定・§2 の 4〜6 へ移した）。

## §10 受け入れ条件（ドラフト）

1. 省略表示で、トリガー一覧と呼び出し先の間にシーケンス欄の見出しがあり、クリックで開閉できる。閉じたときは境界が出ない（§3・§6）
2. 開いた欄にフル表示と同じ表示形式でシーケンスが出て、`▶` が次に実行の行にある。実行の進行・トリガーの選び替え・フックの状態の変化・省略表示への切替で追従する（§3・§8）
3. 行のクリック（押した行で離す）・↑↓ で次に実行が変わり（押している間に実行で選択中のトリガーが変わったら変わらない）、選択の帯がその行にあり、フル表示へ戻ってもその位置になっている。有効でないトリガー・呼び出し先の実行中は（クリックでもキーでも）変わらない。ダブルクリック・ドラッグ・Ctrl+C / V は何もしない（§4）
4. 開閉でウィンドウの大きさが変わらず、トリガー一覧が伸び縮みする。境界をドラッグでき、離した後の高さが再起動後も保たれる。省略表示へ切り替えた後に窓を小さくしても見出しが残り、さらに小さければ下から見切れる（§2-5・§2-8・§5・§7）
5. 開閉が再起動後も保たれる。`compact_sequence_view` が無い・不正な config.json でも既定で動く（§6・§7）
6. 呼び出し先の枠の開閉・既定の高さ・自動で開く挙動・`call_view_heights` の保存が従来どおり（§5・§6・§7）
7. フル表示の出力シーケンス欄の操作（範囲選択・ドラッグ・キー操作・編集）が従来どおり（§4）
8. 省略表示で幅・高さを変えて 500ms 待つと `compact_window_size` に保存され、フル表示へ戻って再び省略表示へ入る・再起動後に省略表示へ入ると、その大きさで開く。最大化・最小化・フル表示中の大きさは保存しない。保存値が無い・不正なら今の動き（§2-9・§7.2）
9. 省略表示で縦を最小まで縮めても、上部・ステータス欄・ステータスバー・両方の見出しが見えている（両方の欄を閉じていればトリガー一覧 3 行も）。欄を開いても最小は変わらず、下の欄の最小を優先してトリガー一覧が縮む。改行を含む値の「次」表示・複数行のメッセージでもステータス欄は 2 行・ステータスバーは 1 行のまま。フル表示へ戻ると従来の最小サイズになる（§2-10・§7.3）
10. 既存テスト（tests / tests_ui / smoke）が通る。既存の呼び出し先の枠のテスト（`tests_ui/test_call_view_compact.py` のペインの枚数・`sash_coord(0)`・既定の高さ）は、
   シーケンス欄を閉じた状態に固定して従来の期待を保つか、期待値を更新する。テストの config.json は隔離する（実 `config/` を汚さない）
