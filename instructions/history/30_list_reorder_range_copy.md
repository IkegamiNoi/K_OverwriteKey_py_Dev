## §2 確定事項（ユーザー 2026-10-02）

- **対象はフル表示のキーマップ一覧・トリガー一覧・出力シーケンスと、プリセット編集ダイアログのプリセット一覧**。省略表示のトリガー一覧は対象外（現行の単一選択のまま）
- **プリセット一覧は範囲選択・ドラッグ移動・上へ / 下へのまとめて移動・範囲削除のみ**（複製・Ctrl+C/V は付けない。ユーザー判断 2026-10-02・v0.4）
- **範囲選択は連続範囲のみ**（Shift+クリック / Shift+ドラッグ / Shift+↑↓）。Ctrl+クリックの飛び飛び選択はしない
- **キーマップ一覧はフォーカス（下線）= アクティブ**と定義し、範囲選択・移動・複製の対象に含める（フェーズの最後のタスク）
- トリガー一覧で範囲選択中、出力シーケンス欄は**下線の行のシーケンス**を表示する
- 範囲選択中の「編集」は下線の 1 行、「削除」は**範囲をまとめて削除（確認あり）**
- ドラッグ中は行がその場で動き、離したときに確定する（挿入線は描かない）
- 移動・複製のあとも「次に実行」は**元のアクションを指したまま**
- 出力シーケンスの上へ / 下へは、範囲選択中は範囲をまとめて動かす。出力シーケンスに「**複製**」ボタン（選択範囲を末尾に複製）
- Ctrl+C / Ctrl+V は**アプリ内で保持**し OS のクリップボードを触らない。一覧にフォーカスがあるときだけ効く。貼り付けは常に末尾・**貼った行を選択**・繰り返し貼れる
- **別の一覧（同じ種類）への貼り付けを許す**（トリガー X のシーケンス → Y、キーマップ A のトリガー → B）
- ラベルの衝突は連番 `ラベル (2)`・`ラベル (3)`（トリガー・キーマップ。空ラベルは空のまま。出力シーケンスの行は連番を付けない）
- **トリガーのキー重複はグレー表示で残す**: 同じキーなら**一覧の上の行が有効**、下の行をグレー表示（理由「上のトリガーと重複」）。並べ替えで有効な行も入れ替わる
- グレー表示の行もキーを変えない編集（シーケンス・ラベル・suppress）はできる。キーを変える編集は現行の重複拒否を適用する
- 呼び出し（`[call] f5`）の呼び出し先が重複していれば有効な行（上）を呼ぶ
- **出力シーケンスの「次に実行」は選択と分け、行頭の `▶` で示す**。次に実行を変えるのは Shift なしのクリックとキー移動（↑↓・Home/End・PageUp/PageDown）だけ（v0.2・キー移動の範囲は v0.10）
- **実行中の状態は有効な行だけが持つ**（キー単位のまま。行単位の識別子は導入しない）。有効な行が変わったらそのキーの状態は削除と同じく消す（v0.2）
- キーマップの並べ替えで代表が変わったら実行中の状態を付け替える。並べ替えの禁止条件は §6.2

## §3 操作（対象の 4 つの一覧に共通。複製・貼り付け〔§3.4〕はプリセット一覧を除く 3 つ）

### §3.1 選択

| 操作 | 結果 |
|---|---|
| クリック / ↑↓ | 単一選択（現行どおり）。アンカー = その行 |
| Shift+クリック / Shift+↑↓ | アンカーから下線の行までを選択（連続範囲）。下線は操作した行 |
| Shift+ドラッグ | 押した時点のアンカーから、ポインタの行までを選択（押下中は帯だけ・離したとき反映 = phase 42 を踏襲） |
| ドラッグ（Shift なし） | §3.2 の移動 |
| 範囲の中の行を押して動かさずに離す | その行の単一選択（押した時点では範囲を潰さない） |

- **Tk の既定の範囲選択の動作は使わず置き換える**（対象 4 一覧の Listbox だけ。`return "break"`）:
  Ctrl+クリックは通常のクリックとして扱う / Shift なしのドラッグで範囲を伸ばさない / 一覧の外へ出たときの選択の延長はしない（§3.2 の自動スクロールに置き換え）/
  Escape は §3.2 の取り消し / Ctrl+/・Ctrl+\（全選択・全解除）・Shift+Ctrl+Home/End・Shift+Home/End は何もしない
- 選択範囲は編集の再描画（移動・複製・貼り付け・削除・編集の後）で保たれる。移動・複製・貼り付けの後は「動かした行 / 貼った行」が選択範囲になる
- **トリガーの実行（キー入力・呼び出し）による再描画では範囲を保たず**、現行どおりの単一選択に戻す（トリガー一覧 = 実行したトリガーの行 / 出力シーケンス = 次に実行の行）
- 省略表示のトリガー一覧は現行の単一選択と phase 42 の同期のまま

### §3.2 ドラッグ移動

- 押した行が選択範囲の中なら**範囲全体**、外なら**その 1 行**（そのとき単一選択に切り替える）を動かす
- ポインタが別の行に入るたびに、動かす塊をその位置へ移した表示にする。一覧の上端 / 下端の外へ出たら自動でスクロールする
- 離したとき確定（データへ反映・未保存化）。**Escape で取り消し**（押す前の並びへ戻し、その後のボタンの解放では確定しない）。並びが変わらなければ何もしない（未保存にしない）
- 規則に反する場合（§4.2・§6.2）は確定せず元に戻し、理由をステータスバーの一時メッセージに出す

### §3.3 上へ / 下へ（出力シーケンスとプリセット一覧・既存ボタン）

- 選択範囲を塊として 1 行上 / 下へ動かす（塊の外側の 1 行と入れ替える）。端では何もしない。規則は §4.2

### §3.4 複製・コピー / 貼り付け

- **Ctrl+C**: 一覧にフォーカスがあるとき、選択範囲（無ければ下線の行）をアプリ内の保管庫に**写し**で保持する（一覧の種類つき）。以後の元の編集は保管庫に影響しない
- **Ctrl+V**: 同じ種類の一覧にフォーカスがあるとき、保管庫の内容の写しを末尾へ追加する。種類が違う・保管庫が空なら何もしない
- **複製ボタン（出力シーケンスのみ）**: 選択範囲の写しを同じ一覧の末尾へ追加する（保管庫は変えない）
- 出力シーケンスの複製・Ctrl+C では、範囲にループの片側だけがあれば**範囲を取った時点で反対側を補う**（§4.3。保管庫には閉じた範囲が入る）
- 貼った行を選択範囲にし、見える位置へスクロールする。未保存にする
- 保管庫は**構成セットの読込・新規作成で空にする**（構成セットをまたぐ貼り付けはしない。構成相対パスの解決先が変わるため）。保存はしない
- キーは Caps Lock に依らず効くよう大文字・小文字の両方をバインドする（`menu_bar.py` に倣う）。テキスト入力欄の Ctrl+C / V は入力欄の通常動作

### §3.5 範囲の削除

- 範囲選択中の「削除」は範囲全体を対象に、件数を示して 1 回確認する。出力シーケンスのループの対削除（現行）は範囲に含まれる各ループに適用する
- キーマップ一覧: 全部消すと 0 個になる場合は削除しない。範囲にアクティブなキーマップを含み、現行の削除の規則で拒否される場合（連続実行中など・`features.md` §4.3）は範囲全体を削除しない

## §4 出力シーケンス

### §4.1 次に実行

- 次に実行の行は行頭に `▶` を付けて示す（他の行は同じ幅の空白。選択とは独立）。グレー表示のトリガー（§5.2）のシーケンスには `▶` を出さない
- 次に実行を変えるのは **Shift なしのクリックとキー移動（↑↓・Home/End・PageUp/PageDown）**（現行どおり実行位置へ反映し周回を作り直す。v0.10）。範囲選択・ドラッグ・貼り付け・複製・上へ / 下へでは変えない
- 追加ダイアログの「末尾に追加」を OFF にしたときの挿入位置（`features.md` §4.6「選択行の直後」）は、範囲選択中は**下線の行の直後**（編集が下線の 1 行を対象にするのと揃える。v0.10）
- 移動・複製・貼り付け・範囲削除の後、次に実行は**同じアクション（行の実体）**を指す。指していた行が削除されたら現行の削除と同じ扱い
- 移動は既存の「上へ / 下へ」と同じく編集として扱い、現行の後処理（周回の作り直し・戻す用の履歴の扱い）を踏襲する

### §4.2 ループの規則（移動）

現行の「ループの行は他のループの行と入れ替えない」を次の判定に置き換える（domain の純関数。`can_move` の一般化）:

- 移動の前後で `analyze_loops` を取り、**対（始まりと終わりの組）を行の実体で比べて同じ**、**対応が崩れた行の実体の集合が同じ**、
  **深さ超過の行の実体の集合が増えない**、の 3 つをすべて満たせば許す。それ以外は移動しない
- これにより、ループを丸ごと別のループの中へ動かす・通常の行をループの内外へ動かすのは許され、ループの行が他のループの行を越えて組が変わる移動は拒否される

### §4.3 複製・貼り付けの拒否

**ループの片側だけの補完（v0.5）**: 範囲（複製ボタン・Ctrl+C で取る行）に、元の一覧で対になっているループの片側だけが含まれるときは、
拒否せず反対側の行を補って閉じる。

- 範囲に「終わり」だけがある → 対の「始まり」を範囲の**先頭の前**に足す / 「始まり」だけがある → 対の「終わり」を範囲の**末尾の後**に足す
- 補う行は元の一覧の対の行の写し（`count` / `infinite` / `label` を含む）。範囲の外にある他の行（対との間の行）は含めない
- 補う行が複数あるときは元の一覧の並び順に置く（先頭の前の始まりも、末尾の後の終わりも、元の一覧で上にあるものから）。これで入れ子の順序が保たれる
  - 例: `L1始まり → テキスト1 → テキスト2 → L1終わり` で `テキスト2 → L1終わり` を取る → `L1始まり → テキスト2 → L1終わり`
  - 例: `[L1終わり … L2始まり]` を取る → `[L1始まり, L1終わり … L2始まり, L2終わり]`
- 補うのは範囲を取った時点（複製ボタン・Ctrl+C）。Ctrl+V は保管庫の内容（閉じた範囲）をそのまま使い、元の一覧を見に行かない
- 貼った行の選択範囲には補った行も含む

次の場合は追加せず理由を示す:

- 範囲（保管庫の内容）に対応が崩れたループの行が含まれる（元の一覧で相手のいない始まり / 終わり。補う元が無いため）
- 貼った後に深さ 9 を超える行が生じる
- 戻す / 先頭への単独登録の規則（`features.md` §4.6 出力シーケンスの編集）に反する

呼び出しの行はそのまま写す（呼び出し先はキーで指すため貼り先の一覧で解決される。循環・深さの検査は現行どおり実行時に任せる）。

## §5 トリガー一覧

### §5.1 有効な行と実行中の状態

- 同じ一覧に同じキーの行が複数あるとき、**一覧で一番上の行が有効な行**。実行中の状態（実行位置・周回・保留中のカウンター・戻す用の履歴・直前のトリガー・
  保留中のステップ・連続実行中のトリガー・再入防止）は**現行どおりキー単位**で持ち、有効な行のものとして扱う。グレーの行は状態を持たない
- **有効な行の交代**: 次の編集操作の前後で「キー → 有効な行の実体」を比べ、別の**既存の行**に入れ替わったキーを「交代した」とする。
  対象の操作 = トリガーの削除（範囲を含む）・並べ替え（ドラッグ）・貼り付け・キー変更。**保存・読込は対象にしない**
  （保存は行の実体を写しで置き換えるが同じ行として扱い、実行位置等を保つ = `data_schema.md` §5.13.1。読込は現行の扱いのまま）
  - 交代したキーの状態は**現行のトリガー削除と同じ処理**で消す（次に有効になった行は状態なしから始まる）
  - **交代するキーに進行中の実行がある場合はその操作をしない**（理由を一時メッセージに出す）。進行中 = 連続実行の実行中・一時停止中 /
    単発の呼び出しの文脈（実行中・一時停止中）/ 保留中のステップ・待ち・file_line の読込で、そのキーが実行元・呼び出し元・呼び出し先のいずれかであるもの。
    呼び出し先 = **現在入っているフレーム**の呼び出し先（まだ入っていない呼び出し先は開始時の写しで動くため交代の影響を受けず、対象にしない。v0.8）。
    現行の削除はキーの検索の失敗で進行中の実行を止めているため、同じキーの行が残る交代ではこれが働かない（codex 敵対的レビュー指摘）
  - キーが一覧から無くなる場合（同じキーの行が他に無い削除・キー変更）は交代ではなく、現行の削除・キー変更の扱いのまま
  - 有効な行のキーを変えた場合は、現行どおり旧キーの状態を新キーへ移す。旧キーに下の行が残れば旧キーは交代となり、上の規則（進行中なら拒否）に従う
- presentation がキーで引いている箇所（§1）は、**選んだ行が有効な行のときだけ**キーの状態を使う。グレーの行を選んだとき:
  シーケンス欄はその行のシーケンスを表示し `▶` を出さない / シーケンス欄のクリックで次に実行を変えない / ステータスの次に実行の要約は出さない
- **アクションが空の行**（`key_input.md` §7.3「無いものとして扱う」）: 有効な行の判定は空かどうかに依らず一番上の行。一番上が空なら、そのキーはトリガーとして無いものとして扱い、下の行も実行しない（置換が動く）

### §5.2 グレー表示と参照

- 有効でない行はグレー表示＋理由「上のトリガーと重複」。理由の優先は 停止 > トグル > 切替 > 上のトリガー（複数なら上位の 1 つ・`key_input.md` §7.3）
- 入力判定・呼び出しの解決・キーボード表示・重なりの判定は有効な行で引く（現行の先頭一致と同じ結果になることを確認し、規則として明記する）
- 重複キーを押したときの案内（`key_input.md` §7.3）は出さない（有効な行が動くため）
- **キー変更時の呼び出しの書き換え**（`features.md` §4.1）: 変えた行が**変更前のキーで有効な行だった場合だけ**、同じ一覧の呼び出しの `target` を新しいキーへ書き換える
- **呼び出しの編集ダイアログの呼び出し先ドロップダウンには、重複でグレーになった行を出さない**（キーで区別できないため。停止 / トグル / 切替との重なりでグレーの行は現行どおり出す）
- 追加・キー変更の重複拒否（`key_input.md` §7.3 の表）は変えない。**キーを変えない編集（ラベル・suppress 等）では重複検査をしない**。重複が生じるのは複製・貼り付け・読込だけ
- 貼り付けたトリガーのキーが停止 / トグル / 切替キーや置換元キーと重なる場合も受け入れ、読込と同じ扱い（グレー表示・置換にはトリガーが勝つ）にする
- 並べ替え・貼り付け・範囲削除の後は、現行の追加・削除と同じく重なりの表の作り直し・フックの再登録・キーボード表示の再描画を行う

### §5.3 複製・貼り付け

- トリガーの写しはキー・ラベル・suppress・連続実行・間隔・シーケンスを含む。読込元のパス・参照元・未保存の印・取り込みの印などの内部の値は写さない（新規扱い = 保存時に新しいファイル）
- ラベルの連番は貼り先の一覧で判定する（§7）

### §5.4 保存

- シーケンスの保存計画の識別子は「トリガー一覧 id + キー + **同じキーの何番目か**」（何番目かは一覧の上から 1 始まりで数える）。
  **1 番目は現行と同じ識別子**（一覧 id + キー）とし、2 番目以降だけ番号を加える（重複が無ければ現行と同一）。保存後の後処理（読込元のパス・参照元の設定）も同じ識別子で行に戻す
  （v0.6・2026-10-03 ユーザー確定。v0.5 までの「行の位置」は識別子を組み立て・分解する 8 ファイル 15 か所の書き換えになるため）
- **保存の計画を作った時点で、対象のトリガー一覧の実体と行の並びを計画に固定する**。照合の後はイベントループを挟まずに書き込み・後処理まで行う
  （照合で同じと確かめた一覧を書くため。v0.7・2026-10-03 ユーザー確定。v0.6 までの「実行・後処理でアクティブなキーマップから一覧を引き直さない」を置き換え）
  （保存ダイアログの表示中も `after` で予約済みの直接切替などが動きうるため。現行の個別保存は実行時にアクティブを引き直している = `trigger_set_file_io.py:75-108`）。
  書き込みの直前に、固定した一覧の行の実体と並びが計画時と同じかを照合し、違えば保存を中止して理由を示す
- 保存の前後で、各キーの実行位置・周回・履歴と次に実行（`▶`）は保たれる
- 個別保存のダイアログで同じキーの行が複数あるとき、行の表示に行番号を併記する（例 `f5（2 行目）`）。1 つだけなら現行どおり
- JSON の形式は変えない

## §6 キーマップ一覧

### §6.1 フォーカス = アクティブ

- 下線の行がアクティブなキーマップ。範囲選択の操作（Shift+クリック / Shift+↑↓ / Shift+ドラッグ）でも、離したとき・キーを離したときに下線の行をアクティブにする
- 切替を拒否した場合（連続実行中など）は、選択範囲も下線も元のアクティブの行だけに戻す（現行の拒否と同じ通知）
- **ドラッグ移動ではアクティブを変えない**（動かす前のアクティブのまま。動かさずに離したときは §3.1 のクリックとして扱う）

### §6.2 並べ替え

- 次のいずれかがある間は並べ替えをしない（理由を一時メッセージに出す）: 連続実行（実行中・一時停止中）/ 単発の呼び出しの文脈（実行中・一時停止中。
  アクションの間隔を待っている間も含む）/ 保留中のステップ（`pending_steps` が空でない）/ 待ち・file_line の読込。
  **ドラッグの開始時と確定（離したとき）の直前の両方で検査**し、確定時に該当すれば元に戻す
- 並べ替えで共有中のトリガー一覧の代表が変わったら、`AppState` の状態を新しい代表 id へ付け替える（`rekey_trigger_set`。上の検査により保留中のステップは無い）
- 個別保存のダイアログの行名は代表のラベルなので、並べ替えで変わりうる（受容）
- 並べ替えは構成セットを未保存にする（並び順は保存されるため）

### §6.3 複製・貼り付け

- キーマップの写しは置換の割り当て・ラベル（連番）・トリガー一覧を含む。**トリガー一覧は共有せず丸ごと写す**（新しい一覧）。新しい id を現行の採番で振る
- 内部の値（キーマップ・トリガー一覧・シーケンスの読込元のパス・参照元・未保存 / 取り込みの印・旧トリガー一覧の移行記録との関係）は写さない。写しは未保存の新規扱い
- **切替キー**: 貼るキーマップ全部の切替キーを **§6.4 のまとめて設定のダイアログ 1 つ**で入力する（v0.9。v0.8 までの「1 つずつダイアログ・キャンセルで残りを中止」を置き換え）。
  キャンセルしたら**何も貼らない**。キーマップの切替キーの重複は持たない

### §6.4 切替キーのまとめて設定（v0.9・2026-10-04 ユーザー確定）

キーマップを増やす 3 つの流れ（**追加・個別読込・貼り付け**）で、切替キーが要るキーマップを 1 つのダイアログでまとめて設定する。
現行（phase 34）の「切替キーの無い既存キーマップを一覧順に 1 つずつアクティブにして編集ダイアログを開く → 続いて追加 / 読込のダイアログ」を置き換える。

- **開く条件**: 既存のキーマップが 1 つ以上あるとき（0 → 1 個の追加・読込は現行どおりダイアログなし・切替キー不要）
- **行**（上から）: ①切替キーの無い既存キーマップ（一覧順）②増やすキーマップ（追加 = 新規 1 行 / 個別読込 = 読み込んだ 1 行 / 貼り付け = 貼る順に全部）。
  行ごとに「名前（既存 / 新規 / 読込 / 貼り付けの区別）・ラベル入力・切替キー入力（キー入力で取得・クリア）」を持つ。行が多いときは縦にスクロールする
- **行が 1 つでも同じダイアログを使う**（現行の追加 / 読込 / 貼り付けのダイアログは残さない。検査・確定を 1 つの経路にするため）。
  高さは行数に合わせ、1 行のときは区別の表示や見出しを省いて現行の編集ダイアログに近い見た目にする（v0.9・ユーザー確定 2026-10-04）
- **ラベルの初期値**: 既存 = 現在のラベル / 追加 = 空 / 個別読込 = 読み込んだラベル / 貼り付け = 連番（§7）。既存の行のラベルも変更できる（現行の編集ダイアログと同じ）
- **入力の検査は OK を押したとき**: 全行の切替キーについて 空・不正・停止 / トグルとの重なり・ダイアログ外のキーマップの切替キーとの重複・**ダイアログ内の行どうしの重複**・
  **全キーマップのトリガーキー・置換元キーとの重複**（`key_input.md` §7.3 の表）。
  **検査は反映後の完成予定の状態に対して行う**（既存のキーマップに加え、読み込む / 貼るキーマップ自身と他の増やす行のトリガー・置換元キーも含める。
  現行は runtime の重なりの表だけを見るため、増やすキーマップのトリガーと同じ切替キーを受理しうる〔`keymap_panel_controller.py:176-185`・codex 敵対的レビュー指摘〕）。
  エラーがあれば理由と行を示してその行の切替キーへフォーカスし、**ダイアログを閉じない**（現行の追加フローの「入力エラーで閉じない」を維持）
- **OK で全行を一度に反映**（既存の切替キー・ラベルの設定と、キーマップの追加）。**キャンセル（Escape・閉じるを含む）では設定データを何も変えない**（途中まで反映した状態を作らない）
  - 反映は、検査・採番・写しの作成をすべて済ませた後に、**アクティブ化・確認ダイアログ・イベントループを挟まずに一度で確定**する。
    現行の 1 行ずつアクティブにして `apply_keymap_edit` を呼ぶ手順（行の途中で失敗すると先の行の変更が残る）は使わない
  - 確定の前に失敗したら、既存のキーマップ・切替キーの表・未保存の印・トリガー一覧の実体を変えない
  - 確定の後に重なりの表の作り直しと一覧・キーボード表示の再描画を行い、フックの再開（§7.2 の停止要求の解除）で追加した切替キーを含めて登録し直す
- **実行中の状態**: ダイアログを開くとフックが止まるのは全ダイアログ共通の扱い（`key_input.md` §7.2）のまま。
  「何も変えない」は設定データについてであり、ダイアログを開いたことによる実行状態の扱いは現行の追加・編集ダイアログと同じ（本書では変えない）
- **アクティブなキーマップは変えない**（現行の 1 つずつアクティブにする手順をやめる。ダイアログはモーダル）
- ダブルクリックでの通常の編集（1 キーマップの編集ダイアログ）は変えない

## §6a プリセット一覧（プリセット編集ダイアログ）

- 移動・範囲削除はダイアログ内の作業用の一覧（`preset_manager.py` の `_temp`）に反映し、OK で確定・キャンセルで破棄する現行の扱いのまま
- 上へ / 下へ（`move`）は範囲をまとめて動かす（§3.3）。移動の規則はなし（ループ等の制約が無い）
- **ドラッグ中の Escape はドラッグの取り消しだけを行い、ダイアログを閉じない**（ダイアログの Escape = 閉じる〔`preset_manager.py:79`・`features.md` §4.6 モーダルの作法〕より優先。ドラッグ中でなければ現行どおり閉じる）
- 複製・Ctrl+C / V は付けない

## §7 ラベルの連番

- 貼るラベルが貼り先の一覧（先に貼った行を含む）の既存のラベルと重ならなければそのまま
- 重なれば、末尾の ` (n)`（n は 2 以上の整数）を除いたものを基にし、`基 (n)` で空いている最小の n（2 から）にする。除いた結果が空なら除かずにそのラベル全体を基にする
- 空のラベルは空のまま。出力シーケンスの行は連番を付けない

## §8 キー操作の割り当て

- 追加するバインドはすべて対象 4 一覧の Listbox だけに付ける（`bind_all` を使わない）。既存の Ctrl 系（menu_bar.py）とは重ならない

## §10 受け入れ条件（ドラフト）

1. 対象の 4 つの一覧で Shift+クリック / Shift+↑↓ / Shift+ドラッグの連続範囲選択ができ、Ctrl+クリックなどで飛び飛びにならない。省略表示は単一選択のまま（§3.1）
2. ドラッグで 1 行・範囲を移動でき、離したとき確定・Escape で取り消し・規則違反は元に戻して理由を出す（§3.2・§4.2）
3. 出力シーケンスの上へ / 下へが範囲をまとめて動かす（§3.3）
4. 複製ボタン・Ctrl+C → Ctrl+V で末尾に写しが付き、貼った行が選択される。別のトリガー / キーマップへも貼れる（§3.4）
5. 次に実行は `▶` で示され、範囲選択・移動・複製・貼り付けで変わらず、同じアクションを指し続ける（§4.1）
6. ループの組が変わる移動・対応が崩れた行・深さ超過・戻す / 先頭への規則違反は動かさない / 貼らない。範囲にループの片側だけがあれば反対側を補って複製 / コピーする（§4.2・§4.3）
7. 同じキーなら上の行が有効・下はグレー＋理由。並べ替えで有効な行が入れ替わり、入れ替わったキーの状態は削除と同じく消える。呼び出しは有効な行を呼ぶ（§5.1・§5.2）
8. グレーの行を選んでも、有効な行の次に実行・周回が変わらない。グレーの行のラベル等をキーを変えずに編集できる（§5.1・§5.2）
9. 重複キーを含む構成セットを保存 → 読込しても、各行のシーケンスが入れ替わらず消えない。保存の前後で実行位置・周回・履歴・`▶` が保たれる。
   保存中にアクティブが変わっても別の一覧を保存しない（§5.4）
9a. 交代するキーに進行中の実行（連続実行・一時停止・単発の呼び出し・保留）があるとき、削除・並べ替え・貼り付け・キー変更を拒否する（§5.1）
10. キーマップの並べ替えで代表が変わっても実行位置・選択行が保たれ、保存後の読込で一覧が正しく付く（§6.2）
11. 連続実行中・一時停止中・単発の呼び出しの間隔待ちを含む保留中はキーマップの並べ替えができない（開始時・確定時の両方）。範囲選択による切替が拒否されたら元に戻る。ドラッグではアクティブが変わらない（§6.1・§6.2）
12. キーマップの追加・個別読込・貼り付けで、切替キーが要るキーマップ（未設定の既存 + 増やすもの）を 1 つのダイアログでまとめて設定できる。行どうしの重複・増やすキーマップ自身のトリガー / 置換元キーとの重複を含む入力エラーではダイアログが閉じず、キャンセルでは設定データが何も変わらない。アクティブは変わらない。OK 後は追加した切替キーで直接切替できる（§6.3・§6.4）
12a. プリセット一覧で範囲選択・ドラッグ・上へ / 下へのまとめて移動・範囲削除ができ、OK で確定・キャンセルで破棄される。ドラッグ中の Escape でダイアログが閉じない（§6a）
13. ラベルの連番が §7 どおり
14. 範囲削除が 1 回の確認で消え、キーマップは 0 個にならない（§3.5）
15. 既存テスト（tests / tests_ui / smoke）が通る

## §11 スコープ外（本フェーズでやらない）

- 省略表示のトリガー一覧の範囲選択・移動・複製 / プリセット一覧の複製・貼り付け
- Ctrl+クリックの飛び飛び選択 / 一覧間のドラッグ（別の一覧へのドロップ）
- OS のクリップボード連携・構成セットをまたぐ貼り付け
- 貼り付け位置の指定（常に末尾）/ Ctrl+X（切り取り）
- グレーの行が自分の実行位置を保つ（行単位の識別子）/ キーマップの切替キーの重複保持
