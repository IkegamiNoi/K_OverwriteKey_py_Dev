## §1 目的 / 背景

アクション要素の `type` が **無い / 空 / 未知 / 非文字列**のとき、実行すると **`value` を文字列として前面アプリへ入力してしまう**。
想定外の文字が他アプリへ入るのを止め、**何も送らずエラーを通知する**。

## §3 設計本文

### §3.1 「種類が不正」の定義

実行時に `type` を**文字列として** `strip().lower()` した値が **`hotkey` / `text` / `mouse_click` のいずれでもない**アクション。
**無い・空・空白のみ・未知の文字列・非文字列**のすべてを含む。
executor は**読込時の正規化を前提にせず**、`type` が非文字列でも例外にしない（`isinstance` で空扱い。正規化を経ない dict
〔テスト・将来の経路〕でも §3.2 が成り立つようにする）。

### §3.2 実行時の扱い

- **何も送らない**（`input_gateway` を呼ばない・send guard にも入らない）。
- **実行時エラーとして通知する**: `on_action_error(action, err)`（= `HookController.show_action_error`）を 1 回呼ぶ。`err` は §3.5。
  **渡す `action` は、`type` を文字列化（非文字列なら `""`）したコピー**とする（`show_action_error` は `type` に直接
  `.strip()` を呼ぶため〔`hook_controller.py:241`〕、生の非文字列を渡すと通知側で `AttributeError` になり「送らなかった」が runner に届かない）。
  元の `action`（runtime のデータ）は書き換えない。
- **例外にしない**（executor 内で通知して処理を終える）。
- **executor は「送った / 送らなかった」を呼び出し元へ返す**。種類が不正で送らなかったときだけ「送らなかった」
  （`hotkey` / `text` / `mouse_click` の既存経路の戻り値は「送った」とし、**その内部のエラー〔hotkey 検証・`x` / `y` 不正・送信例外〕の扱いは変えない**）。
- **シーケンスは止める**（runner が「送らなかった」を受けたとき）:
  - **run_to_end**: `stop_run_to_end` する（`run_to_end_key` を `None` に・予約を取り消す）。index は不正な行のまま残す。
  - **単発**: index を**進めない**（ハイライトが不正な行に残る。直すまで同じ行でエラーになる）。
- 理由 = 本件の目的は「想定外の入力を他アプリへ送らない」。続行すると、通知を閉じた後の**フォーカスの戻り先**
  （親無しの messagebox のためルート窓へ戻る見込み・未確認）へ**同じシーケンスの後続のアクションが自動で送られる**恐れと、
  全要素が不正なときの**連続表示**がある。**案 S が止めるのは「同じシーケンスが通知の後に自動で続くこと」**であり、
  通知の表示中にユーザーが操作した入力は防がない（§3.6）。
- **種類が不正なアクションは、いつ・どの経路で呼ばれても送らない**（判定は `execute` の入口で毎回行う。通知の表示中に
  同じトリガーが再入しても「送らない」で終わり、表示抑止中は通知も重ねない）。

### §3.3 読込時の扱い（案 X は採らない）

- **読込時の正規化は phase 30 のまま**（非文字列は空扱い・要素は残す）。非文字列の `type` は空として §3.2 でエラーになるため、
  **案 X（要素ごと除去）は不要**。
- 要素を残す利点: 一覧に見えて、ダイアログで種類を選び直せば直せる（除去すると次の保存でファイルから消え、直す機会が無い）。

### §3.4 一覧表示・ダイアログ（変更しない）

- 一覧表示（§1 #6）は**現状のまま**（`[<type>] <value>` / 空は `[] <value>`）。
- 編集ダイアログ（§1 #7）は**現状のまま**。空 `type` を `hotkey` として開くのは**直すための初期値**であり、実行時の扱い（エラー）と矛盾しない。
  未知の文字列は表示されたまま OK で「種類が不正です。」になり、種類を選び直すまで保存されない。
- **見つけやすさは通知の内容（§3.5）と単発で index を進めないこと（§3.2）で担保する**（一覧の表記は変えない）。

### §3.5 通知の内容（`err` の文）

- `show_action_error` は既に「種別: <`type`>」「値: <`value`>」を表示する（`hook_controller.py:241-250`）。
  executor が渡す `err` の文は次の形とする:
  「種類が不正です（hotkey / text / mouse_click のいずれか）。種類: <type または「(なし)」> / ラベル: <label>」
  （ラベルが空なら「/ ラベル: …」を省く）。**種類の空は「種別:」欄では空欄のままになるため、`err` 側で「(なし)」と明示する**。
- 値の切り詰めはしない（「値:」欄は既存の表示のまま。presentation を変えないため）。
- **トリガーキー・行番号は含めない**（executor は持っていない。必要なら runner から渡す設計変更が要り、本フェーズの範囲外）。

### §3.6 既知の制約（受容）: 通知の表示中の入力

- 通知（`show_action_error` の messagebox）の表示中も**フックは止まらない**。表示中にユーザーが**正常な**トリガーを押す /
  キーマップのキーを押すと、その**正常なアクション・キーは送られる**。送り先はそのとき前面の窓で、**通知ダイアログが
  前面なら通知ダイアログへ入る**（例: Enter を送るアクションなら通知の OK が押される）。
- run_to_end 中に同じキーで一時停止・再開すると処理がもう一度走り得るが、行き着くのは同じ不正なアクションで
  「送らない」→ run_to_end は停止状態で終わる（停止処理は重なっても無害）。
- **種類が不正なアクションそのものが送られることは無い**（§3.2）。
- これは **hotkey 検証エラー・`x` / `y` 不正など既存のすべての実行時エラーダイアログと共通の性質**で、本件で新たに生じるものではない。
  「通知の間は実行を禁止する」は全エラーダイアログとフック制御に跨る設計のため**本フェーズの範囲外**（§7）。
- Tk の modal 表示中に `after` の予約が処理されるかは**推定（未実測）**。

## §4 正本の改訂内容（案）

§5.11.1 の phase 30 の条項を次へ置き換える:

> **`type` が無い / 空 / 上表以外の値のときは、何も送らず実行時エラーとして通知する**（通知には種類・値・ラベルを含める）。
> **シーケンスはそこで止まる**: 連続実行（run_to_end）は停止し、単発実行は次のアクションへ進まない（直すまで同じアクションでエラーになる）。
> 要素は読込時に除去しない。**一覧表示は `value` を表示する**
> （`[<type>] <value>`・空は `[] <value>`）。編集ダイアログは空 `type` を `hotkey` として開く（直すための初期値）。
>
> §5.11.5（既知の制約）へ追加: 通知の表示中もフックは止まらず、ユーザーが操作した正常なアクション・キーは前面の窓
> （通知ダイアログを含む）へ送られる（種類が不正なアクションは送られない。既存の実行時エラーダイアログと共通）。
>
> ※ `type` の無いアクションの意味を「text として入力」から「エラー」へ変える。§5.1「既存キーの意味変更禁止」の**設計変更による例外**
> （由来は防御的な既定で旧形式互換ではない〔§1 #1〕）。

## §6 受け入れ条件（ドラフト）

1. 次のアクションを実行すると、`input_gateway` のどのメソッドも呼ばれず、`send_guard_count` は 0 のまま、
   `on_action_error` が 1 回・`on_runtime_error` は 0 回呼ばれる（§3.2）:
   `type` 無し / `""` / 空白のみ / `"hotky"` / 非文字列（`["hotkey"]` を **`normalize_actions` 経由**で与えたもの）/
   非文字列（正規化を経ずに直接 `execute` へ渡したもの。§3.1）。
2. `on_action_error` へ渡る `err` が §3.5 の形（種類が空なら「(なし)」/ ラベルがあれば含む・無ければ省く）。
   渡る `action` の `type` が**文字列**（非文字列を直接渡したケースで `""`）で、元の `action` は書き換わっていない（§3.2）。
   **実際の `HookController.show_action_error`（`messagebox` だけダブル）に非文字列 `type` のアクションを通しても例外にならない**。
3. **本物の `ActionExecutor` と `SequenceRunner` を組み合わせて**: run_to_end 中に不正な種類へ達すると停止し
   `run_to_end_key` が `None`・予約が残らない / 単発で不正な種類を実行すると index が進まない（§3.2）。
   不正な種類より前のアクションは送られ、後のアクションは送られない。
   **通知の最中（`on_action_error` のダブルの中）に同じキーで runner を再度呼んでも**、送信は 0 回で、
   最終的に `run_to_end_key` が `None`・予約が残らない（§3.6。停止処理の重複が無害であること）。
4. `hotkey` / `text` / `mouse_click`（大文字小文字・前後空白を含む）は従来どおり送られ、シーケンスも従来どおり進む。
   **hotkey 検証エラー・`x` / `y` 不正時の進み方も従来どおり**（index が進む・run_to_end は続く）（退行なし）。
5. 読込時の正規化・一覧表示・編集ダイアログの挙動は変わらない（§3.3 / §3.4）。
6. 正本 §5.11.1 が §4 の文言へ改訂され、`codebase_map.md` の `ActionExecutor` の呼び出し元の説明（`:520` / `:576` 付近）の近くへ
