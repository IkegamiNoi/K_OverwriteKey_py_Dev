## §1 目的 / 背景

出力シーケンスのマウス操作は現在**単発クリックのみ**で、ドラッグ&ドロップや範囲選択ができない。
**掴む点と離す点の 2 点**と**カーソルの移動速度**を指定して、押したまま移動する操作を送れるようにする。

## §2 確定事項（ユーザー 2026-09-19）

- **保存形式は既存の `mouse_click` を拡張する**（`drag` フラグ + 離す点 + 速度）。**新種別 `mouse_drag` は作らない**。
  理由 = 種別ドロップダウンの項目を増やしたくない / **ドロップダウンの表示と保存時の種別を一致させたい**。
- **UI はチェックボックス方式**。マウス設定の中に「ドラッグ」のチェックを置き、チェックすると**離す点の欄と速度の欄が現れる**。
- **速度は px/秒で指定する**（所要時間 ms ではない）。理由 = 移動距離が変わってもカーソルの体感速度が一定になり、指示を組みやすい。
- **速度の既定値は 1000 px/秒**（実機目視で調整する前提の初期値）。
- **所要時間は 0.15〜5.0 秒へクランプする**（§5-3）。理由 = ①下限が無いと短距離で補間が起きずワープする（§1 の補間条件）
  ②上限が無いと低速指定で UI スレッドが長時間固まり、停止キーも効かなくなる（§1 の実行スレッド）。
  **クランプが効いた区間では指定した px/秒どおりにならない**ことを受容する。
- **`drag` が true のとき `clicks` は 1 固定**（UI の回数欄は無効化する）。キー自体は残す（削除禁止）。
- **実行は `dragTo` を使わず `mouseDown` / `moveTo` / `mouseUp` に分解する**（`dragTo` は例外時にボタンを離さないため）。
- **掴んだ直後 / 離す直前の追加の待ちは入れない**（pyautogui の `PAUSE = 0.1` が各呼び出し後に入るため）。実機で拾われない場合に再検討する。
- **マウス操作は send guard の対象外のまま**（フックはキーボードのみで自己受信しない）。昇格時に正本へ明文化する。
- **座標の取得は同時に 1 つだけ**（掴む用・離す用のボタンは排他）。
- **ドラッグの実行中は `pyautogui.FAILSAFE` を False にし、終了時に必ず元の値へ戻す**（§5-4）。
  理由 = ①FailSafe が**解放そのものを遮る**ため（§1「FailSafe と解放」）
  ②`pyautogui` だけで完結し **OS 分岐を増やさない**（pyautogui は import 時に `_pyautogui_osx` / `_pyautogui_win` / `_pyautogui_x11` を選ぶ。
  **将来の macOS 対応を見据えた判断**）。
  **失うもの = ドラッグ中（最長 5 秒）の四隅による緊急停止**。FailSafe はマウス操作にしか効いておらず
  （キー送信は `keyboard` と `ctypes` を通る）、ドラッグ中はアプリ側もカーソルを動かすため確実に止まる手段ではないことから受容する。
  採らなかった案 = ①解放の直前だけ外す（緊急停止は残るが入れ子の `try/finally` になり、**画面端に沿ったドラッグで補間点が隅に一致すると意図せず中断**しうる）
  ②`ctypes` の `user32.mouse_event` で直接解放（依存はゼロだが **Windows 専用分岐が増え、macOS 対応時に Quartz 版の再実装が必要**）。
- **既知の制約として受容**: ドラッグを知らない読み手（古いビルド / 別実装）がこの JSON を読むと、**掴む位置で単発クリックが 1 回起きる**。
  範囲選択なら「選択されずカーソルだけ移動」、ドラッグ&ドロップなら「何も起きない」で壊れる方向ではないため受容する（§7）。

## §3 データモデル（JSON）

`actions[]` の要素（`mouse_click`）に次のキーを**追加**する。既存キーの削除・意味変更はしない。

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `drag` | bool | `false` | true のときドラッグ操作として実行する |
| `to_x` | int | （drag 時必須） | 離す点の X |
| `to_y` | int | （drag 時必須） | 離す点の Y |
| `drag_speed` | int | `1000` | カーソルの移動速度（px/秒）。**正の数** |

1. **`drag` が false / 未指定なら従来と完全に同じ**（`x` / `y` でクリック）。既存の sequence JSON はそのまま有効。
2. **`drag` の真偽判定は `bool(action.get("drag"))`** とする（`domain` が型を正規化しないため、`"false"` のような文字列は true 扱いになる。
   UI からは常に bool で書かれるので、手書き JSON だけの縁辺ケースとして許容する）。
3. **`drag` が true のとき、`x` / `y` は掴む点、`to_x` / `to_y` は離す点**を表す。
4. **`to_x` / `to_y` の判定は既存の `x` / `y` と同じく `int()` 変換の可否**で行う（`"100"` や `10.9` は受け入れる。`isinstance` で判定しない）。
   欠落 / 変換不能なら**実行時エラーとして報告し、何も送らない**（`_on_runtime_error`）。**クリックへフォールバックしない**
   （意図と違う操作を黙って行わないため。button / clicks を既定値へ倒す既存の寛容さとは区別する = 座標は「意図そのもの」だから）。
5. **`drag_speed` が欠落 / 変換不能 / 0 以下なら既定 1000 を使う**（`clicks` と同じ寛容な扱い）。
6. **`drag` が true のとき `clicks` は 1 として扱う**（値が何であれ押下 → 移動 → 解放を 1 回）。
7. **掴む点と離す点が同一のときは、押して離すだけ（クリック相当）として許容する**（エラーにしない）。
8. **`drag` が false のときは新キー（`drag` / `to_x` / `to_y` / `drag_speed`）を出力しない**
   （`data_schema.md:12-17` の「生成停止」。`pop` 等による能動削除はしない）。
   - **ドラッグ ON で保存したアクションを OFF にして保存し直すと、ドラッグ用の 4 キーは消える**
     （`action_dialog.py:157` が辞書を作り直し、`trigger_panel_controller.py` が元のアクションを置換するため）。
     これは「生成停止」の想定どおりの結果であり、**`x` / `y` / `button` / `clicks` / `label` は消えない**。

## §4 UI（ActionDialog）

- 種別コンボは **hotkey / text / mouse_click の 3 種のまま**（§2）。
- 「マウスクリック設定」フレーム内に **チェックボックス「ドラッグ（範囲選択・ドラッグ&ドロップ）」** を置く。
- **チェック時のみ表示**する欄:
  - 「離す位置 X」「離す位置 Y」+ **「離す位置を取得」ボタン**（既存と同じ `pynput` 方式）
  - 「速度（px/秒）」（既定 1000）
- **チェック時の既存ウィジェットの扱い**:
  - 既存の「X」「Y」ラベルは文言を**「掴む位置 X / Y」**へ切り替える（ラベルを変数に保持する必要がある = §10）
  - **「回数」欄は無効化（`state="disabled"`）し、保存値は 1 に固定する**（§2）
- **座標取得は同時に 1 つだけ**: 片方が取得待ちの間はもう片方のボタンを無効化する。
  実装は既存の `_capture_mouse_position` を**対象の変数・ボタン・ヒントを引数で受け取る形へ一般化**する（§10）。
- 表示 / 非表示の切替は既存の種別切替（`_sync_capture_ui` / `:266`）と同じ方式に合わせる。
- OK 時の検証（`on_ok`）:
  - ドラッグ ON なら `to_x` / `to_y` は**必須**。空 / `int()` 変換不能はエラーダイアログで差し戻し（既存の X/Y と同じ）
  - 速度は空 / 変換不能 / 0 以下なら**既定 1000 を入れる**（差し戻さない）
- 既存アクションを開いたとき（`initial`）は `drag` / `to_x` / `to_y` / `drag_speed` を各欄へ復元する。

## §5 実行（application → infrastructure）

1. `action_executor._execute_mouse_click` は `drag` を見て分岐する。
   - false / 未指定 → 従来どおり `input_gateway.click_mouse(...)`
   - true → `input_gateway.drag_mouse(x, y, to_x, to_y, button, duration_sec)`（**新メソッド**）
2. **所要時間の算出は application 層で行う**（infrastructure は受け取った秒数で動かすだけ）。
   距離 = `hypot(to_x - x, to_y - y)`、`duration_sec = 距離 / drag_speed`。
3. **クランプ**: `duration_sec = min(max(duration_sec, 0.15), 5.0)`。
   - 下限 0.15 秒 = pyautogui の `MINIMUM_DURATION`（0.1）より**必ず大きく**し、常に補間が入るようにする（§1）。
   - 上限 5.0 秒 = UI スレッドの占有時間の上限（§1）。
   - **クランプが効いた区間では指定の px/秒にならない**（短距離は指定より遅く、長距離は指定より速くなる）。仕様として受容する。
   - **上限 5.0 秒は `moveTo` へ渡す引数の上限であり、実時間の厳密な上限ではない**（補間の sleep 約 +0.05 秒と `PAUSE` 4 回分、
     および処理時間が上乗せされる。§1）。UI の占有時間を概ね抑えるための規定として扱う。
4. `drag_mouse` の実装（infrastructure）:
   1. `pyautogui.moveTo(x, y)` で掴む点へ移動
   2. `pyautogui.mouseDown(button=button)`
   3. `pyautogui.moveTo(to_x, to_y, duration=duration_sec)`
   4. `pyautogui.mouseUp(button=button)`
   - **手順全体を FailSafe 無効で行う**: 先頭で `pyautogui.FAILSAFE` を退避して `False` を代入し、**`finally` で必ず元の値へ戻す**。
     `FAILSAFE` が False の間は `mouseUp` の事前チェックも移動中のチェックも通るため、**解放は OS へ必ず届く**（§1 の「FailSafe と解放」）。
   - **例外が起きても必ず解放する**（`finally` の中で `mouseUp`）。ボタンを押したまま残さない
     （キー送信で例外時に押したキーを逆順に離す実装 `input_gateway.py:100-116` と同じ方針）。
   - `dragTo` は使わない（§1 のとおり try/finally が無い）。
   - **`ctypes` を使わない**（`pyautogui` は OS 別の実装を内部で選ぶため、この方式は macOS / X11 でもそのまま動く）。
5. **異常系**:
   - **ドラッグ中は `FailSafeException` が発生しない**（§5-4 で無効化するため）。したがって「離す点を画面隅に指定したドラッグ」も正常に完了する。
     **ドラッグ以外（従来の `click_mouse`）の FailSafe は従来どおり有効**（挙動を変えない）。
   - 画面外・負座標は **OS のカーソル位置設定に従う**（`_pyautogui_win.py` は `SetCursorPos`。マルチモニタの負座標でも動く）。仕様で独自にクリップしない。
   - その他の例外は既存と同じ `_on_runtime_error("送信エラー", ...)`。

## §6 一覧表示（domain）

`format_action_list_item` は `drag` が true のとき次の形で整形する（例）:

```
03. [mouse_click] (100, 200)→(400, 500) left 1000px/s: 範囲選択
```

`drag` が false / 未指定のときは**現在の表示のまま**（`(x, y) button xN`）。

## §7 既知の制約（受容）

- **古い読み手 / 別実装では単発クリックになる**（§2）。`clicks` も 1 に固定されるため連打にはならない。
- **クランプ区間では指定速度どおりに動かない**（§5-3）。
- **補間は最大 20 サンプル/秒**（`MINIMUM_SLEEP = 0.05`）。滑らかさはここで頭打ちになる。
- **ドラッグ中は UI スレッドが塞がる**（最大 5 秒 + `PAUSE` 4 回分）。この間は停止キーなどの後続処理が走らない。
- **手書き JSON で `"drag": "false"` のような文字列を書くと true 扱いになる**（§3-2）。
- **ドラッグ中は `pyautogui.FAILSAFE`（モジュール変数）を False にする**（§5-4）。この間は**四隅による緊急停止が効かない**（最長で 5 秒程度）。
  アクションの実行は UI スレッド上で直列なので他の処理と競合しないが、pyautogui 側の実装が変わると前提が崩れる。
  **FailSafe が解放を遮る構造が解消されたら、この回避は外せる**。
- **ドラッグ ON → OFF の保存でドラッグ用 4 キーが消える**（§3-8。生成停止の想定どおり）。

> v0.1 の「確認事項」5 件（`clicks` の扱い / `dragTo` の可否 / 追加の待ち / send guard / 昇格先）は
> 起票時レビューの裏取りとユーザー採否により**すべて確定済み**（§2 / §10 へ移動）。

## §8 受け入れ条件（ドラフト）

1. 既存の `mouse_click`（`drag` キーなし）の JSON が**挙動・表示とも一切変わらない**（§3-1）。
2. **ドラッグ OFF で保存したアクションに新キーが出力されない**（§3-8）。既存の `x` / `y` / `button` / `clicks` / `label` は消えない。
3. ドラッグ ON のアクションを保存 → 再読込 → 編集ダイアログに 2 点と速度が復元される（§3 / §4）。
3-b. ドラッグ ON で保存 → 再読込 → **OFF にして保存 → 再読込**で、単発クリックとして動作する（§3-8）。
4. `to_x` / `to_y` が欠けた `drag: true` を実行すると**エラー報告のみで何も送らない**（クリックしない）（§3-4）。
5. `drag_speed` が不正値（空 / 文字列 / 0 以下）のとき **1000 として実行される**（§3-5）。
6. 実行が `moveTo → mouseDown → moveTo(duration) → mouseUp` の順で呼ばれ、**移動中に例外が出ても `mouseUp` が呼ばれる**（§5-4・モックで順序を検証）。
6-b. **解放が FailSafe に遮られない**: ドラッグ中は `pyautogui.FAILSAFE` が False で、**終了後（例外時も含む）に元の値へ戻っている**ことを検証する。
   従来の `click_mouse` の経路では `FAILSAFE` を触らないことも併せて確認する。
7. `duration_sec` が「距離 ÷ 速度」で算出され、**0.15 秒未満は 0.15 に、5.0 秒超は 5.0 になる**（§5-3・**`moveTo` へ渡す引数の境界値**をテストで検証）。
   実時間はこれより長くなる（補間の sleep と `PAUSE`）ため、**実時間は実機目視でのみ確認する**（受け入れ条件 11-⑤）。
8. 掴む点と離す点が同一でも例外にならない（§3-7）。
9. ドラッグ ON のとき回数欄が無効化され、保存値が 1 になる（§4）。
10. 一覧表示がドラッグのとき 2 点と速度を示す（§6）。
11. **実機目視**:
    ①メモ帳等で文字列の範囲選択ができる（**短距離 50px 程度 / 長距離 500px 程度の両方**）
    ②エクスプローラ等でドラッグ&ドロップができる
    ③速度を変えると移動の速さが変わる（**100px 超の距離で比較する**）
    ④既存の単発クリックのアクションが従来どおり動く
    ⑤最長（5 秒クランプ）のドラッグ中でも、終了後に停止キー・トグルが正常に効く
    ⑥**離す点を画面の隅に指定したドラッグ**が正常に完了し、ボタンが押しっぱなしにならない（FailSafe 無効化の確認）
    ⑦ドラッグ中に物理マウスを画面の隅へ動かしても**中断せず**（FailSafe 無効）、終了後はボタンが離れている
    ⑧ドラッグ**以外**のマウスクリックでは FailSafe が従来どおり効く（座標 (0,0) のクリックでエラーになる）
12. `tests` / `tests_ui` 全体 + smoke が pass（件数が減らない）。

## §9 スコープ外（本フェーズでやらない）

- ホイールスクロール / マウスボタンの「押す」「離す」を独立したアクションにすること
  （キーボード側の同種要望は [idea_23](../backlog/idea_23_key_press_release_actions.md)）。
- **ドラッグ実行の別スレッド化**（UI スレッド占有の根本解決）。本フェーズは上限クランプで回避する。
- **macOS / X11 対応**（拡張キー送信の `ctypes.windll` とキーフックの `keyboard` が Windows 前提であり、本フェーズの範囲を大きく超える）。
  ただし本フェーズでは **OS 分岐を増やさない**方針を採る（§2）。
- 経由点を複数持つドラッグ（3 点以上のパス）・曲線補間（`tween` の選択）。
- 相対座標・ウィンドウ基準座標・マルチモニタ座標系の規定（現状どおり絶対座標のまま）。
- `mouse_click` を send guard へ入れるかどうかの**挙動変更**（明文化のみ）。
- 座標取得 UI を「1 ボタンで 2 点連続取得」に変える案（起票時レビュー指摘 13・**保留**）。
- hotkey / text アクションの仕様変更。
