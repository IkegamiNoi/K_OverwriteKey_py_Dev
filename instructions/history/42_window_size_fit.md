## §3 フル表示: 3 枠のスクロール

### §3.1 構造

* 3 枠（KeymapBox・FullTriggerBox・SequenceBox）それぞれについて、**枠の見出し（`LabelFrame` の枠）の内側の中身**を、縦のスクロール領域（Canvas + 中身の Frame + 縦の Scrollbar）に入れる。
  横のスクロールは設けない（幅は従来の最小幅の規則で切れない）
* スクロール領域の部品は 3 枠で共通にする（新規の部品 1 つ。phase 57 の `grid_editor_panel.py` の作法を踏襲: 値が変わったときだけ configure・測り直しの結び付けは中身の Frame 1 つ・再入防止・測る前に `update_idletasks()`・スクロールバーの表示は自前の印）
* **中身の窓の高さ = max(Canvas の高さ, 中身の要求高さ)**。Canvas の方が高ければ中身の Frame を Canvas の高さまで伸ばし（今と同じく一覧が伸びて余りを使う）、低ければ要求高さのままにしてスクロールする
* **測り直しの契機**: Canvas の `<Configure>`（大きさの変化）/ 中身の Frame の `<Configure>`（要求高さの変化）/ フォント変更 / `<<ThemeChanged>>` / フル表示の呼び出し先の枠の開閉 / フル表示へ戻る。
  `pane_layout` が最小の高さ・幅を測る前に、各枠の中身の窓の高さを同期してから測る（古い値で測らない）
* スクロールバーは**その枠の中身が収まらないときだけ**出す（3 枠で独立）。**隠すときは `yview_moveto(0)` で先頭へ戻す**（隠れたまま途中までスクロールした状態を残さない）

### §3.2 最小の高さ

* 用語: **メイン領域の基準の高さ** H = 3 枠それぞれの「枠の飾りの高さ（`LabelFrame` の見出し・枠線・padding）+ 中身の Frame の要求高さ」の最大。
  スクロール領域を入れた後は枠の要求高さがスクロール領域の要求高さになるため、**中身の Frame から直接測る**（一覧は既定の行数の半分 = 今の phase 20 の基準のまま）
* **フル表示のウィンドウの最小の高さ = `app.winfo_reqheight()` − (PanedWindow の要求高さ) + ceil(H / 2)**（一時メッセージの余分を引く規則 = `measure_window_min_height` のまま。上部・ステータス欄・ステータスバーは今のまま）。
  PanedWindow の要求高さが H と一致しない場合も、この式（引いて足す）で上部などの高さを今のまま残す
* ウィンドウの高さが今の最小以上なら 3 枠とも収まり、スクロールバーは出ない（今と同じ見た目）。今の最小より低いと、収まらない枠にスクロールバーが出る
* 測る契機・適用（`minsize`・最小より低ければ伸ばす・保存しない）は今の規則のまま（フォント変更・フル表示へ戻る・境界線のドラッグの後）
* 画面の高さが新しい最小にも足りなければ、はみ出しを受け入れる（今と同じ）

### §3.3 幅

* **スクロールバーの幅**: 各枠（3 枠とも）の最小幅に、**今のテーマで実測した縦のスクロールバーの要求幅を常に足す**（スクロールバーの有無で変えない・フォント変更・`<<ThemeChanged>>` で測り直す）。
  ウィンドウの最小幅もこの各枠の最小幅から今の式（`features.md` §4.6）で求める。最小幅のまま高さを縮めて 3 枠すべてにスクロールバーが出ても中身は切れない（§8-1 確定）
* **最小幅は中身の Frame の子から測る**: 今の `pane_measure._stacked_width`（:68-74）は枠（`LabelFrame`）直下の子を見ているため、スクロール領域を入れると子が Canvas 1 つになり測れなくなる。
  一覧の行以外の部品（ボタン列など）は中身の Frame の子を対象にする（出力シーケンスの横並びの測り方も同様に中身の Frame 側を見る）

### §3.4 マウスホイール

* 一覧（Listbox）の上: 一覧には結び付けず、Tk の既定の動き（一覧がスクロールする）に任せる。枠はスクロールしない
* 一覧に付いたスクロールバーの上: 一覧のスクロールとして扱う（枠はスクロールしない）
* それ以外（`LabelFrame`・Canvas・中身の Frame などの容器・ボタン・チェックボックス・間隔の入力欄・余白）: その枠のスクロールバーが出ているときだけ枠をスクロールし、`break` で止める。出ていなければ何もしない
* 結び付けは各枠の中の部品ごと（`bind_all` は使わない・他の窓へ漏らさない）。間隔の入力欄（`ttk.Entry`）の上のホイールで値が変わらないこと
* **Tab でフォーカスが隠れた部品へ移っても自動でスクロールしない**（受容。§8-3 確定）

## §4 省略表示: フック / 表示の Expander

* 上部の「フック」の枠（`CompactHookFrame`）と「表示」の枠（`CompactDisplayFrame`）を、それぞれ Expander にする。見出しのクリックで開閉:
  開 = `▾ フック` + 今の中身 / 閉 = `▸ フック` の 1 行だけ（表示も同じ）。見出しの作法（文言・カーソル・クリック）は省略表示のシーケンス欄に合わせる
* **閉じ方**: 閉じたら枠（`LabelFrame`）ごと `pack_forget` し、同じ位置に見出しの Label（`▸ フック`）を置く（シーケンス欄の `show_heading_at` と同じやり方）。
  開いたときは見出しの Label を外して `▾ フック` を枠の見出しとして出す（見出しを二重に出さない）。並び順（フック → 表示 → トリガー一覧）は開閉で変えない
* 「表示」を閉じると、その中の「フルに戻す」ボタンも隠れる（受容。キーボード操作の表示切替は今のまま効く）
* **開閉の保存**: `config/config.json` の新しいキー `compact_header_view` = `{"hook": <bool>, "display": <bool>}`（true = 開）。
  キーが無い・dict でない = 両方開く / 各値が bool でなければその値だけ開く（独立に検証・エラー表示なし・ファイルは書き換えない）。
  書き込み契機 = 見出しのクリックで開閉したとき（起動設定の書き出し経路 1 本を通す・`compact_sequence_view` と同じ）。
  **書くときは常に `hook` と `display` の両方の値を書く**（今の状態から組み立てる）。`compact_header_view` の中の未知のキーは保持しない
* **大きさ**: 開閉でウィンドウの大きさは変えない。上部の高さの増減はトリガー一覧の欄（シーケンス欄・呼び出し先の枠を含む縦の PanedWindow）が受ける
  （その中の配分は `features.md` §4.6「省略表示のシーケンス欄」の大きさの規則のまま）
* **最小の高さ**: 省略表示の最小の高さは**開いている枠の中身だけ**を数える（閉じた枠は見出しの 1 行）。開閉のたびに測り直し、ウィンドウが新しい最小より低ければ最小まで伸ばす（アプリが決めた大きさ・保存しない）
  （§4.6 の「欄の開閉で最小は変わらない」はシーケンス欄・呼び出し先の枠の話で、本節の上部の枠には当てない）
* **フォーカス**: 閉じるとき、フォーカスがその枠の中にあればトリガー一覧へ移す（見えない部品にフォーカスを残さない）
* 閉じていても機能は変わらない（停止キー・トグルキー・キーボード表示の切替などはそのまま効く）
* フル表示の上部は変えない（Expander にしない）

## §5 ステータス欄のフックの 3 状態

* フックの項目 = `ON`（フック動作中・キーマップ一時停止でない）/ `OFF`（フック停止中）/ `一時停止`（フック動作中・キーマップ一時停止中 = `custom_input_enabled` が偽）。
  **`hook_active` が偽なら `custom_input_enabled` に関係なく `OFF`**（OFF が優先）
* キーマップの項目 = アクティブな keymap の名前だけ（無ければ `(なし)`）。「（フック停止中）」「（一時停止）」を付けない
* 書式: フル表示 = `フック: 一時停止 / キーマップ: <名前> / トリガー: … / 選択中: …`（項目の並びは今のまま）/ 省略表示 = 1 行目 `フック: 一時停止 / キーマップ: <名前>` … （今のまま 2 行）
* 一時メッセージ（キーマップの削除・切替・変更なし）が使う `get_active_keymap_text` は変えない（名前 + 状態の付け足しのまま）。ステータス欄用に名前だけを返す関数を分ける

## §9 受け入れ条件（ドラフト）

1. フル表示で、ウィンドウを今の最小の高さ以上にしたとき、見た目と動きが今と同じ（スクロールバーが出ない・一覧が伸びる）（§3.1・§3.2）
2. フル表示で、今の最小より低くすると収まらない枠にだけスクロールバーが出て、スクロールバー・ホイールで最下段まで届く。一覧の上のホイールは一覧をスクロールする（§3.1・§3.4）
3. フル表示の最小の高さ = `app.winfo_reqheight()` − PanedWindow の要求高さ + ceil(H/2)（§3.2 の測り方）。それより低くできない。フォント −3 / 0 / +3 で成り立ち、フォント +3 で画面 966px にウィンドウが収まる（§3.2）
4. ウィンドウを最小幅・最小の高さまで縮めて **3 枠すべてにスクロールバーが出ても**、ボタン・チェックボックス・見出し・間隔の入力欄が切れない（フォント −3 / 0 / +3）（§3.3・§8-1）
5. 省略表示で「フック」「表示」をそれぞれ開閉でき、閉じると見出し 1 行になり、トリガー一覧の欄が伸びる。ウィンドウの大きさは変わらない。開閉の状態が再起動後も残る（§4）
6. 省略表示の最小の高さが開閉に従って変わり、開いたときに最小より低ければ伸びる（§4）
7. `compact_header_view` が無い・不正な値で両方 / その値だけ開いて起動し、ファイルは書き換えない（§4）
8. ステータス欄のフックが ON / OFF / 一時停止 を正しく出し、キーマップの項目は名前だけ。幅 270 の省略表示でも一時停止が見える（§5）
9. 一時メッセージの文言（キーマップの削除・切替）は変わらない（§5）
10. 既存のテスト（compileall / tests / tests_ui / smoke）が通る。最小の高さの期待（`test_full_view_min_height.py` 等）は本書に合わせて書き換える。
    ステータスの書式の期待（`tests_ui/test_app_ui_flows.py:142,157`）も書き換える。`get_active_keymap_text` を差し替えてステータス欄を見ているテスト
    （`test_status_tooltip.py:131,158,175,208`・`test_compact_window.py:269`・`test_sequence_control_review_fixes.py:100`）は、ステータス欄用の新しい関数の差し替えへ直す
11. スクロールバーが隠れるとき枠が先頭へ戻る。ホイールは一覧・一覧のスクロールバーの上では一覧、容器・ボタンの上では枠をスクロールし、間隔欄の値は変わらない（§3.1・§3.4）
