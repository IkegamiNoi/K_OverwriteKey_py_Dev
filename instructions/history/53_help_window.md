## §1 目的 / 背景

機能の基本的な使い方と、制限（できないこと・注意点）をアプリの中で読めるようにする。
メインの窓の操作を妨げない別の窓に出し、Expander で大まかに括り、フィルターで探せるようにする。
あわせてバージョン情報とライセンスを見られるようにする。**JSON スキーマ（config.json・構成セット・レイアウト）は変えない**。

## §2 確定事項（ユーザー 2026-10-27）

- **メニューバーに「ヘルプ」を新設**。項目 = 「使い方」「よくある質問」/ 区切り /「バージョン情報」「ライセンス」。**F1 などのショートカットは付けない**。
- **ヘルプの窓はモーダルにしない**（メイン・他の窓の操作を妨げない）。**同時に 1 つだけ**。再度開くと前面に出し、指定のタブへ切り替える。
- **タブ = 「主要機能」「QA」**。入口（「使い方」/「よくある質問」）はどちらのタブを先に出すかの違いだけ。

- **フィルターの入力欄にフォーカスがある間はフックを止める**。
- **窓の位置・大きさは記録しない**。**フォントサイズの設定に従う**。
- **「キーボードUIを常に手前」との関係は既存の見張りに任せる**（ヘルプ・ライセンスの窓が前面になるとキーボードUIは手前を外してその窓の下へ回る。追加のコードなし）。※当初「後ろに隠れるのを許容」としていたが、既存の自動の一時解除で隠れないことが分かり改めた（§9-6）。

## §4 ヘルプの窓

### §4.1 窓

- `tk.Toplevel`・題 = 「ヘルプ」。**モーダルにせず、`transient` にもしない**（メインの窓を前面へ出せる）。
- メインの窓の「常に手前」（`always_on_top_var`）が ON なら、開いたとき・前面化のとき・切替のときに、ヘルプの窓（とライセンスの窓）の `-topmost` を同じ値にする。
- **メインの「常に手前」の切替のときの再同期**: ヘルプ・ライセンスの窓の `-topmost` を直したあと、キーボードUIの見張り（`LayoutController`）が持つ「一時解除している」の状態を捨て、次の見張りの判定で手前の属性と重なり順（前面の窓の下へ置く）をやり直させる。そのための小さな窓口を `LayoutController` に足す（**見張りの判定条件は変えない**）。キーボードUIの「常に手前」が OFF・キーボードUIが開いていないときは何もしない。
- 初期の大きさ = 幅 720・高さ 560（画面に収まらなければ収まる大きさへ）。最小 = 幅 420・高さ 300。位置は OS 任せ。位置・大きさは記録しない。
- 窓の管理役（`HelpWindowController`・仮称）が 1 つだけ持つ。閉じたら破棄し、次に開くときは作り直す（状態は持ち越さない）。
- メニューから開いたヘルプの窓は、モーダルのダイアログが開いている間は操作できない（grab のため。§6 の「?」がこれを補う）。
- 開いたときの初期フォーカスは Notebook（フィルターの入力欄にしない＝開いただけでフックを止めない）。
- 前面化（再度開く・「?」）のときは、最小化されていれば `deiconify` してから `lift` + `focus_set`。
- Escape: フィルターの入力欄にフォーカスがあり入力が空でなければ入力を消す。それ以外は窓を閉じる（モーダルダイアログの作法と同じ「× と同じ結果」）。
- アプリの終了時はヘルプの窓も閉じる（終了を妨げない）。

### §4.2 構成

上から: フィルターの入力欄（ラベル「絞り込み:」+ 消去ボタン「×」）→ `ttk.Notebook`（「主要機能」「QA」）→ 各タブは縦スクロールする 1 列の並び。

- 大分類の見出し = 「▶ 大分類名」/「▼ 大分類名」。クリック・Enter・Space で開閉（既存の省略表示の上部と同じ操作感）。
- 開いた大分類の下に項目の見出し（字下げ 1 段・同じ記号）。開くと本文が出る。
- 本文は読み取り専用で、窓の幅に合わせて折り返す。本文の文字は選択・コピーできる（本文をクリックしたら本文へフォーカスを移し、Ctrl+C が入力欄へ流れないようにする。右クリックの「コピー」も出す）。
- マウスホイールで、カーソルのあるタブの並びをスクロールする。
- 部品の分け方は規定しない（例: タブごとに 1 つの読み取り専用 `tk.Text` に見出しと本文を流し込み、開閉・隠すはタグの elide、ハイライトはタグで行う方式が小さく済む。採否は実装タスクで決める）。上の見た目と操作を満たせばよい。

### §4.3 フィルター

- 入力が変わるたびに適用する（Enter 不要）。入力欄はタブの外にあり、2 つのタブで共通。
- **正規化** = Unicode NFKC + casefold（全角半角・英字の大小を同一視。ひらがなとカタカナは区別する）。
  - 入力（検索語）: 全体を正規化し、前後の空白を除き、空白（全角を含む）で区切って語にする。
  - 本文側: **1 文字ずつ正規化**し、正規化後の各文字から元の文字の位置への対応を持つ（ハイライトは元の位置へ当てる。1 文字が複数文字へ広がる〔`ß`→`ss`・`㍿`→`株式会社`〕場合も、広がった全部を元の 1 文字へ対応させる）。
  - 1 文字ずつの正規化と全体の正規化が食い違うのは、正規化後に結合文字（Unicode の一般カテゴリ M*）が現れる場合だけ（例: 本文の `ｶﾞ` は 1 文字ずつだと「カ」+ 結合濁点、全体だと「ガ」）。これを本文に持ち込まない: **データファイルの検査テストで、見出しと本文が NFC であること・各文字を NFKC にした結果に結合文字が含まれないこと（半角の濁点・半濁点・分解形の結合文字を書かない）を確かめる**（本文はこちらで書くので守れる）。この条件の下では、1 文字ずつの結果と全体の結果は一致する。
- **一致** = 「大分類名・項目の見出し・本文」を**改行で区切って**つないだものを正規化した文字列に、すべての語が含まれる項目（境界をまたいだ一致を作らない）。
- 一致した項目は開いた状態で表示し、その大分類も開く。一致しない項目と、一致項目の無い大分類は隠す。
- 項目の見出しと本文の中の一致箇所を、**語ごと・出現ごとにすべて**背景色でハイライトする（大分類名の中はしない）。
- タブ見出し = 入力が空でないとき「主要機能 (N)」「QA (N)」（N = 一致項目数。0 も出す）。空のときは件数を付けない。
- 一致が 0 件のタブには「一致する項目はありません。」を出す（片方のタブだけ 0 件のときも）。
- 入力を空にする（消去ボタン・全削除）と、全項目を表示し、すべて閉じた状態へ戻す。
- 一致判定・正規化は Tk に依存しない純関数にする（単体テストの対象）。

### §4.4 フックとの関係

- フィルターの入力欄が FocusIn したら `suspend_hook_for_dialog()` を呼び、「止めている」の印を立てる（印が立っていれば呼ばない）。
- 印が立っている間に、入力欄の FocusOut か、入力欄または窓の `<Destroy>` の**先に来た方**で `resume_hook_after_dialog()` を 1 回だけ呼び、印を下ろす（既存 `hook_controller.py:58-66` の書き方にならう。フォーカスを持ったまま破棄されて FocusOut が来なくても解除される）。
- Windows の Tk では、アプリが非アクティブになると FocusOut、戻ると FocusIn が届く。**Alt+Tab のたびに停止・再開を繰り返すのが正しい挙動**（他のアプリを操作している間はフックが要る）。
- 入力欄以外（見出し・本文・タブ）にフォーカスがある間は、フックは止めない（ヘルプを見ながらアプリを使える）。
- ダイアログの子のヘルプ（§6）では、ダイアログの停止と入力欄の停止が入れ子になる。カウント方式なので両方が解除されたときだけフックが戻る。
- 止めている間のステータス欄のフック表示は、既存どおり「一時停止」になる。
- 停止は `stop_hook` を通るため、**入力欄へフォーカスを移した時点で、実行中の連続実行・待機は止まり、押したままのキーは離される**（ダイアログを開いたときと同じ。§9-7）。

### §4.5 フォント

- `apply_global_theme` の名前付きフォントを使う。`_apply_font_delta` から、開いているヘルプの窓へ `on_font_changed()` を通知する（見出しの太字など、名前付きフォントから派生させた独自のフォントを作り直す）。
- バージョン情報・ライセンスの窓は名前付きフォントだけを使い、通知は受けない（自動で追従する）。

## §5 本文のデータファイル

### §5.1 置き場所と言語

- `keyseq/presentation/help/content/help_ja.json`（パッケージに同梱する読み取り専用データ。`__file__` 基準で読む）。
- 言語の選び方は本フェーズでは固定で `ja`。ファイル名の `_<言語>` で言語を分け、選び方は多言語対応のフェーズで決める。
- 本ファイルは利用者が編集するものではなく、config の JSON スキーマの対象外（`data_schema.md` に載せない）。

### §5.2 形式

```json
{
  "format": 1,
  "tabs": {
    "guide": [
      {
        "id": "keymap",
        "title": "キーマップ",
        "items": [
          {
            "id": "keymap.switch",
            "title": "キーマップを切り替える",
            "body": [
              {"type": "p", "text": "段落の文。"},
              {"type": "list", "items": ["箇条 1", "箇条 2"]}
            ]
          }
        ]
      }
    ],
    "faq": []
  }
}
```

- `tabs.guide` = 「主要機能」・`tabs.faq` = 「QA」。並び順はファイルの順。
- `id`: 大分類・項目ともファイル全体で一意（項目は「大分類 id.名前」）。§6 の「?」の飛び先に使う。表示はしない。
- `body` の要素は `p`（段落）と `list`（箇条書き・1 段のみ）の 2 種だけ。強調・リンク・画像は無い。
- 読み込みの失敗（ファイルが無い・JSON の誤り・形式の誤り）は例外を外へ出さない。窓の中に「ヘルプを読み込めませんでした。（理由）」を出し、アプリは続ける。形式の誤りが一部だけでも、ファイル全体を失敗として扱う（同梱データであり、検査テストで誤りを出荷しないため。部分表示の分岐を作らない）。
- 検査は単体テストで行う（形式・id の一意・§6.1 の飛び先 id が存在すること）。

### §5.3 本文の内容（初版の大分類・案）

- 主要機能: はじめに（全体像・用語）/ 構成セットとファイル / キーマップ / トリガー / 出力シーケンス（アクションの種類）/ フック / 表示の切替（詳細表示・簡易表示）/ キーボードUI / 画面の枠 / プリセット / ファイルの整理（参照元の掃除・未使用ファイル・退避）
- QA: 動かないとき / できないこと（制限）/ 保存とファイル / キーの入力
- 大分類の最終形と本文は、本文の執筆タスクで下書きし、ユーザーの校正で確定する（本書の改訂は不要。正本反映で `features.md` に大分類の一覧だけ載せる）。

- 飛び先は大分類単位を既定とし、項目まで決まるものは本文の執筆タスクで項目 id へ細かくしてよい（表の更新は本書の改訂で行う）。

### §6.2 置き方

- ダイアログ下端のボタン列の左端に、ボタン「?」（幅は最小）。ホバーで「ヘルプ」のツールチップ（既存 `hover_tooltip.py`）。
- キーの割り当ては無い（F1 なし）。Tab のフォーカス順には入る。

### §6.3 開き方

- 「?」を押すと、ヘルプの窓を**そのダイアログの子の窓**（`tk.Toplevel(dialog)`）として開く。ヘルプの窓は grab を取らない。
  - **実測済（2026-10-27・`.venv` の Tk・SetCursorPos + mouse_event / keybd_event の実入力・3 回とも同じ結果）**: `dialog.grab_set()` の下で、`Toplevel(dialog)` のボタンのクリックと入力欄へのキー入力は届き、ダイアログ自身も操作でき、`Toplevel(root)`（ダイアログの子でない窓）のクリックは届かない。
- 既にヘルプの窓（メインの子・別ダイアログの子）があれば、それを閉じてから開き直す（同時に 1 つの規則を保つ）。同じダイアログの子として既に開いていれば、開き直さず再利用してよい。
- 開いたら: 飛び先のタブへ切り替え、フィルターを空にし、飛び先の大分類（項目 id ならその項目も）を開いて、先頭が見える位置までスクロールする。飛び先の id がデータに無ければ、指定のタブで開くだけにする（例外を出さない）。
- ダイアログを閉じると、子のヘルプの窓も一緒に閉じる（Tk の連鎖破棄。追加の処理は無い）。
- 子のヘルプの窓は、ダイアログのモーダル性の例外（ダイアログが開いている間に操作できる、ダイアログ以外の唯一の窓）として、正本「モーダルダイアログの作法」に追記する。
- 子のヘルプの窓とダイアログの前後関係は保証しない（どちらを前にするかは利用者の操作による）。
- 最小化の扱い（`install_minimize_grab_custody`）・入れ子のダイアログの grab の戻し（`grab_modal`）を変えない。アプリを最小化しても子のヘルプの窓は transient でないため隠れず、預かりで grab が外れている間はほかの窓も操作できうる。これは正本「モーダルダイアログの作法」の「残存リスク」と同じ類として、そこに追記する。

### §6.4 （削除・v0.2）

v0.1 の代替案（「?」のヘルプをモーダルとして重ねる）は、§6.3 の実測で不要になったため削除した。
