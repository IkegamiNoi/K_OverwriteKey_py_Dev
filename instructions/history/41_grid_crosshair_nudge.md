## §1 目的 / 背景

画面の枠で選んだ位置（枠の中心）からクリック位置を少しだけずらしたい。選んだ枠に**十字マーク**（次にクリックする位置）を出し、
**矢印キーでクリック位置をずらせる**ようにする。あわせて、固定だった枠の操作キー（Space / Esc・BackSpace / Enter / Tab）と新しい矢印を
**keymap ごとに好きなキーへ変えられる**ようにする。編集の窓では境界のドラッグ中に、関係する枠の中心へ十字マークを出す。

## §2 確定事項（ユーザー 2026-10-13）

* **十字マーク**: 選んだ枠の中に、次にクリックする位置（クリック点）を十字で示す。
  キーの表示位置が**中央**の keymap では、選んだ枠のキーの文字を十字マークに**置き換える**（左上表示ではキーを残して十字を足す）
* **矢印キーでクリック点を動かす**: 1 回の移動量 = 縦横それぞれ **min(上限 16px, 選んだ枠の幅〔高さ〕の 1/8)**。**Shift + 矢印は 1px**。押しっぱなしのリピートを受ける
* **動かせる範囲は選んだ枠の中だけ**（端で止める）。遠い位置へは枠を選び直す・Space で細分化して選ぶ
* **クリック点は覚えない**: 枠を選ぶ・別の枠を選ぶ・Space・戻る・Tab・クリックで枠の中心へ戻る（Space は選んだ枠そのものを細分化し、ずらした分は捨てる）
* **カーソルもクリック点へ一緒に動かす**
* **矢印キーは枠を選んでいる間だけ suppress**（選択なしでは素通し・アプリのスクロール等に使える）
* **操作キーを keymap ごとに任意化**: 矢印・Space・BackSpace・Enter・Tab を既定値として、好きなキーに変えられる。**各操作のキーは 1 つ**。
  右クリックは独立のキーにせず **Shift + 左クリックのキー**。保存先は keymap の `grid`、設定は「枠を編集…」の窓のパネル
* **固定の追加キー（付け替え不可）**: **Esc = 常に「戻る」**（最上段では素通し・従来どおり）/ **num enter = 常に「クリック」**（Shift と一緒なら右クリック）
* **重なりの扱い**: 「枠を編集…」の OK では、操作キーと枠のキーの重なり・操作キーどうしの重なり・予約キーとの重なりを**拒否**する。
  既存データ・手編集で重なっている場合は拒否・既定戻しをせず、実行時に**枠のキー（枠を選ぶ）を操作キーより優先**する
* **編集の窓の十字マーク**: 境界をドラッグしている間、その境界に関係する枠すべての中心へ十字マークを出す
  （段の境界 = 上下 2 段の全部の枠 / 列の境界 = 左右 2 枠）。離したら消す。細分化のボタンの並びは対象外
* 上限 16px・十字の大きさ・色は固定値（設定にしない）。1 フェーズ（phase 57）でタスクを分けて進める

## §3 用語

* **クリック点**: 選んでいる枠の中で、Enter（左クリックの操作）でクリックする位置。枠を選んだ時点では枠の中心
* **操作**: 枠の表示中にキーへ割り当てる機能。`deepen`（深くする）/ `back`（戻る）/ `click`（クリック）/ `next_screen`（次の画面へ）/
  `up` / `down` / `left` / `right`（クリック点を動かす）の 8 種
* **操作キー**: 操作に割り当てた付け替えできるキー。**各操作に 1 つ**
* **固定の操作キー**: `esc`（back）と `num enter`（click）。付け替えできず、`ops` に持たない

## §4 データ（`grid.ops`）

```json
"grid": {
  "enabled": true, "monitors": {...}, "sub": {...},
  "ops": {"deepen": "space", "back": "backspace", "click": "enter", "next_screen": "tab",
          "up": "up", "down": "down", "left": "left", "right": "right"}
}
```

* `ops` は**任意キー**。無い = 全操作が既定（上の値・ログなし）。dict でない = 全操作が既定（警告ログ）。**操作ごとに独立に正規化**し、不正な操作だけ既定へ戻す（警告ログは keymap ごとに 1 回・戻した操作名を並べる）
  * 不正 = 文字列でない・空・修飾キー（shift / ctrl / alt / windows の左右）・固定の操作キー（`esc` / `num enter`）
  * キー名は `grid_key_name`（trim + 小文字）。未知の操作名は捨てる
  * **操作どうし・枠のキー・設定で変わる予約キーとの重なりでは戻さない**（§5 の優先順位で解決する）
* **保存**: 正規化後に 8 操作すべてが既定と同じなら**書かない**（`label_position` と同じ作法・既存の `grid` を保存し直しても差分が出ない）。
  既定と違えば 8 操作すべてを書く
* 4 経路（`config.py` / `config_service` / `split_loading.py` / `split_payloads.py`）は `grid` を丸ごと `normalize_grid` に通すので、`normalize_grid` が `ops` を扱えば足りる
* **実行時の読み出し**: domain に守りの関数 `ops_of(grid)` を置き、正規化済みの 8 操作（既定で埋めたもの）を返す。セッション・振り分け・編集の窓はこれを使う
* **編集の窓の結果の取り込み**（`keymap_panel_controller.py:494-512`）: 窓の結果は既定と違うときだけ `ops` を持ち、取り込み側は結果に `ops` があれば写し・無ければ `grid` から `ops` を消す（`label_position` と同じ作法）
* **枠のキーの読込時の固定の予約キーは修飾キーだけ**にする（`FIXED_RESERVED_KEYS` は廃止して `MODIFIER_KEY_NAMES` を使う）。enter / num enter / space / esc / backspace / tab は
  操作キー（固定を含む）へ移り、読込時の枠のキーとの重なりは §5 の優先順位で解決する（編集の窓の OK では §8 のとおり拒否する）
  * 受容: アプリで保存し直していない手編集のファイルで枠のキーに space・esc 等を含む形は、これまで既定へ戻っていたが今後は戻らず、その深さでは枠のキーが勝つ（例: 細分化に space があると深さ ≥1 では Space で細分化できない）

## §5 振り分け（枠の表示中）

### 優先順位

1. 停止・トグル・直接切替キー（従来どおり）
2. ctrl / alt / windows 押下中・修飾キー単独は素通し（従来どおり）
3. **今の深さの枠のキー** → その枠を選ぶ（shift + 枠のキーも同じ・従来どおり）
4. **操作キー**（下表）
5. 上記以外は素通し（トリガー・置換は効かない・従来どおり）

* 3 と 4 で同じキーなら 3 が勝つ（その深さではその操作は使えない。別の深さでは使える）。セッションの `handle` は**枠のキーを先に**判定する
* 操作キーどうしが重なっていれば、`deepen` → `back` → `click` → `next_screen` → `up` → `down` → `left` → `right` の順で先のものが勝つ（手編集のときだけ起こる）。
  固定の操作キー（`esc` / `num enter`）は `ops` に入らないので操作どうしで重ならない
* **Shift**: 枠のキー・deepen・back・next_screen は Shift を無視する（従来の「shift + 枠のキー = 枠のキー」と同じ）。Shift が意味を持つのは click（右クリック）と up / down / left / right（1px）だけ
* **何もしない場合はクリック点も変えない**（画面が 1 つのときの next_screen・4px 未満の deepen・最上段の back・選択なしの矢印）

### キーの意味（従来の表を操作で書き直す）

| 操作 | 既定（付け替え可） | 固定 | 意味（従来と同じ部分は §4.7 の表どおり） |
|---|---|---|---|
| 枠のキー | — | — | その枠を選ぶ（強調）+ **クリック点を枠の中心にし**カーソルをそこへ |
| deepen | space | — | 選んでいる枠を今の領域にして 1 つ深くする（ずらしたクリック点は捨てる）。4px 未満なら何もしない |
| back | backspace | esc | 1 つ浅く戻り、細分化した枠を選んだ状態・クリック点はその中心。**最上段では esc は素通し・付け替えたキーは suppress して何もしない**（従来の Esc / BackSpace の差を保つ） |
| click | enter | num enter | **クリック点**（選択なしで深さ ≥1 なら今の領域の中心）で左クリック。**Shift + click のキー（num enter を含む）で右クリック**。後は最上段・選択なしへ |
| next_screen | tab | — | 次の画面へ・最上段・選択なし |
| up / down / left / right | up / down / left / right | — | 選んでいる枠の中でクリック点を動かす（§6）。選択なしでは素通し |

### suppress する集合

* **実効の集合 = 常時の集合 ∪（深さ ≥1 なら {esc}）∪（選択ありなら {up, down, left, right の操作キー}）∪（今の深さの枠のキーのうち、常時の集合から除いたもの）**
  * 常時の集合 = （今列挙されている全画面の最上段のキー ∪ 細分化のキー ∪ {deepen, back, click, next_screen の操作キー} ∪ {num enter}）**−（{esc} ∪ {up, down, left, right の操作キー}）**
  * つまり **esc と矢印の操作キーは、条件（深さ ≥1 / 選択あり）を満たすか、今の深さの枠のキーであるときだけ suppress する**。
    手編集で別の画面・別の深さの枠のキーに esc や矢印があっても、最上段の Esc の素通し・選択なしの矢印の素通しは崩れない
    （その代わり Space 直後の UI 反映前に打った、細分化の枠のキーとしての esc / 矢印はアプリへ届きうる＝手編集のときだけ・受容）
* セッションが状態の変化ごと（`_changed` → `_publish_snapshot`）に実効の集合を計算して `suppress_keys` 1 本で公開する。
  **振り分け（`_route_grid_key`）は `key in suppress_keys` だけを見る**（`esc` の固定分岐と `esc_active` は廃止。「選択あり」の印も持たない）。
  セッションの `handle` も同じ定義に揃え、キー名の固定分岐（enter / tab / backspace / space）を操作キーの引き当てに置き換える（esc・num enter だけは固定の操作キーとして引き当てる）
* UI スレッドの反映前後の 1 打の漏れ・余分な suppress（Space 直後の Esc・枠を選んだ直後の最初の矢印 等）は受容
* esc と矢印の操作キー以外では、操作キーが枠のキーと重なっていても集合は和を取るだけ（どちらでも suppress する）
* キーリピート: 枠のキー・deepen・back・next_screen はリピートを無視、click はリピートでクリックしない（suppress はする）、**up / down / left / right はリピートを受けて動かす**

## §6 クリック点の移動

* 移動量: 横 = `max(1, min(16, floor(枠の幅 / 8)))`・縦 = `max(1, min(16, floor(枠の高さ / 8)))`（px・物理座標）。
  **Shift を押していれば 1**（Shift の判定は Enter と同じく振り分けた時点の物理的な押下）
* 範囲: 選んでいる枠の矩形の中（左上を含み右下を含まない〔`[left, max(left, right-1)] × [top, max(top, bottom-1)]`〕）へ切り詰める。端に着いていれば動かない
  * **幅・高さが 0px の枠**（手編集のごく小さい比率が丸めで 0px になる・`geometry.py` `_boundaries` の `round`）: その向きの範囲は 1 点（`left` / `top`）になり、その向きには動かない。
    選択・クリックは従来どおり（JSON は直さない・実行時の守りだけ）。十字の腕も同じ範囲へ切り詰める（0px の向きの腕は描かれない）
* 動かしたらカーソルを新しいクリック点へ移す（従来と同じ経路・失敗時は §4.7「失敗したとき」どおり畳む）
* 枠の中心 = 従来の `rect_center`（クリック点の初期値もこれ）

## §7 描画

### 枠の窓（表示中）

* 選んでいる枠のクリック点に十字マークを描く。腕の長さ 12px（中心から上下左右）・線幅 2px・色 = 選んだ枠の強調の色（固定値）。
  腕は選んだ枠の矩形の中へ切り詰める
* キーの表示位置が中央の keymap では、**選んでいる枠のキーの文字を描かない**（十字に置き換える）。左上表示では従来どおりキーも描く
* 十字は選択があるときだけ（選択なし・深さ ≥1 で選択なしのときは描かない。深さ ≥1・選択なしの click は今の領域の中心をクリックするが十字は出さない＝受容）

### 編集の窓

* **ドラッグ中** = 境界の上でボタンを押してから離すまで。その間、関係する枠すべての**中心**へ同じ十字を描く（段の境界 = 境界の上下 2 段の全部の枠 / 列の境界 = 境界の左右 2 枠）。
  ドラッグに追従して描き直し、離したときに描き直して消す（今の `on_release` は描き直さないので足す）
* キーの表示位置が中央のときは、その枠のキーの文字を十字に置き換える（ドラッグ中だけ）

## §8 操作キーの設定（編集の窓のパネル）

* パネルに「**操作キー**」の欄を足す: 8 操作それぞれに**キーのボタン 1 つ**と、欄全体の「**既定に戻す**」。固定の操作キー（Esc = 戻る・num enter = クリック）は説明の文字で示す（ボタンにしない）
  * ボタンをクリックして選び、続けて押したキーをそのボタンのキーにする（取り込みの名前は §7.4 のとおりフックと同じ）。
    ボタンを押したらフォーカスを窓のキャンバスへ戻す（細分化のボタンと同じ）。最上段の枠の選択・細分化のボタンの選択とは排他
  * **Esc は従来どおり選択の解除**（操作キーのボタンの選択も解除する。esc は固定の操作キーなので取り込む必要が無い）。選択なしの Esc はキャンセル
  * 選択の解除は従来の経路（画面の切替・既定に戻す・細分化の並びの作り直し・別の選択への移動）でも操作キーのボタンに及ぼす
* 編集した結果は窓の OK で下書きへ入り、編集ダイアログの OK で確定（従来の形の編集と同じ・取り込みは §4）。操作キーは keymap 全体で 1 組（画面ごとではない）
* **OK の検査**（従来の検査に足す・理由とどの操作かを示して拒否し窓を閉じない）:
  * 操作キー: 空 / 操作どうしの重複 / 修飾キー / 固定の操作キー（esc / num enter）/ 設定で変わる予約キー（従来の枠のキーと同じ集合）
  * **枠のキーと操作キー（固定の esc / num enter を含む）の重なり**: 対象は細分化のキー ∪ **今列挙できた画面それぞれの実効の最上段の形**（記録が無ければ既定）∪ **組み込みの既定の形**（今後つなぐ記録の無い画面が使うため）。
    今つながっていない画面の記録は窓で直せないので検査せず、実行時の優先順位に任せる
  * 枠のキーの検査の固定の予約キーは修飾キーだけになり、代わりに上の「操作キーとの重なり」で拒否する
* **自動割当・振り直し**は今の操作キーと固定の操作キーを飛ばす（固定の予約キーの代わり）

## §9 受け入れ条件（ドラフト）

1. 枠を選ぶと十字マークが枠の中心に出る。中央表示ではその枠のキーの文字が消え、左上表示では残る（§7）
2. 選択ありで矢印を押すとクリック点とカーソルが移動量どおり動き、Shift+矢印で 1px、枠の端で止まる。リピートで連続して動く（§6）
3. 選択なしの矢印はアプリへ届く。選択ありの矢印は届かない。手編集で細分化・別の画面にだけ esc / 矢印の枠のキーがあっても、最上段の Esc・選択なしの矢印はアプリへ届く（§5）
3a. 丸めで幅・高さ 0px になる枠を選んでも、矢印でクリック点が枠の外へ出ない（§6）
4. Enter / Shift+Enter がずらしたクリック点で左 / 右クリックする。選び直し・Space・戻る・Tab・クリックの後は中心へ戻る（§2・§5）
5. 操作キーを変えた keymap で、新しいキーで全操作が効き、元のキー（素通し対象になったもの）はアプリへ届く（§5）
6. 編集の窓で操作キーを設定・既定に戻せる。OK の検査が §8 の重なりを拒否する（§8）
7. `ops` の無い・既定と同じ `grid` は読込・保存で差分が出ない。不正な操作は操作ごとに既定へ戻る。手編集で枠のキーと重なった操作キーは枠のキーが勝つ（§4・§5）
8. 編集の窓で境界をドラッグ中、関係する枠の中心に十字が出て、離すと消える（§7）
9. 既存のテスト（compileall / tests / tests_ui / smoke）が通る。ただし固定の予約キー（enter / space 等）で既定へ戻る・「固定予約」の文言を期待するテスト
   （`tests/test_screen_grid.py` の該当箇所）は、本書 §4・§8 に合わせて「修飾キーだけ」「操作キーとの重なり」の検査として書き換える
