## §1 目的 / 背景

key_hold で押したままにした**通常キー（`a` 等）を、離すまでキーリピートさせる**。
今は押下（keydown）を 1 回送るだけで、Windows は合成入力にタイプマティックリピートを付けないため、メモ帳等の文字入力では 1 文字しか入らない。
押している間、OS のキーボード設定と同じ間隔で keydown を送り直し、実キーボードの長押しと同じ連続入力にする。
**application（リピートのタイマー）・infrastructure（OS のリピート設定の取得）・presentation（ダイアログのチェック・配線）・domain（判定・書式）。JSON に key_hold の任意キーを 1 つ追加（後方互換）。**

### 現状監査（2026-10-11・メイン実測 + 起票時 deep-reviewer）

## §2 確定事項（ユーザー 2026-10-11）

1. **リピートの間隔は OS の設定に合わせる**（Windows のキーボード設定「表示までの待ち時間」「表示の間隔」。アプリに間隔の設定 UI は作らない）
2. **対象は修飾キー以外**（shift / ctrl / alt / windows は左右ともリピートしない。押されている状態だけで効くため）
3. **key_hold の押す行（キーボード）に「リピートする」チェックボックス**を置き、行ごとに JSON へ保存する
4. **新しく作る行は ON・キーの無い既存の行は OFF 扱い**（phase 51 で作った行の挙動を変えない）
5. **リピートは同時に 1 つだけ・最後にリピートを始めたキー**（実キーボードと同じ・案 A）（v0.3）
6. **一覧ではリピートする押す行に ` (リピート)` を付ける**（v0.3）
7. **エラーの知らせのダイアログを出す前にリピートを止める**（押したままは保つ・再開しない）（v0.3）
8. **知らせのダイアログを出している間はリピートを一切しない**（開始・text の後の再開・送り直しをすべて断る。入れ子対応。表示中に断った開始は閉じた後も復活させない。押す自体は送る）（v0.4・確定前の Codex 敵対的 high。表示中もフック・連続実行・予約済みの入力は動くため）
9. **リピートの対象のキーを含む hotkey・直接置換を送る前にリピートを止める**（その送信の終わりで OS 上は離れるため。押したままの記録は phase 51 どおり残す・含まない送信は触れない）（v0.4・確定前の Codex 敵対的 medium）

## §3 データモデル（JSON）

key_hold（`data_schema.md` §5.11.9）に任意キーを 1 つ追加:

| キー | 型 | 意味 |
|---|---|---|
| `repeat` | bool | **キーボードの押す行だけ**で意味を持つ。`true`（bool）のときだけリピートを求める。キー無し・`false`・非 bool（文字列 `"true"`・数値を含む）は求めない |

- 例: `{"type": "key_hold", "edge": "down", "value": "a", "repeat": true, "label": ""}`
- 読込の正規化はしない（他の key_hold のキーと同じく実行時に判定。`normalize_actions` は未定義キーを保持する）。**`repeat` の型不正は実行時エラーにしない**（求めない扱い・押すは送る。リピートは付加機能で、押す / 離すの安全側の動作は変わらないため）
- 離す行・マウスの行・修飾キーの押す行の `repeat` は無視する（エラーにしない）
- 旧版アプリは `repeat` を未定義キーとして無視する（リピートしないだけ）

## §4 実行

### 4.1 用語と対象
- **リピートが有効な押す行** = キーボードの押す行で、`repeat` が `true`、かつキーが修飾キーでない（§4.6）もの
- リピートの対象は**同時に 1 つだけ**（§2-5）。実キーボードと同じく、最後にリピートを始めたキーだけがリピートする

### 4.2 開始・切替
- **リピートが有効な押す行の送信が成功したら**、そのキーを「リピートの対象」にして**待ちからリピートを始める**（前の対象があればそのリピートは止める。前のキーの押したままは保つ。後のキーを離しても前のキーのリピートは再開しない＝実キーボードと同じ）
- **それ以外の操作は今のリピートに触れない**: `repeat` が `false`・無しの押す行（別のキー）、修飾キーの押す行、マウスの押す / 離す、リピートの対象のキーを含まない hotkey・直接置換
- 例外: **今のリピートの対象と同じキーの押す・離すの送信**は §4.3 のとおり（同じキーを `repeat` が無い行で押し直すとリピートは止まる）

### 4.3 止める場所（1 本の規定）
- **今のリピートの対象のキーについて、押す・離すの送信を始める前に、必ずリピートを止める**（予約を取り消す）。経路を問わない:
  離す行 / 自動で離す（phase 51 §5 の表のすべて・`release_owner` / `release_all` / `release_keyboard`）/ text の前の一時的な離す（`suspend_keyboard`）/ 同じキーの押す行・押し直し（`_press`）/
  **リピートの対象のキーを含む hotkey・直接置換**（§2-9。`HeldInputs` を通らない送信なので、`ActionExecutor` の hotkey・直接置換の送信の前に、送るキーのどれかが対象と同じキー〔phase 51 の同じキーの判定 = スキャンコード + 拡張フラグ〕なら止める。止めた後は再開しない）
- その後、**押すが成功し、その押すがリピートが有効な押す行によるもの**なら、§4.2 で改めて待ちから始める。離す・失敗・それ以外の押すなら止まったまま
- これにより、離す送信の失敗で集合に残ったキー・押すの補償の離すの失敗で残ったキーもリピートしない（OS 上の状態が分からないため送り直さない。次の自動の解放で離すを送り直すのは phase 51 のとおり）。アプリの終了（`release_all`）でも予約は残らない

### 4.4 text / file_line の前後
- 送る前の `suspend_keyboard` で §4.3 により止まる。送り終えた後の `resume_keyboard` の押し直しは**リピートの切替に数えない**（§4.2 の対象を変えない）
- 押し直しが成功したら、**text の前にリピートの対象だったキー（止める前に対象だったもの）だけ**を待ちからやり直す。それ以外のキーの押し直しではリピートを始めない
- 送信の失敗で押し直さない場合（phase 51 §4.4）は再開しない

### 4.5 送り直し
- 「表示までの待ち時間」の後に 1 回目、その後「表示の間隔」ごとに keydown を送り直す（`press_key` と同じ送信経路・send_guard の中・keyboard の記録に載せない）
- 送り直しは **UI スレッドの予約（`after`）**で行う。別スレッドは使わない。**`after` が注入されていなければリピートしない**（押すは送る）
- 送り直しは集合の記録（持ち主・順序）を変えず、**押下中の表示の更新も起こさない**
- 間隔は**リピートを始める時点で OS から読む**（§6 の換算）。途中で OS の設定を変えても、次に始めるまでは前の値
- **遅れても追いつくための連打はしない**（Tk の `after` の精度〔約 15.6 ms〕・UI スレッドの詰まりで間隔は伸び得る。次の予約は送り直しの後に「表示の間隔」で取る）
- **古い予約の発火**: 予約ごとに世代番号を持ち、発火時に今のリピートの対象・世代と合わなければ送らずに終える

### 4.6 修飾キーの判定
- 修飾キー = keyboard の `all_modifiers` の名前と、検査を通る別名（`control` / `left control` / `right control` / `win` / `left win` / `right win` / `cmd` / `left cmd` / `right cmd` / `altgr` / `option` / `left option` / `right option` 等。実装時に keyboard の `_canonical_names` の別名表から修飾キーに当たるものを洗い出して列挙する）
- 判定は domain に 1 関数で置く（キー名を trim + 小文字にして集合で引く。domain は keyboard に依存しない）

### 4.7 送り直しの失敗
- 送り直しの送信が例外になったら、**リピートを止め**、そのキーに離すを送る（成功したら集合から外す・失敗なら残す＝phase 51 §2-22）。エラーを知らせる（リピートを始めた行の action で・既存の送信エラーの知らせの口）
- 実行中のトリガーは止めない（リピートは実行の外で動くため。押す行の時点では送れていた）

### 4.8 知らせのダイアログとリピート（§2-7・§2-8）
- エラーの知らせ（モーダル）を出す前に**リピートを止める**（押したままは保つ・閉じた後も再開しない）。`enter` / `space` 等のリピートがダイアログを即座に閉じるのを防ぐ
- 対象: ActionExecutor・runner・フックの各エラーの知らせの口（`show_action_error` 等。知らせる前の 1 か所で止める）
- **表示中の抑止**（§2-8）: 知らせを出している間（入れ子は数で数える）は、リピートの開始（§4.2）・text の後の再開（§4.4）・予約の発火（§4.5）をすべて断る。発火した予約は送らずに終える。表示中に断った開始は閉じた後も復活させない（押す・押し直し自体は従来どおり送る）。表示中もフック・連続実行・予約済みの入力は動く（既存）ため、次の key_hold 行の開始もここで断る

### 4.9 自分の送信とフック
- 送り直しは send_guard の中で送るため、トリガー・直接置換の判定には入らない（phase 51 §6 と同じ）。確認して実行の長押しの無視（`features.md` §4.2.11）にも影響しない
- **リピート中は send_guard / replay の時間が毎秒数十回生じ、その一瞬に届いた物理入力（停止キー・トリガー・離す等）を取りこぼす頻度が上がる**＝受容（既存の性質の頻度が上がるだけ。1 回の送信は一瞬）。実機目視で停止キー等が効くことを確かめる（§8）

## §5 UI

- **アクション編集ダイアログ**の key_hold の入力欄に「**リピートする**」チェックボックスと「（修飾キーは除く）」の注記を足す。**「押す」かつ「キー」のときだけ表示**（離す・マウスのボタンでは隠す。動作のコンボ・対象の切替で表示を切り替える）
  - **ON で始まる場合**: 新しく作る行 / 別の種類の行を key_hold に変えた場合 / 既存の key_hold の離す行・マウスの行を押す + キーに変えた場合（いずれも「このダイアログで初めて押す + キーになった」とき）
  - 既存の key_hold の押す + キーの行を開いたら `repeat` が `true` のときだけ ON
  - OK 時: 押す + キーの行は `repeat` を常に書く（`true` / `false`）。離す・マウスの行には書かない（既存のキーがあれば消す）。**`action_dialog.py` の組み直しで `repeat` を引き継ぐ**
  - キー名が修飾キーのときもチェックは操作できる（実行時に無視・§4.6）
- **一覧の書式**（§2-6）: リピートが有効な押す行（`repeat` が `true`・押す・キー・修飾キーでない・行として正しい）は `[押す] a (リピート)`（括弧は座標の表記 `(100, 200)` に合わせて半角）。それ以外・不正な行の `[key_hold] …` には付けない。フル表示・省略表示・呼び出し先の表示枠で同じ（domain の書式関数 1 か所）
- 押下中の表示（ステータス欄）は変えない

## §6 責務の置き場（実装の方針）

- **OS のリピート設定の取得** = infrastructure（`InputGateway` に 1 つ）。`SystemParametersInfoW`（`SPI_GETKEYBOARDDELAY` = 0x16・`SPI_GETKEYBOARDSPEED` = 0x0A。UINT / DWORD で受ける）。
  **換算**: 待ち = 250 × (n + 1) ms（n = 0〜3）/ 間隔 = round(1000 / (2.5 + n × 27.5 / 31)) ms（n = 0〜31。n = 0 → 400 ms・n = 31 → 33 ms）。範囲外の値・取得失敗・Windows 以外は既定値（待ち 500 ms・間隔 33 ms）
- **リピートのタイマー** = application の小さなクラス（例: `application/key_repeat.py` の `KeyRepeater`。対象は高々 1 つ）。`after` / `after_cancel`・送り直しの送信・知らせの口（`on_repeat_error(action, message)`）を注入で受ける。
  `HeldInputs` は押す・離すの送信の前後で `KeyRepeater` の「止める」「始める（action を渡す）」「text の前後の控え / やり直し」を呼ぶだけ（タイマーの状態は `HeldInput` の記録に入れない＝表示の更新を起こさない）
- **判定と書式** = domain（`key_hold.py`: `repeat` の判定・修飾キーの判定・一覧の書式）
- `ActionExecutor._execute_key_hold` はリピートが有効かを判定し、action とともに `HeldInputs.press_key` へ渡す。`ActionExecutor` の hotkey・直接置換の送信の前に、対象のキーを含むかを判定して止める（§4.3・同じキーの判定は gateway の `key_identity`）。
  知らせの前に止める口と表示中の抑止（§4.8）は、presentation の知らせの口（`show_action_error` 等）から `KeyRepeater` の「抑止を始める / 終える」を呼ぶ（入れ子は数で数える）
- ダイアログ = `dialogs/action_key_hold_fields.py`（チェック・表示の切替）・`dialogs/action_dialog.py`（組み直しで `repeat`）。App の配線 = `app.py`（`KeyRepeater` に `after` / `after_cancel`・間隔の取得・知らせの口を渡す）

## §8 受け入れ条件（ドラフト）

自動テスト（偽の gateway と偽の `after` で送信と予約を記録）:
1. リピートが有効な押す行（`a`）で、待ちの後に 1 回・以後間隔ごとに keydown を送り直す。離す行で止まり、以後送らない（§4.2・§4.5）
2. `repeat` 無し・`false`・非 bool の押す行はリピートしない。修飾キー（`shift` / `right ctrl` / 別名 `control` / `win` 等）は `true` でもリピートしない（§3・§4.6）
3. phase 51 §5 の自動で離す各入口で止まる。離す送信が失敗して集合に残ったキー・押すの送信と補償の離すがともに失敗したキーもリピートしない（§4.3）
4. text の送信の間は止まり、押し直した後に**元の対象だけ**が待ちからやり直す。止まっていたキー・他のキーは再開しない。送信の失敗では再開しない（§4.4）
5. 案 A の切替: 別のキーのリピートが有効な押す行で切り替わる。`repeat` 無しの押す行・修飾キー・マウス・対象を含まない hotkey では切り替わらない。同じキーを `repeat` 無しで押し直すと止まる。対象を含む hotkey（`ctrl+a`）・直接置換（`a`）を送る前に止まり、再開しない（§4.2・§4.3）
6. 送り直しの例外でリピートが止まり、離すを送り、エラーを知らせ、実行中のトリガーは止まらない（§4.7）
7. 古い予約の発火では送らない・`after` が無ければリピートしない・送り直しで表示の更新が呼ばれない（§4.5）
8. OS の設定値からの換算（n の両端と中間）・範囲外 / 取得失敗の既定値（§6）
9. 知らせのダイアログの前にリピートが止まる。表示中はリピートの開始（runner の次の key_hold 行・予約済みのトリガーから）・text の後の再開・予約の発火をしない。閉じた後も表示中に断った開始は復活しない（§4.8）
10. ダイアログ: 押す + キーのときだけチェックを出す（動作・対象の切替で表示が変わる）・ON で始まる場合（新規・別の種類から・離す / マウスから）・既存のキー無しは OFF・保存で `repeat` を書く / 消す・組み直しで保たれる。一覧の書式（§5）
11. 既存テスト（tests / tests_ui / smoke）が通る

実機目視（ユーザー・ホスト OS）:
12. メモ帳で `[押す a (リピート), 待機 2000ms, 離す a]` を実行すると、実キーボードの長押しと**おおむね同じ速さ**（見比べて明らかな差が無い）で `a` が連続して入り、離すで止まる
13. 押したままの状態でフック停止・ダイアログを開く・アプリ終了のそれぞれでリピートが止まる
14. `[押す shift, 押す a (リピート), …, 離す a, 離す shift]` で大文字の `A` が連続して入る
15. リピート中に物理の停止キー・トリガーが効く（§4.9）。リピート中にエラーの知らせが出たときに止まる（§4.8）

## §9 スコープ外（本フェーズでやらない）

- マウスのボタンの連打（オートクリック）
- アプリ独自のリピート間隔の設定（OS の設定に合わせる・§2-1）
- 修飾キーのリピート（§2-2）
- 複数のキーの同時リピート（案 A の場合）
- 物理キーボードの押下とリピートの協調（ユーザーが同じキーを物理で押した場合等）
- IME 系のキー（半角 / 全角・かな・変換等）の除外（リピートすると IME の状態が高速で切り替わり得る。チェックを外せば避けられる＝受容）
