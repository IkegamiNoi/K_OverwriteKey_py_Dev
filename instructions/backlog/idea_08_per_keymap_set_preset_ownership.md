# idea_08_per_keymap_set_preset_ownership.md

## 概要

**hotkey プリセットを「keymap_set ごとの持ち物」として個別に持てるようにする機能。**
保存系リデザインでは、プリセットを**アプリ全体で共有するライブラリ**として `config/config.json` の
グローバル参照へ移す方針（案2・別フェーズ）だが、それとは別に「この構成セット専用のプリセット」を
持ちたい需要があるため、上書き（個別指定）の仕組みを将来機能として分離する。

## 起票経緯（2026-07-27）

保存系リデザインの設計討議（ユーザー要望 2026-07-26〜27）で、プリセットの扱いについて
「アプリ全体で共有するライブラリが近い（→ config.json グローバル化＝案2 を採用）」「keymap_set ごとの
持ち物は別途機能追加が良いので idea 化」とユーザーが判断（P-a の回答）。その「別途機能」分を本 idea に切り出す。

## 現状

- プリセットは keymap_set が `hotkey_presets_path` で参照し、実体は固定
  `config/user/hotkey_presets/default.json`（`config_service.py:22` `HOTKEY_PRESETS_RELATIVE_PATH` /
  `:592` で keymap_set へ相対/絶対パスを保存）。keymaps/sequences のような個別保存ボタン・source_path・
  dirty 管理は持たず、**カスケード保存時に固定ファイルへ書かれるだけ**の半共有ファイル。
- 保存系リデザインの別フェーズ（暫定 07 予定・案2）で、この参照を **config.json のグローバル既定プリセットへのパス**へ
  移し、全 keymap_set が共有する形にする予定。

## 提案（方向性・要設計）

- グローバル既定プリセット（案2）に対し、**keymap_set 側で個別プリセットを指定できる上書き機構**を用意する
  （点5 の「停止/トグルキーの個別指定」と同型のパターン: グローバル既定 + 個別指定フラグ）。
- UI 起動口・個別指定の持ち方（フラグ + パス）・グローバル/個別の解決順序は着手時に詰める。
- 案2（グローバル化）の設計と整合させる必要があるため、**案2 の確定後に着手**する。

## 想定スコープ

- 含む: keymap_set ごとの個別プリセット指定（上書き）機構・UI・解決順序。
- 含まない: プリセットのグローバル化そのもの（=案2・別フェーズ）/ プリセット編集 UI の刷新。
- 影響レイヤ: presentation + application（プリセット解決） + スキーマ（keymap_set に個別指定フラグ追加・後方互換）。
- 仕様変更: あり（新機能 + スキーマ追加）。**前提: プリセット config.json グローバル化（案2・暫定 07 予定）の完了**。優先度: 低。
