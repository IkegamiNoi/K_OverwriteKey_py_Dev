# idea_34_focus_restore_after_minimize.md

## 概要

モーダルダイアログを開いたままアプリを最小化し、復元すると、**モーダル性（grab）はダイアログへ戻るが
キーボードフォーカスはメイン窓に残る**。そのためクリックしない限り**ダイアログ上で Escape が効かない**。
**復元時にフォーカスも最前面（最内）の表示中モーダルへ戻したい**。

## 起票経緯（2026-09-23）

phase 28 task_05 の実機目視 C②（暫定仕様 [22](../history/22_dialog_keyboard_focus.md) §8-10 の
フォーカス復帰の再現確認）で**再現**。§2.1-4 / §3.1-5 / §11 で「フォーカス復帰はスコープ外・
再現したら idea 化」と確定済のため起票した。ユーザーは「復帰時にフォーカスも最前面のダイアログへ
合わせる仕様」と認識していたが、既存仕様が戻すのは grab のみだった。

## 現状

- `keyseq/presentation/modal.py:33-59` `return_custody`（`install_minimize_grab_custody` 内・App の `<Map>`）は、
  預かった窓（無ければ台帳 `_active_modals` の最内の表示中モーダル）へ **`grab_set()` だけ**を行い、
  `focus_set()` はしない。
- 預かりが空（最小化で隠れなかった保持者）の場合は復元時に何もしない。
- 正本 `spec_detail/features.md` §4.6 の最小化条項（`:187-202`）は「**復元後もモーダル性は戻る**」のみで、
  フォーカスは規定していない。
- 初期フォーカスは phase 28 で `grab_modal` の責務になった（`modal.py:65` `_apply_initial_focus`）が、
  **モーダル化の時点のみ**を規定（暫定仕様 22 §3.1-5）。

## 提案（方向性・要設計）

- 案 A: `return_custody` で grab を戻した窓へ、**その窓の最後のフォーカス先**（`focus_lastfor()`）を
  `focus_set()` する。預かりが空の経路でも、表示中の最内モーダルへ同様に戻すかを決める。
- 案 B: 各モーダルの `<FocusIn>` / App の `<FocusIn>` で「grab 保持者の外にフォーカスが来たら保持者へ戻す」。
  最小化以外（Alt+Tab での復帰等）も拾えるが、結線が広がる。
- 制約: 暫定仕様 22 §3.1-4 の方針に合わせ **`focus_force` / `lift` は使わない**（アプリ内の
  `focus_set` で足りる見込み。復元直後はアプリが OS フォーカスを持つ前提だが要実測）。
- 着手時はまず実測: 復元直後の `focus_get()` の値 / `<Map>` 時点でアプリが OS フォーカスを持つか /
  `focus_set` を `<Map>` 内で即時に行うか `after_idle` へ回すか。

## 想定スコープ

- 含む: 最小化 → 復元時のフォーカス復帰（presentation 層 `modal.py` のみの見込み）。
  正本 `features.md` §4.6 へ条項追加（**仕様変更あり**）。
- 検討: 内側ダイアログを閉じた後の外側へのフォーカス復帰（phase 28 目視 C①。暫定仕様 22 の probe 3 では
  外側へ戻ったが、実機で再現した場合は本 idea へ合流させる）。
- 含まない: OS レベルの窓アクティブ化、stdlib ダイアログ（`messagebox` 等）が開いている間の最小化。
