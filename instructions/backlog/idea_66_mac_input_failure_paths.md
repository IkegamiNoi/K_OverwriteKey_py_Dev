# idea_66_mac_input_failure_paths.md

## 概要

**macOS の入力の失敗経路で、押下の記録が残る・入力が黙って消える弱点を直す**（phase 75 の完了判定前の Codex 敵対的レビューの 5 件）。どれも稀な失敗経路で Windows には影響しない。直すときは Mac 実機で再現と確認をする。

## 起票経緯（2026-11-22）

phase 75 task_14（正本反映）のフェーズ完了判定の Codex 敵対的レビュー（needs-attention・high 2 / medium 3）。メインが ①②④ をコードで裏付け。ユーザー判断「idea に起票して phase 75 は完了扱い」（`decisions_archive/75_mac_support.md`）。

## 現状

1. **［high・裏付け済み］修飾キーの離しの送信失敗**: `macos/backend.py:239-264` の `_send` は、送信に失敗すると `_sent_modifiers` を送信前の状態へ戻す。修飾キーの down が成功した後に up の送信だけが失敗すると、その修飾キーは「送信側で押している」記録に残り、以後の物理キーに付く（ショートカットになる）。この一時の押下は `HeldInputs` に載らず、フックの停止の `release_all` でも離れない。
2. **［high・裏付け済み］tap の再有効化と上位の押下状態**: `macos/event_tap.py:193-194` の無効化の知らせでは tap 内の修飾の状態だけを消し、`KeyStateManager`（`InputRouter` が見る押下状態）には伝えない。無効化中に離した修飾キーが上位では押されたまま残り、カーソルグリッドの素通しやリピートの判定がずれる。正本 `key_input.md` §7.9「押下状態を掃除する」と食い違う。
3. **［medium・設計］キュー版の排出がモーダルで止まる間の期限切れ**: `presentation/hook_dispatcher.py:108-134`。受け付けた時点でフックは元のキーを抑止するので、排出がエラーダイアログで止まっている間に 1.0 秒を過ぎた置換・キーの記録は、元の入力も結果も失われる（`on_discard` が無い・64 件に達しなければ過負荷の知らせも出ない）。
4. **［medium・裏付け済み］2 つ目のマウスボタン**: `macos/backend.py:405` の `mouse_up` はボタンを問わず `MouseHoldTap` を止める。左を保持したまま右を押して離すと、左の保持中の移動がドラッグに変換されなくなる（正本 `features.md` §4.8「保持中の移動」と食い違う）。
5. **［medium・設計］配布ビルドの版の照合**: 両 OS の `.spec` は決まった名前のアーカイブをコピーするだけで、PyInstaller が実際に収集した `mouseinfo` / `pynput` の版・Python / Tcl / Tk の版と `third_party.json`・`sources/` を照合しない（`tests/test_third_party.py` が `.venv` の版と表を照合するのが今の唯一の網）。

## 提案（方向性・要設計）

- 1: 送信側の一時の押下を、離しが成功するまで記録して、フックの停止・終了で離し直す。
- 2: 再有効化の後、振り分けを再開する前に上位の押下状態も消す（同期できないなら既存の障害の停止の経路に乗せる）。
- 3: 排出を止めるモーダルに入る前に新しい入力を素通しにする / 抑止済みの入力が期限切れになったら停止と取りこぼしを知らせる（暫定仕様の改訂が要る）。
- 4: ドラッグに変換するボタンを覚え、そのボタンの up だけで止める。複数のボタンの保持の規則を決める。
- 5: ビルドの前に収集物の版を対象 OS の表と照合し、sdist を版のハッシュで照合する（`packaging/`）。

## 想定スコープ

- 含む: `os_backend/macos/`・`presentation/hook_dispatcher.py`・`packaging/`・それぞれのテスト。
- 3 は §7.9 のディスパッチャの規則の変更（暫定仕様先行）。1・2・4 は正本どおりに実装を直す。
- Mac 実機での再現と確認が要る。
