# idea_44_screen_grid_colors.md

## 概要

**画面の枠（phase 56）の配色を見直す**: 枠の線・キーの文字・選んだ枠の強調・左上表示の文字の下地の色の組み合わせ。
明るい画面・暗い画面のどちらの上でも見分けやすい組み合わせを探す。

## 起票経緯（2026-10-13）

出所: phase 56 task_06b の実機目視でのユーザーの指摘（「色の組み合わせはまだ考える余地がある」）。
文字の大きさと下地は同じ目視で決めた（暫定 40 v0.7 §7: 左上 = UI フォントの大きさ + 暗い下地・中央 = 下地なし）。

## 現状

- 色は固定値（設定にしない・暫定 40 §7・§12）
- 枠の窓 `keyseq/presentation/screen_grid/grid_overlay_window.py`（線 `#66d9ef`・選択 `#ffcc66`・段 ≥1 の外側の暗く `#202028` + stipple）
- 文字の描画 `keyseq/presentation/screen_grid/cell_label.py`（左上の下地 `LABEL_BACKING = #14141c`）
- 編集の窓 `keyseq/presentation/dialogs/grid_editor_window.py`（半透明の背景 `#202028`・線と選択の色は枠の窓と同系）
- 透過色 `#ff00fe` と重なる色は使えない

## 提案（方向性・要設計）

- 案 A: 固定のまま組み合わせだけ見直す（線を 2 色の縁取りにする・文字を白 + 下地を半透明風の濃い色 等）
- 案 B: 配色を少数のプリセット（明るい背景向け / 暗い背景向け）から keymap ごとに選べるようにする（暫定 40 §12 のスコープ外の解除になる）
- どちらも実機（明るいアプリ・暗いアプリ・動画等の上）で見比べて決める

## 想定スコープ

- presentation のみ（案 B なら keymap の `grid` に任意キーが増える = JSON スキーマ変更）
- 枠の操作・形・保存の挙動は変えない
