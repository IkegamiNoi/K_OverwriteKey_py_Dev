# idea_22_full_view_min_height.md

## 概要

**フル表示のウィンドウに縦方向の最小サイズを設ける**。目安は**各一覧の既定の高さの半分**（ユーザー案）。

## 起票経緯（2026-09-17）

出所: phase 18 task_05 の実機目視（ユーザー）。暫定仕様 16 §6 で縦方向のサイズ変更はスコープ外としたため分離。

## 現状

- phase 18 の `wm minsize` は**幅だけ**を制約し、高さは 1（暫定仕様 16 §3-4 / `controllers/pane_layout_controller.py`）。
- 一覧の既定の高さ: キーマップ管理・トリガー一覧 = `Listbox(height=12)`（`keymap_box.py` / `trigger_box.py`）、
  出力シーケンス = `Listbox(height=18)`（`sequence_box.py`）。phase 18 で 3 つとも縦にも伸びるようになった。
- 初期 geometry は `780x820`（`app.py:90`）。

## 提案（方向性・要設計）

- 最小の高さ = ヘッダの要求高さ + 各枠で「一覧を既定の行数の半分（6 行 / 9 行）にしたときの要求高さ」の最大 + 余白。
  フォント設定ごとに再計算する（幅と同じ更新契機に乗せる）。
- 省略表示では適用しない（幅と同様に切替時に解除）。

- presentation のみ。JSON の変更なし。
- 暫定仕様 16（または昇格後の正本 `features.md` §4.6）の改訂が要る → 仕様変更フロー。phase 18 の幅コントローラの拡張になる見込み。
