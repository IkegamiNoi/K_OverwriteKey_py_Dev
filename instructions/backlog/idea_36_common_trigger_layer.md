# idea_36_common_trigger_layer.md

## 概要

トリガー一覧をキーマップ従属にした後、**どのキーマップでも有効な共通トリガー**を持てるようにする。
**共通トリガー + キーマップ別トリガーの 2 層構成**にし、キーマップごとに同じトリガーを複製しなくて済むようにする。

## 起票経緯（2026-09-24）

出所: 設計議論からの分離。トリガー一覧のキーマップ従属化（phase 34 予定）の検討で、
共通トリガー層は「現時点では不要・後で欲しくなる可能性がある」とユーザー判断（2026-09-24）。起票のみ。

## 現状

- 現在はトリガー一覧が構成セットに 1 つ（keymap_set の `trigger_set_path`・`data_schema.md` §5）。
- phase 34 でトリガー一覧をキーマップファイル側の参照へ移し、キーマップごとに持たせる予定（共通層は作らない）。

## 提案（方向性・要設計）

- 構成セット（keymap_set）に共通トリガー一覧の参照を持たせ、アクティブキーマップのトリガー一覧と併せて判定する。
  **参照は新キー（例: `common_trigger_set_path`）で持つ**。既存の `trigger_set_path` は phase 34 で
  「旧形式の読込元（移行用）」の意味に据え置くため、共通用へ転用しない（意味変更禁止・未移行ファイルとの混同回避）。
- 要設計: 共通とキーマップ別でキーが重なった場合の優先 / 登録時の重複禁止範囲 /
  置換元キーとの重複（キーマップ別では置換優先の予定）/ 共通トリガー側のシーケンスの持ち方 /
  トリガー一覧 UI での 2 層の見せ方。

## 想定スコープ

- 含む: データ構造（keymap_set 側の参照追加）・入力判定・トリガー一覧 UI・保存カスケード。
- 含まない: phase 34 のキーマップ従属化そのもの。
- 仕様変更あり（data_schema / key_input / features）。着手時は暫定仕様先行モード。
