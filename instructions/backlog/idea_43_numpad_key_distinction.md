# idea_43_numpad_key_distinction.md

## 概要

**テンキー（numpad）のキーを主キーボードのキーと区別する**。入力の判定（トリガー・直接置換の元・切替キー・停止キー等）・出力（hotkey・key_hold・直接置換の先）・記録・表示（キー取得・一覧・キーボード表示）のすべてで区別する。
既存設定の `1` 等は**主キーボードだけ**を指し、テンキーは新しい名前で書く（テンキーで反応していた既存の設定はテンキーで反応しなくなる）。

## 起票経緯（2026-10-11）

ユーザー要望（phase 53 完了後に次フェーズとして希望）。対象の範囲と既存設定の扱いは 2026-10-11 にユーザーが選択。

## 現状

- テンキーの `1` と主キーボードの `1` は同じ名前 `1` として扱われる（入力・出力・記録とも）
- 正本 `key_input.md` §7.7 の拡張キーの規定は「名前で区別できないテンキーの Enter・`/` は対象外（名前は主キーボード側のキーを指す）」
- 詳細は起票前の現状監査（codex-explorer）で暫定仕様書に記載する

## 提案（方向性・要設計）

- テンキー用のキー名（例: `num 1` / `num enter` / `num /`）を定め、フックで受けたキーをスキャンコード + 拡張フラグ（または keyboard の `is_keypad`）で区別する
- 送信はテンキーのスキャンコード / VK で送る
- NumLock オフ時のテンキー（矢印・home 等として届く）の扱い・重なり判定・名前の検査・キーボード表示の配置を決める

## 想定スコープ

- domain（キー名・正規化）・application（入力の判定・重なり）・infrastructure（送信）・presentation（記録・表示）
- 既存設定の意味の変更（`1` が主キーボードだけになる）を伴う。JSON の形は変えない見込み（キー名の値が増える）
- 暫定仕様先行の見込み
