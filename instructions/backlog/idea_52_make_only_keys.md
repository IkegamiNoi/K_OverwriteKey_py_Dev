# idea_52_make_only_keys.md

## 概要

**押下だけが続けて届き、離しが届かないキー（例: 無変換 = 走査コード 241・変換 = 242）をフックで扱えるようにする**。
今は 2 つの不具合が起きる。
- 2 回目の押下が送信ガードの最中に届いて OS へ素通りする（IME が切り替わる）
- 3 回目の押下で再び置換して二重送信になる。押下状態にも残る

あわせて、こうしたキーをレイアウトで名前付けするための「受け取り用の追加の走査コード」（暫定 45 §3.1 の `extra_scan_codes`・v0.5 で取り下げ）を設計し直す。

## 起票経緯（2026-10-18）

phase 62（idea_49・暫定 45）の実機目視から分離した。
- jis.json の無変換・変換が効かなかった。実測すると、フックには 241 / 242 で届いていた
- `extra_scan_codes` を足す task_03b を実装したが、二重送信と IME の素通りが起きた
- そこで低レベルフックの生の値を測り、押下だけが続けて届くと分かった。ユーザー判断 A で task_03b を戻し、本 idea へ分離

## 現状（2026-10-18 実測・Windows 11・JIS）

* 無変換: `DOWN vk=0x1A(VK_IME_OFF) scan=241 ext=1` が約 60 ms の間に 3 回。UP は無い
* 変換: `DOWN vk=0x16(VK_IME_ON) scan=242 ext=1` が 3 回。UP は無い
* 半角/全角: `UP vk=0xF4 scan=41` → `DOWN vk=0xF3 scan=41`（もとから変わった順）。かな = 112
* 環境:
  * MS-IME のキーの割り当てはオフ
  * `HKLM\...\Keyboard Layout` に `Scancode Map` は無い
  * キーを置き換える常駐ツールは無い
  * i8042prt は `PCAT_106KEY` / `kbd106.dll`
  * キーボード本体が LANG2 / LANG1（HID）として送っている見込み（未確認・機種は未確認）
* 関連コード:
  * 送信ガード中は素通り: `application/input_router.py:88-90`
  * リピートの判定: `input_router.py:96`
  * 押下状態: `application/key_state_manager.py`
  * keyboard ライブラリの走査コード: `scan_code or -vk`（`.venv/Lib/site-packages/keyboard/_winkeyboard.py:529`）

## 提案（方向性・要設計）

* 押下だけのキーの判定: 走査コード（241 / 242 等）または VK（`VK_IME_ON` / `VK_IME_OFF` 等）の表、あるいは「同じキーの押下が短い間に続き、離しが来ない」の検出
* 判定したキーは次のように扱う
  * 続けて届く押下を 1 回にまとめる
  * まとめた分も抑止する（送信ガード中でも、直前に抑止したキーの続きなら抑止）
  * 押下状態に載せない（すぐ離した扱い）
* 名前付け: レイアウトの行に受け取り用の追加の走査コードを書く（暫定 45 v0.4 §3.1 の設計・Codex 敵対的レビューの指摘〔修飾キーの禁止の適用・受け取り専用の行の送信〕を含む）を再利用する
