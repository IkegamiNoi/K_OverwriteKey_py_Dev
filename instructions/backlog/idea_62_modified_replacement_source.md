# idea_62_modified_replacement_source.md

## 概要

**キー置換の置換元に、修飾キー付きの組み合わせ（例: `Shift+A`）を指定できるようにする。** いまは置換元を単一キーとして扱い、修飾キーは素通しするため、`Shift+A` → `A` のような置換は作れない。

## 起票経緯（2026-11-21）

出所: phase 75 task_13 の Windows 実機確認（exe）の際のユーザー要望。

## 現状

- 置換元は単一キーで、押されている修飾キーはそのまま OS へ届く（`Shift+A` は `Shift` + 置換先として送られる）。
- 置換の送信先の Shift の扱いは `instructions/common/spec_detail/key_input.md` の「キー置換の送信の Shift」（phase 74）を参照。
- 置換元の記録（キーボードUI・キーマップ編集）は修飾キーを読み飛ばす（idea_57 と同じ箇所）。

## 提案（方向性・要設計）

- 置換元を「修飾キー + キー」で持てるようにし、一致したときは押されている修飾キーを打ち消してから置換先を送る。
- 単一キーの置換と、修飾キー付きの置換が同じキーにあるときの優先順位（修飾付きを優先する案）。
- 打ち消した修飾キーを、送信後に元の押下状態へ戻すかどうか。
- トリガー（修飾付きのトリガー）との重なりの判定と、キーボードUI での表示方法。

## 想定スコープ

- 含む: キーマップの保存形式（後方互換で項目を足す）・フックの判定・送信・キーボードUI / キーマップ編集の記録と表示。
- 含まない: hotkey・key_hold の変更。
- 仕様変更あり（`data_schema.md` / `key_input.md` / `features.md` に跨る見込み → 暫定仕様先行）。関連: idea_57（置換先に修飾キー）・idea_53（送信中の物理入力）。
