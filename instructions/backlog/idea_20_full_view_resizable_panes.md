# idea_20_full_view_resizable_panes.md

## 概要

フル表示のメイン領域（**キーマップ管理 | トリガー一覧 | 出力シーケンス**）で、
**アプリ幅を変えたときに伸縮するのをトリガー一覧にする**。さらに**境界線のドラッグで
キーマップ管理・出力シーケンスの幅を変えられる**ようにし、**変えた幅は再起動後も復元する**。

## 起票経緯（2026-09-16）

ユーザー要望（phase 17 完了後）。方向性は同日ユーザー確定:
①**幅は保存する**（再起動後も残す）②操作は**フレーム間の境界線をドラッグ**
③ドラッグの差分は**トリガー一覧が吸収**（ウィンドウ幅は変えない・トリガー一覧に最小幅）。

## 現状

- `keyseq/presentation/views/full_view/full_view.py` の `main_area` で 3 つの LabelFrame を `pack(side="left")`。
  **`expand=True` は出力シーケンス（`SequenceBox`）だけ**で、キーマップ管理・トリガー一覧は `fill="y"`
  （幅は中身の要求サイズ）。
- 幅を変える UI はない。フル / 省略表示の切替時に geometry を退避・復元している（`app.py:333-376`）。
- UI 設定の永続化は `config/config.json`（例: `ui_font_delta_pt`）。**書き込みは起動設定の書き出し経路
  1 本を通す**規約あり（`spec_detail/data_schema.md` §5.4 付近・§5.9.4）。
- 正本 `features.md` / `data_schema.md` に幅配分の記述なし。

## 提案（方向性・要設計）

- 境界線（仕切り）を 2 本置く: キーマップ管理 | トリガー一覧 / トリガー一覧 | 出力シーケンス。
  実現手段の候補: `tk.PanedWindow`（ttk 版は無い）/ 自前の細い Frame + `<B1-Motion>` で隣の幅を設定。
- 保存キー案: `config.json` に両端フレームの幅（px）を持つ。**フォントサイズ変更・画面 DPI 差で
  中身の最小幅が変わる**ため、復元時のクランプ規則が要る。
- 要設計: 最小幅（各フレーム・特にトリガー一覧）/ ウィンドウを縮めて収まらない場合の優先順位 /
  保存タイミング（ドラッグ終了時か終了時か）/ 省略表示との往復 / 壊れた値の扱い。

## 想定スコープ

- 含む: presentation（`full_view.py` と周辺）+ config.json のキー追加（**後方互換・既定は現状相当**）。
- 含まない: 省略表示（CompactView）のレイアウト / 縦方向のサイズ変更。
- 仕様変更あり（`features.md` の UI 構成 + `data_schema.md` の config.json キー）→ **暫定仕様先行モード**の見込み。
