# idea_67_win_d_with_os_file_dialog.md

## 概要

**Windows で OS 標準のファイル / フォルダの選択（プリセット管理の保存から上書き確認の前に出るもの）が前面のとき、Win+D でアプリが最小化されない**。
修正の必要は低い（ユーザー判断）。**低優先・確認として残す**（再発や実害の報告があれば調べる）。

## 起票経緯（2026-11-25）

出所: [phase 80](../phase/80_win_d_restore_blank_dialog/phase.md) task_02 の Windows 目視（ユーザー）。アクションの追加・編集 → プリセット管理 → 保存のファイルの選択を開いて前面にした状態で Win+D を押すと、最小化されなかった。

## 現状

- 正本 `features.md` §4.6「モーダルダイアログの作法」の末尾 = **保証の範囲外: OS 標準のダイアログ**（ファイル選択・メッセージボックス。これが開いている間の最小化も含む）。今回の挙動はこの範囲内。
- ファイル / フォルダの選択は `filedialog.asksaveasfilename` 等（`presentation/controllers/config_io/` 配下）。Tk は OS のダイアログを自前のモーダルループで出すため、keyseq の最小化の預かり（`modal.py`）は関与しない。

## 提案（方向性・要設計）

- まず実測: 最小化されないのが OS のダイアログの仕様（Win+D の対象外）か、Tk のモーダルループの影響か、App 側の窓も残るのかを確かめる。
- 実害が無ければクローズ（対応不要）。

## 想定スコープ

- 含む: 実測と記録のみ。
- 含まない: OS 標準のダイアログの置き換え。
- 仕様変更: なしの見込み（既に保証の範囲外）。
