# idea_11_save_as_preset_copy_rollback.md

## 概要

**構成セットの別名保存で個別プリセットの複製に成功した後、keymap_set 本体の保存が失敗しても
複製と参照の更新が巻き戻らない**。孤児となった複製ファイルと、**メモリ上だけ新しい保存先を指す
`hotkey_presets_path`** が残り、**未保存マーク（dirty）も立たない**。
補償削除・参照の復元、または最低限 dirty を立てて部分成功を可視化する。

## 起票経緯（2026-08-16）

出所: **phase 09 task_08（正本反映）の `codex-adversarial-reviewer` 指摘（High 3）**。
暫定仕様 08 は**複製の失敗時**（＝ keymap_set 保存ごと中止）しか規定しておらず、
**複製成功 → 後段失敗**が未定義だった。**現状は既知の制約として正本 §5.10.4 へ明記**し、
是正は本 idea へ分離した（**優先度低**・ユーザー判断 2026-08-16）。

## 現状

`KeymapSetIo.save_keymap_set_to`（[keymap_set_io.py:114](../../keyseq/presentation/controllers/config_io/keymap_set_io.py)）の順序:

1. `relocate_individual_hotkey_presets` … 新 stem の個別パスを算出し、
   **コピー先に実体が無ければ `copyfile`** で複製
2. `app.data["hotkey_presets_path"]` を新パスへ更新
3. `save_runtime_data` … keymap_set 本体・子ファイル・config.json を書く

**3 が例外を投げると `showerror` して `False` を返すだけ**で、1・2 は戻らない。
`set_dirty(False)` の手前で抜けるため **dirty は保存前の値のまま**（保存前が clean なら
「参照先が変わったのに未保存マークが出ない」）。

### 実害の想定（限定的）

- ディスク上の keymap_set は**旧パスを指したまま**なので、**次回起動時の読み込み先は変わらない**。
- ただし同一セッションでプリセットを再編集して確定すると、保存先は**メモリ上の新 stem の複製**になる。
  このとき**【S】の上書き確認は発火しない**（複製の内容 = ダイアログが読み込んだ一覧のため
  内容比較が一致する）。**無警告で複製側へ書かれる**。
- **keymap_set を保存し直せば新パスが永続化されて解消**するが、保存せずに終了すると
  編集が反映されていないように見える（**データ自体は複製側に残るので失われない**）。
- 前提が例外系（ディスクフル / 権限 / パス不正）のため**発生頻度は低い**。

## 提案（方向性・要設計）

1. **補償**: 後段失敗時に、**このフローで作成した複製だけを削除**し
   `hotkey_presets_path` を旧値へ復元する（**既に存在していた複製先は消さない**＝
   「コピー先に実体があれば複製しない」と対称にする）。
2. **可視化（最小）**: 補償はせず、後段失敗時に **dirty を立てる**（参照が変わったことを未保存として通知）。
3. **順序の入れ替え**: keymap_set の保存に成功してから複製する。ただし
   **§5.8.6 の書き込み順序（子 → 上位 → keymap_set → 起動設定）**との整合と、
   複製失敗時に「参照先が実体を持たない」状態になる点の検討が要る。

## 想定スコープ

- **含む**: `KeymapSetIo.save_keymap_set_to` の失敗経路、`ConfigService.relocate_individual_hotkey_presets`
  の戻り値（**このフローで複製を作ったか**の区別が要る）、`tests_ui` の失敗経路テスト。
- **含まない**: 保存全体のトランザクション化（§5.8.6 の best-effort 方針は維持）。
- **影響レイヤ**: presentation（保存フロー）+ application（複製 API の戻り値）。
  **正本の改訂を伴う**（§5.10.4 の既知の制約を差し替える）ため、着手時は仕様変更フロー必須。
- **優先度**: **低**（例外系が前提・データは失われない）。
