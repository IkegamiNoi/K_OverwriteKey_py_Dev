# idea_50_capture_jis_special_keys.md

## 概要

**キーの取得（キーボードUI の編集・切替キー・トリガー 等）で JIS の特殊キー（無変換・変換・半角/全角・かな）を取れるようにする**。今は押すと IME に横取りされて Tk に `??`（VK 229）で届き、どのキーか判別できない（取得されず IME の ON/OFF だけが切り替わる）。

## 起票経緯（2026-10-17）

phase 61（idea_47・キーボードUI の取得で VK を走査コードへ変換）の実機目視で、F1 / F10 / F12 は直ったが JIS の特殊キーは取れなかった。確認用の窓（Tk・Windows 11・JIS 配列・MS-IME）で実測した結果、Tk のイベントからは判別できないと分かり、phase 61 の範囲外として分離（ユーザー判断）。

## 実測（2026-10-16〜17・確認用の窓）

* **通常（入力コンテキストあり）**: 4 キーとも押したときは keysym `??`・VK 229（`VK_PROCESSKEY`）。**IME が OFF でも同じ**（IME の切替用のキーとして IME が先に処理する）。`ImmGetVirtualKey` も 0xE5 を返し、元の VK を取り戻せない。離したときは一部だけ届く（VK 0xF4・0xF0）
* **入力コンテキストを外した（`ImmAssociateContext(hwnd, NULL)`）**: キーごとに違う VK で届く
  * 無変換 = VK 0x1A（`VK_IME_OFF`）・変換 = VK 0x16（`VK_IME_ON`）← MS-IME のキーの割り当て（無変換 = IME OFF / 変換 = IME ON）に従った VK。`MapVirtualKeyW` の走査コードは 241 / 242 で、物理の走査コード（123 / 121）と違う
  * 半角/全角 = 押すと VK 0xF4（走査コード 0）・離すと VK 0xF3（走査コード 41）
  * かな = VK 0xF2（走査コード 112 = jis.json の `kana`）
* **Tk のキーイベントは物理の走査コードを持たない**（VK だけ）。VK は IME の設定しだいで変わるので、VK から物理キーを確実に逆算できない

## 追記（2026-10-21・ユーザー要望）

* key_hold の「押す」で `muhenkan` を使いたい、という要望から再確認した。**テキストで `muhenkan` と入れて登録すれば、JIS レイアウトの選択中は動く**（`InputGateway._resolve_key` がレイアウトから走査コード 123 を引いて送る・ユーザーの実機で確認済み。JIS 以外のレイアウトでは `Unknown key name` で失敗する。`ime nonconvert` ならレイアウトによらず 123）
* ただし、**トリガーとシーケンスの記録ボタン**（`trigger_dialog.py` の取得・`action_key_hold_fields.py` の「1 キーを記録」）で押すと `??` になり、「このキーは取得できません」と出て記録できない。この 2 つも本 idea の取得の入口に含める
* keymap 側の取得（`keymap_panel_controller.py` の VK → 走査コード → レイアウト）を流用する案は効かない見込み。物理キーの VK が 229 / 0x1A になり、123 へ逆算できないため（上の実測）

## 提案（方向性・要設計）

* **推奨: 取得中だけフック（keyboard ライブラリ・物理の走査コードが分かる）で押されたキーを読む**。名前はフックの実行時と同じ解決（`LayoutController.resolve_key_name_from_scan_code`）にすれば、取得とフックで名前が揃う（idea_45・idea_49 とも関係）。今は取得中にフックを止めているため、「取得用にだけ読む」形を設計する
* 代替: 取得中は入力コンテキストを外し（phase 60 は開閉の方式を採用）、VK → 名前の表を IME の VK（0x1A / 0x16 / 0xF4 / 0xF2）まで持つ。IME の設定に依存するので推奨しない

## 想定スコープ

* 含む: 取得の入口（少なくともキーボードUI の編集・切替キー・トリガーとシーケンス〔key_hold〕の記録ボタン）で JIS の特殊キーを取る / 影響レイヤ = presentation（取得）・infrastructure（フック）
* 含まない: フックの実行時の名前（既に走査コードで取れている）
* 仕様変更: `key_input.md` §7.4（取得の名前の作り方）の見込み
* 関連: idea_45（取得の記号キーの名前）・idea_49（特殊キーの名前をレイアウトだけが決める）・phase 60（取得中の IME）
