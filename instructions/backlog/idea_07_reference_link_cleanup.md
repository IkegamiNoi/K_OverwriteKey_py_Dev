# idea_07_reference_link_cleanup.md

## 概要

**子ファイル（keymap / trigger_set / sequence）に記録した「参照元（上位ファイル）」の実在を一括確認し、
参照できなくなったものを該当項目から削除する掃除機能。** Phase β で導入する「参照元記録（共有可視化）」の
リストは、上位ファイルの移動・削除で**陳腐化しうる**（案A・軽量記録を採用）。その後始末をユーザー操作でまとめて行う。

## 起票経緯（2026-07-27）

保存系リデザインの設計討議（ユーザー要望 2026-07-26〜27）で、Phase β の参照元記録を
**案A（子JSONに参照元リストを記録・軽量だが陳腐化しうる）** とする合意に伴い分離。
「陳腐化は許容し、別途掃除機能で回収する」というユーザー方針（β-a / β-e の回答）に基づく。

## 現状

- 現時点では参照元記録そのものが未実装（Phase β で導入予定）。本 idea は **β の完了後**に着手する。
- Phase β では、子JSON に上位ファイルパスを **config_root 内なら相対・外なら絶対**（`to_config_relative_or_absolute` 規約）で
  記録する予定。上位ファイルを移動/削除しても子側は検知できず、リストに実体のない参照元が残る。

## 提案（方向性・要設計）

- **対象**: 子JSON に記録された参照元（上位パス）が**実在するか**を検査し、実在しないものをリストから除去する
  （ユーザー回答 β-e）。逆方向（keymap_set が指す子ファイルの実在チェック=孤児検出）は**含めない**（別途必要なら追加 idea）。
- **起動口**: `menu_bar` へメニュー項目を追加（ユーザー回答 β-f）。
- **UI**: 検査結果（除去対象の一覧）を提示し、まとめて削除してよいか確認してから実行する想定（要設計）。
- 検査単位（全 keymap_sets 配下を走査するか、現在開いているセットの子のみか）は着手時に詰める。

## 想定スコープ

- 含む: 子JSON の参照元リストの実在検査と除去、menu_bar への起動口、確認 UI。
- 含まない: 孤児ファイル（どの keymap_set からも参照されない子）の検出・削除 / 参照元記録そのものの実装（=Phase β）。
- 影響レイヤ: presentation（+ 検査ロジックは application 側の純関数に置く余地あり）。
- 仕様変更: あり（新機能）。**前提: Phase β（参照元記録）の完了**。優先度: 中〜低（保守機能）。
