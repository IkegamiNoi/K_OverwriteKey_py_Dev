# idea_38_file_line_async_read.md

## 概要

出力シーケンスの **file_line のファイル読込を UI スレッド外で行う**。現在は実行のたびに UI スレッドで同期読込しており、
**ネットワーク上のパス（UNC）や応答しないドライブを指定すると UI が止まり、停止操作や待機の取り消しも効かなくなる**（1 MB 上限では待ち時間を制限できない）。
ユーザーは「早めに対応した方がよい」と判断（2026-09-27）→ **次フェーズ（phase 38）で最初に対応する**。

## 起票経緯（2026-09-27）

phase 37 のフェーズ完了判定前の Codex 敵対的レビュー（Sol medium）が High で指摘。v0.3 時点では「別スレッド読込より上限の方が簡単」として 1 MB 上限を採用済みで、
phase 37 では既知の制約として正本に明記した（暫定仕様 [26](../history/26_sequence_control_actions.md) §2-29）。

## 現状

- `keyseq/application/file_line_reader.py` の `read_file_line` が `os.path.getsize` → 読込 → 復号を同期で行う。
- 呼び出しは `keyseq/application/action_executor.py` の file_line 分岐（UI スレッドで runner から呼ばれる）。
- 単発実行の非同期待機（保留中ステップ・世代番号・取り消し契機）の仕組みが `keyseq/application/sequence_runner.py` にある（流用候補）。

## 提案（方向性・要設計）

- ファイル取得をワーカースレッドで行い、完了時に `after()` で UI スレッドへ戻して送信する。読込中はそのステップを「保留中」とし、同じトリガーの再押下を無視する（待機と同じ扱い）。
- 取り消し（フック停止・無効化・キーマップ切替・位置変更等）と古い結果の破棄を世代番号で行う。
- 読込時間の上限（例: 数秒でエラー）を設けるか。連続実行・戻す履歴との関係（読込中の停止で 1 段積むか）。

## 想定スコープ

- 含む: file_line の非同期読込・取り消し・タイムアウト・テスト。
- 含まない: file_line 以外の種別の非同期化。
- 仕様変更あり（`data_schema.md` §5.11 の file_line・`features.md` §4.2）→ 暫定仕様先行モードの見込み。
