# task_05_integration_check

## 目的

**phase 10 の実装（task_01〜04）を通しで確認し、受入条件 1〜15 の充足を判定する**
（暫定仕様 09 **§5**）。実装タスクは task_04 で出揃っており、
**本タスクでコードは原則変更しない**（**実機目視で見つかった不具合の是正のみ**変更してよい）。

**是正が仕様変更を伴う場合は枝番タスクへ切り出す**（phase 09 の 07b〜07g と同じ流儀）。
本タスクは**通し確認と実機目視の実施**に徹する。

**レイヤ制約**: 是正が必要になった場合も**最小差分**。設計変更が要るなら
`.claude/rules/spec_change_workflow.md` に従い**ユーザー判断を仰ぐ**（独断で仕様を緩めない）。

## 対象範囲

### 1. 自動確認（`verifier` が実測）

phase 全体の差分（**`2b12ef8..HEAD`** = phase 10 起票直後〜task_04）に対して通しで再実測する。

- `-m compileall -q keyseq main.py tests tests_ui` が clean
- `-m unittest discover -s tests` が **pass**（現行 **264**）
- `-m unittest discover -s tests_ui` が **pass**（現行 **236**・**ハングしないこと**）
- `-m tests.smoke_app` が pass
- 実行後に worktree ルートへ **`user/` が生成されていない**こと

### 2. 二次レビュー（**2 本立て・省略しない**）

`.claude/rules/agent_selection.md` の「フェーズ完了判定前」に従う。

- **`deep-reviewer`**（Claude 側）— 対象は **`2b12ef8..HEAD`** の差分と暫定仕様 09 v0.4 の整合
- **`codex-adversarial-reviewer`**（Codex 側）— 同じ差分に敵対的レビュー
- 指摘は**提示のみ**。採否は**ユーザー確認**を経て決める

### 3. 実機目視（**ユーザーが実施**し、結果をメインセッションへ報告）

**準備（陳腐化の作り方）**: アプリを終了した状態で、`config/user/` 配下の子JSON
（`keymaps/*.json` / `trigger_sets/*.json` / `sequences/*.json`）を開き、
**`_parent_refs` の配列へ実在しないパスを 1〜2 件足す**
（例: `"user/keymap_sets/deleted_set.json"`）。**既存の要素は消さない**。

| # | 操作 | 期待 | 受入 |
|---|---|---|---|
| 1 | 陳腐化が無い状態で **設定 →「参照元を掃除…」** | **「掃除する項目はありません。」**が出て、一覧ダイアログは**出ない** | 10 |
| 2 | 上記の準備で陳腐化を作り、構成セットを読み込んでから掃除を起動 | 一覧に**対象の子ファイル**が出る。**消える参照元のパスが全件表示**される（件数だけに丸められない）。**要約行の件数**が実際と合う | 1 / 2 / 9 |
| 3 | その一覧で**キャンセル**（または × で閉じる） | **ファイルが 1 つも変わらない**（`_parent_refs` が元のまま）。**未保存マーク（dirty）も付かない** | 10 |
| 4 | もう一度開いて**実行** | 実在しない参照元だけが消え、**実在する参照元は残る**。**結果通知**（更新したファイル数 / 除去した件数）が出る。**実行後も未保存マーク（dirty）が付かない** | 4 / 6 |
| 4b | 掃除ダイアログの表示中と、閉じた後に**フックの状態を見る**（**実行 / キャンセル / × / Esc の 4 経路**）| 表示中は**フックが停止**し、閉じると**元の状態へ戻る**（開く前に動いていたなら再開する）| §3-3 |
| 5 | 続けてもう一度**掃除を起動** | **「掃除する項目はありません。」**（冪等。2 回目は何も起きない）| 12 |
| 6 | **子JSON を開いて中身を確認**（実行後）| **`_parent_refs` 以外のキーが変わっていない**（`mappings` / `actions` / `label` 等）。**全件が実在しなかった子は `[]` になっている**（キー自体は残る）| 7 / 8 |
| 7 | **アプリを開いたまま、エクスプローラで現在の構成セット（keymap_set）のファイルを別フォルダへ移動** → 掃除を起動 | **移動した構成セット自身への参照は「消える」一覧に出ない**（保護のため残す旨が出る、または一覧に現れない）。**実行しても残る** | 5 |
| 8 | **参照元が 1 件だけの子**を作り（他を消す）、その 1 件を実在しないパスにして掃除 | **「参照元が 0 件になる」警告**が出る。**子ファイル自体は削除されない**（実行後もファイルが残る）| 10b |
| 9 | **新規作成直後（未保存）**の構成セットで掃除を起動 → **「いいえ」** | **何も起きない**（保存ダイアログも一覧も出ない・ファイル不変）| 5b |
| 10 | 同じ状態で起動 → **「はい」** → **別名保存ダイアログでキャンセル** | **掃除が実行されない**（一覧が出ない・ファイル不変）| 5b |
| 11 | 同じ状態で起動 → **「はい」** → **保存を完了** | 保存後に**そのまま検査へ進む**（対象があれば一覧が出る / 無ければ 0 件メッセージ）| 5b |
| 12 | 掃除の**前後で構成セットを保存**して比較 | 掃除後は**「N 個の上位で共有中・全てに影響します」の誤警告が減る**（実在しない上位が数に入らなくなる）| 12 |
| 13 | **保護対象だけの子**を作る（子の `_parent_refs` を**現在の構成セットのパスだけ**にして、その構成セットのファイルを移動する）→ 掃除を起動 | **（v0.5）「掃除する項目はありません。」**が出て一覧が出ない（**書くものが無いため**）| §3-3 |

- **7 と 9〜11 は特に重要**（7 = 保護対象／9〜11 = 巻き戻り防止の導線）。
- 目視で不具合が出た場合は**本タスク内で是正**する（最小差分 + `reviewer` 再実施）。
  仕様変更を伴うなら**枝番タスクへ切り出す**。
