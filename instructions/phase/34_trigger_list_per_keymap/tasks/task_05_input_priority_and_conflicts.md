# task_05_input_priority_and_conflicts

## 目的

入力判定の優先順位と、キーの重なりの扱いを暫定仕様 25 §7（§7.1〜§7.4）と §8.5 に合わせる。
- 優先順位を **停止 > トグル > 直接切替 > 置換 > トリガー** にする（置換とトリガーを入れ替える）。
- 編集時の重複拒否をキーマップ単位の規則にする。
- 読込時の重なりは**開始を止めず**、グレー表示・キーボード表示・ステータスの案内で知らせる。**フック開始を止めるのは「停止 = トグル」だけ**。

**JSON スキーマ不変**。application（`input_router.py` / `trigger_service.py` / `keymap_service.py` / `hook_coordinator.py` / `action_executor.py`）と
presentation（`hook_controller.py` / `trigger_panel_controller.py` / `keymap_panel_controller.py` / `app.py` の停止・トグルキー取得の重複検証 / `keyboard_window.py`）。
重なりの判定（どの割り当てがどれに負けるか）は **1 箇所の純関数**（domain または application）に置き、入力判定・グレー表示・案内・開始検証がそれを共有する（判定の一元化）。

## 対象範囲

### 重なり判定の共通関数（新規・置き場は domain か application の既存モジュール近傍。実装判断）

- 入力: runtime（全キーマップ・アクティブ id）と解決済みの停止 / トグルキー。
- 出力（例）: アクティブキーマップの各トリガーについて「負ける相手」（停止 / トグル / 直接切替 / 置換 / なし）、各キーマップについて「切替キーが負ける相手」（停止 / トグル / なし）。
  §7.3 の表の優先（停止 > トグル > 切替 > 置換）で 1 つに決める。
- 全キーマップのトリガーキー集合・全キーマップの置換元キー集合・アクティブの置換元キー集合を返す補助も同じ場所へ（§7.2 の拒否判定で使う）。

### §7.1 入力判定（`input_router.py`）

- 順序を 停止 > トグル > 直接切替 > **置換 > トリガー** にする（トリガー・置換はアクティブキーマップのもの）。「キーマップ一時停止（`custom_input_enabled=False`）」中は現行どおり停止 / トグル以外すべて無効。
- **§8.5 の案内のための情報**を InputRoute に載せる: 押されたキーが、上位の割り当てに負けたグレー表示の割り当て（トリガー / 切替キー）にも該当する場合、その種類と相手を付ける（例: `shadowed=("trigger", "stop")`）。
  一時停止中は停止 / トグル以外の案内を付けない。置換元キーと停止 / トグルの重なりは付けない（§8.5）。

### §8.5 案内の表示（`action_executor.py` ほか）

- 上位の動作を実行した後、ステータスに案内を出す。文言は暫定 §8.5 の例に揃える:
  「<キー> は停止キーと重複しているため、トリガーは実行されません。トリガーのキーを変更してください」/
  「<キー> は停止キーと重複しているため、キーマップ <名前> へ切り替えられません。切替キーを変更してください」/
  「<キー> は切替キーと重複しているため、トリガーは実行されません。…」/「<キー> は置換と重複しているため、トリガーは実行されません。…」。
  トグルキーの場合は「一時停止/再開キー」と表記（改名は task_07 だが、この文言は新名称で書く）。
- **上位の動作の表示を消さない**: 停止キーでフックが止まる場合は「停止しました」相当の既存表示と案内を併記する（上書きしない）。

### §7.2 編集時の重複拒否

- トリガーキーの追加・変更（`trigger_panel_controller.py:380-420` 付近）: 既存の拒否（停止 / トグル / 直接切替 / 同キーマップの既存トリガー）に **同キーマップ（アクティブ）の置換元キー**を追加。直接切替キーは全キーマップ分（現行どおり）。
- 置換元キーの割り当て（`keymap_panel_controller.assign_keymap_from_keyboard_ui` 付近）: **同キーマップのトリガーキー**を拒否に追加。
- 直接切替キーの割り当て（`keymap_panel_controller.validate_keymap_switch_assignment`）: トリガーとの重複判定を**全キーマップのトリガーキー**に広げる（現行 `trigger_service.key_exists` はアクティブ分のみを見る）。
- 停止 / トグルキーの取得時の重複検証（`app.py:140-158`）: **全キーマップのトリガーキー / 全キーマップの置換元キー**・直接切替キーと照合する。
- 別キーマップのトリガーと置換元キーの重複は許す。

### §7.3 グレー表示

- **トリガー一覧**（`trigger_panel_controller.py` の一覧描画）: 負けるトリガーの行をグレー表示にし、理由（「停止キーと重複」/「一時停止/再開キーと重複」/「切替キーと重複」/「置換と重複」）を行に添える。編集（キー変更・削除）はできる。重なりが解消すれば通常表示に戻る（一覧の再描画時に再判定）。
- **キーマップ一覧**（`keymap_panel_controller.py` の一覧描画）: 直接切替キーが停止 / トグルと重なるキーマップの行をグレー表示＋理由。**一覧からの選択・編集はできる**（無効化しない）。
- **キーボード表示**（`keyboard_window.py:99-118`）: 置換元キーとトリガーが重なるキーは**置換の表示を優先**（現行はトリガー優先）。予約キー（停止 > トグル > 切替）が最後に上書きする現行の順は維持。
- 再描画の契機: 一覧の再描画・停止 / トグルキーの変更・トリガー / 置換 / 切替キーの編集（既存の再描画経路に判定を載せる。アクティブ切替時の再描画は task_06）。

### §7.4 フック開始の検証（`hook_controller.validate_hook_configuration` / `hook_coordinator._can_process_input`）

- **開始を止める重複は「停止キーとトグルキーが同じ」だけ**。停止 / トグルとトリガー・置換元キー・直接切替キーの重なりの検証（`hook_controller.py:193-222`）は外す。
- 「トリガーが 1 件も無い」判定は**全キーマップのトリガー・置換元キー**で行う（`can_enable_custom_input` も同様）。

### テスト（追加・更新）

- 既存テストの期待値更新は、優先順位の入れ替え・開始検証の縮小・拒否範囲の変更によるもののみ。アサーションを緩めない。テスト補助で runtime を書き換えない。キーマップ 0 個のフィクスチャを作らない。未モックの実ダイアログを開かない。
- 新規:
  1. 重なり判定の共通関数: 各優先の組合せ（停止 / トグル / 切替 / 置換 × トリガー、停止 / トグル × 切替キー）・複数該当は上位 1 つ・別キーマップの置換とトリガーは重ならない。
  2. 入力判定: 置換とトリガーが同キーなら置換が実行される / 案内情報が付く・一時停止中は付かない。
  3. 案内の文言と「停止しました」との併記。
  4. §7.2 の各拒否（トリガー ← 同キーマップ置換元 / 置換元 ← 同キーマップトリガー / 切替キー ← 全キーマップのトリガー / 停止・トグル ← 全キーマップのトリガー・置換元）と、別キーマップ間は許すこと。
  5. グレー表示: トリガー一覧・キーマップ一覧の行の表示と理由・解消で戻る・グレーでも選択 / 編集できる。
  6. キーボード表示で置換が優先される。
  7. 開始検証: 停止 = トグルだけ開始できない・停止とトリガー / 置換元 / 切替の重なりでは開始できる・アクティブに無くても他キーマップにトリガーがあれば開始できる。
