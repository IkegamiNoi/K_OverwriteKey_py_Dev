# task_02_dialog_layout

## 目的

子ファイル保存ダイアログ（構成セットの保存で出す子一覧）を、正本 `features.md` §4.6「子ファイル保存ダイアログ」（phase 44 task_01 で改訂・ユーザー確認済み 2026-10-04）に合わせる:
行数に合わせた高さ（上限は画面の 6 割）・列の境界 3 つのドラッグ（差は保存先パスが受け持つ）・ウィンドウの幅の変化は保存先パスだけ・4 つの文言の列の省略表示。
**presentation 限定（`controllers/config_io/child_save_dialog.py`）・domain / application 不変・スキーマ不変・列幅は保存しない。**

## 対象範囲

### `keyseq/presentation/controllers/config_io/child_save_dialog.py`（子一覧ダイアログ `_create_action_dialog` 系のみ）

- **大きさ**: 固定の `geometry("960x480")` と `minsize(max(720, …), max(320, …))` をやめ、正本どおりに:
  - 開いたときの幅 = 960px（最小幅を下回れば最小幅・画面の幅を超えれば画面の幅）
  - 開いたときの高さ = 見出し + 全行 + ボタンが収まる高さ。上限は画面の高さの 6 割（タイトルバー込みの外形で数える。Tk の `winfo_rooty() - winfo_y()` 等でタイトルバーの高さを見積もる）。超えたら縦スクロール。6 割が最小の高さを下回るなら最小の高さ
  - 最小の高さ = 見出し + 1 行 + ボタン / 最小の幅 = 種別・対象名・共有状況の今の幅 + 保存先パスの最小幅 + 操作列 + スクロールバー + 余白。**列の幅を変えたら `minsize` を当て直す**
- **列の幅**: 種別・対象名・共有状況・操作は固定幅（`columnconfigure(..., minsize=幅, weight=0)` 等）、**保存先パスだけ `weight=1`**。ウィンドウの幅の変化は保存先パスだけが受ける
  - 既定の幅: 種別・共有状況 = 内容（見出しを含む）の最大幅 / 対象名 = 内容の最大幅（上限は開いたときの一覧の幅の 3 割）/ 保存先パス = 残り。操作列 = ラジオの必要幅
  - 各列の最小幅 = 見出しの文字の幅 + 列の間の余白（現行の `padx=(0, 8)`）
- **境界のドラッグ**: 見出し行の 3 つの境界（種別|対象名・対象名|保存先パス・保存先パス|共有状況）にドラッグできる取っ手（細い `ttk.Separator` / `Frame` に `cursor="sb_h_double_arrow"` 等）を置く
  - 種別|対象名・対象名|保存先パス: 右へ動かすと左の列が広がり保存先パスが同じだけ狭まる / 保存先パス|共有状況: 左へ動かすと共有状況が広がり保存先パスが同じだけ狭まる（逆向きは逆）
  - 列は最小幅より狭くならない。保存先パスが最小幅のときは、保存先パスを狭める向きのドラッグはその位置で止まる
  - 取っ手は見出し行だけ（行の部分にはない）。ドラッグ中もスクロール位置・ラジオの選択を変えない
- **省略表示**: 現行の対象名・保存先パスの省略表示とツールチップ（`_add_text_cell`・`_bind_content_width`・`_fit_text`）を **種別・共有状況にも**広げる（既定の幅では内容が収まるので初期表示では省略されず、ドラッグで狭めたときに省略される）。
  列の幅が変わるたびに省略を当て直す（`last_fit_width` のキャッシュが列の幅の変化で無効になること）
- 既存の要件を保つ: 初期表示で省略が効いている / ラジオ列を切らさない / 縮小しても OK・キャンセルが見える（ボタンはスクロール領域の外）/ スクロール領域内の子の上でもホイールが効き、閉じたらバインドを残さない
- 依存確認・再計算先の上書き確認のダイアログ（同ファイルの別ダイアログ）は変えない

### `tests_ui/test_child_save_dialog.py`（追加・修正まで）

- 行が少ない（例 2 行）とき、開いた高さが見出し + 2 行 + ボタン程度で、旧 480 より小さい / 行が多い（例 60 行）とき、外形の高さが画面の高さの 6 割以下でスクロールできる
- ウィンドウの幅を広げると保存先パスの列だけが広がり、種別・対象名・共有状況・操作の幅が変わらない
- 3 つの境界のドラッグ（`event_generate` の `<ButtonPress-1>` / `<B1-Motion>` / `<ButtonRelease-1>`）: 隣の列が増えた分だけ保存先パスが減る（合計が変わらない）/ 最小幅で止まる / 保存先パスが最小幅のとき止まる / ドラッグ後に `minsize` の幅が当て直される
- 種別・共有状況を狭めると省略表示になりツールチップで全文が出る
- 既存の表示要件のテスト（固定サイズ 960×480・最小 720×320 を前提にしたもの）は新しい規定へ追随させる（期待値の変更は正本の改訂に沿うものに限る）
