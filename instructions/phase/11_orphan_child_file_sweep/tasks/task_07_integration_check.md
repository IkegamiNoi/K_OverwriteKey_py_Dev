# task_07_integration_check

## 目的

**phase 11（検出 → 隔離 → 復元 → 削除）を通しで統合確認する**。根拠は phase.md タスク 7
+ 暫定仕様 10 **§5 受け入れ条件 1〜22**。

- **コードを変更しないタスク**。実測・二次レビュー・実機目視の観点提示と結果受領が成果物。
- **レイヤ制約**: **全レイヤ不変**。テストの追加もしない（不足を見つけたら報告し、
  対応の要否はユーザーが決める）。
- **task_01〜06b は個別に green だが、通しで確認していない**。ここで初めて
  「隔離 → 復元」「隔離 → 削除」の往復と、フェーズ全体の退行を見る。
- 二次レビューは **`deep-reviewer`（複数タスクを跨ぐ差分）+ `codex-reviewer`（標準レビュー）**
  の 2 本立て（`.claude/rules/agent_selection.md` のレビュー表・統合テスト行）。

## 対象範囲（新規文書のみ・コード不変）

### 1. `verifier` による全スイート実測

`.venv` の python で以下を実行し、結果を受け取る（worktree ルートから）。

```
..\..\..\.venv\Scripts\python.exe -m compileall -q keyseq main.py tests tests_ui
..\..\..\.venv\Scripts\python.exe -m unittest discover -s tests
..\..\..\.venv\Scripts\python.exe -m unittest discover -s tests_ui
..\..\..\.venv\Scripts\python.exe -m tests.smoke_app
```

- **基準値**: `tests` **399**（skip 5）/ `tests_ui` **287**（skip 0）。**減ったら退行**。
- skip 5 件は **Windows の symlink 作成権限不足（WinError 1314）**。
  **同観点はジャンクション版が実行されている**ため観点の抜けではない。skip がこれ以外に
  増えていたら報告する。
- 実行後に worktree ルートへ **`user/` も `quarantine/` も生成されていない**こと。

### 2. 受け入れ条件 1〜22 の充足状況の突合

暫定仕様 10 **§5** の 22 条件それぞれについて、**自動テストで担保済み / 実機目視が要る /
本フェーズ対象外** のいずれかに分類し、担保元（テスト名 または 目視観点の番号）を対応づける。

- **条件 16 の件数は古い**（`tests` 267 / `tests_ui` 238）。**実測値 399 / 287 へ読み替える**
  （条件そのものの改訂は task_08 で行う。ここでは読み替えの明示に留める）。
- **自動テストで担保できていない条件が見つかったら、そのまま報告する**。
  テストを足すかどうかはユーザーが決める（**このタスクで勝手に足さない**）。

### 3. 二次レビュー 2 本

- **`deep-reviewer`** — 対象は **task_01〜06b の差分全体**（基点 = phase 11 開始前のコミット）。
  観点は 5 観点 + 前提・未定義挙動・条項間の矛盾・実装可能性・暫定仕様との整合。
  **個別タスクで採用済みの判断を蒸し返させない**ため、確定事項（下記）をプロンプトへ明示する。
- **`codex-reviewer`**（標準レビュー） — 同じ基点で別視点。
- **確定事項として渡す（蒸し返し禁止）**: ①§4-A = 警告して実行は許す（degraded 不採用）
  ②§3-8 検証④のみ `allow_invalid_manifest` で上書き可（**①②③は緩和しない**・v0.5）
  ③削除の TOCTOU 2 件は受容済（§3-12-6 / §3-12-7・v0.6）
  ④復元は `state` ではなく実体の有無で判定する。

### 4. 実機目視の観点リストの作成とユーザーへの提示

**ユーザーが実機で確認する手順書**を作り、提示して結果を受領する。
**最低限、次を含める**（`session.md` の申し送り + 不可逆操作の確認）:

1. **隔離実行後の `quarantine/<unit>/` の中身**と `manifest.json` の `state`
   （元の相対構造が保たれているか・`state` が実体と整合するか）。
2. **`quarantine` を書込み不可にした状態**で隔離を実行したときの**中止表示**
   （マニフェストが書けないなら 1 件も動かないこと）。
3. **走査ディレクトリの追加 / 削除**と、**アプリ再起動後の保持**
   （加えて **keymap_set を保存した後も設定が消えない**こと = 受け入れ条件 14）。
4. **隔離 → 復元の往復で元に戻ること**（同名ファイルがある場合はスキップして報告されること）。
5. **隔離 → 削除で実体が消えること**（削除前に**不可逆の明記と全件提示**が出ること）。
6. **マニフェスト不正な単位の削除時に警告文が出ること**
   （「中身を確認できません」「ディレクトリごと削除します」が別行で出る・**復元は不可のまま**）。
7. **読めない keymap_set があるとき、一覧の先頭に警告が出て「実行 / キャンセル」の 2 択になる**
   （受け入れ条件 17）。
8. **孤児候補 0 件のときはダイアログを出さず通知のみ**（受け入れ条件 13）。

各観点に**再現手順・期待結果・実際の結果の記入欄**を持たせる。

### 5. `instructions/phase/11_orphan_child_file_sweep/integration_result.md` の作成

実測値 / 受け入れ条件の突合表 / 二次レビュー 2 本の結果と採否 / 実機目視の結果 を記録する。
**task_08 で正本へ反映すべき事項**（既知の 6 件 + 本タスクで見つかったもの）を末尾に列挙する。

1. **`verifier` 実測が全 pass**。`tests` **399 以上**（skip 5・**それ以外の skip が増えていない**）/
   `tests_ui` **287 以上** / compileall clean / smoke pass。
2. 実行後に worktree ルートへ **`user/` も `quarantine/` も生成されていない**。
3. **受け入れ条件 1〜22 の突合表**が作られ、各条件に担保元

4. **`deep-reviewer` を実施**し、指摘と採否（**採用 / 修正して採用 / 保留 / 除外**）が記録されている。

7. `integration_result.md` が作成され、**task_08 への申し送り事項**が列挙されている。
