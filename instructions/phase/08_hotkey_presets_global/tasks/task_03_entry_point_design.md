### 確定内容（ユーザー確定 2026-08-06）

- **方式 = 案B: 注入 API を 1 本に束ねる**。
  `ConfigService.apply_global_defaults(runtime, *, config_root)` を新設し、
  **hook キーの全体デフォルト注入 + グローバルプリセットの供給**をこの 1 本で行う。
  - hook キー部分は**既存 `apply_global_hook_key_defaults` をそのまま呼ぶ**（挙動不変・冪等）。
  - プリセット部分は `load_global_hotkey_presets_path` → `load_named_list` で読む。
  - **戻り値は runtime（破壊的更新）**・**冪等**・**例外を投げない**（読めなければ縮退。§既知の制約）。
- **呼ぶ場所 = runtime を新規化・置換する 5 経路**:
  新規作成 / Import / 例を復元 / 空データ起動 / **App 初期化（`app.py:77`）**。
  **`app.py:77` も新方式へ寄せる**（起動シーケンスの上書き順序に依存した「5 個目の穴」を塞ぐ）。
- **束ねた API を使わない経路（重要）**: `App.toggle_hook_keys_individual` の **ON→OFF** は
  **従来どおり `apply_global_hook_key_defaults` を直接呼ぶ**。
  **理由**: 束ねた API を使うとキーの個別指定を切り替えただけで**プリセットまで再読込**され、
  編集中のプリセットを取りこぼす。**「hook キー単独の注入」と「runtime 置換時の全体注入」は別物**。
- **`apply_global_hook_key_defaults` は公開のまま残す**（名前・引数も変えない。上記の単独注入で使い、
  テスト 6 箇所が直接呼ぶため）。
- **プリセット供給の縮退規則（本タスクで確定・実測から判明した分岐）**:
  グローバルのプリセットファイルが**無い / 壊れている / 空リスト**のとき（`load_named_list` は
  いずれも `[]` を返し区別できない）、**runtime の既存プリセットを置き換えない**。
  - これにより **新規作成は従来どおり組込プリセット 8 件**（`DEFAULT_CONFIG`）・
    **空データ起動は空のまま**となり、**各経路の従来挙動が保たれる**。
  - **既知の制約**として明記する: 「ユーザーがグローバルのプリセットを**全削除**した状態」と
    「グローバルファイルが**無い**状態」は区別できないため、前者でも新規作成では組込 8 件が現れる。
- **通常読込（`build_runtime_data_from_split`）は本 API を経由しない**（phase 07 の hook キーと同じ構造）。
  通常読込はグローバルを**無条件に採用**する（task_02 で確定済み・空なら空）。**この非対称は意図的**であり、
  正本へもそのまま書く。

### 敵対的レビューの結果と採否（2026-08-06・**指摘 2 件ともユーザーが採用** → v0.5）

`codex-adversarial-reviewer` = **needs-attention**。**両指摘とも実コードで裏取り済み**。

1. **[high] 空リスト縮退規則が §2 を破る** → **採用**。`load_named_list`（不存在・破損・空をすべて `[]` に潰す）を
   使わず、**`list | None` を返す読み出し**へ変更する。**読めたら空リストでも採用**（全削除が復活しない）、
   **読めない（不存在・破損）なら置き換えない**。**通常読込も同じ規則へ統一**する
   （→ **task_02 のテスト「不存在・破損 → `[]`」は task_04 で「置き換えない = 組込 8 件」へ更新する**）。
2. **[medium] 入口台帳が不完全** → **採用**。`app.data` を置き換える**実測 9 箇所**を
   **入口台帳（E1〜E5 / L1〜L3 / N1）**として §3-2 へ列挙し、受入条件 7 を台帳全経路へ拡張。
   受入条件 9（読めた空 / 読めない の区別）を追加。

**未回答だった論点**（レビュアーが触れなかった分）はメインが判断し v0.4 の記述を維持:
ON→OFF の単独注入（例外の理由を §3-2 に明記済み）/ `app.py:77` の起動順序（E1 として台帳化）/
正本 `data_schema.md` §5.9・`codebase_map.md`「解決点は 4 つ」との整合は **task_08 の正本反映で更新**する。
