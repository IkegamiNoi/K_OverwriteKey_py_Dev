## 対象範囲（tests/ のみ・本体不変）

`tests/test_sequence_runner_select_before_run.py` に追加する（既存のテストの作り方を手本）:

1. **受け入れ条件 7（呼び出し）**:
   - 単発のステップの呼び出しを持つトリガー T（全体 ON）: T を選んだ状態で押す → 1 ステップ進む → 続けて T を押しても選ぶだけは挟まらず次のステップへ進む（runner が押したキー T を選ぶため）
   - 連鎖の別のトリガー（呼び出し先 U）を押したら 1 回目は選ぶだけ
   - 待機中の呼び出し先を呼ぶトリガー: 1 回目 = 選ぶだけ・2 回目 = 従来どおり（無視）／一時停止中の呼び出し先を呼ぶトリガー: 1 回目 = 選ぶだけ（一時停止を捨てない）・2 回目 = 従来どおり（捨てて進める）。既存の呼び出しのテスト（`tests/test_sequence_runner_call.py`）の組み立てを手本にする
2. **受け入れ条件 8（待機明け・v0.5 の文言）**:
   - K の単発の待機中に、別のトリガー J を**選ぶだけの押下**（`handle_key("j")`・選択の注入が J を返すようになる）で選ぶ → 待機が明けても select("k") が呼ばれない
   - **待機が続く**シーケンス（文字・待機・文字・待機）で、1 つ目の待機中に J を選ぶ → 1 つ目・2 つ目の待機明けのどちらでも K を選び直さない（J のまま）
   - 選択を変えなければ、待機明けに K が選び直される（従来どおり）
3. **長押しの無視の終わり（v0.5 の文言）**: 選ぶだけにした K の後、K 以外の**トリガー**の押下で無視が終わる（既存テストにあれば重複させない）。トリガーでないキーは runner に届かないため対象外（テスト不要）
