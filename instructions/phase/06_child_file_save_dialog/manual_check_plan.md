## 1 周目 = 起動 A

### R1 個別保存のパス解決（v0.5-J / 2026-08-01 ①）

1. アプリ起動直後（構成セット未保存の状態）、トリガーを 1 つ追加
2. トリガー枠の **「保存」** → 保存先を選んで確定

**期待**: リポジトリルート直下に `user/` フォルダが**できない**。書かれるのは `config/user/...` 配下のみ。

### R2 個別「トリガー一覧を保存」で子の一覧が出る（v0.5-K / 2026-08-01 ②）

1. 既存の構成セットを **ファイル > 読込（構成セット）…** で開く
2. 出力シーケンスを 1 つ編集（トリガー一覧自体は触らない）
3. トリガー枠の **「保存」**

**期待**: **sequence 行だけの一覧ダイアログ**が出る（トリガー一覧の行は出ない）。
無確認で全 sequence が上書きされない。

### R3 一覧ダイアログの見た目（v0.5-L / v0.5-M / v0.4-C / 目視 9）

R2 か R4 で出した一覧ダイアログ上で確認する。

| # | 確認 | 期待 |
|---|---|---|
| 3-1 | 初期表示 | 対象名・保存先が **「…」だけになっていない**（リサイズ前から読める） |
| 3-2 | 行の上でマウスホイール | **スクロールする**（canvas 余白の上だけでなく行の上でも） |
| 3-3 | ウィンドウを縦横に縮める | **ラジオ列が消えない** / **OK・キャンセルが常時見える** |
| 3-4 | dirty な子が 10 行以上のとき | 画面からはみ出さない（縦スクロールで到達できる） |

### R4 一括保存の基本（目視 1 / 2 / 7 / 8）

1. 子を 2 つ以上変更（例: トリガー一覧 + 出力シーケンス）→ **ファイル > 保存**
   → **期待**: 一覧が出て、行ごとに 保存 / 別名保存 / 保存しない を選べる
2. その一覧で **キャンセル**
   → **期待**: **ファイルが 1 つも書かれない**・未保存表示が残る
3. もう一度 **保存** → 一部の行で「保存しない」を選んで OK
   → **期待**: 「保存しない」を選んだ子は**保存後も未保存マークが残る**
4. 続けて何も変更せず **保存**
   → **期待**: 一覧ダイアログが**出ない**（「保存しました」は出てよい＝仕様どおり）

### R5 所有元不明・共有中の表示（目視 3 / 4）— 要準備

**準備**（アプリを終了してからファイルを編集）:
- 3 用: `config/user/sequences/<任意>.json` から `_parent_refs` キーを**削除**
- 4 用: 別の `config/user/sequences/<任意>.json` の `_parent_refs` に**存在する別の keymap_set のパスを 1 つ追加**（計 2 件にする）

1. 該当の構成セットを読込 → その sequence を編集 → **保存**

**期待**:
- `_parent_refs` 無しの行 … 既定が**別名保存**・**「所有元不明」**表示
- 2 件参照の行 … **「N 個の上位で共有中・全てに影響します」**警告つきで、上書きも選べる

### R6 依存確認と別名保存後の挙動（目視 5 / 6 + 2026-07-29 ①）

1. 出力シーケンスを **別名保存**、トリガー一覧を **保存しない** にして OK

**期待（現行 = v0.4-D/E）**:
- 上位（トリガー一覧）の共有状況が**単独所有（表示「この構成のみが所有・既存を上書き」）または「新規作成」なら
  確認は出ず自動保存**され、完了メッセージで事後通知される
- **「所有元不明 / 別の構成 / 共有中」のときだけ 4 択**（保存 / 別名保存 / 保存しない / キャンセル）が出る。
  文面で**保存が必要になった理由**が分かること。**既定ボタンは「別名保存」**（Enter で上書きされない）
- 4 択で **「選び直す」（＝キャンセル）→ 一覧へ戻る**
- **別名保存を選んだ後に一覧が再表示されない**（v0.3-A で廃止済み。再表示されたら退行）
- 再計算で保存先が変わった「保存」行に既存ファイルがあり共有状況が「単独」以外のときだけ、
  **行単位の小さな上書き確認**が出る（v0.3-A2）

2. 「保存しない」を選んだ場合 → もう一度 **保存**
   → **期待**: 上位の索引が**次回保存で追随**する（保存後に再読込して中身が正しい）

### R7 個別「別名保存」後の索引追随（v0.5-N）

1. トリガー枠（または出力シーケンス枠）の **「別名で保存」** で新しい名前へ保存

**期待**: 保存直後に**構成セット側へ未保存マークが付く** → **ファイル > 保存** で索引が新パスへ追随する。
アプリを再起動して読み直すと**新しいファイルの内容**が読まれる（旧ファイルではない）。

### R8 新規作成直後の個別保存（v0.4-H / task_13）

1. 構成セットを読込・保存して trigger_set のパスが確定した状態にする
2. **ファイル > 新規作成**
3. 直後にトリガー枠の **「保存」**

**期待**: **前の構成の trigger_set が書き換わらない**。保存先の選択ダイアログが出る（キャンセルすれば何も書かれない）。

### R9 「例を復元」（v0.6 O / P / Q）— 2026-08-02 の指摘

1. 既存の構成セットを **読込** → 何か変更して未保存にする
2. **ファイル > 例を復元**
   → **期待（P）**: **未保存の確認が先に出る**（復元前）
3. 確認を通して復元 → **ファイル > 保存**
   → **期待（O）**: **別名保存ダイアログが出る**（元の keymap_set が黙って上書きされない）
   → **期待（Q）**: 保存先を決めた後、**子の一覧（トリガー一覧 + f1 + f2）が出る**。
     既存の同名 sequence（`config/user/sequences/f1.json` 等）があれば**既定は別名保存**
4. 保存後、元の keymap_set ファイル / 元のトリガー一覧ファイルを開いて**変更されていない**ことを確認
