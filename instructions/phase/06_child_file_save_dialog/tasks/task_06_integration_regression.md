# task_06_integration_regression

## 目的

暫定仕様 05 §10 の**受入条件 1〜11 を通す統合退行**。task_01〜05 で入った挙動変更が、
条件ごとに**どのテストで固定されているか**を対応付け、**未固定の条件にテストを足す**。
既存の特性テストが旧挙動を前提にしていないかを点検し、必要なものだけ期待値を更新する。

- レイヤ制約: **テストと検証結果文書のみ**。**production コードは原則変更しない**
  （受入条件を満たさない不具合が見つかった場合のみ、最小修正 + 本タスク定義への追記）。
- **実機目視はユーザーが行う**（本タスクで実施。チェックリストは下記 4）。

## 対象範囲（テスト + 検証結果文書のみ）

### 1. 既存特性テストの点検と更新

- `tests_ui/test_config_io_characterization_keymap_set_startup.py`（`save_keymap_set` 系 20 箇所）:
  現在は**ダイアログを経由せず pass している**（fake app / mock 経由）。
  **各テストが「ダイアログを通らない理由」を確認**し、次のいずれかへ整理する。
  - 意図的にダイアログを迂回している（＝ 保存経路の別の側面を見ている）→ **そのまま**。
    ただし新経路が挟まったことを 1 行コメントで明示する
  - 実挙動と乖離している（旧挙動を固定している）→ **期待値を更新**する
- `tests_ui/test_config_io_characterization.py` / `tests/test_config_service.py` は
  **後方互換の担保**（`_parent_refs` 無しの既存 JSON・保存 JSON の完全一致アサート）として
  無修正で pass する状態を維持する。**アサーションを緩めない**（phase 04 からの運用）。

### 2. 受入条件 1〜11 の対応表と不足分の追加

`instructions/phase/06_child_file_save_dialog/integration_result.md`（**新規**）に対応表を作る。

| 列 | 内容 |
|---|---|
| # | 受入条件の番号（暫定仕様 05 §10） |
| 条件 | 条件の要約（1 行） |
| 固定テスト | `<ファイル>::<テスト名>`（複数可）。自動化できないものは「実機目視」 |
| 結果 | pass / fail / 目視 OK |

- **各条件に最低 1 つの固定手段**を割り当てる。既存テストで満たせるものは既存を挙げ、
  **不足分だけテストを追加**する（新規テストの追加先は `tests/` か `tests_ui/` の
  既存ファイルに寄せ、**新規ファイルは作らない**）。
- 特に**まだ固定されていない可能性が高い条件**（起票時点の見立て。実測で判断すること）:
  - **条件 4**（別の keymap_set に属する子 → 既定が別名保存）: `SHARE_OTHER_PARENT` の
    行が実際に一覧へ出るところまでの通し
  - **条件 5**（共有ファイルは「N 個で共有中」警告つきで上書きを選べる）
  - **条件 7**（保存途中で失敗しても親索引が旧状態のまま取り残されない）:
    子の書き込みを 1 つだけ失敗させ、**親 keymap_set.json の索引が旧パスのまま**であることを確認
  - **条件 8**（複数 keymap_set を `config/user/keymap_sets/` に保存しても trigger_set が
    keymap_set 名基準で分離され既定では互いに上書きしない）: 2 セットの通し
  - **条件 9**（trigger_set の source_path が keymap / sequence と一貫して扱える = idea_05 解消）
- **保存 JSON の比較はバイト列**で行う（暫定仕様 §10 の安全網）。

### 設計メモ / 制約

- 本タスクは**確認が主目的**。テストを通すために production の挙動を変えたくなったら、
  **それは受入条件との乖離**なので `.claude/rules/spec_change_workflow.md` に従い報告する
  （独断で仕様を緩めない）。
- 新規テストは**受入条件に紐づくものだけ**追加する（網羅率を上げるための追加はしない）。
- 条件 7（失敗時の旧索引維持）は task_03 の実装契約。**再実装せず、外から観測できる形で固定**する
  （書き込み失敗の注入は monkeypatch で行い、`os` を広くモックしない）。
