# task_09c_input_acceptance

## 目的

暫定 29 v0.6 §4.7 の**application 側**を実装する: トリガーの押下の受け付け（処理中は他を無視・止まっている間は受け付ける）/ 単発の呼び出しの一時停止 /
単発の待機が処理中に明けたときの扱い / 一時停止中のものを「確認して捨てる」口（確認そのものは callback で受け取り、ダイアログは task_09d）。

> 注意: 仕様書の `f5` は例示のキー。実装・テストは実際のキーを使う。

## 対象範囲

1. **押下の判定**（`sequence_runner.py` `handle_key`）: §4.7「押下の扱い」の 1〜3 の順に判定する。
   - 処理中 = 連続実行の実行中（一時停止していない）/ 単発の file_line の読込中 / 単発の呼び出し中（一時停止していない）。
   - 連続実行の一時停止中は他の単発のトリガーが動く（今の「連続実行中は同じキー以外を return」を改める）。
   - 他のトリガーの連続実行の開始: 一時停止中のもの（連続実行・単発の呼び出し）があれば「確認して捨てる」（下の 4）を通し、OK なら捨てて開始・それ以外は何もしない。
     無ければ既存どおり（単発の待機の保留は既存どおり取り消し）。
   - `sequence_runner.py` は 542 行あるため、判定・一時停止・確認の処理は**新しいモジュール**（例: `sequence_runner/input_acceptance.py` の mixin。既存の `call_wait.py` 等と同じ形）へ置く。
2. **単発の呼び出しの一時停止**（`call_wait.py`・`PendingStep`）: 処理中の単発の呼び出しのキーを押すと一時停止・もう一度で再開（§4.7「単発の呼び出しの一時停止」）。
   - 次のステップの予約を取り消し文脈を保持（文脈の中の待機は残りを捨てる・file_line の読込中は結果を捨てて再開時に読み直す＝連続実行の一時停止と同じ）。保留は残し、履歴は積まない。
   - 再開は最上段の呼び出し先の間隔の後に続きから。一時停止の状態は `PendingStep` に持たせてよい（フィールド追加）。
   - 一時停止中の単発の呼び出しを打ち切る既存の契機（停止操作・キーマップの切替・位置変更・編集・構成セットの読込）は既存どおり打ち切り（確認なし）。
   - 単発の file_line の読込中・待機中に同じキー → 既存どおり無視。
3. **単発の待機が明けたとき**（`sequence_runner.py` `_resume_single_wait`）: 処理中のもの（上の定義。一時停止中は数えない）があれば、何も送らず、
   待機の次から**先行処理**をして位置を「次に実行」する行に合わせ、その押下を終える（戻す履歴は既存の規則で状態が変わっていれば 1 段）。次の押下でそこから続ける。
4. **確認して捨てる口**: runner に「一時停止中のものの一覧（キー）」「確認して捨てる」を用意する。
   - 捨てる = 停止操作による打ち切りと同じ（単発の呼び出し = 位置は呼び出しの行・§4.5 の打ち切りの履歴 / 連続実行 = `stop_run_to_end` と同じ）。
   - 確認は runner に注入する callback（例: `confirm_discard(keys) -> bool`。未注入なら確認なしで True とみなすか、テストで差し替えられる形）。
   - **callback を呼んでいる間**は「確認中」の印を立て、`handle_key` はすべて無視する。presentation が参照できるよう印を公開する（キーマップの切替キーの無視は task_09d）。
   - **OK の後の照合**: 呼ぶ前に状態（一時停止中のもの〔キーと世代〕・処理中の有無・単発の保留の集合・戻す / 先頭への対象のキー）を控え、OK の後に変わっていれば元の操作をやめ何も捨てない。
   - 捨てる範囲: 連続実行の開始・キーマップの切替 = 一時停止中のもの**すべて** / 戻す・先頭へ = **対象だけ**。
5. **戻す / 先頭へ**（`sequence_history.py` `apply_control` と runner `_control`）: 対象が一時停止中の連続実行・単発の呼び出しなら「確認して捨てる」を通し、OK なら対象を捨ててから実行。
   キャンセル・照合でやめた場合は既存の「保留中の対象の拒否」と同じ扱い（拒否のメッセージは出さない）。処理中のもの（単発の file_line・呼び出し中、待機）が対象なら既存どおり拒否。
   確認を差し込む形（対象の決定を分ける / callback を渡す）は実装者の判断でよい。
6. **キーマップの切替の可否**（`app_state.py` `can_switch_keymap`）: 連続実行が**実行中**（一時停止していない）のときだけ拒否に改める。
   一時停止中の確認・捨てる処理の呼び出しは presentation（task_09d）が 4 の口を使う。
7. **テスト**（`tests/`）: 受け入れ条件 §8-4b の application 部分。少なくとも:
   単発の file_line / 呼び出しの実行中に他の単発・連続実行の開始・一時停止中の再開が無視される / 待機中は他が動く /
   単発の呼び出しの一時停止 → 他の単発が動く → 再開で続きから（同じ入力を二度送らない・呼び出し先の間隔の後）/
   連続実行の一時停止中に他の単発が動く / 一時停止中の連続実行・単発の呼び出しがあるときの別の連続実行の開始: 確認 OK で捨てて開始（1 段）・キャンセルで何も変わらない・確認中に状態が変われば何もしない /
   確認中の押下は無視 / 戻す・先頭へで対象が一時停止中: OK で捨ててから実行・キャンセルで何も変わらない / 待機が処理中に明けると何も送らず先行処理後の位置で終え、次の押下で続き /
   `can_switch_keymap` が一時停止中は True。既存テストで「連続実行中は他のトリガーを無視」を前提にしたものは、実行中（一時停止していない）の前提に合わせて直す（一時停止中を前提にしていたものは仕様変更に合わせて期待を変える）。

## 申し送り（task_09b のレビューの参考）

- `call_run_to_end.py` `_run_to_end_call_matches` の `token + 1 == current_token` は一時停止 1 回分のずれしか吸収しない。通知の表示中に一時停止 → 再開 → 一時停止を繰り返すと照合が外れる。
  一時停止の処理を触る際に、トークンの扱いを一時停止の回数に依らない形にできるなら直す（必須ではない。直した場合はテストを 1 件足す）。
