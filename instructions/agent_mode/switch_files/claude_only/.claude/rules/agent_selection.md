# エージェント選択ルール（Claude のみモード）

作業種別ごとの「メインセッションで行うか / どのサブエージェントへ委任するか」の基準。
Codex CLI を使わない環境向けの構成。実装・レビューとも Claude 系エージェントで完結させる。
（Codex 併用構成への切り替えは `instructions/agent_mode/switch_agent_mode.py`）

---

## ■ 実装（コードを書く作業）

### 既定: `implementer`

- タスク定義に基づく実装は、原則 `implementer` エージェントへ委任する
- 呼び出し時は以下をプロンプトに含める
  - 対象タスク定義ファイルのパス
  - 実装対象範囲と対象外の明記
  - **タスクに対応する単体テストの実行まで**を実装範囲に含めること

### メインセッションが直接行ってよい作業

- 数行程度の軽微な修正（typo・定数値・ドキュメント修正等）
- state ファイル（`.claude_data/state/` 配下）やタスク文書の更新
- フェーズ末の正本反映タスク（ユーザー承認済み内容の `spec_detail/` への転記。文書作業のため）

上記以外の実装をメインセッション自身が行うことは不可
（実装とレビューの分離・コンテキスト汚染防止のため）。

---

## ■ 起票・調査

- 暫定仕様書・phase.md・タスク分割の起票は**メインセッション**が行う
  （ユーザーとの反復確定が必要なため）
- 起票前の既存コード調査・影響範囲調査・「このフェーズで読むファイル」選定は、
  読み取り専用の **`Explore` エージェント**へ委任し、結論（ファイルパス + 要点）のみ受け取る。
  メインセッションがソースを広く直読みしてコンテキストを肥大させない

---

## ■ 動作確認・テスト実行

- タスク単位の単体テスト実行は実装委任に含める（上記 implementer への指示事項）
- 統合確認（テストスイート全体・smoke 等）は **`verifier` エージェント**へ
  委任し、メインセッションは pass/fail + 失敗詳細の要約のみ受け取る
  （テストの生ログをメイン文脈へ載せない）。判定・完了宣言はメインセッションが行う
- `/refactor_check` のメトリクス収集（手順 1〜2・M1〜M6）も `verifier` へ委任する
  （判定〔手順 3 以降〕と提案書起票はメイン）
- 実機目視はユーザーが行い、結果をメインセッションへ報告する

---

## ■ レビュー

| タイミング | 使用エージェント |
|---|---|
| 各タスクの必須レビュー（CLAUDE.md「レビュー（必須）」） | `reviewer`（`.claude/rules/review.md` の5観点） |
| 暫定仕様書のユーザー確定前 | `reviewer`（仕様レビュー観点を明示して依頼） |
| 統合テスト・複数タスクを跨ぐ動作確認時 | `reviewer`（統合観点を明示して依頼） |
| フェーズ完了判定前・設計判断に不安がある時 | `reviewer`（敵対的レビュー観点を明示して依頼） |

- **レビュー・検証エージェントの起動はメインセッションの責務**。サブエージェントはサブエージェントを
  起動できないため、implementer 等へ「reviewer に依頼せよ」と指示しない（実行不能・自己申告の温床）
- 実装者（implementer）とレビュアー（reviewer）は同系モデルのため、レビュー依頼文に
  **実装の経緯・実装時の判断を前提にしない**こと（差分と仕様だけから判定すること）を明示し、
  別視点レビューとして成立させる
- **暫定仕様レビュー**の観点指定例: 「`instructions/history/NN_<topic>.md` の仕様内容を対象に、
  前提の誤り・未定義挙動・条項間の矛盾・実装可能性・正本 spec_detail との整合を疑う」
- **敵対的レビュー**の観点指定例: 「実装方針・設計判断・前提条件を疑い、弱点・見落とし・
  より単純な代替案がないかを挙げる」
- レビューの指摘は提示のみで、修正・採否はユーザー確認を経て決める
- 各タスクの必須レビューと、統合テスト時・フェーズ区切りの二次レビューは別インスタンスで実施し、
  どちらか一方だけで完了判定を確定させない

---

## ■ 禁止事項

- ユーザー確認なしでメインセッション自身が実装を代行すること
  （「メインセッションが直接行ってよい作業」に該当する軽微な修正を除く）
- `implementer` の結果を無レビューで完了扱いにすること
- 統合テスト・フェーズ完了時・暫定仕様確定前のレビューを、報告なしに省略すること
