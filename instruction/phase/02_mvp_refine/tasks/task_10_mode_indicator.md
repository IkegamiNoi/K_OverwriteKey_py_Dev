# task_10_mode_indicator.md

## 配置層

presentation のみ

## 目的

現在のモードを画面上で視認できる UI を追加する。
特に **通常モードとビューモードで WASD の意味が変わる** ため、誤操作防止の観点から必須。

仕様正本:
- `instructions/common/spec_detail/key_input.md` §3 補足「現在モードを視認できる UI を用意する」
- `instructions/common/spec_detail/features.md` 4.10（モード横断のマウス操作と固有挙動）

---

## 実装内容

### A. 表示位置

- 既存の key_guide フッター（`src/presentation/key_guide.py`）に併記する案
  - フッター先頭または末尾に「[NORMAL]」「[VIEW]」「[GRID]」等のラベル
- もしくはキャンバス左上にオーバーレイ表示する案
- 私見: **フッター併記**が最小差分

### B. モード表示文字列

| Mode | 表示 |
|---|---|
| NORMAL | 通常 |
| EDIT | 編集 |
| VIEW | ビュー |
| GRID | グリッド |
| CUSTOM_CREATE | カスタム作成 |
| CONNECT | 接続 |
| HELP | ヘルプ |

### C. 視認性

- 現在モードのラベルは太字 / 色変更などで目立たせる
- モード切替時に即座に表示更新（既存のモード変更通知に乗せる）

### D. key_guide の連動

- 現在モードに応じてフッターのキー説明を切り替える既存機構があれば流用
- なければ最小限のモード別表示を追加

---

## 要件

- domain / application 層は変更しない
- 既存のキャンバス描画 / レイアウトに大きな影響を与えない
- フッターの高さが大きく変わらないこと

---

## 完了条件

### 機能面

- 各モードに遷移するとフッター（または該当 UI）の表示が切り替わる
- 通常モードとビューモードでフッターのキー説明が異なる
- グリッドモード時の対象軸 / スコープ / 選択ライン情報も視認できる（task_05 と連携）

### 静的確認

- `compileall` クリーン

### レビュー

- サブエージェントレビュー（視認性 / 不要変更の有無）

---

## 注意事項

- task_04 / task_05 完了後に着手するのが自然
- フッターに収まらない情報量になる場合は、別 UI（オーバーレイ等）を検討
- アクセシビリティ（コントラスト等）に最小限配慮
