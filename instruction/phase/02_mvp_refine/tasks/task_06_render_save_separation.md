# task_06_render_save_separation.md

## 配置層

presentation のみ

## 目的

グリッドの **描画範囲と保存範囲を分離** する。
描画は保存範囲（`MapState.columns` / `rows`）に依存せず、ビューポートに応じて決定できる構造に整える。

このタスクは描画リファクタの **土台** であり、実際の無限描画ロジックは task_07、縮小時非表示は task_08、自動拡張は task_09 で実装する。

仕様正本:
- `instructions/common/spec_detail/viewport.md`「描画範囲と保存範囲の分離」
- `instructions/common/spec_detail/features.md` 4.4「描画範囲と保存範囲の分離」

---

## 実装内容

### A. 概念整理

- **保存範囲**: `MapState.columns` / `rows` で定義された行 / 列の集合（既存）
- **描画範囲**: ビューポートに表示される領域に対応する行 / 列のインデックス範囲（新規概念）
- 両者は独立。保存範囲を超える「仮想的な」行 / 列も描画対象になりうる

### B. `src/presentation/coordinate_system.py` の整理

- `world_extent` / `column_x_positions` / `row_y_positions` は保存範囲に依存（既存）
- 新規: 「ビューポートに表示される範囲のグリッド線位置」を計算する関数を追加
  - 例: `visible_grid_lines(view_state, screen_width, screen_height, default_width, default_height) -> list[float]`
  - 戻り値はワールド座標での描画線位置リスト（保存範囲外も含む）
- 既存の保存範囲ベースの関数は維持（ノード描画 / ヒットテスト等で使用継続）

### C. `src/presentation/painters.py` `draw_grid` の整理

- 現状: 保存範囲のグリッド線のみ描画（`xs + [width]` 等）
- 変更後（このタスクではインターフェースだけ整える）:
  - `draw_grid` は「描画範囲を計算 → 線を引く」の構造にする
  - 描画範囲は B で追加する関数で取得
  - **本タスクでは保存範囲とビューポートの交差で動作するように整える**（実質既存と同じ範囲を描画）
  - 無限描画への拡張は task_07 で実施

### D. ノード描画 / エッジ描画

- 保存範囲ベースのまま無変更（保存範囲外にはノード / エッジは存在しない）
