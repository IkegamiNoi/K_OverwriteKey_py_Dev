# レビュー目的

* アプリとしての一連の流れが成立しているか確認する
* 設定・保存・読込・再描画の整合性を確認する
* MVP として実用に耐えるかを評価する

# 設定観点

* [ ] 設定ファイル読込の責務が infrastructure に収まっている
* [ ] 設定値が application / presentation へ適切に渡される
* [ ] クイック作成マス数などが実際に反映される
* [ ] 将来のキー割り当て差し替えを妨げない構造になっている

# 保存・読込観点

* [ ] UI から保存できる
* [ ] UI から読込できる
* [ ] 保存後の状態が壊れていない
* [ ] 読込後に描画が正しく再現される
* [ ] エラー時の表示が分かりやすい
* [ ] 不正ファイル読込時に破綻しない

# 統合観点

* [ ] presentation → application → domain の流れが自然
* [ ] infrastructure 呼び出しの経路が整理されている
* [ ] UI イベントとユースケースが密結合していない
* [ ] 再描画タイミングが適切
* [ ] 状態更新と表示更新にズレがない

# MVP成立観点

* [ ] ノード作成ができる
* [ ] ノード編集ができる
* [ ] 接続ができる
* [ ] クイック作成ができる
* [ ] カスタム作成ができる
* [ ] 保存 / 読込ができる
* [ ] スクロール / パン / ズームができる
* [ ] 主要なエラーに対して最低限のフィードバックがある

# 安定性観点

* [ ] 起動時に落ちない
* [ ] 主要操作でクラッシュしない
* [ ] 空データや最小データでも動作する
* [ ] ノード数が少ない場合と多い場合の差が極端でない
* [ ] 入出力異常時のハンドリングが最低限ある

# 保守性観点

* [ ] PySide6 固有実装が presentation に閉じている
* [ ] 仕様書との差分が整理されている
* [ ] 今後の拡張ポイントが把握しやすい

# ブロック完了判断

* [ ] MVP として一通り使用可能
* [ ] 次の拡張フェーズへ進めるだけの安定性がある
* [ ] 修正すべき設計課題が一覧化されている
