# レビュー目的

* PySide6 による描画基盤が妥当か確認する
* ワールド座標とビュー座標の分離が成立しているか確認する
* スクロール・パン・ズーム前提の描画構成が崩れていないか確認する
* 今後の入力・編集機能を乗せられる土台になっているか確認する

# UI基盤観点

* [ ] メインウィンドウとキャンバス領域の責務が分かれている
* [ ] PySide6 依存が presentation 層に閉じている
* [ ] キャンバスが今後の入力処理を受けられる構造になっている
* [ ] ステータスバーや補助表示の受け皿がある

# ViewState観点

* [ ] ビュー原点が管理されている
* [ ] ズーム倍率が管理されている
* [ ] ワールド座標 → ビュー座標変換がある
* [ ] ビュー座標 → ワールド座標変換がある
* [ ] 描画とヒットテストで同じ変換基盤を使える
* [ ] ViewState が domain に漏れていない

# 描画観点（共通）

* [ ] 描画処理が domain/application に侵食していない
* [ ] 描画用の補助計算が presentation に閉じている
* [ ] パン後も描画が破綻しない
* [ ] ズーム後も描画が破綻しない
* [ ] 画面サイズ変化に対して極端に壊れない

# グリッド描画観点

* [ ] rows / columns の定義を正しく反映している
* [ ] 間隔変更に追従できる設計になっている
* [ ] 交点の位置がノード描画と整合する
* [ ] ズーム時も位置ずれしない

# ノード描画観点

* [ ] ノードの位置がグリッド交点と一致する
* [ ] ノード選択状態が視認できる
* [ ] テキスト表示が基本的に成立している
* [ ] ズーム時の視認性が極端に悪化しない

# 接続線描画観点

* [ ] 構造から線が自動生成されている
* [ ] 選択ノードの関連線ハイライトができる
* [ ] ノード移動やグリッド変更時に線位置が追従する前提になっている
* [ ] 交差しても最低限破綻しない

# 性能観点

* [ ] ノード数が増えても描画設計が極端に悪化しにくい
* [ ] 毎回不要な再計算をしていない
* [ ] ビュー変換の実装が不必要に複雑化していない

# ブロック完了判断

* [ ] 入力処理を追加しても描画基盤を大きく崩さずに進められる
* [ ] スクロール・パン・ズーム前提の土台ができている
* [ ] 次ブロックへ進めるだけの安定性がある
