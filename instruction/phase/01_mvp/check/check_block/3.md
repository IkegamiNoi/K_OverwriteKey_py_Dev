# レビュー目的

* 入力処理と表示処理の責務分離が保たれているか確認する
* key_input_policy.md と実装の整合性を確認する
* 編集モード・通常モード・ビュー操作が競合していないか確認する
* ユーザー操作の体験として破綻がないか確認する

# 入力処理観点

* [ ] キー入力が直接業務ロジックを呼んでいない
* [ ] キー入力 → アクション → 実処理 の流れになっている
* [ ] マウス入力が必要最小限の責務に収まっている
* [ ] ホイール入力がビュー操作として扱われている
* [ ] 選択状態管理が一貫している

# key_input_policy 整合性観点

* [ ] モード構成が方針書と一致している
* [ ] 通常モードのキー割り当てが一致している
* [ ] 編集モードの Enter / Esc の扱いが一致している
* [ ] カスタム作成モードの移動キーが一致している
* [ ] 接続モードの移動キーが一致している
* [ ] ヘルプ / ダイアログの優先順位が一致している
* [ ] IME 制御方針と実装が矛盾していない
* [ ] 将来のキーマップ差し替えに耐えられる構造になっている

# 編集モード観点

* [ ] 編集開始時に適切にフォーカスが移る
* [ ] 編集終了後にフォーカスがキャンバスへ戻る
* [ ] Enter が改行として扱われる
* [ ] 確定操作が仕様通り動く
* [ ] Esc のキャンセル動作が仕様通り動く
* [ ] IME 未確定状態の Esc 優先処理が考慮されている
* [ ] 編集中に通常ショートカットが誤発火しない

# ビュー操作観点

* [ ] スクロールが自然に動く
* [ ] パンが自然に動く
* [ ] ズームイン / ズームアウトが自然に動く
* [ ] ズーム後のクリック位置が正しく解釈される
* [ ] 選択ノードへのフォーカス移動が破綻しない
* [ ] 表示倍率リセットが機能する
* [ ] 全体表示が最低限成立する

# ガイド・フィードバック観点

* [ ] 現在モードに応じたキーガイドが表示される
* [ ] 実際の操作と表示されるガイドが一致する
* [ ] クイック作成失敗時に理由が分かる
* [ ] エラー表示が不足していない
* [ ] 状態表示が誤解を生まない

# UX観点

* [ ] 通常操作の流れが重くない
* [ ] 操作の予測可能性が保たれている
* [ ] 編集・作成・接続・ビュー移動のモード境界が分かりやすい
* [ ] 学習コストを下げる表示が機能している

# ブロック完了判断

* [ ] 主要操作が一通り自然に使える
* [ ] 入力と表示の責務分離が保たれている
* [ ] 統合フェーズへ進めるだけの完成度がある
