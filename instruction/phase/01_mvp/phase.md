# phase.md

## フェーズ名

Python / PySide6 初期MVP実装フェーズ

---

## フェーズの目的

Python + PySide6 によるマインドマップアプリの MVP を、task 単位で順番に実装する。

このフェーズは、まだ対象機能が未実装である前提で、仕様に沿って `01_mvp/tasks/task_01_*.md` から順番に積み上げるためのフェーズである。

---

## このフェーズで読むファイル

以下を順に読むこと。

1. `common/app_overview.md`
2. `.claude/rules/` 配下のポリシー（存在する場合）
3. `01_mvp/check/check.md`
4. 対象の `01_mvp/tasks/task_XX_*.md`

### 必要な場合のみ追加で読む

- task に直接関係する補助資料
- task 実装に必要な最小限の関連ファイル
- 該当ブロックのレビュー用チェックリスト

---

## このフェーズの前提

- MVP は未完成である
- 実装は `task_01` から順番に行う
- 未完了タスクを飛ばさない
- 各タスクは独立に完了判定する

---

## このフェーズで優先すること

- 仕様通りに順番に実装する
- Python / PySide6 に適した構成へ落とし込む
- domain / application を UI 非依存に保つ
- presentation 層だけに PySide6 依存を閉じ込める
- 各タスクを完了まで持っていく
- タスクごとに評価と修正を行う
- ブロック完了時に横断レビューを行う
- 後続タスクの先取り実装を避ける

---

## このフェーズで守ること

- タスクは必ず `task_01` から順番に実施する
- 1タスクごとに実装・確認・修正・完了判定を行う
- 評価を飛ばさない
- 必要最小限のファイルのみ読む
- 仕様・タスク・チェックリストの不整合を見つけた場合は、勝手に拡張せず最小修正で整合させる

---

## このフェーズで禁止すること

- 全 task の一括読込
- 無関係なファイル探索
- タスク外の機能追加
- 後続タスクの先取り実装
- 無関係なリファクタ
- 大規模構造変更
- domain / application への PySide6 import
- ビュー状態を保存対象の layout データへ混入させること

---

## 基本作業順

1. 対象 task を読む
2. 関連する共通仕様を最小限読む
3. 実装方針を決める
4. 実装
5. 動作確認またはテスト
6. `01_mvp/check/common_check.md` でタスク単体評価
7. 指摘があれば修正
8. 完了判定
9. ブロック末尾なら `01_mvp/check/check_block/` の該当ファイルで横断評価
10. 次の task へ進む

---

## 完了条件

- 各 task の完了条件を満たしていること
- `01_mvp/check/check.md` の観点で問題がないこと
- サブエージェントレビューを完了していること
