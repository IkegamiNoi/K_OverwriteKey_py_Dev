# task_check.md

> EDIT REQUIRED: 「層の責務」「テスト・確認」のコマンド・「仕様書との整合」の保存ファイル名は
> プロジェクトのアーキテクチャ・言語に合わせて書き換えること（以下は Python / オニオン構成の例）。

各フェーズのタスク完了時に共通で確認するチェックリスト。

タスク単位で参照すること。フェーズ固有の確認項目は各タスクファイル / フェーズの `phase.md` 側に持つ。

---

# 完了条件
- [ ] タスクに記載された完了条件を満たしている
- [ ] 実装内容がタスクの目的から逸れていない
- [ ] 不要な機能追加をしていない
- [ ] 仮実装 / TODO / デバッグ出力を残していない

# 層の責務
- [ ] 指定された層に実装されている
- [ ] 他層の責務を持ち込んでいない
- [ ] オニオンアーキテクチャの依存方向を壊していない（domain / application は PySide6 非依存）

# 保守性
- [ ] ハードコード過多になっていない
- [ ] 今後の拡張を妨げる密結合がない
- [ ] 命名が役割に合っている

# テスト・確認
- [ ] 最低限の動作確認を行った
- [ ] 追加したロジックに対する確認方法が明確
- [ ] 既存機能を壊していない
- [ ] `python -m compileall` がクリーン
- [ ] 既存テストがあれば実行している

# サブエージェントレビュー
- [ ] 別エージェント（reviewer）によるレビューを実施した
- [ ] レビュー観点（仕様適合性 / 依存方向 / 責務分離 / 不要変更の有無 / チェック漏れ）を確認した
- [ ] レビュー判定（採用 / 修正して採用 / 保留 / 除外）を明示した
- [ ] 必要に応じて `.claude_data/state/decisions.md` に判定を記録した

# 仕様書との整合
- [ ] 仕様書（`instructions/common/spec_detail/`）を独断で書き換えていない
- [ ] 仕様変更が必要な場合は `.claude/rules/spec_change_workflow.md` に従って報告した
- [ ] 既存の保存ファイル（layout.json 等）/ JSON フォーマットを壊していない

# 想定外の先行実装
- [ ] 想定外の差分を発見した場合は `.claude/rules/anti_patterns.md` 第9項に従って判定した
- [ ] 採用 / 修正して採用 / 保留 / 除外 のどれかを明示した
