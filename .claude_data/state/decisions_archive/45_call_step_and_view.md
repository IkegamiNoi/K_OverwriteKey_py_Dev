## 確定した設計判断（ユーザー）

| # | 判断 | 採らなかった案と理由 |
|---|---|---|
| 1 | 呼び出しの行ごとにステップ（既定）/ 一括を選ぶ。JSON は `all: true` = 一括・表示 `[call]` / `[call all]`・チェックボックス「一括で実行」（v0.5・task_01〜03a の実機目視で反転） | 一括を既定・`step` キー = 新しい機能で利用が少なく、読みやすさを優先 / 表示 `force` = 意味が伝わりにくい |
| 2 | `all` の無い既存の呼び出しの行はステップで動く（移行しない） | 読込時の置き換え = 利用が少ないので不要 |
| 3 | 連続実行が呼び出し先の停止の行に達したら連続実行の一時停止（続きがあれば）/ 完了まで進んだら終える | 呼び出し先の停止は読み飛ばす（phase 40 のまま）= 停止が効かない不満の原因 |
| 4 | **写し・呼び出し文脈をやめ、呼び出し元と呼び出し先を参照で連動させる**（v0.6・task_05 の実機目視）。呼び出し先の状態は 1 つ・今の位置から呼ぶ・参照中の印が無ければ連動しない・複数の呼び出し元が同じ呼び出し先を参照してよい | 開始時点の写し（v0.5）= 呼び出し先を選んでも進みが見えず、表示の枠と実体が食い違う |
| 5 | 戻す履歴は各トリガーが自分の状態だけを持ち、同じ押下の番号の段が一番上のトリガーをまとめて戻す（ユーザー提案） | 押した側に連鎖全体を積む = 交互に進めると上書きする |
| 6 | 「送った」は連続実行 1 回ごと（連鎖のどの段でも数える）。v0.5 の §10-4a（一括の互換）は置き換え | 文脈ごとの印（v0.4〜v0.5）= 連動では文脈が常駐しない |
| 7 | 呼び出し先の表示枠 = 常設の Expander（起動時は閉・印が立つと自動で開く・自動では閉じない・開閉はトリガーごとでメモリ上・見出しのクリックで開閉）。フル表示は出力シーケンスの一覧の下・省略表示はトリガー一覧の下（省略表示にも出す = ユーザー指示）。境界線は控えめ。高さはフル / 省略で別に `config.json` へ | 止まったときだけ開いて消える（v0.5）= ちらつく / 省略表示には出さない（推奨案だった） |
| 8 | 実行中の連続実行の連鎖の呼び出し先はダイアログを経ない操作で変えない（一時停止中は可・M3「実行中に動作が変わる処理はしない」）/ 一時停止中の連続実行のトリガーが呼び出し先として末尾に達したら終える（M4）/ 伝播で一時停止中の呼び出し元を進めるとき待機・停止の行で止める（L1）/ まとめて戻す対象のどれかが待機中・一時停止中なら対象と同じ扱い（L2） | — |
| 9 | 連続実行の T が待機中の呼び出し先 U を呼ぶときは §4.2.10 の単発の待機の取り消しを優先（無視は単発の T だけ・2026-10-05） | 連続実行でも無視 = 連続実行の開始で単発の待機を取り消す既存規則と矛盾 |
| 10 | ダイアログを開いたとき（フック停止）は処理中の予約だけを取り消し、位置と印は残る（v0.6 で v0.4 の「打ち切りの受容」を解消） | — |
| 11 | （完了判定前レビュー M1）単発の呼び出しの一時停止で各トリガーへ書き戻して履歴を積む（実装のまま・戻すは止めた時点で区切られる） | 1 押下で 1 段にまとめる = 一時停止中に連鎖のトリガーが動くと状態が食い違う |
| 12 | （M2）単発の呼び出しの実行中に連鎖の呼び出し先の位置・内容を変えたら、その呼び出しを取り消し変えた位置を優先（待機・file_line と同じ・task_07a） | 連続実行と同じく断る / 上書きを受容 |
| 13 | （M3）呼び出し先の完了で外から進めた呼び出し元の次の待機は待たない（受容） | 次の押下の頭で待つ = コード変更に見合わない |
| 14 | （M4）呼び出し先が単発の呼び出しの一時停止中なら捨てて（通知）進める（task_07a） | 黙って無視（実装の当初）= 何も起きない理由が分からない |

## メイン判断（実装中・正本へ反映済み）

- 呼び出し元のキー変更で参照中の印は新しいキーへ移る（§4.5.1 の「キー変更で消える」を既存の rekey と揃えた・task_11）
