## 確定した設計判断（ユーザー）

| # | 判断 | 採らなかった案と理由 |
|---|---|---|
| 1 | 同じトリガー一覧のトリガーキーで参照し、先頭から末尾まで一括で実行して戻る（呼び出し先の位置は変えない・単発でも 1 押下で丸ごと） | ジャンプ = 位置の飛び先が分かりにくい（暫定 26 §13） |
| 2 | **開始時点のコピー**（辿れる呼び出し先を深さ 9 まで・内容と間隔）だけで最後まで実行（v0.3・Codex 敵対的） | 実行中に都度引く = 途中の編集・改名で挙動が変わる |
| 3 | 入れ子は深さ 9 まで・循環は編集時に拒否し実行時も検出・無限ループは実行時エラーのみ | 編集時の無限ループ検査 = 後からの編集を捕まえられない |
| 4 | 間隔 = 呼び出し先の「間隔(ms)」（連続実行 OFF でも欄を編集可能・見出しは据え置き〔v0.4・幅 780〕） | 呼び出し元の間隔 = 部品ごとの調整ができない |
| 5 | 打ち切りは呼び出しの行に残し次の押下で最初から / 戻す履歴は状態が変わったときだけ 1 段（呼び出し先のカウンター差分を含む） | 途中から再開 = 文脈を長く保持する必要 |
| 6 | キー変更で同じ一覧の呼び出しの `target` を書き換える・グレー表示のトリガーも呼べる・表示 `[call] f5（ラベル）` | — |
| 7 | 上限 10,000 は呼び出しの 1 ステップ全体で入れ子をまたいで通算（v0.5）・送る前と後の先行処理も通算（v0.9） | 段ごとに数える = 送るものの無い呼び出しが止まらない |
| 8 | **処理中（連続実行の実行中・単発の file_line 読込中・単発の呼び出し中）は他のトリガーを無視 / 止まっている間（待機・一時停止）は受け付ける**・単発の呼び出しにも一時停止（v0.6・実機目視） | 「呼び出し中も他のトリガーは動く」（暫定 28 §9）= 送信が混ざる |
| 9 | 一時停止中のものを捨てる操作は**ステータスバーの通知**（他の連続実行の開始・キーマップの切替 = 捨てて通知 / 戻す・先頭へ = 2 回押し）（v0.7） | 警告のダイアログ（v0.6）= 操作中のアプリからフォーカスを奪う（実機目視で不可） |
| 10 | **待機は直前に送った行の後の待ち**（送った後の先行処理で同じステップの中で待つ・明けても送らない / 送る前に達した待機は読み飛ばす / 連続実行は待機の前に間隔なし / 止めた後・停止の後は続く待機も読み飛ばす）（v0.8・実機目視） | 待機の行で押すと待つタイマー型（v0.7 まで）= 個別の間隔として使いにくい |
| 11 | 戻す / 先頭へだけのトリガーは連続実行 ON でも先に捨てず 2 回押し（v0.9・完了判定前レビュー） | 連続実行の開始として全部捨てる = 2 回押しの規定と衝突 |
