## 問題

**ダイアログを開いたままアプリを最小化（Win+D）すると、二度と復元できない**。
シェルの復元要求が**非表示になった grab 保持者へ向かい**、App に `<Map>` が届かない（実測で確定。
**phase 16 由来ではない**ことも実機で確認）。再現手段は `instructions/phase/17_minimize_grab_custody/diagnostics/`。

## 確定した設計判断（ユーザー 2026-09-16・暫定仕様 §2）

| # | 判断 | 採らなかった案と理由 |
|---|---|---|
| 1 | **最小化の間だけ grab を預かる**（App の `<Unmap>` で外し `<Map>` で張り直す） | (a) ダイアログ側で自窓の `<Unmap>` を拾う = **`iconify()` では子に `<Unmap>` が飛ばず**、Win+D と通常最小化で挙動が割れる |
| 2 | **復元は WM 任せ**（`deiconify` / `lift` / `focus_force` を呼ばない） | 触ると**中間窓が消える**（実測） |
| 3 | **預かるのは非表示になった保持者だけ**（v0.4） | 無条件に外すと、`transient` を持たない窓等**最小化で隠れない表示中のモーダルから grab を奪う** |
| 4 | **保持者が消えていたら生存かつ表示中の最内モーダルへ張り直す** = `modal.py` に**台帳**を持つ | 案 (ii) `winfo_children()` の走査 = どれがモーダルか判定できない |
| 5 | **預かり中に開いたモーダルは預かり窓を直前の保持者にする**（v0.4） | しないと新窓を閉じたとき誰も grab を持たない |
| 6 | **`grab_current()` 解決不能（stdlib ダイアログ）なら預からない・再 grab しない**（v0.4） | 「保持者なし」と同一視すると **stdlib ダイアログの grab を奪う** |
| 7 | **stdlib ダイアログ経路は対象外**（症状は残す） | — |
| 8 | 置き場所 = **`modal.py` の `install_minimize_grab_custody(app: tk.Misc)`** | `app.py` 直結線 = grab 処理の集約が崩れる / 新コントローラ = 2 ハンドラには過剰 |
| 9 | 正本 = **`features.md` §4.6 の冒頭条項を「表示されている間は」で限定 + 最小化の条項追加** | — |
