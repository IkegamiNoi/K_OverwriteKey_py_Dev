## 問題

Escape を bind しているのにキーボードフォーカスをダイアログ内へ移していないダイアログ
（孤児ファイルの棚卸し / 隔離の管理 / 参照元を掃除）があり、実使用で Escape が親の App へ抜けた。
既存テストは `focus_force()` を先に呼ぶためこの欠落を検出できなかった。

  **C**（Escape bind なし・5）。

## 確定した設計判断（ユーザー確定 2026-09-22 〜 09-23）

- **フォーカスは `grab_modal` の責務へ集約**（案 B。個別修正の案 A は不採用）。
- **実装方式 = 明示引数** `grab_modal(window, parent=None, *, focus=None)`（省略時は窓自身）。
  **推測型（`focus_lastfor()` 既定 / `after_idle` で補正）は実測で反証**: 未マップの窓への `focus_set()` は
  Tk 内で保留されマップ後に解決されるため、`grab_modal` 側から既存の明示指定を検出できず、
  **群 A の初期フォーカスを奪う**（v0.1 → v0.2 で変更）。
- **`focus_force` / `lift` は呼ばない**（他アプリで作業中のユーザーから入力を奪わない）。
- **群 C にフォーカスが入る挙動変化を受容**し、**正本へ Escape 条項も追加して群 C の 5 経路へ Escape を結線**
  （× と同じ閉じ方へ。`io_dialogs.py` のみ `on_cancel`）。
- **フォーカスの復帰（閉じた後・最小化復帰後）はスコープ外**。実機目視で再現確認のみ。
- **idea_18 を同梱**。同型スケルトンの共通化は合流させない（`current.md`「別タスク化候補」に残置）。

## 実装上の判断

- **idea_18 の根 = 配送の遅さではなくフォーカス不在**（task_04 の診断）。Tk はキーをフォーカス窓へ再配送するため、
  **そのダイアログを持つ Tk アプリが入力フォーカスを持たないと Escape は破棄される**。既存テストは `focus_force()` が
  効いたかを確認せずに送っていた。→ 案 B（待つだけ）では直らない（届かなかったイベントは後から来ない）。
  **`send_escape` = フォーカスがダイアログ配下に入ったのを確認してから送り、破棄を上限つきで待つ**。
  失敗は診断情報つきで fail（`skipTest` は使わない）。
- **案 A（ハンドラ直呼び）は併用しない**: 実配送のまま安定させられるので「実際に届くか」の検証を捨てる理由がない。
- `ActionDialog` の `mouse_click` 経路（`disabled` 化）は、`focus_set` との前後関係でフォーカス先が変わらないことを実測。

## task_05e（v0.7・押しっぱなし Esc の退行修正）

- 実現形 = 3 ダイアログの `_on_escape` を **①記録・取得中 → 停止して `_escape_held` を立てる ②`_escape_held` → 閉じない
  ③それ以外 → 閉じる** の順にし、常時結線の `<KeyRelease-Escape>` で印を消す。**Esc 以外の停止（ボタン・記録完了）では印を立てない**。
- **判定順は v0.7 の敵対的レビューで確定**: 印を先に見ると、離したことを取りこぼして印が残ったまま記録を再開した場合に
  **再開後の Esc が停止に届かない**。取りこぼし時は「記録・取得中でないときの次の Esc が 1 回だけ無視される」を受容。
- 群 A の「閉じない」検査は `acquire_focus`（`send_escape` の確保部分を公開）へ揃えた（M2）。
- 実測: `tests_ui` 507 → **509** ×2 / **変異検査**（印の分岐除去 → 押しっぱなしのテスト赤 / 判定順逆転 → 再開のテスト赤）/
  `reviewer` 完了可 / **実機目視 A3 OK**（3 経路）。
