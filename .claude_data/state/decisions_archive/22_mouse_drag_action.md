## 問題

出力シーケンスのマウス操作が**単発クリックのみ**で、範囲選択もドラッグ&ドロップも送れない。
掴む点と離す点の 2 点 + カーソルの移動速度を指定して、押したまま移動する操作を送れるようにする。

## 確定した設計判断（ユーザー 2026-09-19・暫定仕様 19 §2）

| # | 判断 | 採らなかった案と理由 |
|---|---|---|
| 1 | **既存の `mouse_click` を拡張**（`drag` / `to_x` / `to_y` / `drag_speed` を追加） | 新種別 `mouse_drag` = 種別ドロップダウンが増え、表示と保存時の種別がずれる |
| 2 | **UI はチェックボックス方式**（チェックで離す点と速度の欄が現れる） | 常時表示 = クリックだけの利用者に無関係な欄が出る |
| 3 | **速度は px/秒で指定**（既定 1000） | 所要時間 ms 指定 = 距離が変わると体感速度が変わり指示を組みにくい |
| 4 | **所要時間 = 距離 ÷ 速度を 0.15〜5.0 秒へクランプ** | 下限なし = pyautogui が補間せず瞬間移動（補間は `duration > 0.1` のときだけ）/ 上限なし = UI スレッドが長時間固まり停止キーも効かない（アクションは `app.after(0, ...)` で UI スレッド実行） |
| 5 | **`dragTo` を使わず `mouseDown` / `moveTo` / `mouseUp` へ分解**し、`finally` で必ず離す | `dragTo` は try/finally を持たず、移動中の例外でボタンが押しっぱなしになる |
| 6 | **ドラッグ中は `pyautogui.FAILSAFE` を False にし `finally` で復元**（v0.4 で方式変更） | ①解放直前に FailSafe 判定が走るため**離す点が隅だと解放自体が遮られる** ②解放直前だけ外す案 = 画面端沿いのドラッグで補間点が隅に一致すると意図せず中断 ③`ctypes` で直接解放 = Windows 専用分岐が増え macOS 対応時に再実装（**OS 分岐を増やさない**を優先） |
| 7 | **`drag` true のとき `clicks` は 1 固定**（キーは残す・回数欄は無効化） | 回数を掛ける = 意味が定義できない |
| 8 | **`to_x` / `to_y` の欠落・変換不能は実行時エラーで何も送らない**（クリックへフォールバックしない） | 座標は「意図そのもの」。button / clicks の寛容さとは区別する |
| 9 | **`drag_speed` の欠落・変換不能・0 以下（NaN 含む）は既定 1000** | 厳格化 = 手書き JSON の縁辺ケースで実行不能になる |
| 10 | **`drag` false のとき新 4 キーを出力しない**（生成停止。能動削除はしない） | `pop` による削除 = §5.1 の「既存キーの削除禁止」に反する |
| 11 | **マウス操作は send guard の対象外のまま**（明文化のみ） | guard へ入れる = 挙動変更。フックはキーボードのみで自己受信しない |
| 12 | **失うものを受容**: ドラッグ中（最長 5 秒程度）の四隅による緊急停止 | FailSafe はマウス操作にしか効かず、ドラッグ中はアプリ側もカーソルを動かすため確実な停止手段ではない |
