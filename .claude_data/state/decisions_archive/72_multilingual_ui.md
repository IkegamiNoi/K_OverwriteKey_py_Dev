## 確定した設計判断（ユーザー 2026-11-01〜11-04）

| # | 判断 | 採らなかった案と理由 |
|---|---|---|
| 1 | 日英 2 言語・言語は設定で選ぶ・言語コードごとのファイル・一覧は置いたファイルから | OS の言語に合わせる = 利用者が選べない |
| 2 | 次回の起動から反映し、選んだ直後に選んだ言語で知らせる。知らせから「今すぐ再起動」（普段の終了を通し同じ Python・引数・作業フォルダで起動し直す・v0.6） | 即時反映 = 約 1,000 か所の作り直しと開いている子窓・編集中の状態の扱いが要る / 再起動ボタンなし = ユーザーが不便と判断 |
| 3 | `ui_language` が無いときは英語（今の利用者もアップデート後は英語で開く・案 A） | 無いときは日本語 = 新規の利用者に日本語が出る |
| 4 | 訳が足りない文言は 選んだ言語 → 英語 → 日本語 → キー | 日本語へ直接 = 3 言語目で読めない文言が出やすい |
| 5 | 内側の層も作る時点で `tr`（言語は実行中に変わらない） | キー + 引数の例外を presentation で訳す = 約 290 か所の形を変える |
| 6 | `tr` / `tr_in` の最初の引数を位置専用・静的検査の許可を内容・場所・理由の組で照合し未使用の許可も失敗（Codex 敵対的の採用） | — |
| 7 | 英語の表記 E1〜E7: sentence case + **機能名は文中も各語の先頭を大文字**（v0.5。Mac でも文言を分けないため機能名の一貫を優先） | OS ごとの作法（Mac の title case 等）に合わせて文言を分ける |
| 8 | アクションの種類の表示名は種類のコンボボックス・マウスのボタンに使う。**出力シーケンスの一覧の行頭の印は全言語共通の英語の短い名前**（`[click]`・`[scroll]`・`[press]` / `[release]`・v0.7） | 言語ごとの表示名（メイン推奨）= 幅が増え言語ごとに見た目が変わる |
| 9 | メニューの項目名はどの言語でも「Language」（v0.6） | 「言語 / Language」の併記 = 言語が増えると足し続けることになる |
| 10 | 英語のヘルプの変換・無変換は「一部の特殊キーの注意 + JIS は例」・キー名に日本語を併記 | JIS を主題に書く = 日本語以外の読者には主題でない |
